# FS-008 아이콘 홈·업무·학습 도움말 화면 설계

작성: 2026-09-20. 상태: 화면 설계 및 로컬 상태 시제품 완료. 실제 React/API/DB 구현과 브라우저 표시 검증은 미완료.

## 1. 이번에 결정한 화면 구조

사용자 제공 Odoo 이미지처럼 독립된 정사각형 아이콘과 짧은 이름, 넓은 간격을 사용한다. 자체 SVG 아이콘을 작성했으며 외부 이미지·폰트에 의존하지 않는다. 밝은 회보라 배경과 청록색 동작 버튼은 검토용 색상이며 최종 브랜드 확정은 아니다.

- 홈: 사업장·개인 공간 표시, 학습 이어하기, 앱 검색, 6개 앱 아이콘. QMS/WMS/ERP는 실행 버튼 없이 준비 중으로 분리한다.
- 학습: 과정 목적, 전체 7단계, 준비물, 현재 단계 이어하기.
- MES: 같은 업무 화면에서 가이드/자유 탐색 진입을 구분한다. 업무 데이터는 전환해도 유지한다.
- 도움말: 목적·준비사항은 먼저 표시하고 순서·오류·다음 업무는 접어서 제공한다.
- 결과: 업무 실적 확정과 전체 학습 완료를 구별하고 다음 공정의 투입 근거를 설명한다.
- 모듈 관리: 항상 필요한 공통/학습과 선택 앱을 구분한다. 비활성화는 삭제가 아니다.

## 2. 화면 및 이동 계약

| 화면 | 주요 내용 | 진입 / 복귀 | 제품 완료 근거 |
|---|---|---|---|
| H01 앱 홈 | 아이콘·검색·이어하기 | 모든 화면의 상단 로고 → 홈 | 검색/접근 가능 앱 목록 |
| L01 학습 경로 | 과정 v1.0·현재 단계·준비 조건 | 학습 시작 아이콘 / 업무의 학습 경로 버튼 | 서버의 시도와 단계 상태 |
| M01 공정 실행 | 지시·LOT·설비·투입·실적 | MES 아이콘 또는 L04 이어하기 | 해당 공간/세대의 실행 상태 |
| M02 확정 결과 | 양품·불량·다음 업무 | 확정 후 / 이어하기 | 확정 실적 재조회 |
| N01 업무 연결 | 이전 양품→다음 투입 | 결과의 다음 업무 / 결과로 복귀 | 다음 공정 선행 조건 |
| C01 모듈 관리 | 켜짐/꺼짐·차단 이유 | 홈 아이콘 / 부족 조건 해결 링크 | 설정 API 및 의존/진행 업무 검사 |
| E01 후속 화면 | FEMS/BEMS/통합 연결 개념 | 각각의 아이콘 / 홈 복귀 | 상세 구현 예정 표시 |

진입 흐름: 홈 → 학습 → 준비 조건 → 업무 → 결과 → 다음 업무. 자유 탐색도 동일 업무 화면을 사용한다. 이전 화면 방문은 업무 상태를 되돌리지 않는다.

시제품은 L01~L03 완료 예시에서 L04 다이 접착에 진입한다. 시작 → 양품 995/불량 5/사유 → 예시 확정 → 다음 공정 설명까지 동작한다. L05 실행이나 전체 학습 채점은 구현하지 않았다. 현재 상태는 메모리에만 있고 새로고침 시 초기화된다. 자유 탐색의 임의 수량 저장도 이 시제품에서는 지원하지 않으며 제한 이유를 표시한다. 제품에서는 업무 정합성이 유효하면 저장하고 과제 조건 차이만 별도로 안내한다.

## 3. 상태·오류 설계

| 상황 | 화면 표현 / 처리 | 근거 AC |
|---|---|---|
| 정상 실행 | 시작 전 → 진행 중 → 확정 결과. 다음 공정 투입 가능 수량 표시 | 06–08 |
| 합계 불일치·사유 누락 | 입력을 보존하고 폼 옆에 원인·수정 안내. 확정하지 않음 | 13 |
| 모듈 꺼짐 | 필요한 앱 이름과 모듈 관리 진입 제공. 자동 활성화 금지 | 02 |
| 발행 지시가 있는 MES 끄기 | 해당 업무 정리가 필요하다는 이유 표시 | 34 |
| 준비정보 부족 | 누락된 품목/경로/설비와 수정 위치 표시 | 03 |
| 요청 중 | 실행 버튼 중복 조작 차단. 요청 처리 상태 표시 | 16–19 |
| 응답 불명 | 성공/실패로 단정하지 않고 동일 요청 결과 확인 제공 | 19 |
| 학습 기록만 실패 | 생산 완료를 유지하고 진도 확인 재시도 제공 | 21 |
| 세션 만료 | 로그인 후 확정 저장분 복구, 미저장 내용 구분 | 33 |
| 세대 변경 | 완료 기록 보존, 미완료 시도는 실습 다시 준비 안내 | 26–28 |
| 자유 수량과 과제 차이 | 업무 성공 유지, 학습 과제와 차이를 별도 표시 | 32 |
| FEMS/BEMS 비활성 | MES 완료는 유지, 후속 과정의 필요 조건만 표시 | 30 |

위 표는 제품 구현 계약이다. 시제품에서 직접 모사한 것은 정상 L04, 합계/사유 오류, 모듈 설정과 MES 끄기 차단이다. 나머지 네트워크·권한·초기화 상태는 설계만 했으며 실제 구현 때 AC별 검증을 연결한다.

## 4. 공통 UI 구성과 데이터 연결

| 구성 요소 | 책임 | 관련 설계 데이터 |
|---|---|---|
| AppShell / AppLauncher | 홈 복귀, 앱 가용 상태, 공간 맥락 | workspace, workspace_module |
| LearningResume / StepTrail | 현재 시도·단계 표시 | learning.attempt, step_progress |
| WorkContext | 지시·LOT·경로·설비 요약 | work_order, lot, route_step, equipment |
| OperationForm / ResultSummary | 실행 가능 동작·입력·확정 결과 | operation_execution, operation_result |
| LearningHelp | 목적·준비·순서·오류·다음 연결 | course_version, step, question |
| ModuleSettings | 선택 앱과 차단 이유 | workspace_module + 소유 모듈 정책 |
| Feedback | 입력 오류·요청 처리·복구 안내 | API 오류 계약 / request_receipt |

UI의 숨김/비활성 상태는 권한 검증을 대신하지 않는다. 서버는 공간·세대·권한·모듈·업무 상태를 다시 검사한다. 화면을 열거나 버튼을 누른 사실만으로 학습 완료를 기록하지 않는다. 신규 테이블이나 컬럼이 필요하지 않아 FS-007 Excel/메타데이터 버전은 유지했다.

## 5. 반응형·접근성 기준

- 넓은 화면은 홈 6열 아이콘, 업무와 도움말 2열. 850px 이하는 홈 3열과 업무/도움말 세로 배치.
- 480px 이하에서는 입력을 1열, 이어하기 안내와 버튼을 세로로 배치한다. 목표 최소 폭은 360px이다.
- 기본 button/input/label/details를 사용하고 키보드 포커스 외곽선을 표시한다. 상태는 색상뿐 아니라 텍스트로 표현한다.
- 화면 이동 후 제목으로 포커스를 옮긴다. 오류 영역은 role=alert, 설정 결과는 role=status를 사용한다.
- 실제 360px 오버플로·키보드 전체 동선·스크린리더·대비 측정은 브라우저 검증 단계에 남아 있다.

## 6. 산출물·검증·제약

시제품: `prototypes/fs-008-ui.html` (파일을 브라우저로 직접 열어 사용). 이전 `factory-studio.html`은 이전 시점 참고본으로 유지한다.

실행한 검사: Node VM에서 스크립트 문법, 8개 화면 템플릿 렌더 함수, 합계/사유 오류 시 확정 차단, 정상 확정 상태, 홈 복귀 후 결과 이어보기, MES 끄기 차단, FEMS 켜기/끄기를 검증했다. DOM은 최소 스텁을 사용했으므로 브라우저 테스트가 아니다.

브라우저 검증 시도: 번들 Playwright의 브라우저 실행 파일이 없었고 설치된 Chrome 실행도 SIGABRT로 실패했다. 이후 브라우저 도구가 로컬 HTML URL을 보안 정책으로 차단하여 더 이상 우회하지 않았다. 실제 렌더링, 스크린샷, 클릭/키보드/모바일 검증은 미완료다.

일정: FS-008 설계 산출물 완료. 실행 기반 구축 후 브라우저 검증 환경을 마련하고 FS-012 앱 홈 구현에서 시각·접근성 검증을 수행한다. 실제 사용자 검토에 따라 간격·색상·아이콘은 조정한다. 이번 결과로 구현 일정이나 사용자 시험 시간을 단축 확정하지 않는다.
