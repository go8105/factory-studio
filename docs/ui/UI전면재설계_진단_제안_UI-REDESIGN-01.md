## 2. 결론 먼저

**문제는 디자인 시스템의 부재가 아니라 적용률이다.**

- 토큰은 있다. `shared/styles.css` `:root`에 색·간격·폭·반경·높이 50여 개.
- 공통 컴포넌트도 있다. `DataTable`·`FormPanel`·`DetailPanel`·`EmptyState`·`ErrorNotice`·`Badge`·`Field`·`MasterScreen`·`useDiscardGuard` 등 20여 개.
- 규약도 있다. UI-02가 스크롤 소유권·패턴 3종·반응형 기준점까지 문장으로 못 박았다.

그런데:

| 항목 | 공통 | 각자 구현 |
|---|---:|---:|
| 표 `<table>` | 1 (`components.tsx:440`) | **56곳** |
| 상태 배지 | 1 (`Badge`) | **6가지 방식** |
| 오류 표시 마크업 | 1 (`ErrorNotice`) | **7가지 변형** |
| 조회 훅 | 1 (`useApiLists`) | `useGet` 4벌 + 모듈 전용 3벌 |
| 하드코딩 색상값 | 토큰 50여 개 | `#` 리터럴 **470개** |
| 앱 셸 | `SolutionLayout` 10개 모듈 | flow·factory·cad-cam·포털 내 공간 4갈래 |

**UI-02 이후 1년 넘게 솔루션이 6 → 11개, 화면이 55 → 152개로 늘면서 규약이 따라가지 못했다.** 전면 재작성이 아니라 적용률 회복 + 탐색 구조 재설계가 맞는 처방이다.

## 4. 진단 — 사용자가 보는 순서대로

### 4-1. 탐색 구조(IA)가 가장 나쁜 지점

**두 개의 내비게이션이 동시에 경쟁한다.**

- 위: 전역 헤더 10개(앱 런처 · CAD·CAM · 3D 공장 · 전체 흐름 · 내 공간 · 내 계정 보안 · 도움말 · 사용자 관리 · 운영 기록 · 나가기). `App.tsx:85-116`에 **하드코딩**이고 메뉴 카탈로그를 쓰지 않는다.
- 왼쪽: 솔루션 사이드바 최대 23항목 + 그룹 7개 + 행마다 ★ + 상단 "즐겨찾기 / 전체 메뉴" 토글.

어느 쪽이 주 내비인지 화면이 말하지 않는다. 업무 화면에서 자주 쓰는 것은 왼쪽인데, 시선이 먼저 닿는 위쪽에 관리·계정 링크가 늘어서 있다.

**지금 어느 솔루션에 있는지 헤더가 알려주지 않는다.**
헤더는 늘 "Factory Studio · 제조 현장의 올인원 시스템"이다. 솔루션 이름("FEMS 에너지관리")은 사이드바 맨 위 작은 회색 글씨뿐이다. 사이드바를 접으면 단서가 사라진다.
덧붙여 "올인원 시스템"은 FS-013 D1(독립 솔루션)과 어긋나는 문구다. UI-DESIGN-01이 2026-10-09에 이미 지적했으나 홈 제목에 남아 있다.

**솔루션 전환이 막다른 길이다.**
사이드바 하단 "다른 앱" 목록이 모듈마다 `*Layout.tsx`에 **복사**돼 있고 서로 다르다.

| 모듈 | "다른 앱" 구성 | 근거 |
|---|---|---|
| gw | MES·ERP·FEMS 3개뿐 | `gw/GwLayout.tsx:129-136` |
| bems | 9개 + 포털 3개 | `bems/BemsLayout.tsx` |
| cmms | GW 누락 | `cmms/CmmsLayout.tsx:6-15` |
| 전체 | **어느 모듈에도 `/hr`·`/cmms`·`/work-os`가 없다** (gw만 일부 보유) | 9개 `*Layout.tsx` |

즉 CMMS·HR에 들어가면 사이드바로는 나올 수 없다. 헤더 "앱 런처"를 거쳐야 한다.

**내부 식별자가 사용자 라벨에 노출된다.** 사이드바와 페이지 제목에 `F-01`·`M-03`·`W-12`·`E-02`가 그대로 보인다. 설계 추적용 ID이지 사용자 언어가 아니다. (다만 도움말·문서가 이 ID로 연결돼 있어 단순 삭제는 못 한다 — 5-1에 대안.)

**모바일에서 전역 내비 절반이 사라진다.** 375px에서 헤더 `nav`의 내용 폭은 **620px**이고 `overflow-x: auto`다. 가로 스크롤은 되지만 스크롤 단서가 없어 "내 공간" 이후 항목이 보이지 않는다. 페이지 자체가 넘치는 결함은 아니다(`document.scrollWidth = 375`).

### 4-4. 체감 성능

1440×900 로컬에서 FEMS·WMS 대시보드는 첫 1~2초 **완전한 백지**다(스켈레톤·로딩 표시 없음). MES는 "불러오고 있습니다" 텍스트만 나온다. 공통 `Loading`에 `delay={300}` 옵션이 있으나 대시보드 전체에는 적용돼 있지 않다.

### 4-5. 잘 되어 있는 것 (바꾸지 말 것)

- 토큰 체계와 색 정체성(백자·먹색·쪽빛, 그림자 4%)은 일관되고 저채도 업무 화면에 맞다.
- `DataTable`·`FormPanel`의 패널 패턴(1600px 붙음 / 1599px 겹침 / 600px 전체)은 설계가 촘촘하고 포커스 가둠·Esc·배경 클릭까지 처리한다.
- `useDiscardGuard`는 훅 하나로 40화면 미저장 보호를 건다.
- FEMS 대시보드(F-01)·ERP 견적(E-02)처럼 규약을 지킨 화면은 보기에 문제없다.
- 메뉴 카탈로그 단일 출처(`menu_catalog.json`)는 이미 옳은 구조다. 쓰지 않는 곳이 문제다.

## 6. Figma 연동 — 가능한 것과 불가능한 것

### 현재 상태

- **Figma MCP(`plugin:figma:figma`)는 이 환경에서 인증되지 않았다.** 사용자가 `/mcp`로 승인해야 도구를 쓸 수 있다. 승인 전에는 Figma 읽기·쓰기 모두 불가능하다.
- 과거 기록: 2026-09-27 `whoami` 결과 **Starter 플랜 · View 좌석**(`docs/progress.md:3868`). 2026-10-13 CAD-UI03에서 Design 파일 생성에는 성공했다(5가족 17 variants · 20 변수 · 3 텍스트 스타일 · 113 인스턴스). 다만 마지막 보정 후 **screenshot 3건이 Starter MCP tool call limit으로 전부 거절**돼 최종 검증을 못 했다.

### 경고

7화면 한 파일이 한도에 걸렸다. **"전체 UI 구조를 Figma에 다시 잡는다"를 글자 그대로 하면 152화면 × 11솔루션이고, Starter 플랜에서는 완주할 수 없다.** 중간에 끊기면 "반쯤 만든 Figma 파일"이 코드와 따로 노는 세 번째 기준본이 된다. 지금 문제(기준본이 여럿)를 키우는 결과다.

### 제안하는 Figma 범위

코드가 기준본이고 Figma는 **합의·검토 도구**다. 다음까지만 만든다.

| 단계 | 산출물 | 대략 규모 |
|---|---|---|
| F1 | **변수(토큰)** — `styles.css` `:root`를 Figma 변수로. 색 20 · 간격 6 · 반경 3 · 폭 5 · 글자 6 | 약 40 변수 |
| F2 | **핵심 컴포넌트** — Button(3) · Field(2) · Badge(3) · DataTable 행 · FormPanel · EmptyState · ErrorNotice · PageTitle · Sidebar 항목 | 9가족 · 20 variants 안팎 |
| F3 | **대표 화면 4장** — ① 솔루션 대시보드 ② 조회 목록 ③ 목록+패널 ④ 새 앱 셸(헤더·솔루션 전환) | 4 프레임 |

나머지 148화면은 Figma에 그리지 않는다. 같은 3패턴의 반복이므로 코드에서 컴포넌트로 찍는다.
F1~F3도 한도에 걸릴 수 있다. **한 단계씩 끊어서 하고, 끊기면 그 지점을 기록하고 멈춘다.** 검증 못 한 것을 완료로 쓰지 않는다.

Figma 작업 전에는 `figma:figma-use`·`figma:figma-generate-library`·`figma:figma-generate-design` 스킬을 규칙대로 먼저 불러온다.
