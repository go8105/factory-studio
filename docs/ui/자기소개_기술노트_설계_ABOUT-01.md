## 2. 결론 먼저

- **경로:** `/about`(자기소개), `/notes`·`/notes/:slug`(기술 노트). 둘 다 `Private` 밖, `Entry`처럼 앱 셸(`Layout`) 없이 단독 화면.
- **구현:** 새 라이브러리 없음. 콘텐츠는 `content/about/*.md|json`, `content/notes/*.md` 정적 파일. 렌더링은 기존 `shared/content.tsx`의 `import.meta.glob` + `MarkdownContent` 재사용. 백엔드·DB 변경 없음.
- **디자인:** AGENTS.md 7장 기준(백자 `#F7F7F6`, 먹색 `#1A1C1E`, 쪽빛 `#1F2D3D`, 단색 라인 아이콘, 그림자 ≤4%, 저채도 배지). **PC(1440) 기준으로 설계한다(사용자 결정 2026-11-08).** 모바일 전용 시안은 만들지 않는다.

## 6. 기술 노트 (`/notes`)

### 6-1. 방식
- **Notion API 실시간 연동은 하지 않는다.** 토큰 관리·비공개 글 노출 위험·응답 지연이 생긴다. 고른 글만 다시 써서 `content/notes/<slug>.md`로 둔다.
- 머리말(front matter 없이 기존 `contentTitle` 규칙과 맞춘다): 1행 `# 제목`, 2행 `> 2026-11-08 · 카테고리 · 태그1, 태그2`. 별도 파서를 만들지 않기 위해서다.
- 목록은 파일명 앞 날짜(`2026-11-08-flux-query-branching.md`) 역순.
- 카테고리 6종: FEMS 아키텍처 · 산업 데이터 수집 · AI · MES·DB · 배포·인프라 · 제조 IT 기초.

### 6-2. 첫 묶음 후보 (5~6편) — 원본은 제목만 확인, 본문 분량은 다시 쓸 때 확인

## 9. 예상 문제점 · 제약

1. **링크 미리보기(카톡·슬랙):** SPA라 크롤러가 JS를 안 돌리면 `/about`의 og 태그가 index.html 기본값으로 나온다. **결정(Q4): Nginx가 `/about`에만 og 태그가 다른 정적 `about.html`을 내보내고, 그 안에서 같은 SPA 번들을 띄운다.** 공용 og는 그대로.
2. **수치 갱신:** 공인시험 결과(2026.11), 경력 기간은 시간이 지나면 낡는다. JSON 한 곳에만 둬서 갱신 지점을 하나로.
3. **원천 자료 불일치** — 공개 전 확정 필요(Q1).
4. **브랜치:** 이 문서는 `ui-redesign-01` 위에서 갈라졌다. 구현은 UI-REDESIGN 작업 머지 이후가 안전하다(공통 CSS 변경과 충돌 가능).
