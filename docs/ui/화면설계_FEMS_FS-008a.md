## 1. FEMS는 무엇을 보여주는가

**계측값을 받아 설비별로 배분하고, 생산량과 묶어 원단위를 내고, 목표·요금·배출량으로 환산해 보여주는 솔루션이다.**

평가자 관점의 3분 동선은 다음과 같다.

```
대시보드(전체 소비·목표 달성률)
  → 설비별 배분 (어느 설비가 많이 쓰는가)
  → 원단위 분석 (제품 1개당 얼마나 쓰는가)
  → 배출량·요금 (그래서 돈과 탄소가 얼마인가)
```

**계측 수집 파이프라인은 만들지 않는다.** MQTT·알람 서버 없음. 계측값은 seed로 생성한다. 화면은 조회·등록·분석만 담당한다.

## 2. 메뉴 구조 (14화면)

```
FEMS
├─ F-01  대시보드
├─ 에너지 현황
│   ├─ F-02  계측 조회
│   ├─ F-03  설비별 배분
│   └─ F-04  배출량 현황
├─ 원단위·목표
│   ├─ F-05  생산량 등록
│   ├─ F-06  원단위 분석
│   └─ F-07  목표 대비 실적
├─ 요금
│   └─ F-08  요금 산정
└─ 기준정보
    ├─ F-09  사업장·공간
    ├─ F-10  설비
    ├─ F-11  에너지원
    ├─ F-12  계측기·채널
    ├─ F-13  환산·배출계수
    └─ F-14  요금제
```

### 기준정보 등록 순서 강제

`fems.meter_channel`은 `energy_source`와 `meter`를 모두 참조한다. 따라서 등록 순서가 강제된다.

```
사업장 → 공간 → 설비 ┐
                    ├→ 계측기 → 채널
        에너지원 ────┘
```

**신규 사용자가 F-12(채널)부터 들어가면 선택할 상위 항목이 없어 막힌다.** 기준정보 화면 상단에 등록 순서 안내 스텝을 공통으로 두고, 선행 데이터가 없으면 해당 단계로 보내는 링크를 빈 상태에 넣는다. (8장 갭 G-07 참조)

## 3. 대시보드와 현황

### F-01 대시보드

| 항목 | 내용 |
|---|---|
| 목적 | FEMS에 들어온 사람이 3초 안에 "이번 달 얼마나 썼고 목표 대비 어떤가"를 안다 |
| 데이터 | `energy_reading` `energy_allocation` `energy_target` `energy_factor` `tariff` |
| 기본 범위 | 활성 세대 / 전체 사업장 / 당월 |

```
┌──────────────────────────────────────────────────┐
│ 에너지 개요                    [당월 ▾] [사업장 ▾] │
├──────────────────────────────────────────────────┤
│ ┌────────┐ ┌────────┐ ┌────────┐ ┌────────┐      │
│ │ 총 소비 │ │ 목표대비│ │ 예상요금│ │ 배출량 │      │
│ │ 1차환산 │ │  %     │ │  KRW   │ │ tCO2eq │      │
│ └────────┘ └────────┘ └────────┘ └────────┘      │
├──────────────────────────────────────────────────┤
│ 에너지원별 구성          │  일자별 추이            │
│ (전력·가스·용수 막대)     │  (선)                  │
├──────────────────────────────────────────────────┤
│ 설비별 소비 상위 5        │  최근 계측 품질 이상    │
└──────────────────────────────────────────────────┘
```

- **에너지원별 구성은 1차에너지 환산 후에만 합산한다.** 전력 kWh와 가스 Nm³를 그대로 더하지 않는다(AGENTS §3). 환산계수는 `energy_factor.factor_kind = PRIMARY`.
- "계측 품질 이상"은 `energy_reading.quality`가 정상이 아닌 건수. FS-005b 시드에 누락 구간을 의도적으로 심어 두었으므로 빈 카드가 되지 않는다.
- 빈 상태: 기준정보가 없으면 KPI 대신 **"기준정보를 먼저 등록하세요"** 안내와 F-11로 가는 링크.

### F-02 계측 조회

| 항목 | 내용 |
|---|---|
| 목적 | 채널별 원시 계측값을 기간·해상도로 확인한다 |
| 데이터 | `energy_reading` `meter_channel` `meter` `energy_source` |
| 필터 | 기간, 사업장, 계측기, 채널, 에너지원, 품질 |

- 해상도는 **1시간 고정**이다. FS-005b에서 1분 해상도는 30일·9대 기준 388,800행이라 게스트 진입이 불가능하다고 확정했다. 화면에 해상도 선택기를 두지 않는다.
- 표 + 선 그래프 전환. 기본은 표.
- 품질 이상 행은 저채도 배지로 표시한다. **빨강을 쓰지 않는다**(AGENTS §7 저채도 상태 배지).
- 누락 구간은 행을 건너뛰지 말고 **"결측"으로 표시한 행**을 남긴다. 값이 없는 것과 조회되지 않은 것은 다르다.

### F-03 설비별 배분

| 항목 | 내용 |
|---|---|
| 목적 | 계측값을 설비 단위로 배분한 결과를 본다 |
| 데이터 | `energy_allocation` `equipment` `meter_channel` |

- `method_key` / `method_version` / `basis`를 행 상세에 노출한다. **"어떻게 배분했는가"를 설명할 수 있는 것이 이 화면의 존재 이유다.**
- `input_revision`이 다른 결과가 섞이지 않도록, 기본은 최신 revision만 표시하고 이전 revision은 토글로 연다.
- MES 실행 참조는 FS-014에서 제거됐다. **배분 단위는 설비다.** 공정·LOT 기준 배분은 하지 않는다.

### F-04 배출량 현황 (Q3 ①로 신규)

| 항목 | 내용 |
|---|---|
| 목적 | 에너지 소비량을 배출량으로 환산해 본다 |
| 데이터 | `energy_reading` `energy_factor(EMISSION)` `energy_source` |
| 산식 | **총 에너지 소비량 × 배출계수** |

- 에너지원별로 계수가 다르므로 **원별 산출 후 합산**한다.
- `effective_year`로 계수 연도를 맞춘다. 조회 기간이 두 연도에 걸치면 구간별로 다른 계수를 적용한다.
- **환산계수(PRIMARY)와 배출계수(EMISSION)를 섞지 않는다.** F-01의 1차에너지 환산과 이 화면의 배출량은 다른 계수를 쓴다. 화면에도 그 구분이 보이게 각 값 옆에 계수 출처(`source_note`)를 표시한다.
- 산출 결과는 **저장하지 않는다.** 조회 시 계산이다. (갭 G-04 참조)

## 4. 원단위·목표

### F-05 생산량 등록

| 항목 | 내용 |
|---|---|
| 목적 | 원단위의 분모가 되는 생산량을 입력한다 |
| 데이터 | `production_record` |

- FEMS는 품목 마스터를 갖지 않는다(FS-013 §3.5). **품목은 코드 문자열로 직접 입력**한다. MES와 코드가 같을 수는 있으나 무결성은 강제되지 않는다.
- 확정된 기록은 불변이다. 정정은 새 버전으로 처리한다(AGENTS §3).
- 화면에 "MES를 쓰는 환경이라면 생산실적에서 자동으로 넘어오는 값"이라는 안내를 둔다. 독립 솔루션 설계를 감추지 않고 드러낸다.

### F-06 원단위 분석

| 항목 | 내용 |
|---|---|
| 목적 | 제품 1단위당 에너지 사용량을 보고 기준선과 비교한다 |
| 데이터 | `energy_baseline` `production_record` `energy_allocation` |
| 산식 | 기간 에너지량 ÷ 기간 양품 생산량 |

- **에너지원이 다르면 원단위끼리 합산할 수 없다.** 1차에너지 환산 후에만 합산·비교가 성립한다(AGENTS §3). 화면에서 "합계 원단위"를 보여줄 때는 반드시 환산 후 값임을 표기한다.
- 분모가 0이면 계산하지 않고 **"생산량 없음"**으로 표시한다. 0으로 나눈 결과를 무한대나 공백으로 두지 않는다. FS-005b 시드에 생산량 0 구간이 의도적으로 있다.
- 기준선(`energy_baseline`) 대비 증감률을 함께 표시한다.

### F-07 목표 대비 실적

| 항목 | 내용 |
|---|---|
| 목적 | 월 목표와 실적을 비교한다 |
| 데이터 | `energy_target` `energy_allocation` `energy_reading` |

- `target_scope`에 따라 사업장·설비·에너지원 단위 목표가 섞여 있다. **범위가 다른 목표를 한 표에 합산하지 않는다.** 범위별로 섹션을 나눈다.
- `target_month`는 `'YYYY-MM'` 문자열이다. 월 선택기는 문자열로 질의한다.
- 목표가 없는 구간은 "미설정"으로 두고 달성률을 계산하지 않는다.

## 5. 요금

### F-08 요금 산정

| 항목 | 내용 |
|---|---|
| 목적 | 사용량에 요금제를 적용해 예상 요금을 낸다 |
| 데이터 | `tariff` `energy_reading` `energy_source` |
| 산식 | 기본요금 + (사용량 × 사용량 단가) |

- **시간대별 차등(TOU) 가중치를 적용하지 않는다.** `tariff`는 `basic_charge`와 `usage_rate` 단일 구조이며 시간대 구분 컬럼이 없다. 단일 요금제 전제다.
- `effective_from` / `effective_to`로 적용 구간을 고른다. 조회 기간이 요금제 개정을 걸치면 구간을 쪼개 계산하고, 화면에 적용된 요금제를 구간별로 표시한다.
- 통화는 KRW 단일. `currency` 컬럼은 있으나 1차는 고정이다.
- 산출 결과는 **저장하지 않는다.** (갭 G-04)

## 6. 기준정보 (F-09 ~ F-14)

6화면 모두 **목록 + 등록/수정 패널** 동일 패턴이다. 개별 서술 대신 공통 규칙으로 정의한다.

| 화면 | 테이블 | 선행 조건 |
|---|---|---|
| F-09 사업장·공간 | `site` `location` | 없음 |
| F-10 설비 | `equipment` | 공간 필요 |
| F-11 에너지원 | `energy_source` | 없음 |
| F-12 계측기·채널 | `meter` `meter_channel` | 설비·에너지원 필요 |
| F-13 환산·배출계수 | `energy_factor` | 에너지원 필요 |
| F-14 요금제 | `tariff` | 에너지원 필요 |

### 공통 규칙

- **삭제는 RESTRICT다.** 참조 중인 기준정보는 삭제할 수 없다. 오류 메시지에 **무엇이 참조 중인지 건수와 함께** 표시한다. "삭제할 수 없습니다"만 띄우면 사용자가 다음 행동을 못 정한다.
- 비활성화(`is_active = false`)와 삭제를 구분해 안내한다. 대부분의 경우 답은 삭제가 아니라 비활성화다.
- 코드 필드는 세대 범위 안에서 유니크하다. 중복 입력 시 인라인 오류.
- 선행 데이터가 없는 빈 상태에서는 **선행 화면으로 가는 링크**를 제공한다(2장 등록 순서 참조).

### F-12만의 구조

계측기 1건이 채널 N개를 갖는 **마스터-디테일**이다. 좌측 계측기 목록, 우측 선택된 계측기의 채널 목록.

- 채널마다 `energy_source`가 달라질 수 있다. 한 계측기가 전력과 가스를 동시에 잴 수 있는 구조다.
- `multiplier`(계기 배수)는 기본 1이며, 값이 1이 아니면 목록에서 눈에 띄게 표시한다. 계기 배수 오입력은 모든 하위 계산을 조용히 틀리게 만든다.

### F-13만의 구조

`factor_kind`로 PRIMARY(환산)와 EMISSION(배출)이 한 테이블에 섞여 있다. **탭으로 분리한다.** 같은 표에 두면 사용자가 배출계수를 환산계수 자리에 넣는 사고가 난다. 이건 AGENTS §3이 "섞지 말라"고 명시한 지점이다.

## 7. 공통 규격 후보

FEMS에서 임시로 정하지 않고, **포털 스토리보드에서 확정할 공통 컴포넌트 후보**로 올린다.

| 항목 | FEMS에서 필요한 형태 |
|---|---|
| 기간 선택기 | 당월·전월·최근 7일·직접 지정. 월 단위는 `'YYYY-MM'` 문자열 |
| 범위 필터 | 사업장 → 공간 → 설비 계층 선택 |
| 데이터 표 | 정렬·페이지·CSV 내려받기. 대량 조회 없음(1시간 해상도) |
| 상태 배지 | 저채도. 품질·확정·활성 3종 |
| 빈 상태 | 사유 + 다음 행동 링크. "데이터 없음"만 두지 않는다 |
| 오류 표시 | 인라인 우선. RESTRICT 오류는 참조처 건수 포함 |
| 계산 근거 패널 | 배분 방법·적용 계수·적용 요금제를 펼쳐 보는 공통 패널 |
| 미저장 결과 안내 | 배출량·요금처럼 계산만 하고 저장하지 않는 화면의 공통 문구 |

마지막 두 개는 FEMS 고유로 보이지만 ERP의 분개 미리보기가 같은 성격이다. 공통으로 올릴 근거가 된다.

## 8. 스키마 갭 목록 — 이 작업의 핵심 산출물

화면을 그리며 발견한 것이다. **아직 스키마를 고치지 않았다.** 사용자 확인 후 처리 방침을 정한다.

| # | 갭 | 내용 | 심각도 | FS-008b 처리 결과 |
|---|---|---|---|---|
| **G-01** | `energy_allocation.kwh` | 컬럼명과 의미가 **전력 전용**이다. FS-005c에서 FEMS를 다중 에너지원(전력·가스·용수)으로 확장했는데 배분 결과 컬럼은 `kwh` 하나다. 가스 Nm³를 `kwh` 컬럼에 넣으면 단위가 거짓이 된다 | **높음** | 적용 — quantity 개명·비음수 CHECK (FS-008b) |
| **G-02** | 배분 결과의 단위 | G-01과 연결. `energy_allocation`에 `unit` 컬럼이 없다. `meter_channel.unit`을 따라간다고 가정해야 하는데 명시가 없다 | **높음** | 적용 — unit 추가·채널 단위 복합 FK (FS-008b) |
| **G-03** | 1차에너지 환산 결과 | F-01·F-06에서 원별 값을 환산해 합산하는데, 환산 결과를 담을 곳이 없다. 조회 시 계산이면 성능·재현성 문제는 없으나 **설계 의도가 문서에 없다** | 중 | 해소 — PRIMARY 환산 후 조회 합산; 결과 비저장 |
| **G-04** | 미저장 산출물의 범위 | 배출량(F-04)·요금(F-08)을 저장하지 않기로 했는데, 이는 ERP 분개 미리보기와 같은 결정이다. **문서에 명시된 적이 없다** | 중 | 해소 — 배출량·요금 조회 계산, 결과 비저장 |
| **G-05** | `energy_reading.owner_module` | BEMS 폐기(FS-013) 후 값이 `FEMS` 고정이 됐을 가능성이 높다. 잔재 컬럼인지 확인 필요 | 낮음 | 적용 — meter/channel/reading owner 3개 제거; 단위 FK 유지 (FS-008b) |
| **G-06** | `production_record`와 `energy_baseline`의 품목 | 둘 다 품목을 코드 문자열로 갖는다. **두 코드가 일치한다는 보장이 없어** F-06 원단위 분석이 조용히 빈 결과를 낼 수 있다 | 중 | 해소(화면 안내) — 코드 자동완성으로 완화; DB 일치 보장 아님 |
| **G-07** | 기준정보 등록 순서 | DB는 FK로 순서를 강제하지만 **화면 안내가 설계에 없다.** 스키마 문제가 아니라 화면 명세 누락. 본 문서 2장으로 해소 | 해소 | 해소 — 본문 등록 순서 안내 유지 |
| **G-08** | 공장 전체 분모 | FS-014b에서 이미 제약으로 기록된 항목. 공장 전체 원단위의 대표 공정 선정 규칙이 없다 | 기록됨 | 보류 — 공장 전체 대표 공정 선정 규칙 별도 정의 |

### 처리 제안

- **G-01·G-02는 같은 문제다.** `kwh` → `quantity` 로 개명하고 `unit` 컬럼을 추가하는 것을 제안한다. 다중 에너지원을 지원한다고 해놓고 배분 결과만 전력 전용인 것은 설계 모순이다. **이것이 마지막 스키마 수정이 되어야 한다.**
- G-03·G-04는 스키마 변경 없이 **문서 명시**로 해소된다.
- G-05는 확인 후 판단. 남겨도 해는 없다.
- G-06은 화면에서 **생산량 등록 시 기존 코드 자동완성**을 제공해 완화한다. 스키마 변경 없음.

## 9. 이번 작업에서 하지 않은 것

- **스키마 변경 없음.** 갭은 목록화만 했다.
- 포털·MES·ERP 화면 설계. 후속 작업이다.
- HTML 시제품 제작. 본 문서는 텍스트 명세다.
- 실제 화면 구현·브라우저 검증·접근성 확인.
- 색상·타이포그래피 토큰 확정. AGENTS §7 기준만 참조했고 값은 포털에서 정한다.
- FS-008의 기존 시제품(`docs/archive/prototypes/fs-008-ui.html`) 개정. 학습 요소 제거는 포털 작업에서 처리한다.
