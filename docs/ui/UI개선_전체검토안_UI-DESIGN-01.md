# 도움말·디자인 스킬·UI 전체 검토안 — UI-DESIGN-01

2026-10-09. 도움말·스킬 적용 완료 / 화면 구조 변경은 사용자 전체 확인 대기. [구조 검토 시제품](previews/UI-DESIGN-01.html). 시제품 버튼은 검토용이며 실제 분석·세션 생성 기능은 없다.

## 기획 의도 검토

제조 업무를 살펴보려는 방문자는 빠르게 체험에 들어가고, CAD·CAM 사용자는 설계나 경로에 집중하며, 공장 방문자는 탐색과 공정 체험을 구별할 수 있어야 한다. 기존 백자·먹색·쪽빛 정체성과 기능을 유지한다.

원본 [Taste](https://github.com/Leonxlnx/taste-skill)와 [Impeccable](https://github.com/pbakaus/impeccable)는 Codex에서도 사용할 수 있다. 프로젝트의 `.agents/skills/`에 고정 revision으로 설치한 뒤 적용 범위를 보정했다. 원문·라이선스·출처를 보존했고 실행기·다운로드·hook·agent 설정은 포함하지 않았다. Taste 기본 v2의 원문은 experimental이므로 프로젝트의 적용 기준을 고정한다. GPT 변형은 강제 GSAP·모의 난수 실행 등의 지침이 업무 앱과 맞지 않아 선택하지 않았다.

- **Taste**: 랜딩 전용, 구성 편차 5 / 모션 2 / 밀도 4. 기존 Vite/CSS·한글 글꼴 유지. 장식보다 실제 제품과 체험 진입.
- **Impeccable**: CAD·CAM/공장 Operate, 도움말 Read. 작업 우선순위·상태·오류·키보드·모바일·렌더링 성능을 기준으로 적용.

## 현재 문제와 제약

| 화면 | 코드에서 확인한 문제 | 개선 기준 |
|---|---|---|
| Entry.tsx 랜딩 | 이미 단순하지만 임의 영문 번호와 “올인원” 문구가 독립 솔루션 정의와 어긋남 | 실제 제공 기능을 짧게 설명하고 별칭 진입을 선명하게 |
| CAD 외부 셸 | 포털·셸·iframe 헤더가 높이를 나눠 쓰며 min-height 640px로 이중 스크롤 가능 | 제목·뷰 전환을 압축하고 작업 공간 높이 확보 |
| NC 검토 | 300px 입력 열에 파일·소재·전력·품질 조건이 누적되고 결과·휴디와 동선이 떨어짐 | 준비 단계/중앙 경로/오른쪽 결과로 구분 |
| E1/E2 | 각각 다른 폭·도구 배치, 도구·속성·오류의 공통 위계 부족 | 기존 기능에 공통 도구·속성·상태 규칙 적용 |
| 3D 공장 | 건물/층/걷기/시연/초기화/검사/트럭 버튼이 상단에서 경쟁 | 탐색과 공정 실행을 분리하고 선택 설비만 상세 표시 |

NC 모델·선택 ID/revision·원본 보존·품질 차단·미정 소비·실마이크 미검증은 UI 변경으로 해소되지 않는다. 공장 CNC 시연과 NC 검토는 별개다. 관리자 비누 POC는 공개 도움말·랜딩 이미지에 노출하지 않는다. UI가 바뀌어도 전력 절감 실적이나 실제 CNC 실행을 주장하지 않는다.

## 전체 UI 제안

### 랜딩 — Taste

제목 초안: **“제조 업무를 살펴보고, 직접 설계해 보세요.”** 왼쪽은 제목·짧은 설명·별칭 진입·로그인, 오른쪽은 제조 업무/CAD·CAM/3D 공장의 실제 범위를 보여준다. 동일한 카드 반복 대신 여백과 구분선으로 읽는 순서를 만든다. 최신 공개 합성 화면을 증거 이미지로 사용하되 비공개 제품 자료나 허구 실적은 쓰지 않는다. 검토 시제품은 구성 판단용이며 제품 화면 이미지는 후속 구현에서 추가한다.

기존 guest POST·멱등·별칭 보존·오류·회원 로그인·개인정보 안내를 유지한다. 기존 하단 솔루션 목록도 정확한 제공 범위로 남긴다.

### CAD·CAM — Impeccable

외부 제목과 뷰 전환은 작게, 화면별 도움말은 일관된 위치. NC는 왼쪽 준비 단계(파일/공구·소재·STEP/장비·소비/품질·대기), 중앙 경로·소재와 재생, 오른쪽 품질·시간·kWh·후보 비교·휴디로 구분한다. 상세 조건을 펼치고 닫되 입력값·분석 상태를 잃지 않는다. 입력 변경 시 기존 결과와 번호가 무효라는 안내는 결과 옆에 남긴다.

E1/E2는 왼쪽 생성·선택 도구, 중앙 스케치/형상, 오른쪽 선택 속성·작업 조건을 정돈한다. 일반 도구와 전문 편집 도구의 진입을 구별하고 Undo/Redo는 보이는 버튼과 단축키를 함께 유지한다. 공통 색·버튼·라벨·간격 규칙을 적용하되 공정/커널/파일 형식은 변경하지 않는다.

### 3D 공장 — Impeccable

상단은 건물·층·탐색 모드, 중앙은 기존 3D 장면, 오른쪽은 선택 설비와 실행 조건, 하단은 시연 재생·초기화·현재 이동 안내. 설비가 없으면 공정 목록을 표시한다. 1인칭 진입 시 이동·검사·나가기 조작으로 전환한다. 트럭/검사 체험은 맥락에 맞는 위치에 둔다.

그래픽 준비/오류, 외관 시 CNC 차단, 탭 숨김 정지, 키 초점·blur 처리, 시연 상태와 수량 의미를 그대로 보존한다. 모델·카메라·애니메이션 엔진의 재작성은 범위 밖이다.

## 상태·반응형·검증

1440/1280px은 작업 공간 우선, 900px 이하에서는 패널을 순차 배치·접기. 390px에서 가로 넘침 없이 입력→뷰포트→결과로 읽는다. 작은 화면에서 데스크톱과 같은 밀도로 강제하지 않는다. 실제 편집기 모바일 조작 가능 여부는 구현 후 검증한다.

포커스·라벨·4.5:1 일반 글자 대비, 색 외 상태 설명, 빈 상태·로딩·오류·결과 무효화·마이크 실패·권한 차단을 확인한다. 장식용 무한 모션·추가 WebGL·새 UI 패키지는 사용하지 않는다. 검토 시제품의 단순 도형은 공간 배치 예시이며 완성 CAD/공장 모델이 아니다.

## 질문과 권장안

**기존 색상과 기능을 유지하고, 위 랜딩·CAD·CAM·3D 공장 구성 전체를 후속 UI-DESIGN-02의 구현 범위로 확정할까요?**

권장안은 이 구성으로 진행하는 것이다. 범위는 레이아웃·표현·접근성·도움말이며 계산 모델·DB·운영 배포를 포함하지 않는다. AGENTS.md §2의 “사용자의 전체 설계 확인 후 제품 개발을 시작한다”와 §1의 한 작업 ID 원칙에 따라 구조 변경은 이번 시제품 확인 뒤 시작한다. 이번 도움말·스킬 설치와 도움말 진입 연결은 사용자가 명시한 범위로 완료한다.
