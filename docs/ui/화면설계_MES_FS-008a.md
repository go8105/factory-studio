# FS-008a MES 화면 설계

작성일: 2026-09-22
전제: [FS-013 전환 결정](../plan/독립솔루션_전환결정_FS-013.md) · 스키마 v0.8.0 / FS-014b (`mes` 21테이블)
선행: [포털 화면 설계](화면설계_포털_FS-008a.md) 6장의 공통 규격을 따른다.
성격: **스토리보드 4차 — MES.** FS-008a 화면 설계의 마지막이다.

---

## 1. MES는 무엇을 보여주는가

**계획이 지시가 되고, 지시가 LOT이 되고, LOT이 공정을 지나 제품이 되는 과정을 추적한다.**

```
생산계획 → 작업지시 → LOT 발행
                        ↓
        공정 실행 → 자재 투입 → 실적 확정 (양품/불량)
                        ↓
              패킹(BOX → PALLET) → 완제품 입고
```

판단 기준은 **추적성**이다. 완제품 박스 하나를 집었을 때 어느 LOT에서 왔고, 어느 설비를 지났고, 어떤 자재가 들어갔는지 역으로 따라갈 수 있어야 한다.

### 범위 경계 두 가지

| 항목 | 처리 |
|---|---|
| **재고 원장** | WMS 소유. **자재 투입 기록만 남기고 차감하지 않는다** |
| **품질 검사** | QMS 미구현. 실적 확정 → 패킹 **직결** |

두 경계 모두 화면에 명시한다. 감추면 결함으로 보이고, 적으면 범위 판단으로 읽힌다.

생산 방식은 **MTS(재고생산)** 다. `work_order.order_type`에 MTO 확장이 예약돼 있으나 ORDER 값은 거부한다.

## 3. 대시보드

### M-01 대시보드

| 항목 | 내용 |
|---|---|
| 데이터 | `work_order` `lot` `operation_result` `finished_goods_receipt` |

```
┌──────────────────────────────────────────────────┐
│ 생산 개요                              [당월 ▾]   │
├──────────────────────────────────────────────────┤
│ ┌────────┐ ┌────────┐ ┌────────┐ ┌────────┐      │
│ │ 진행중  │ │ 당월생산│ │ 양품률 │ │ 입고완료│      │
│ │ 지시 n │ │ 수량   │ │  %     │ │ 팔레트 │      │
│ └────────┘ └────────┘ └────────┘ └────────┘      │
├──────────────────────────────────────────────────┤
│ 공정별 진행 현황          │  불량 사유 상위        │
│ (사출→조립→검사 파이프라인)│                       │
├──────────────────────────────────────────────────┤
│ 계획 대비 실적            │  처리 대기            │
│                          │  · 미확정 실적 n      │
│                          │  · 미패킹 LOT n       │
└──────────────────────────────────────────────────┘
```

- **공정별 진행 현황이 이 화면의 중심이다.** 사출 → 조립 → 검사 3공정에 LOT이 몇 개씩 걸려 있는지 파이프라인으로 보여준다. 숫자 카드만 있으면 제조 시스템처럼 보이지 않는다.
- 양품률 = `Σ good_qty ÷ Σ output_qty`. 시드에 **전량 불량 LOT**이 심어져 있어 100%가 되지 않는다(FS-005b).
- "처리 대기"에서 M-07·M-08로 바로 넘어간다.

## 4. 생산계획

### M-02 생산계획

| 항목 | 내용 |
|---|---|
| 데이터 | `production_plan` `production_plan_line` `item` |

- `target_month`는 `'YYYY-MM'`, `target_week`는 `'YYYY-Www'` 문자열이다. 정수가 아니다.
- **ERP 판매계획 참조는 `sales_plan_code` 문자열이다.** FK가 아니므로 유효성 검증이 없고, ERP 계획 목록을 조회해 고를 수도 없다. 수기 입력이다.
  - 화면 안내: "ERP와 독립이므로 판매계획 코드는 직접 입력합니다. 실제 운영에서는 인터페이스로 연계합니다."
  - **계획 없이도 생산계획을 세울 수 있다.** 이게 독립 솔루션의 증명이다.
- 계획 라인의 **배정 현황**을 표시한다. 계획수량 100 중 작업지시로 80이 배정됐으면 잔여 20을 보여준다.

### M-03 작업지시

| 항목 | 내용 |
|---|---|
| 데이터 | `work_order` `production_plan_line` `route_version` `bom_version` `item` |

- 계획 라인에서 수량을 배정해 지시를 만든다. **배정 합계가 계획수량을 넘을 수 없다**(FS-006b).
- 경로 선택은 **게시된 `route_version`만** 노출한다. 시드에 미게시 경로가 1건 있으므로 필터가 동작하는지 눈에 보인다.
- BOM은 **선택 사항이다**(`bom_version_id` nullable). BOM 없이 지시를 낼 수 있고, 그 경우 자재 투입 시 기준 소요량이 없다(갭 M-G05).
- 상태: 등록 → 발행 → 진행 → 완료 / 취소. 발행 시 LOT이 생성된다.
- **취소는 사유 필수**다. `cancel_reason`이 비어 있으면 저장하지 않는다.

## 5. 생산실행

### M-04 LOT 현황

| 항목 | 내용 |
|---|---|
| 데이터 | `lot` `work_order` `route_version` |

- **작업지시 1건 : LOT 1건**이다(`||..o|`). 한 지시를 여러 LOT으로 쪼개는 분할 생산은 현재 구조로 불가능하다(갭 M-G04).
- LOT을 열면 **전체 이력이 한 화면에 나온다.** 이 화면이 추적성의 증거다.

```
┌────────────────────────────────────────────────┐
│ LOT-2026-0312            지시 WO-0045  진행중   │
├────────────────────────────────────────────────┤
│ 품목  PRD-001 소형 커넥터      계획수량 1,000   │
│ 경로  RT-003 v2 (사출→조립→검사)                │
├────────────────────────────────────────────────┤
│ ① 사출   설비 IJ-02   완료   투입1,000 양품 980 │
│    투입자재  RM-101  1,050 EA                  │
│ ② 조립   설비 AS-01   진행중                    │
│ ③ 검사   ─            대기                      │
└────────────────────────────────────────────────┘
```

- 완료 사유(`completion_reason`)가 있으면 함께 표시한다. 정상 완료와 중단 완료가 구분돼야 한다.

### M-05 공정 실행

| 항목 | 내용 |
|---|---|
| 데이터 | `operation_execution` `route_step` `equipment` `process` |

- 경로 단계 순서대로만 시작할 수 있다. 앞 단계가 안 끝났는데 뒤 단계를 시작하려 하면 막는다.
- 설비를 선택할 때 **해당 공정에 배정된 설비만**(`process_equipment`) 보여준다.
- **설비 동시 점유를 막는 규칙이 스키마에 없다**(갭 M-G07). 한 설비에서 두 LOT이 동시에 실행 중인 상태가 데이터상 가능하다. 화면에서 경고하되 차단은 SERVICE 정책이다.
- 시작·종료 시각을 기록한다. FEMS의 설비별 에너지 배분이 이 구간과 대응하지만, **FK는 없다**(FS-014에서 제거). 설비와 시간으로만 간접 대응한다.

### M-06 자재 투입

| 항목 | 내용 |
|---|---|
| 데이터 | `material_issue` `bom_version` `bom_line` `item` `lot` |

```
┌────────────────────────────────────────────────┐
│ 자재 투입           LOT-2026-0312 / ① 사출      │
├────────────────────────────────────────────────┤
│ 적용 BOM  BM-001 v3                            │
│ 자재       기준소요   로스율   투입수량         │
│ RM-101     1,000 EA    5%     [1,050]         │
│ RM-205       200 EA    0%     [  200]         │
├────────────────────────────────────────────────┤
│ ⓘ 투입 기록만 남기며 재고를 차감하지 않습니다.   │
│   재고 원장은 WMS 영역으로 범위에서 제외했습니다.│
└────────────────────────────────────────────────┘
```

- **BOM 기준 소요량을 기본값으로 채우고 사용자가 수정한다.** 로스율을 반영한 값이 제안된다.
- BOM이 없는 지시면 기본값 없이 빈 입력이다. 그 사실을 화면에 알린다.
- **재고 차감 안내를 반드시 둔다.** 이게 없으면 "재고가 안 줄어드는 버그"로 보인다.
- 자재 LOT(`material_lot_id`)은 선택 사항이다. **NULL이면 UNIQUE 제약이 중복을 막지 못한다**(기존 제약). 같은 실행·같은 자재의 중복 투입을 화면에서 먼저 검사한다.

### M-07 실적 확정

| 항목 | 내용 |
|---|---|
| 데이터 | `operation_result` `operation_execution` |

- 투입 / 산출 / 양품 / 불량 수량을 입력한다. **양품 + 불량 = 산출** 등식을 화면에서 검증한다.
- 불량이 있으면 **사유 필수**다.
- 확정 후 수정 불가. 재산정은 새 버전으로 처리한다(AGENTS §3).
- **QMS가 없으므로 양품·불량을 작업자가 직접 판정한다.** 검사 성적 근거가 없다는 뜻이다. 화면에 "품질 검사는 QMS 영역으로 범위에서 제외했습니다"를 명시한다.
- 시드에 **전량 불량 LOT**이 있으므로 양품 0 케이스의 표시가 깨지지 않아야 한다.

## 6. 포장·입고

### M-08 패킹

| 항목 | 내용 |
|---|---|
| 데이터 | `packing_unit` `packing_member` `lot` |

- **BOX → PALLET 2단 계층**이다(`parent_packing_unit_id`).
- **단일 품목 포장이 원칙이다**(FS-006b). 한 BOX에 서로 다른 품목을 섞지 않는다.
- LOT의 양품 수량을 초과해 담을 수 없다. 이는 **SERVICE 정책**이며 DB 제약이 아니다(갭 M-G08).
- 화면 구성: 좌측 미패킹 LOT 목록, 우측 BOX 구성. 드래그가 아니라 **수량 입력** 방식으로 둔다. 드래그는 모바일에서 깨진다.
- 패킹 번호는 자동 채번한다.

### M-09 완제품 입고

| 항목 | 내용 |
|---|---|
| 데이터 | `finished_goods_receipt` `packing_unit` |

- **PALLET 단위로 입고**한다. 입고된 팔레트가 ERP 출하의 대상이 된다.
- 다만 **ERP는 `packing_no` 문자열로만 참조한다**(FS-013). MES에서 입고해도 ERP 출하 화면에 자동으로 뜨지 않는다. 수기 입력이다.
- 화면에 패킹번호를 **복사하기 쉽게** 배치한다. 사용자가 ERP로 넘어가 붙여넣어야 하므로, 이 작은 배려가 데모 흐름을 끊지 않는다.

## 7. 기준정보 (M-10 ~ M-15)

공통 규칙(삭제 RESTRICT, 참조처 건수 표시, 비활성화 우선)은 포털 6장을 따른다.

| 화면 | 테이블 | 선행 조건 |
|---|---|---|
| M-10 사업장·공간 | `site` `location` | 없음 |
| M-11 설비 | `equipment` | 공간 |
| M-12 품목 | `item` `item_unit_conversion` | 없음 |
| M-13 공정 | `process` `process_equipment` | 설비 |
| M-14 공정 경로 | `route_version` `route_step` | 품목·공정 |
| M-15 BOM | `bom_version` `bom_line` | 품목 |

### 등록 순서

```
사업장 → 공간 → 설비 ┐
                    ├→ 공정 ─┐
                             ├→ 공정 경로
           품목 ─────────────┘
             └→ BOM
```

기준정보 화면 상단에 순서 스텝을 공통으로 두고, 선행 데이터가 없으면 빈 상태에서 해당 화면으로 보낸다.

- **M-12 품목은 ERP 품목과 독립이다.** 상단에 명시한다. "이 품목은 MES 전용입니다. ERP 품목과 코드가 같아도 별개 데이터입니다."
- **M-14·M-15는 버전 관리다.** 게시(`published_at`) 전에는 지시에서 선택되지 않는다. 게시된 버전은 수정 불가이며 변경은 새 버전으로. 시드에 미게시 경로가 있으므로 목록에서 상태 구분이 보인다.
- M-14는 **공정 순서(`sequence_no`) 편집**이 핵심이다. 순서를 바꾸면 LOT 실행 순서가 바뀐다. 이미 사용 중인 버전은 잠근다.

## 8. 스키마 갭 목록

| # | 갭 | 내용 | 심각도 | FS-008b 처리 결과 |
|---|---|---|---|---|
| **M-G01** | 재고 미보유 | 자재 투입 시 **재고 부족을 검증할 수 없다.** 음수 재고도 감지 불가. WMS 미구현의 결과이며 설계 의도 | 낮음(설계) | 해소(설계 의도) — WMS 재고 미보유 유지 |
| **M-G02** | `material_issue` NULL 중복 | `material_lot_id`가 NULL이면 UNIQUE가 중복 투입을 막지 못한다. **기존에 기록된 제약**이며 SERVICE 검사로 보완 | 중(기록됨) | 해소(기존 정책) — NULL 중복 SERVICE 검사 유지; 실행 미검증 |
| **M-G03** | 검사 근거 없음 | QMS 미구현으로 양품·불량을 작업자가 직접 입력한다. 판정 근거가 데이터에 없다 | 낮음(설계) | 해소(설계 의도) — QMS 없는 수기 양품·불량 입력 유지 |
| **M-G04** | 지시 : LOT = 1:1 | 한 지시를 여러 LOT으로 분할 생산할 수 없다. **실무에서는 흔한 패턴이다.** 의도인지 제약인지 확인 필요 | **중** | 해소 — 1지시:1LOT 의도, UK 유지 |
| **M-G05** | BOM 없는 지시 | `bom_version_id`가 nullable이라 BOM 없이 지시가 가능하다. 그 경우 자재 투입에 기준 소요량이 없다. **의도적 유연성인지 누락인지 불명** | 중 | 해소 — BOM 선택 허용; 없으면 기준 소요량 기본값 없음 |
| **M-G06** | 설비 상태 없음 | `equipment`에 가동·정지·점검 상태 컬럼이 없다. 설비 가동률을 낼 수 없고 정지 중 설비에 실행을 배정할 수 있다 | 중 | 보류 — 이번 범위 밖, 상태 컬럼 추가 없음 |
| **M-G07** | 설비 동시 점유 | 한 설비에서 두 LOT이 동시에 실행 중인 상태가 데이터상 가능하다. 방지 규칙이 스키마에 없다 | **중** | 적용 — 동일 설비 미종료 실행 시 시작 거부 SERVICE 정책 |
| **M-G08** | 패킹 수량 초과 | `Σ packed_qty ≤ LOT 양품 수량`을 DB 제약으로 표현할 수 없다(여러 행 참조). SERVICE 정책으로 명시 필요 | 중 | 적용 — 부모 잠금·합계 재조회·초과 롤백 SERVICE 정책 |

### 처리 제안

- **M-G04가 가장 먼저 답이 필요하다.** 1:1이 의도라면 화면에 "한 지시는 한 LOT으로 생산합니다"를 적으면 끝난다. 의도가 아니라면 `lot`의 유니크 제약을 풀어야 하고 이건 파급이 크다. **소량 다품종 시드(지시 30 / LOT 26)에서는 1:1이 자연스러우므로 의도로 확정하는 것을 제안한다.**
- **M-G06·M-G07은 같은 뿌리다.** 설비에 상태가 없으니 점유도 관리할 수 없다. 둘 중 하나만 고른다면 **M-G07을 SERVICE 정책으로 명시**하는 쪽이 싸다. 설비 상태 컬럼 추가는 가동률 화면까지 따라와 범위가 커진다.
- M-G05는 확인만 하면 된다. **BOM 선택 허용이 의도**라면 화면 안내로 해소된다.
- M-G08은 FS-014b의 소명 한도와 같은 성격이다. SERVICE 정책 문서에 함께 적는다.
- M-G01·M-G03은 화면 안내로 해소한다. 스키마 변경 없음.
