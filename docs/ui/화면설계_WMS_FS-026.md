# WMS 화면 설계 revision 2 — FS-026

작성일: 2026-09-28. **전체 설계 확인 대기 / 제품 화면 미구현.**
전제: [승인 결정](../plan/WMS확장_입고검수예약_결정_FS-026.md), [모듈 revision 2](../modules/wms/WMS_모듈설계_FS-026.md), [기존 W-01~07](화면설계_WMS_FS-024.md).
UI-02/03의 D·L·P·W 패턴과 PageTitle/DataTable/FormPanel/DetailPanel/Badge/EmptyState/useDiscardGuard를 재사용한다. 별도 UI 체계를 만들지 않는다.

## 1. 동선과 메뉴

```
입고 예정 등록(W-08) → 트럭 도착(3D 또는 W-08)
 → 합격·격리·부족 입력 → 검수 확정
 → 정상/격리 재고 확인(W-02) → 예약 등록(W-09)
 → ERP에서 출하 확정 → W-09에서 출하 연결·반영
 → 예약 소진 및 차감 전표/원장 확인(W-04/05)
```

ERP를 쓰지 않는 체험은 수동 예정·검수·예약/해제까지 가능하다. 원자재 예약은 등록/해제만, ERP 고객 출하 연결은 완제품만 지원한다. ERP 출하 확정은 ERP 화면에서 하며 WMS가 대행하지 않는다.

기존 메뉴/경로 유지. 입출고에 **W-08 입고 예정·검수 `/wms/inbounds`**, **W-09 출고 예약 `/wms/reservations`** 추가. 상세는 기존 `?open=<id>` 패널 방식. 페이지 새로고침/직접 링크 시 GET으로 서버 상태를 복원한다.

## 2. 기존 화면 개정

| 화면 | 차분 |
|---|---|
| W-01 대시보드 | 정상 현재고·격리·활성 예약·예약 부족 지표. 품목별 단위 분리, KG와 EA를 하나의 총수량으로 합산하지 않음. 기존 음수/미반영 지표 유지. 입고 대기/검수 대기와 예약 부족은 W-08/09 필터 링크 |
| W-02 재고 현황 | 정상/격리 유형 필터, 현재고·활성예약·예약가능 열. ERP 미출하 지시는 하단 참고 지표로 분리. 현재고0/예약>0 행 유지, 위치별 부족 배지. 격리는 예약가능 ‘대상 제외’이며 총현재고에 포함. ERP 꺼짐은 참고 지표만 조회불가 |
| W-03 원천 반영 | ERP 매입 상태에 검수대기/검수완료/검수후 매입취소. 관리 열에서 예정 연결 또는 검수 상세로 이동. 선점된 원천의 직접 반영 차단. 전량 부족은 전표 링크 대신 검수 상세. 일괄 결과는 신규반영/검수완료/검수대기/실패를 구분 |
| W-04 재고 전표 | 검수입고 유형 읽기 상세·입고예정 링크. 기존 조정에 원 입고번호와 사유 안내. 격리 유형 간 이동은 사유 필수. 재고 부족은 기존 허용/경고 |
| W-05 원장 | 검수입고 필터·정상/격리 위치 표시. 부족 수량은 원장0이므로 W-08에서 확인하도록 안내 |
| W-06 창고·위치 | 정상/격리 유형 필드. 기본 위치는 정상만. 사용된 위치 유형변경·진행건 참조 비활성화 거부 시 원인과 이동/해제 안내 |
| W-07 품목·단위 | 기존 기능 유지. 진행 예정/활성 예약 참조 품목 비활성화 오류 안내. 기존 KG/EA·환산 규칙 유지 |

현재고/예약 지표는 현재 시점, 월 필터는 이동 실적만 적용한다. 부족 배지는 색 외에 ‘예약 부족 15 EA’처럼 수치와 단위를 표기한다. 기존 FS-024 화면의 “가용=현재고−ERP 미출하” 설명은 새 정의로 바꾸고 도움말도 함께 변경한다.

## 3. W-08 입고 예정·검수 — L + W 패널

```
입고 예정·검수 W-08                         [입고 예정 등록] [?]
[창고] [상태] [예정일 범위] [조회]
번호        예정일   차량     원천          상태       관리
IN-…        …        모의01   PI-0004       도착       검수
IN-…        …        —        수동          예정       상세
```

등록/PLANNED 편집 패널: 업무 중복 방지 번호, 창고, 예정일, 차량, 공급처 참고 코드와 명세(품목/LOT/기본 단위 예정량/정상 위치/격리 위치). 품목은 기존5종만 시드하며 사용자는 기존 기준정보 범위에서 선택한다. 격리 위치는 격리량을 입력할 예정이면 미리 지정한다. 도착 후 수정 불가 안내. LOT는 완제품 필수, 원자재 입력칸 없음.

ERP 연결은 저장 후 별도 행동이다. 원천 후보는 미반영·미선점·확정 매입만 표시한다. 품목별 환산 예정량 대조를 보여 주고 ‘연결’하면 선점한다. 직접반영/취소/수량불일치 대상은 사유를 표시한다. 연결 끊기는 검수 전만 가능하고 사유 필수. 수동 검수 완료 후 ‘ERP 매입 대사 연결’은 **추가 입고 없음** 문구와 함께 별도 제공한다.

상세 헤더: 번호·상태·예정/도착/확정 시각, 원천 경로(수동/검수경유), 매입 대사 상태. 상태별 행동:

| 상태 | 행동 |
|---|---|
| 예정 | 편집, ERP 연결/해제, 도착 처리, 3D 트럭 보기, 취소 |
| 도착 | 검수 입력, ERP 연결/해제, 취소 |
| 검수 완료 | 읽기, 전표/재고 보기, 미연결 수동 건 ERP 대사 연결 |
| 취소 | 읽기만 |

검수 폼은 예정/합격/격리/부족/정상위치/격리위치/사유를 줄별로 표시한다. 부족은 예정−합격−격리로 미리 계산하고 음수면 오류다. 확정 요청에는 부족도 보내며 서버가 식을 재검증한다. 확정 전 요약은 “정상 +95 KG · 격리 +3 KG · 부족 2 KG”. **단위가 다르면 품목별로 따로 표시**한다. 전량 부족은 “입고 재고 0, 검수 완료 기록만 생성”을 명시한다.

‘검수 확정’ 클릭 시 결과 수량/이후 수정 불가를 확인하는 대화 후 API를 한 번 호출한다. 진행 중 버튼 비활성. 실패하면 입력값 보존, 응답 유실은 서버 재조회 후 확정 여부를 확인한다. 확정 성공은 상태/전표 링크를 갱신한다. cancel/release에는 사유 폼이 있으며 검수/예약 확정과 혼동되지 않게 행동명을 구분한다.

ERP 꺼짐이면 연결 및 연결건 확정은 비활성 + 이유 안내. 수동 미연결 검수는 가능하다. 매입 취소는 경고와 ‘실물 정정은 재고 전표에서’ 링크를 보인다. 검수 결과를 자동으로 0으로 바꾸지 않는다.

## 4. W-09 출고 예약 — L + W 패널

```
출고 예약 W-09                                [예약 등록] [?]
[상태] [품목] [부족만] [조회]
번호      참고 출하지시  배분 요약       상태/부족        관리
RSV-…     SO-…           FG-C100 40 EA    활성 · 부족15    상세
```

등록: 업무 중복 방지 번호, ERP 출하지시 참고(선택/직접참고), 품목·위치·LOT·수량 줄. 참고 번호는 자동 소진 약속이 아님을 명시한다. 각 줄에 현재고/예약/예약가능을 나란히 보여 준다. 격리 위치는 선택 불가. 전체 줄 등록 직전 서버가 다시 검사한다. 충돌이면 실패 줄과 최신 수량을 표시하고 입력은 보존한다.

상세: 배분·현재 부족·참고 ERP 출하지시 대조·상태·해제사유·소진 출하/전표 링크. 원자재 묶음은 ‘등록·해제 지원, 출하 연결 대상 아님’. 활성 묶음의 행동은 ‘예약 해제’, 완제품이면 ‘ERP 출하 연결·반영’이다.

출하 연결 패널: ERP 확정·미반영 출하 후보, 예약과 출하의 품목/단위/LOT/packingNo/참고지시 대조 결과. 전량 일치한 대상만 확정 가능. 선택 후 서버가 다시 검증한다. 미리보기 성공을 확정 보장으로 표시하지 않는다.

불일치 또는 이미 반영된 출하는 이유를 표시하고 W-03 기존 원천 반영으로 이동할 수 있다. **자동으로 무연결 반영을 실행하지 않는다.** 기존 반영을 택하면 예약이 남아 해제가 필요하다는 안내를 한다. 예약 후 부족이어도 ERP 확정 출하 연결 반영은 허용하며, 확정 요약에 예상 음수 경고를 표시한다.

예약 해제는 사유를 입력하고 원장 변경 없음 안내. 소진/해제 후 줄 수정은 불가, 새 등록으로 처리한다. 자동 만료/부분 소진 버튼은 없다.

## 5. 3D 트럭 패널

공장 외부의 트럭 입고 패널에서 WMS PLANNED 예정 하나를 선택한다. 선택 요약은 번호·차량·예정 품목/수량, 행동 ‘트럭 도착 시연’. 외부 진입→하역장 정차 애니메이션 뒤 동일 `/inbound-notices/{id}/arrive` API를 호출한다. 애니메이션은 실물 입고나 차량 GPS가 아니다.

- 시연 중 예정 선택 잠금, 중복 클릭 방지. 요청에는 화면에서 읽은 expectedVersion 사용.
- 서버 응답 성공 후 ‘도착 · 검수 대기’와 W-08 검수 링크를 표시한다. 재고증가 카운터는 표시하지 않는다.
- API 실패는 ‘도착 저장 확인 필요’, GET 재조회/재시도 제공. 화면 이탈 후 서버 도착 완료라면 재진입 시 정차 상태, PLANNED라면 초기 상태. 애니메이션 진행률은 영구 저장하지 않는다.
- 중간 화면 이탈은 도착 미완료일 수 있다. 뒤늦은 응답이 다른 예정 UI를 덮지 않도록 요청 대상 ID/취소 처리를 한다.
- WMS 비활성/예정 없음/접근 불가 각각 안내. 서버 확인 없이 로컬 성공으로 대체하지 않는다. 3D를 쓰지 않는 사용자는 W-08 도착 처리로 같은 상태 전이를 수행한다.

## 6. 공통 UI·도움말·검증

W-08/09 목록은 서버 페이지 기본50/최대100. query filter와 open ID를 URL에 유지한다. 넓은 화면 편집 패널, 360px는 기존 반응형 패널. 명세 표는 패널 내부 스크롤이며 페이지 전체 가로 넘침 금지. 미저장 입력은 useDiscardGuard. 필드 오류·상태 안내 role=alert/status, 패널 열기/닫기 포커스 복귀, 키보드 조작. 색만으로 상태를 표현하지 않는다.

도움말 `content/help/wms/w-08.md`, `w-09.md`를 구현 때 추가하고 W-01~07 및 포털 사용자 참고 문서 목록을 개정한다. “직접 반영 vs 검수 경유”, “ERP 취소 vs 실물 반품”, “현재고 vs 예약가능”, “원자재 예약의 한계”, “트럭은 도착만”을 예제로 설명한다. CNC 알루미늄 블록과 기존 WMS 품목이 자동 연결된다고 설명하지 않는다.

화면 검증은 모듈 AC-139~164에 대응한다. 기존 W-01~07 회귀, W-08 정상/전량부족/취소/ERP꺼짐, W-09 부족/소진실패/응답유실, 3D 도착/새로고침을 API 통합·브라우저로 확인한다. **이번 단계는 문서 설계이며 화면 구현·브라우저 검증은 하지 않았다.**
