# GW-EXT-A — 공유 공간·실제 계정 화면 상세 설계 r1

2026-10-05 · 설계 확인 대상, 화면 미구현. [CORE API](../modules/core/CORE_공유공간_상세설계_GW-EXT-A.md) · [GW API/ACL](../modules/gw/GW_공유협업_상세설계_GW-EXT-A.md) · [UI-02](공통UI규약_UI-02.md).

공식 P/G 화면 번호는 main 충돌 확인 후 배정한다. 아래 UX-Axx는 설계 로컬 식별자다. 기존 G01~07 경로와 개인/게스트 체험은 유지. TEAM 신규 기능에 UI-02의 D/P 패턴·FormPanel·DetailPanel·DataTable·기존 확인영역 사용, 신규 시각 패턴 금지. GW 클래스는 gw-, core 신규는 core-team- 접두어.

## 1. 진입·공간 표시

앱 공통 헤더에 공간명 + 개인 체험/공유 팀 표시, 연결된 실제 직원명을 표시한다. TEAM에는 “역할 체험” 드롭다운을 렌더링하지 않는다. COMPANY에는 게스트 진입/공개 가입·초기화·시드 버튼이 없으며 직접 API도 거부한다. 공간 모드는 사용자가 UI로 바꿀 수 없다.

```text
[Factory Studio] [공유 팀 · 회사명 ▾] [직원명] [로그아웃]
GW  업무 현황 | 기안함 | 결재함 | 문서함 | 게시판 | 관리
[내 결재 대기 3] [내 진행 2]              ← 본인에게 허용된 건수
문서번호  제목  기안자  상태  현재 담당자  처리
선택 상세 → 고정 상신본 / 결재 단계 / 실제 처리 이력
```

예시 숫자/회사명은 설명용이며 제품 시드/처리량이 아니다.

공통 선택 조건: 미바인딩 직원도 /me·내연결확인에 접근 가능, 문서화면은403안내. 빈 TEAM과 API 실패를 구분한다. 등록 기능이 없는 사용자는 빈상태에 관리자전용 버튼을 보지 않는다.

## 3. 공간 선택·다중 탭

1. 미저장 상태에서 공간 선택 → 기존 변경 버리기/계속 편집 확인. 명령 처리 중 선택 금지.
2. 선택 API에 expectedContextVersion, 성공 후 인증 context 업데이트와 모든 업무 캐시/역할/상세 선택 폐기. 공간 홈에서 새 데이터 조회.
3. 다른 탭은 BroadcastChannel 등 알림으로 즉시 비우되 이를 보안 검사로 신뢰하지 않는다. 요청의 X-Workspace-Id/X-Context-Version을 서버가 확인한다.
4. 지연된 이전공간 응답은 request 시작context와 현재context를 비교해 버린다. 409 CONTEXT_CHANGED 시 자동재전송하지 않고 “다른 탭에서 공간이 바뀌었습니다”→현재세션조회/공간재선택.
5. 네트워크오류면 기존공간표시를 유지하고 확인 대기. 회사A의 입력을 회사B에 자동 저장하거나 localStorage로 이관하지 않는다.

## 4. 초대·계정 권한 관리

초대 폼: loginId(회사에 등록된 로그인 ID), 만료 표시(기본24시간 설정), 수락 후 MEMBER로 참여한다는 안내. 실제메일 전송버튼은 A에 없음. 성공 패널의 초대링크 복사 버튼은 최초 1회 제공, 닫으면 다시 보기 없음. 목록에는 대상 표시명/상태/만료/초대한 사람만. 생성응답유실 시 “링크를 확인할 수 없습니다. 재발급하면 이전 링크는 무효화됩니다.”

수락 페이지는 로그인 전 token을 서버조회/로그에 보내지 않는다. 외부 analytics 없는 페이지에서 fragment를 지우고 필요시 session 메모리로만 유지한다. 로그인 redirect로token 전달하지 않고 복귀 후 링크를 다시 열도록 안내한다. 로그인한계정에 맞는 초대인지 서버에서 검증하며 수락 성공 후 사용자가 공간 전환을 누른다.

정지/소유권이전: 영향(후속 접속/승인차단, 미결업무는보류)·대상·사유·추가인증·확정. 조직 직급 변경과 플랫폼역할을 같은 필드로 표시하지 않는다. 최종OWNER 오류는 현재OWNER정보의 허용범위만표시, 실패를성공토스트로내보내지 않는다.

## 5. 조직·직원·권한

조직은 코드불변, 상위조직선택에서 자기/하위제외, 서버순환검사. 비활성 시 활성자식/현재직원 있으면409로 이동대상 안내. 조직이동은 소속종료/신규소속 이력으로 표시한다.

G07 TEAM 모드: 직원이름·사번·조직·직무·활성·계정연결상태. 실제 loginId/subject는 관리자에게 필요한 최소범위만, 일반디렉터리에서 숨김. “직원 등록”과 “계정 연결 요청”을 분리한다. 연결 요청은 관리자, 동의는대상직원. 이미연결된직원의 계정 바꾸기 버튼없음.

보안역할 표: ORG_ADMIN 조직관리, ROUTE_ADMIN 결재선관리, BOARD_PUBLISHER 공지게시, SECURITY_ADMIN 권한관리, AUDITOR 명시허용문서감사. 직무와역할의차이 설명. 권한부여가 모든문서열람권한은아님을 표시.

## 6. 기존 G01~07 TEAM 동작

- G01: 본인기안/대기/허용공지, 전체공간총건수숨김. 상신본금액합계로 비공개문서존재를노출하지않음.
- G02: 실제기안자 읽기전용, 일반기안만선택. 결재후보는활성연결된직원만. 조직명/직무는표시용. 실제계정선택과역할체험을 혼합하지않음.
- G03: 본인현재단계만. 재배정된경우 기존담당자/새담당자·사유·처리주체 이력표시. 요청응답유실은같은키재시도, 권한회수403/404면본문즉시비움.
- G04: “열람 가능한 문서”로 제목변경, “공간전체”필터제거. 기안자에게만 읽기담당자 추가/회수패널, 권한추가는결재권한아님. 허용되지않는이전/후속링크숨김.
- G05: 공개범위 WORKSPACE/ORG, ORG선택과부서표시. 초안은작성자전용, 게시후공개범위수정없음. 게시후본문불변규칙유지.
- G06: 전직원조회, ROUTE_ADMIN만편집. 기안자가포함된템플릿은상신전거부.
- G07: 체험에서는기존직무권한, TEAM에서는실제역할grant로판정. 모드별 도움말을 분리한다.

## 7. 미결 재배정

비활성담당자 단계선택→새활성담당자(기안자·기존다른단계·자기제외)→사유→추가인증→확정. 화면에 “담당자만 바뀌며 기존 승인과 상신본은 바뀌지 않습니다” 표시. 신규담당자는자신의결재함에서직접승인. 이미처리된단계/동시에다른관리자가재배정한경우409후새상태확인. 원문열람권한없으면상세로이동하지않음.

## 8. 공통 오류·접근성·도움말

400 필드아래,403권한/추가인증,404존재또는열람불가,409현재버전/재조회,422새요청키필요를구분. 5xx/네트워크에서입력보존하되권한회수후민감본문은지운다. 입력내용을오류로그에담지않는다.

1440px 분할패널/360px 전체패널, 표만가로스크롤, label/키보드/포커스복귀/저채도배지+텍스트. 새화면은UI-02공통컴포넌트. 앱내링크·공간전환 미저장보호, 새로고침/탭닫기 beforeunload 보조. 브라우저뒤로가기 라우터전환여부는구현전기술검토, 미완료를완료로표시하지않음.

도움말은 core 팀공간/초대/권한회수 + GW 실제직원/열람범위/재배정, 기존 역할체험 문서와 구분. 사용자참고문서에는 “관리자도 자동으로 문서를 읽지 못함”, “퇴사자 연결을 다른계정으로 바꾸지 않음”을 실제 예로 설명한다. 상태가설계단계인경로는제품런처/도움말목록에미리공개하지않는다.

## 9. 5분 인수 동선
