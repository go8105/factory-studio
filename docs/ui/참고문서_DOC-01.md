## 1. 목적과 독자

현재 `/help`는 화면 ID 목록 한 장이다. 평가자가 "무엇을 왜 이렇게 만들었는가"를 3~5분 안에 찾아 읽을 수 있는 **참고 문서 사이트**로 확장한다.

| 항목 | 확정 (2026-09-27 사용자) |
|---|---|
| 주 독자 | **평가자** (채용 담당자·기술 면접관). 가상 현장 사용자는 부 독자 |
| 스크린샷 | **1차 제외.** UI-03이 남아 있어 캡처가 곧 낡는다 |
| 따라하기 | **대표 1개 + 짧은 것 2개** |
| 저장소 | 비공개(`go8105/factory-studio`). 따라서 설계 문서는 **요약 재작성본이 유일한 공개 창구**이며 GitHub 원문 링크를 두지 않는다 |

## 2. 불변 조건

- **읽는 문서다.** 진도·완료 체크·이어하기·점수 없음. 완료 상태를 `localStorage`에도 저장하지 않는다. (FS-013 D4)
- **DB·API 없음.** 전부 `content/help/` 정적 Markdown. (FS-013 D6)
- **기존 URL 유지.** 업무 화면 `? 도움말`이 연결하는 `/help/<솔루션>/<화면id>`는 바꾸지 않는다.
- 로그인 없이 열린다 (현재 `session.tsx`가 `/help`를 허용 — 유지).
- 새 의존성 없음. `react-markdown`·`remark-gfm`만 사용한다.

### ③ 사용자 참고 문서 트리

트리는 **새로 정의하지 않는다.** 각 솔루션 메뉴 배열(`mesScreens`·`erpScreens`·`femsScreens`)의 `group`을 그대로 쓴다. 메뉴가 바뀌면 트리도 따라 바뀐다.

```
ERP 경영관리
 ├ 영업        E-02 견적 · E-03 판매계획 · E-04 수주
 ├ 출하·매출   E-05 … E-08
 ├ 채권·수금   E-09 · E-10
 └ …
```

포털 P-01~07과 공통 이용 안내는 `포털` 묶음으로 둔다.

## 4. 파일·코드 구조

```
content/help/
  common.md              (기존)
  portal/ mes/ erp/ fems/ (기존 54)
  design/d-01.md … d-08.md
  guide/s-01.md … s-03.md
  concept/mts.md …
```

- **목록 파일(manifest)을 두지 않는다.** 구역은 경로 앞부분, 순서는 파일명, 제목은 첫 `#` 줄에서 얻는다. 현재 `content.tsx`의 `import.meta.glob`이 새 폴더를 그대로 읽는다.
- 첫 화면의 "많이 찾는 문서" 4~5개만 컴포넌트 상수로 둔다.
- 출처는 지금처럼 문서 끝 `<!-- sources: … -->` 주석에 둔다. `skipHtml`이라 화면에 나오지 않는다.

## 5. 화면 설계

### 5.1 첫 화면 `/help`

```
┌───────────────────────────────────────────────────────────┐
│ ▓▓ 쪽빛 띠  참고 문서                                      │
│ ▓▓ 이 시스템을 무엇으로, 왜 이렇게 만들었는가               │
├───────────────────────────────────────────────────────────┤
│ [ 문서 검색 ……………………………………………… ]                          │
│                                                           │
│ 설계 문서                     │ 업무 따라하기               │
│ 왜 이렇게 만들었나             │ 게스트 데이터로 직접 해 보기  │
│ 많이 찾는 문서                 │ 많이 찾는 문서               │
│ ▢ 세 솔루션을 독립으로 나눈 이유 │ ▢ 판매계획에서 수금까지      │
│ ▢ 만들지 않은 것과 그 이유      │ ▢ 매입 전표에서 지급 소명까지 │
│ ▢ 가입 없는 즉시 체험          │ ▢ 원단위와 목표 대비 실적     │
│ ───────────────────────────── │ ─────────────────────────── │
│ 사용자 참고 문서               │ 개념·용어                   │
│ MES 15 · ERP 18 · FEMS 14 ·   │ MTS · LOT · 소명 · 원단위 … │
│ 포털 7 · 공통 이용 안내         │                             │
└───────────────────────────────────────────────────────────┘
```

- 좌측 트리는 문서 화면에서만 둔다. 첫 화면은 구역 카드 4개가 목차 역할을 한다.
- 색: 띠 `#1F2D3D` 위 백자 글씨, 본문 백자 `#F7F7F6`, 문서 아이콘은 단색 SVG 라인.

### 5.2 문서 화면 `/help/<키>`

```
┌ 트리 (240px) ──┬ 본문 ─────────────────────────┬ 이 문서 목차 ┐
│ 설계 문서       │ 참고 문서 › 설계 문서            │ 결정          │
│  d-01 …        │ # 세 솔루션을 독립 제품으로…     │ 검토한 대안   │
│ 업무 따라하기   │                                 │ 선택 이유     │
│ 사용자 참고     │ ## 결정 …                       │ 한계          │
│  ▸ MES         │                                 │              │
│  ▾ ERP         │ [이 화면 열기 →]  (화면 문서만)   │              │
│    영업 …      │ ← 이전 문서        다음 문서 →   │              │
│ 개념·용어       │                                 │              │
└────────────────┴─────────────────────────────────┴──────────────┘
```

- **이 문서 목차:** 본문 `##` 제목에서 만든다. `h2`에 id를 붙인다.
- **이 화면 열기:** 화면 문서(`erp/e-09`)만 표시한다. 메뉴 배열에서 id로 경로(`/erp/receivables`)를 찾는다. 세션이 없으면 기존 진입 흐름(P-01)을 그대로 탄다.
- **이전/다음:** 같은 구역 안에서 트리 순서대로 연결한다.
- **현재 위치 표시:** 상단 경로(참고 문서 › 구역 › 문서)와 트리의 현재 항목 강조.
- **390px:** 트리는 네이티브 `<details>` "문서 목록"으로 접는다. 문서 목차는 숨긴다. 가로 스크롤 0.

### 5.3 검색

- 이미 번들에 들어 있는 `help` 원문 전체에서 **제목 + 본문 부분 문자열**을 찾는다 (대소문자 무시). 문서가 약 80개라 색인·형태소 분석·라이브러리가 필요 없다.
- 결과: 제목, 구역 배지, 일치 문장 한 줄. 제목 일치를 본문 일치보다 위에 둔다.
- 첫 화면과 문서 화면 상단에서 같은 입력창을 쓴다. 검색어는 `?q=`로 둔다 (공유 가능, 개인정보 아님).
- 한계: 띄어쓰기가 다르면 찾지 못한다 ("매출채권" vs "매출 채권"). 문서가 수백 개로 늘면 색인 방식으로 바꾼다.

## 6. 유형별 작성 틀

| 유형 | 제목(`##`) 순서 | 분량 |
|---|---|---|
| 설계 | 결정 → 검토한 대안 → 선택 이유 → **한계** → 관련 문서 | 한 화면~두 화면. 표 1개 이하 |
| 따라하기 | 목표 → 준비 상태 → 단계(번호, 단계마다 화면 ID·입력값·확인할 결과) → 끝나면 보이는 것 → 막힐 때 | 대표 12단계 이내, 짧은 것 6단계 이내 |
| 개념 | 한 줄 정의 → 왜 필요한가 → 이 제품에서는 → 관련 화면 | 반 화면 |
| 화면 참고 | 기존 틀 유지 (하는 일 → 먼저 필요한 것 → 주요 동작 → 이럴 때 막힙니다 → 관련 화면) | 기존 |

### 설계 문서 공개 기준 (저장소 비공개 전제)

- **쓰지 않는다:** 서버 주소·호스팅 업체·배포 경로·인증서·계정·비밀정보, 실제 회사·고객 정보, 내부 작업 경위(누가 어떤 브랜치에서 무엇을 고쳤는지).
- **작업 ID(FS-013 등)는 본문에 쓰지 않는다.** 평가자에게 의미가 없다. 출처 주석에만 남긴다.
- **수치는 출처와 대조한다.** 예: 71테이블, 시드 7,469행, 세대 복사 10회 중앙값 0.4555초, 스모크 159건 통과. 대조하지 못한 수치는 싣지 않는다.
- 설계 문서의 "한계"는 빼지 않는다. 한계를 스스로 적는 것이 평가자에게 가장 설득력 있는 부분이다.

## 9. 검증 기준 (DOC-02)

- vitest: 모든 메뉴 화면에 도움말 문서가 있다 · 트리에 없는 고아 문서 0 · 검색이 제목·본문 일치를 찾고 제목 일치를 위에 둔다 · 없는 키는 404 (`constructor` 같은 객체 기본 키 포함) · 화면 문서에만 "이 화면 열기"가 보인다.
- Playwright: `/help` 구역 4개 · 트리 이동 · `?q=` 검색 · 업무 화면 `? 도움말` → 기존 URL 그대로 열림 · 1440/390 가로 넘침 0 · 로그인 없이 열람.
- 번들: `Help` lazy 청크에 메뉴 배열을 가져오면서 업무 화면 코드까지 딸려 들어오는지 빌드 결과로 확인한다. 딸려 오면 배열만 별도 파일로 뺀다.
- 기존 스모크 전체 통과.
