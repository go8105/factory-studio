작성: 2026-10-01 · **전체 설계 승인 완료(사용자 “구현 진행해줘”), 화면은 FS-030b 예정**.
기준: [승인 결정서](../plan/GW도입_전자결재_결정_FS-030.md), [모듈/API/권한 계약](../modules/gw/GW_모듈설계_FS-030.md), [UI-02](공통UI규약_UI-02.md). D60~69/AC220~239를 따른다. 새 UI 패턴·전자문서 편집기는 만들지 않는다.

## 1. 공통 틀·역할 체험

SolutionLayout / PageTitle / DataTable / Pagination / FormPanel / DetailPanel / Badge / Field / EmptyState / ErrorNotice / useDiscardGuard를 재사용한다. 추가 클래스는 `gw-` 접두어, 기존 토큰과 UI-02 스크롤 규칙을 따른다. 홈은 systems.json의 경영·협업 묶음, 구현 전에는 타일을 공개하지 않는다. 신규 업무 경로는 공통 미저장 링크 이동 보호(UI-04)에 포함한다.

GW 상단에는 **“담당자 역할 체험”** select와 “내 공간에서 합성 담당자를 바꿔 업무를 체험합니다. 실제 직원 로그인 변경이 아닙니다.” 안내를 둔다. 선택 직무·이름은 모든 화면에 같은 방식으로 표시한다. G-07 계정/권한 관리라는 명칭을 쓰지 않는다.

역할 전환은 미저장 입력이 있으면 기존 변경 버리기/계속 편집 보호를 거친다. 요청 중에는 역할/대상 변경과 중복 클릭을 막는다. 역할 변경 시 대기 목록과 availableActions를 다시 조회하고 이전 역할 응답은 무효화한다. 세대 변경·모듈 off·세션 만료 시 이전 역할/상세 캐시를 사용하지 않는다. 보관된 비활성 역할은 선택 해제하고 활성 역할 선택을 안내한다.

일반 목록 page/검색/종류/상태/open은 URL query에 보존한다. page는 API offset/limit으로 변환한다. 상세 URL은 `/gw/documents?open=<id>`를 모든 결재 링크의 기본 진입으로 사용하고 G-02/03에서도 같은 상세 컴포넌트를 쓴다. ERP 번호 링크는 ERP 내 검색 파라미터로 연결하며 외부 URL은 받지 않는다.

## 3. G-01 업무 현황

상단 KPI는 **내 초안 / 내 진행 / 현재 결재 대기 / 내 기안 종결** 건수다. 선택 역할에 맞는 목록으로 연결한다. 최근 결재 문서와 최근 공지·자유 글을 각5개 표시한다. 전사 매출·생산·금액 합계를 넣지 않는다. 금액은 각 문서 통화와 함께 표시한다.

역할 없음은 “체험 담당자를 선택하세요”와 G-07 이동, 데이터 없음은 기안 등록/시드 사용 안내, 모듈 off는 공통 사용 설정 안내를 표시한다. 로딩 실패를0건으로 표현하지 않는다.

## 4. G-02 기안함 / G-04 상세

목록: 문서번호·제목·일반/ERP매입·상태·기안자·현재담당자·상신시각·관리. G-02는 내 기안이라는 기준을 표시하고, G-04는 공간 안 전체 기록이며 기밀 ACL이 없음을 도움말에 설명한다.

초안 FormPanel wide:

1. 일반 기안/ERP 매입 선택, 현재 역할(기안자) 표시.
2. ERP면 검색 가능한 원문 후보 표: 번호·거래처·공급가/세액/합계·통화·초안/확정. 확정은 **사후 검토** 안내. 후보 선택 후 명세/금액 미리보기, 사용자가 공급가·거래처를 직접 수정하지 못한다.
3. 제목·본문(textarea, plain text), 일반 기안만 선택금액/통화. 길이·정밀도 오류는 Field 아래 표시.
4. 결재선 선택→복사될 단계(순번·이름·직무) 표. 기안자 포함·중복·비활성은 설명하고 저장을 막되 서버 검사도 유지한다.
5. **초안 저장**. 저장만으로 상신되지 않는다. 생성 성공 후 해당 상세를 열고 최신 version 적용.

상세 위→아래 구성:

- 문서번호·상태·회차·기안자, “상신 당시 문서에 대한 검토 기록이며 ERP 확정을 제어하지 않습니다.”
- 본문/일반 금액, ERP라면 **고정된 원문** 금액·명세와 별도 **현재 원문 비교**. 저장본을 현재 ERP 값으로 덮어쓰지 않는다.
- 단계 표(대기/현재/승인/반려/건너뜀), 의견·실제 처리시각. “건너뜀”은 반려/회수로 종료된 미처리 단계이며 승인처럼 보이지 않는다.
- 이전/후속 문서 링크, 사건 순번·행위·합성 담당자·실제 주체 종류·SEED 표시·사유. 실제 actor_key는 내부 감사용이며 화면에 세션 식별자를 노출하지 않는다.
- 상태/역할별 버튼. 서버 availableActions에 따라 표시하고 권한 실패 이유를 안내한다.

초안은 편집/결재선 다시 선택/ERP 원문 갱신/상신. 상신 확인 영역에서 대상·기안자·단계·고정 금액/통화·ERP 사후 검토 여부를 다시 보여준다. ERP 변경 충돌이면 입력 유지→원문 비교→명시적 갱신→재검토를 요구한다. 원문 갱신은 초안만 가능하며 자동 상신하지 않는다.

진행 중은 기안자이며 승인0건일 때만 회수(사유필수). 반려/회수는 **새 초안으로 재상신 준비** 버튼, 기존 후속이 있으면 그 링크만 표시한다. 승인 완료본에는 수정·회수·재상신 버튼이 없다. 별도 신규 기안은 G-02에서 시작한다.

## 5. G-03 결재함

현재 역할·현재 단계의 대기 건만 기본 조회한다. 다른 역할 문서를 볼 수 있어도 그 역할로 바꾸기 전에는 승인 버튼을 제공하지 않는다. 상세는 G-04와 동일하다.

승인: 의견선택→확인 영역 “상신본을 검토하고 N단계를 승인합니다”→확정. 마지막 단계면 “결재가 완료됩니다” 추가. 반려: 사유2~500자→확인→확정. 첫 승인 이후 회수 불가를 보여준다.

ERP 변화가 있을 때 안내 예:

| 상황 | 문구/행동 |
|---|---|
| 원문 내용 변경 | “현재 ERP 내용과 다릅니다. 아래 고정된 상신본을 검토합니다.” |
| 초안→확정 | “ERP에서 확정된 문서입니다. GW 결재와 별개로 처리됐습니다.” |
| 원문 취소 | “ERP 원문이 취소됐습니다. 이 결재는 기존 상신본 검토 이력입니다.” |
| 원문 없음/꺼짐 | “현재 원문 조회 불가. 저장된 상신본은 열람·결재할 수 있습니다.” 원인 구분 |

서버 충돌 때 성공 토스트/다음 단계로 이동하지 않는다. 같은 멱등키 재시도와 서버 상태 다시 확인을 제공한다. 성공 응답을 상세 상태에 즉시 적용한 후 목록 갱신; 목록을 기다리며 이전 version으로 다음 행동하는 문제를 방지한다.

## 6. G-05 게시판

공지/자유 구분·상태·검색, 열은 번호·제목·작성 역할·게시 시각·정정/철회 표시. 조회수·댓글수·첨부 아이콘 없음. plain text 본문, 제목/본문 공백 trim 및 길이 제한. 새 글은 초안으로 저장하고 게시를 따로 확인한다.

공지는 BOARD_ADMIN 작성자만, 자유 글은 작성 역할만 편집/게시/철회/정정한다. 직무를 바꾸거나 비활성 역할을 API로 보내도 서버가 확인한다. 게시 후 편집 버튼 대신 **정정 글 작성**과 **철회**를 제공한다. 정정 초안 생성만으로 원글은 바뀌지 않는다. 이전/후속 글 링크, 철회사유·사건 이력은 유지한다. 삭제 버튼 없음.

## 7. G-06 결재선 / G-07 체험 담당자

G-06: 코드/명칭/단계수/활성 목록→패널. 단계별 활성 담당자 select와 위/아래 버튼(드래그 전용 UI 없음), 최대3명. “템플릿 변경은 이미 기안된 문서에 자동 반영되지 않습니다. 초안에서 결재선을 다시 선택하세요.” 비활성 결재선은 새 선택에서 제외하고 과거 상세는 유지한다.

G-07: 코드/이름/직무/활성 목록→패널. 직무는 STAFF·MANAGER·EXECUTIVE·BOARD_ADMIN의 한글 이름. 실제 직원 등록이라고 표시하지 않는다. 진행 결재/초안 참조로 비활성화가 거부되면 해당 참조 건수/같은 공간 문서 링크를 안내한다. 마지막 활성 운영 담당자 보호 안내. 서버 검사를 클라이언트에서 우회하지 않는다.

## 8. ERP E-11 및 포털·도움말 변경

E-11 **상세**에 “GW 결재” 한 구역만 추가. 진행 중 우선, 없으면 마지막 상신된 종결 회차. 배지+GW문서번호 링크, 동일번호 ERP 원문의 현재 digest/status 비교. 과거 승인인데 원문 변경이면 “과거 상신본 승인 · 원문 내용 변경”, 이후 새 진행이면 “결재 진행” 표시. GW off=“결재 조회 불가”, 없음=“결재 기록 없음”. ERP 확정/취소 버튼과 전표 상태는 그대로다. 목록 전체에 배지를 달거나 GW 쪽에서 ERP 상태를 쓰지 않는다.

포털: lazy route·업무 경로/미저장 보호·진입목록·홈/GW 아이콘·참고문서 화면 목록·솔루션 전환 링크·systems.json status/to 갱신. 문구 숫자는 기존 자동 계산 유지. 도움말 `content/help/gw/g-01~07.md` 및 사용자 참고 `portal/gw-flow`를 c에서 추가한다. 설명 핵심은 역할 체험, 상신본/현재원문 차이, 반려/회수/재상신, 게시/정정, ERP 통제 없음이다.

흐름 맵 노드 `approval_review`(gw/g-03), 기존 매입 노드→GW는 “ERP 문서 조회”, GW→ERP는 “결재 상태 배지(읽기 전용)”로 표현한다. 구현 시 기존 노드 ID를 확인하고 노드/연결 수를 기준값에 더한다. 원문/결재의 소유권과 화살표 의미가 자동 ERP 확정처럼 보이지 않게 한다. 공지 게시판은 GW 도움말에서 설명하고 EIP 전사 공지 집계 노드는 만들지 않는다.

## 9. 공통 실패·접근성·검증

- 1440px 목록+넓은 패널, 360px 전체화면 패널. 표는 컨테이너 안 가로 스크롤만 허용, 페이지 자체 overflow 없음. 제목·금액·단계를 색만으로 구분하지 않는다.
- 열 때 입력/닫기에 포커스, Escape는 미저장 보호, 닫으면 시작 버튼으로 복귀. 모달 안 Tab 이동은 기존 공통 구현 사용. 미저장 상태에서 역할/원문/라우트/앱 안 링크 변경은 보호. 브라우저 앞뒤 이동 보호는 기존 제품의 미구현 제약을 유지하며 완료라고 주장하지 않는다.
- API 실패는 필드400·충돌409·세션401/410·모듈off를 구분. stale GET/화면이탈 응답 무효화, 요청 중 중복 버튼 차단, 네트워크 유실은 재조회/동일요청재시도, input 보존.
- API/e2e: 신규 ERP 초안→상신→역할전환→승인/반려→재상신→완료/ERP배지, 회수경합, ERPoff/변경/삭제, 공지권한·게시/정정/철회, 잘못된역할 직접API, 다른공간/구세대, 모바일/키보드/도움말. 결재선1/3단계와2단계 시드 모두 테스트.
- 게스트 생성은 nickname 필수. Codex 전용 DB·전용 포트 사용, 공유8000/5173 동시 스모크 금지. 현재는 화면 설계 문서만 작성했으며 브라우저 검증은 미실행이다.

G-01~07과 E-11 배지 동선은 사용자 “구현 진행해줘”로 승인됐다. FS-030a DB 완료 보고 후 확인을 받아 FS-030b에서 화면을 구현한다.
