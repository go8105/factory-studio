# FS-008a 포털 화면 설계

작성일: 2026-09-22
전제: [FS-013 전환 결정](../plan/독립솔루션_전환결정_FS-013.md) · 스키마 v0.8.0 / FS-014b (`core` 11테이블)
선행: [FEMS 화면 설계](화면설계_FEMS_FS-008a.md) 7장의 공통 규격 후보를 본 문서 6장에서 확정한다.
성격: **스토리보드 2차 — 포털.** ERP·MES는 후속.

---

## 1. 포털은 무엇을 하는가

**로그인시키고, 앱으로 보내고, 세 솔루션이 어떻게 이어지는지 설명한다. 그게 전부다.**

업무 데이터를 다루지 않는다. `core` 11테이블은 인증·공간·세대·운영만 담는다(FS-013 D1).

### 이 화면이 포트폴리오에서 갖는 무게

평가자가 **가장 먼저 보고, 3~5분 판단의 프레임을 결정하는 화면**이다. 여기서 "학습 사이트"로 인식되면 이후 ERP·MES 화면도 그 프레임으로 읽힌다. 문구 하나가 생각보다 결정적이다.

| 치명적 실패 | 회피 방법 |
|---|---|
| 가입 강제 | 게스트 버튼을 로그인보다 크게. 첫 화면에서 바로 진입 |
| "준비 중" 남발 | 미구현 4종은 설명 카드로 분리. 아이콘 그리드에 섞지 않는다 |
| 빈 화면 | 진입 즉시 시드 데이터가 채워진 상태 |

## 4. 화면별 설계

### P-01 진입

| 항목 | 내용 |
|---|---|
| 목적 | 3초 안에 안으로 들여보낸다 |
| 데이터 | `app_user` `auth_session` `workspace` |

```
┌──────────────────────────────────────┐
│           Factory Studio             │
│   제조 현장의 세 시스템을 만들었습니다  │
│                                      │
│   ┌────────────────────────────┐     │
│   │  가입 없이 둘러보기  →      │     │  ← 주 동선
│   └────────────────────────────┘     │
│                                      │
│   계정이 있다면 로그인                 │  ← 부 동선, 텍스트 링크
└──────────────────────────────────────┘
```

- **게스트가 기본이다.** 로그인은 텍스트 링크로 격하한다.
- 게스트 진입 시 `workspace(kind=GUEST)` + `data_generation`을 만들고 템플릿 세대를 복사한다(TX-12).
- **복사는 약 6,840행 단일 트랜잭션이다.** `statement_timeout 10초` 부족 우려가 미해소 제약으로 남아 있다. 진행 표시를 반드시 둔다.
  - 1초 미만이면 표시하지 않는다(깜빡임 방지)
  - 초과 시 "예시 데이터를 준비하고 있습니다" + 진행 표시
  - 실패 시 재시도 버튼. **부분 생성 상태를 남기지 않는다**(전량 롤백)
- 게스트 만료(`workspace.expires_at`)를 진입 시점에 안내한다. 나중에 사라지는 걸 미리 알려야 한다.

### P-02 앱 런처 (홈)

| 항목 | 내용 |
|---|---|
| 목적 | 세 솔루션으로 보낸다. 아직 없는 것을 정직하게 보여준다 |
| 데이터 | `workspace` `workspace_module` `data_generation` |

```
┌────────────────────────────────────────────────────┐
│ Factory Studio            [내 공간]  [도움말]  (김) │
├────────────────────────────────────────────────────┤
│                                                    │
│  제조 현장의 세 시스템                               │
│  MES · ERP · FEMS를 각각 독립된 솔루션으로 만들었습니다│
│                                                    │
│  ┌──────────────────────────────────────────┐      │
│  │ 세 시스템은 어떻게 이어지는가              │      │
│  │ 판매계획에서 출하·매출까지 전체 흐름 보기 → │      │  ← P-03
│  └──────────────────────────────────────────┘      │
│                                                    │
│   ┌────┐      ┌────┐      ┌────┐                  │
│   │MES │      │ERP │      │FEMS│                  │
│   └────┘      └────┘      └────┘                  │
│   생산관리     경영관리     에너지관리               │
│                                                    │
│  ─────────────────────────────────────────         │
│  아직 만들지 않은 것                                │
│   QMS 품질 · WMS 물류 · BEMS 건물 · SCM 공급망      │  ← P-04
│  설계 범위에서 의도적으로 제외했습니다. 이유 보기 →   │
└────────────────────────────────────────────────────┘
```

- **구현 3종과 미구현 4종을 시각적으로 분리한다.** 기존 시제품처럼 같은 그리드에 섞으면 클릭했을 때 실망이 온다. 미구현은 아이콘 없이 텍스트 목록으로 낮춘다.
- "아직 만들지 않은 것 / 의도적으로 제외했습니다"는 **약점을 강점으로 바꾸는 문구다.** 범위를 정하고 이유를 설명할 수 있다는 신호가 된다.
- `workspace_module.enabled`가 false인 앱은 흐리게 표시하고 P-06으로 보낸다.
- 앱 검색은 3종뿐이므로 **제거한다.** 7개일 때는 의미가 있었지만 3개에서는 장식이다.

### P-03 전체 업무 흐름

| 항목 | 내용 |
|---|---|
| 목적 | 세 솔루션이 어떤 순서로 이어지는지 한 장으로 보여준다 |
| 데이터 | **정적 파일** (FS-013 D6). DB 조회 없음 |

- `process_map` 3테이블 폐기의 대체물이다. 노드·연결을 JSON으로 두고 렌더링한다.
- 노드를 누르면 해당 앱의 화면으로 이동한다. 미구현 노드는 P-04 카드로.
- 구현 노드와 미구현 노드를 **선 스타일로 구분**한다(실선/점선).
- 원천 내용은 `architecture/MTS_전체흐름_노드정의서_FS-005a.md`의 노드 17개다. 학습 관련 기술만 걷어내고 재사용한다.

### P-04 설명 카드

| 항목 | 내용 |
|---|---|
| 목적 | 만들지 않은 4종에 대해 "왜 안 만들었나"를 설명한다 |
| 데이터 | 정적 파일 |

각 카드 구성: **무엇을 하는 시스템인가 / 왜 이번 범위에서 뺐는가 / 넣는다면 어디에 붙는가.**

- 세 번째 항목이 핵심이다. WMS라면 "재고 원장을 소유하며 MES의 자재 투입이 여기서 차감된다"처럼 **접합점을 말할 수 있어야** 설계를 이해한 것으로 보인다.
- **SCM은 이번에 새로 추가된 항목이다.** 기존 준비 중 카드 3종(FS-004a)에 없으므로 내용을 새로 써야 한다.

### P-05 도움말

| 항목 | 내용 |
|---|---|
| 목적 | 학습 과정을 대체한다. 화면별 맥락 도움말의 모음 |
| 데이터 | 정적 파일 |

- 진도·채점·이어하기 없음. **읽는 문서다.**
- 원천 문안은 `modules/learning/학습경로_수용기준_FS-004.md`와 `학습과정확장_FS-004a.md`의 업무 설명 문장이다. 과정 구조·확인 질문은 제외한다.
- 각 업무 화면의 `?` 버튼이 해당 항목으로 연결된다.

### P-06 내 공간

| 항목 | 내용 |
|---|---|
| 목적 | 세대 초기화와 앱 사용 여부를 관리한다 |
| 데이터 | `workspace` `data_generation` `workspace_module` |

- **예시 데이터 초기화**: 새 세대를 만들고 이전 세대를 퇴역시킨다. 되돌릴 수 없음을 경고한다.
- **앱 사용 여부 토글**: `workspace_module.enabled`. 끄면 런처에서 흐려진다.
- 게스트는 만료 시각과 남은 시간을 표시한다.
- 세대 정리는 자식 → 부모 순이며 실행 중에는 업무 화면 진입을 막는다.

### P-07 운영 기록 (관리자)

| 항목 | 내용 |
|---|---|
| 목적 | 작업 실행 이력과 감사 로그를 본다 |
| 데이터 | `job_run` `audit_event` |

- 평가자에게 보여줄 화면은 아니지만 **`audit_event`가 살아 있음을 증명하는 유일한 화면**이다. 소명 물리 삭제 이력이 여기에 남는다(FS-014b).
- 읽기 전용. 관리자 역할만 접근.
- 게스트·일반 사용자에게는 메뉴 자체를 노출하지 않는다.

## 5. 권한 모델

FS-013에서 "`core.role`은 플랫폼 역할만"이라고 정했으나 **역할 목록이 정의된 적이 없다.** 여기서 제안한다.

| 역할 | 범위 |
|---|---|
| `GUEST` | 자기 임시 공간만. P-07 접근 불가. 초기화 가능, 만료 있음 |
| `OWNER` | 자기 개인 공간. P-06 전체. P-07 접근 불가 |
| `ADMIN` | P-07 접근. 전체 `job_run`·`audit_event` 조회 |

**업무 권한(메뉴·기능 접근)은 각 솔루션이 자체 보유한다.** 포털 역할이 ERP 메뉴 권한을 결정하지 않는다. 이 3종은 플랫폼 계층 전용이다.

## 6. 공통 규격 확정

FEMS 문서 7장에서 올린 후보를 여기서 확정한다. **이후 ERP·MES는 이 규격을 따른다.**

### 6-1. 색

| 토큰 | 값 | 용도 |
|---|---|---|
| 배경 | `#F7F7F6` 백자 | 페이지 바탕 |
| 전경 | `#1A1C1E` 먹색 | 본문·제목 |
| 강조 | `#1F2D3D` 쪽빛 | 주 버튼·활성 탭 |
| 면 | `#FFFFFF` | 카드·표 바탕 |
| 경계 | 먹색 12% | 구분선 |
| 보조 텍스트 | 먹색 55% | 설명·캡션 |

**상태색은 저채도 3종만.** 정상 / 주의 / 이상. **빨강을 쓰지 않는다**(AGENTS §7). 색만으로 의미를 전달하지 않고 항상 텍스트를 병기한다.

### 6-2. 그림자와 모서리

- 그림자 최대 4%. 카드 1단계만. 중첩 금지.
- 모서리 반경 2단계: 카드 12px, 버튼·입력 8px.

### 6-3. 아이콘

**단색 SVG 라인 아이콘으로 통일한다.** 기존 시제품의 면 채운 컬러 아이콘(MES 초록, FEMS 주황)은 교체한다. 앱마다 다른 색을 쓰면 3개가 서로 다른 제품처럼 보인다.

### 6-4. 공통 컴포넌트

| 컴포넌트 | 규격 |
|---|---|
| 기간 선택기 | 당월·전월·최근 7일·직접 지정. 월 단위는 `'YYYY-MM'` 문자열로 질의 |
| 범위 필터 | 계층 선택(사업장 → 공간 → 설비). 솔루션마다 계층 깊이가 다름 |
| 데이터 표 | 정렬·페이지·CSV 내려받기. 열 고정 |
| 상태 배지 | 저채도 3종 + 텍스트 병기 |
| 빈 상태 | **사유 + 다음 행동 링크.** "데이터 없음"만 두지 않는다 |
| 오류 | 인라인 우선. RESTRICT 오류는 **참조처 건수 포함** |
| 계산 근거 패널 | 접었다 펴는 패널. 배분 방법·적용 계수·분개 규칙을 담는다 |
| 미저장 결과 안내 | 계산만 하고 저장하지 않는 화면의 공통 문구 |
| 확정 잠금 표시 | 확정된 행은 수정 불가임을 자물쇠 아이콘 + 툴팁으로 |

마지막 세 개는 FEMS(배출량·요금)와 ERP(분개 미리보기·채권 확정)가 공유한다.

### 6-5. 레이아웃

- 포털은 **상단 헤더만.** 사이드바 없음.
- 각 솔루션은 **좌측 사이드바 + 상단 헤더.** 헤더에 앱 전환 드롭다운과 포털 복귀를 둔다.
- 솔루션 간 이동이 한 번에 되어야 한다. 평가자가 3분 안에 세 개를 다 보려면 홈으로 돌아가는 왕복이 없어야 한다.

| **P-G04** | SCM 설명 카드 내용 | 이번에 새로 추가된 4번째 카드. 원천 문안이 없다 | 낮음 | 보류 — SCM 설명 문안 후속 작성 |
| **P-G05** | 게스트 만료 처리 | `workspace.expires_at` 도달 시 사용자 경험이 설계된 적 없다. 작업 중 만료되면? | 중 | 적용 — 활성 작업 보호·세션 종료 후 TX-12 회수 SERVICE 정책 |
| **P-G06** | `workspace_module` 유지 여부 | 앱 on/off는 학습 과정에서 "모듈을 끈 상태로 완주" 검증(AC-86·92)을 위한 장치였다. **학습 폐기 후 이 기능이 필요한지 재판단 필요** | 중 | 해소 — 앱 on/off를 독립성 시연 수단으로 유지 |

### 처리 제안

- **P-G01·P-G06은 같은 성격이다.** 학습 중심 설계의 잔재로 보인다. 삭제하면 `core` 11 → 9가 된다. 다만 P-G06은 "앱을 끌 수 있다"는 것 자체가 모듈 독립성의 시연이 되므로 **남기는 쪽을 제안한다.** P-G01은 삭제 후보다.
- P-G02는 본 문서 5장 승인으로 해소된다.
- P-G03은 FS-011(개발 규약)에서 경로를 정하는 것이 맞다. 여기서 정하면 규약과 어긋난다.
- P-G05는 화면 설계 문제이자 정책 문제다. **작업 중 만료는 막고 세션 종료 후 회수**하는 방향을 제안한다.
