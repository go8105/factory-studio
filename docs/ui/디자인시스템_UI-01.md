# UI-01 공통 디자인 시스템과 앱 레이아웃

작성: 2026-09-26 (Claude Code) · 브랜치 `ui-01-design-system`
대상: 포털·MES·ERP·FEMS·3D 공장 전체 구현 화면(55개 경로)

## 1. 점검한 문제와 원인

| 문제 | 원인(코드) | 조치 |
|---|---|---|
| 큰 화면에서도 본문이 좁다 | `main { max-width: 1160px }`, 헤더 `padding: calc((100vw - 1080px) / 2)` | 업무 화면은 폭 제한 없음(`main.wide`), 헤더·사이드바·본문 시작선을 `--gutter` 하나로 통일 |
| KPI가 3+1로 줄바꿈 | 좁은 본문(약 830px)에 `minmax(200px)` 격자 | 본문이 넓어져 4개가 한 줄. 모바일은 2열(`minmax(150px)`) |
| 차트·업무가 첫 화면 아래로 밀림 | h1 36px + eyebrow + 설명 + 32px 여백, 패널 패딩 28px, 본문 15px·줄간격 1.65 | 페이지 헤더 한 줄(제목 22px + 화면 ID), 패널 16/20px, 본문 14px·1.5 |
| 메뉴마다 크기·배치가 다름 | 레이아웃 3벌 복제(`FemsLayout`·`MesLayout`·`ErpLayout`), `form-actions`·`toolbar`·`filter-inline`·`field-error`는 스타일이 없었음, select는 일부 영역에서만 스타일 | 공통 `SolutionLayout`, 모든 입력 요소 공통 스타일, 누락 클래스 정의 |
| 어디를 봐야 할지 불명확 | 행 작업이 회색 밑줄 글자, 안내·오류가 같은 색, 상세가 목록 아래 화면 밖에 열림 | 행 작업은 쪽빛 글자 버튼, 안내(`role=note`)·경고·오류(`role=alert`) 색 구분, 상세가 화면 아래쪽에 열리면 스크롤(`RevealAnchor`) |
| 360px에서 상단 메뉴 두 줄·'나가기'가 둘째 줄 | 헤더 nav `flex-wrap` | 메뉴는 가로 스크롤 한 줄, '나가기'는 브랜드 줄 오른쪽 고정 |
| 3D 캔버스가 아래로 밀림 | 큰 제목·두 줄 조작부, 설비 상세가 캔버스 아래 | 제목 한 줄, 조작부 한 줄 툴바, 캔버스 높이 = 뷰포트 − 170px, 넓은 화면에서 설비 상세는 장면 오른쪽 위에 겹쳐 표시 |

## 2. 원칙

- 업무 도구다. 장식보다 현재 상태와 다음 행동을 먼저 보여 준다.
- 폭은 화면에 맞게 쓴다. 읽기 중심(도움말 본문 880px)만 폭을 줄인다.
- 글자를 줄이거나 `zoom`·`transform`으로 축소하지 않는다. 최소 12px(보조), 본문 14px.
- 유리 효과·블러·그라데이션·과한 애니메이션을 쓰지 않는다. 그림자는 최대 4%.
- 상태는 색만으로 구분하지 않는다(배지에는 항상 글자).
- 페이지별 임의 값·`!important`를 추가하지 않는다. 토큰과 공통 클래스만 쓴다.

## 3. 토큰 (`frontend/src/shared/styles.css` `:root`)

| 범주 | 토큰 |
|---|---|
| 면 | `--bg` #F7F7F6(백자) · `--surface` #FFF · `--surface-2` #F1F2F0 |
| 글자 | `--ink` #1A1C1E(먹색) · `--muted` #5D6165 |
| 선 | `--border` 12% · `--border-strong` 24% |
| 강조 | `--accent` #1F2D3D(쪽빛) · `--accent-hover` · `--accent-soft` · `--focus` |
| 상태 | `--ok-*` · `--warn-*` · `--danger-*` · `--info-*` (bg/fg 쌍, 저채도) |
| 글자 크기 | `--fs-xs` 12 · `--fs-sm` 13 · `--fs` 14 · `--fs-lg` 16 · `--fs-xl` 22(페이지 제목) · `--fs-num` 24(KPI) |
| 간격 | `--s1`~`--s6` = 4·8·12·16·20·24 |

| 컨트롤 | `--control` 34px · `--control-sm` 28px |
| 앱 틀 | `--header-h` 52 · `--sidebar-w` 232 · `--gutter` 24(모바일 16) |

## 4. 앱 레이아웃

- **헤더**: 52px, 상단 고정. 브랜드·주 메뉴·나가기. 모바일은 두 줄(브랜드+나가기 / 메뉴 가로 스크롤).
- **솔루션 레이아웃** (`shared/SolutionLayout.tsx`): 232px 사이드바(상단 고정, 자체 스크롤) + 본문.
  - 넓은 화면: 사이드바 머리의 버튼으로 **접기**(52px 레일). 상태는 `localStorage`(`fs.sidebar.collapsed`)에 저장하고, 읽지 못하면 펼친 상태.
  - 800px 이하: `<details>` 요약 버튼이 **서랍**을 연다. 열면 첫 메뉴로 포커스, Esc·배경 클릭·✕로 닫고 요약 버튼으로 포커스 복귀, 메뉴를 누르면 닫힘.
  - 세 솔루션은 메뉴 배열만 넘긴다(`femsScreens`·`mesScreens`·`erpScreens`, 기존 export 유지).
- **페이지 헤더** (`PageTitle`): 제목 + 화면 ID + 한 줄 설명 + 도움말 링크.
- **본문 폭**: `/fems`·`/mes`·`/erp`는 `main.wide`(여백은 레이아웃이 담당). 포털 화면은 전체 폭, 도움말 본문 패널만 880px.

## 5. 공통 컴포넌트·클래스

| 요소 | 규칙 |
|---|---|
| 버튼 | 기본(주요, 쪽빛) · `.secondary`(흰 바탕) · `.link-button`(행 작업, 쪽빛 글자). 높이 34/28px. hover·`:focus-visible`(2px 링)·disabled(45%, not-allowed)·`aria-busy` |
| 입력 | input·select·textarea 공통 34px, `aria-invalid`는 적색 테두리, `.field small`/`.field-error`는 오류 문구 |
| 저장·취소 | `.form-actions`: 폼 끝 구분선 아래, 주요 버튼 먼저 |
| 필터 툴바 | `.filter-bar`(라벨 위·컨트롤 아래, 한 줄 줄바꿈) · `.toolbar`(한 줄) |
| 표 | `DataTable`: 결과 수 → 표(테두리 컨테이너, 내부 가로 스크롤, 첫 열 고정) → 페이지 이동(여러 페이지일 때만). 숫자 열 자동 오른쪽 정렬·고정폭 숫자(`id`·`*Id` 제외), 28자 넘는 글자는 줄임표 + `title`로 전체 값. 직접 쓴 표는 `th/td.num` |
| 목록+상세 | `.master-grid`: 목록 + 오른쪽 360px 상세/등록 패널(상단 고정, 1024px 이하에서 아래로). 목록 아래에 열리는 상세는 `RevealAnchor`로 보이게 스크롤 |
| KPI | `.kpi-grid` + `.stat-tile`: 라벨·값(단위 분리)·기준 설명·상태 배지 |
| 차트 | `.reading-chart`: 제목(단위 포함)·축·기간/값 안내 문구 |
| 배지 | `.badge`(정상) · `.warning` · `.issue` — 둥근 알약, 글자로 의미 전달 |
| 알림 | `.notice` 경고 · `[role=note]` 안내 · `[role=alert]` 오류 |
| 탭 | `.tabs`: 세그먼트 형태, `aria-current`/`aria-pressed` |
| 로딩·빈 상태 | `Loading`(지연 표시) · `EmptyState`(점선 상자 + 다음 행동 링크) · `ErrorNotice`(코드·상세·다시 시도) · 모듈 꺼짐·세션 만료 화면 기존 유지 |

## 6. 화면 유형별 적용

- **대시보드**(F-01·M-01·E-01): 1366×768에서 4 KPI 한 줄, 주요 차트·처리 대기가 첫 화면에 보인다. 1920×1080에서는 MES 대시보드 전체가 한 화면.
- **목록**: 결과 수·CSV → 표 → 페이지 순서 통일. 금액·수량 오른쪽 정렬.
- **등록·수정**: 오른쪽 고정 패널, 필드 간격 12px, 저장·취소 위치 통일. 입력값·검증 규칙·API 호출은 바꾸지 않았다.
- **포털**: 같은 헤더·패널·배지 규칙. 도움말은 읽기 폭.
- **3D 공장**: 캔버스 최대 확보, 설비 상세는 넓은 화면에서 장면 위 오른쪽(이동 패드와 겹치지 않도록 높이 제한), 모바일에서는 캔버스 아래.

## 7. 하지 않은 것 (의도)

- 모달을 새로 만들지 않았다. 현재 구현에 모달이 없고, 짧은 확인은 기존 2단계 버튼(삭제 → 삭제 확정)이 담당한다. 모달 규칙(포커스 이동·복귀·미저장 보호)은 모달이 필요한 기능이 생길 때 적용한다.
- 업무 규칙·데이터 의미·권한·DB/API 계약·검증 규칙은 바꾸지 않았다. 새 업무 기능을 만들지 않았다.
- 수치 표시 형식(소수 자릿수 등)은 데이터 의미에 해당해 그대로 두었다.
