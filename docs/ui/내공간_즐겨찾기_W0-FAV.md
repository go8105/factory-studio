# 내 공간·즐겨찾기 W0-FAV

2026-10-09~10 사용자 구현 요청: 참고 폴더의 React 시제품과 첨부 화면 2장의 내 공간/메뉴 추가 구성을 적용한다. 각 솔루션 사이드바도 등록한 메뉴만 보도록 연결한다. 다음을 구현 범위로 확정한다.

- 내 공간 위에는 자주 사용하는 메뉴 카드, 솔루션 필터, 메뉴 추가/순서 편집, 사용 안내와 실제 최근 방문 메뉴를 둔다. 기존 앱 사용 여부·공간 상태·예시 초기화 기능은 아래에 유지한다.
- 메뉴 추가 창은 데스크톱에서 솔루션/분류별 선택/선택한 메뉴 3열, 모바일에서는 세로로 읽는다. 선택은 임시 상태이며 적용할 때 저장하고 취소하면 버린다. 체크박스·검색·등록 수·제거·드래그 및 키보드 사용 가능한 순서 이동을 제공한다.
- 현재 구현된 9솔루션 108화면 정의를 API와 프런트가 공유한다. 참고 시제품의 미구현 메뉴는 현재 제품의 실제 메뉴로 대체한다. 기본은 GW 기안·결재·기록·게시판, MES 현황, WMS 현황 6개다.
- 사이드바는 기본적으로 해당 솔루션에 등록한 즐겨찾기를 등록 순서대로 표시한다. 전체 메뉴 전환과 등록/해제 버튼, 내 공간 구성 링크를 남겨 빈 목록에서도 다시 메뉴를 선택할 수 있다. 메뉴 숨김은 접근 권한 변경이 아니다.
- 메뉴 구성·사이드바 모드는 회원 개인 공간 또는 게스트 공간에 서버 저장한다. 회원 재로그인·다른 기기에서 공유하고 예시 데이터 세대 초기화에도 보존한다. 게스트 만료·삭제 때 함께 정리된다. 최근 방문 내역은 이 브라우저의 공간별 키에만 보관한다. 저장 범위 질문에 답이 없는 상태에서는 계정·공간 서버 저장을 기본으로 진행한다고 사용자에게 알렸다.
- 꺼진 앱의 메뉴 구성은 지우지 않고 사용 꺼짐을 표시한다. 실행은 기존 모듈 사용/권한 검사를 따른다. 개인정보·업무 레코드·문서 원문을 메뉴 설정에 담지 않는다.

## API·저장 계약

core의 공간·플랫폼 설정 범위이며 업무 스키마나 업무 FK를 추가하지 않는다. `core.workspace.menu_preferences`에는 순서가 있는 `menuIds`와 `sidebarMode(all/favorites)`만 저장하고 별도 `menu_preferences_version`으로 다른 창의 변경을 검사한다. NULL은 기본 구성, 빈 menuIds는 사용자가 모두 제거한 구성이다.

`GET /api/v1/core/workspace/menus`는 자기 공간 설정을 읽는다. `PUT`은 expectedVersion, CSRF와 Idempotency-Key가 필요하다. 공간 잠금 아래 버전·요청 영수증·감사와 함께 한 트랜잭션으로 저장한다. 같은 키 재전송은 같은 결과, 다른 본문은 422, 다른 창의 버전은 409. 메뉴 ID 중복/미구현 메뉴는 400이다. 불확실한 응답은 본문·키를 유지해 재시도하며 이동·새 편집을 잠근다. 확인된 저장 이후의 단순 재조회는 PUT을 반복하지 않는다.

스키마 0.22.1/173표/1,918컬럼/412FK, `gw_a_dsn31 → w0_fav_workspace_menus → w0_fav_menu_shape`. 후자는 JSON null 모드 거부 보강이며 전용 DB에 적용한 초기 revision을 수정하지 않았다. Excel·실제 ERD를 함께 갱신했다. 목표 설계의 core.workspace도 같은 설정 컬럼·CHECK 및 base_task W0-FAV로 동기화했다. 목표 업무 표·FK는 그대로 유지한다.
