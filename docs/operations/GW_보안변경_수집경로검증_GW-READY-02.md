## 기존 수집과 검증 구분

MFA 등록/로그인·복구·코드 재발급·다른 세션 회수·로그아웃·HR 회사/직원 생성·역할/중지 변경은 기존 수집 경로이며 이번 관련 회귀에서도 확인한다. GW 직원 연결·역할/문서 ACL 변경은 앞선 회사 경로 검증 이력이 있고 이번에 해당 전체 테스트를 새로 실행한 것으로 표시하지 않는다. 기록을 파일에 남긴 것, DB에 반영된 것, 모든 경로의 누락이 없다는 것은 서로 다른 조건이다.

## 아직 전체 인수로 인정하지 않는 경로

- common/auth의 세션 유휴 만료 연장은 아래18차의 명시적 재생 제외 대상으로 판정했다. throttle의 초기0 새 창/최종 갱신 시각은 거부 횟수 증가와 구분한다. 모든 카운터 의미·부하·복구 인수는 별도다.
- core.service.create_member_account 및 HR 초기 회사/예제 계정 생성·중지·활성화는18차에서 계정 상태 수집을 연결했다. seed/나머지 운영 스크립트·실서버 도구 실행 인수는 별도이며 전체 자동 기록을 주장하지 않는다.
- 복원 도구의 계정/세션 제한 재적용은 원본 변경 수집과 구분한다. 복원 대상에 기록을 재생하는 행위를 원본 변경 기록으로 다시 수집하지 않는다.
- 직접 SQL/DB 소유자 작업, 배포/계정 초기 설정, 향후 SSO 변경은 별도 통제·인수 대상이다. 이번 파일 검색만으로 모든 쓰기 경로를 발견했다고 인정하지 않는다.
- 파일 삭제/변조·독립 최신성·거래 취소·외부 사본·격리 복원 검사는 각각의 기존 검증 범위를 따른다. 초기 설정이 없던 과거 변경을 소급 수집하지 않는다.

## 전체 회수 인수의 남은 기준

경로 목록의 책임자 검토, 누락 없는 실행 근거, 변경 이후 현재 원본과 checkpoint의 연결, 격리 복원 후 세션/미완료 인증 회수·회수 계정 거부, 관리자/직원 대표 업무를 함께 검증해야 한다. 이번 변경은 로그인 요청·거부 경로의 실제 누락을 보완한 단계다. completenessConfirmed/전체 revocationsReapplied/ready를 true로 바꾸지 않는다.

| 세션 유휴 만료 연장 | 매 요청별 별도 암호화 의도는 남기지 않음 | 절대 만료 상한·제한 재적용 뒤 이전 토큰 거부 |

추가 초기 설정 기록은 core 소유 계정/역할/회사 멤버십 상태다. HR 업무 원문이나 비밀번호를 복사하지 않는다. 평상시 HR 사용자 관리의 기존 HR 소유 스냅샷 수집을 대체하지 않는다. 원본/계정 상태 수집에 실패하면 같은 트랜잭션을 취소한다. 실제 계정 생성·비밀번호 설정·운영 도구 실행은 이번 개발에서 수행하지 않았고 소유 합성DB의 진입 함수만 검사했다.

세션 연장은 기존 미회수 세션의 유휴 만료를 절대 만료 안에서 조정한다. 복원은 모든 기존 세션을 회수하므로 이 연장을 원본 허용 상태로 재생하지 않는다. 매 HTTP 요청마다 계정 전체를 암호화해 기록하면 잠금/보관 부하가 크게 늘기 때문에 권한·발급/회수 변경과 구분한다. 이 제외가 모든 세션 경로 검증 완료나 전체 수집 완전성을 뜻하지는 않는다. 향후 세션 재사용/복원 정책을 바꾸면 이 판단도 다시 검증해야 한다.

throttle의 새 창 초기0과 updated_at 갱신은 실패/발급 횟수 증가와 구분한다. 현재 횟수 증가는 기존 기록·checkpoint 최댓값 재적용으로 다루며, 운영 환경의 모든 제한 창 의미/부하 검증은 남아 있다. 직접SQL·기타seed/관리도구·향후SSO·실환경 장애와 전체 권한 회수 인수까지 마치기 전에는 completeness/ready를 올리지 않는다.

## 19차 격리 복원 접근 거부 시나리오

기존 test_backup_journal_restore.py의 실제 PostgreSQL dump/restore 두 경로(수동 지문, 폴더 교체+전달 확인 자동 지문)를 보강했다. 원본은 합성 관리자/직원 회사이며 실제 10인 회사 인수와 구분한다.

1. 백업 전 관리자/직원 세션과 합성 미완료 로그인 요청을 준비한다.
2. 백업 뒤 직원 연결 회수·재개, HR 역할 변경을 수행한다. 원본 직원의 기존 세션은 HR 역할 변경으로 이미 회수되는 것이 정상이다.
3. 최신 checkpoint와 독립 지문으로 새 접속 제한 DB를 복원한다.
4. 직원 계정/HR 계정 제한, GW 연결 정지·회사 보존 중지, 모든 기존 세션 회수, 미완료 요청 EXPIRED를 대조한다.
5. 제품의 실제 인증 판별 함수로 복원본의 옛 관리자/직원 토큰이 모두401 거부되는지 확인한다. 미완료 요청의 인증 확인도401이며 새 세션이 생기지 않아야 한다.
6. 검사 후에도 복원DB datconnlimit=0을 유지한다. 테스트 소유 superuser로 내부 검증할 뿐 직원 연결을 열지 않는다.
7. 원본의 관리자 토큰/운영 준비 HTTP 조회는 계속 사용 가능하고, 역할 변경으로 회수된 직원 토큰은 거부되며 계정 자체는 활성/직원 역할을 유지하는지 확인한다. 원본 미완료 요청도 임의로 만료시키지 않는다.

기존 checkpoint 검사는 OTP/복구코드 소비, 암호 변경, HR 역할 하향, 불확실 ACL/보존 중지를 각각 다룬다. 두 경로를 조합했더라도 모든 운영 쓰기의 무누락·실회사 장애/부하·운영 개방 승인을 의미하지 않는다. 서명 증거의 전체 revocationsReapplied/checkpointCompletenessConfirmed와 ready는 계속 false다.


## 29차 관측 기록계열 진단 · 개별 경로 완전성과 구분

기존 `tools/gw_identity_journal.py --expected-head <별도확인한지문> --classify-transactions --review-report <0700폴더의새파일>`은 검증한 기록/DB 감사/거래판정을 `recordingFamilies`로도 집계한다. 인증(core.security.intent.v1)·HR(hr.users.intent.v1)·GW(gw.company.intent.v2) 각각 MISSING(기록없음)/SETTLED(관측거래정리)/UNSETTLED(미확인포함)와6종 거래상태 건수를 제공한다. 계정·본문·operation원문은 출력하지 않는다.

하나라도 기록없음/미확인 또는 과거v1·미지원계열이 있으면 계열결과 BLOCKED다. 모두정리돼도 PARTIAL이며 모든 개별경로 실행·기록저장실패시롤백·최신지문/전체회수/원본유지·직접SQL/운영자경계는 별도 검증한다. 같은계열의 다른operation 기록을 특정경로의 실행근거로 인정하지 않는다. 없는계열을 과거형식으로 채우지 않는다.

기존CLI 종료코드는 거래상태 기준이다. 따라서 취소가확인된 인증기록1건만 있으면 exit0이어도 HR/GW는 MISSING·계열결과BLOCKED일수있다. exit0을 수집완전성이나 운영승인으로 사용하지 않는다. completenessConfirmed/revocationsReapplied/releaseAuthorized=false 유지. unsigned검토보고서는 제품 ACCEPTANCE 등록이나 checkpoint입력으로 쓰지 않는다.


## 30차 회사 범위 GW 연결·역할 7경로 진단

기존 기록CLI의 `--company-id <양의회사번호>`를 `--classify-transactions` 또는 `--review-report`와 함께 지정한다. `FS_CODE_REVISION`이 필요하다. 같은 읽기전용 REPEATABLE READ 거래에서 활성회사 현재정책/세대·DBhead를 읽어 `identityRoutes`를 출력/보고에 연결한다. GW_IDENTITY_ROUTES_V1은 최초설정·연결요청/수락/취소/중지/재개·역할변경7개다. 인증/HR/문서ACL 전체목록은후속이다.

다른회사/세대기록 제외·정확operation만 분류·대상ID미출력. MISSING은기록없음, ABORT_ONLY는전체거래취소만관측, UNSETTLED는미확인포함, COMMIT_OBSERVED는미확인없이감사확정을관측한것이다. 다른operation/과거형식으로 채우지않으며 이후미확인에 과거성공대체없음.

현재정책/제품/DB는 assessment기준이다. 과거기록에 실행코드버전이없어 executionRevisionVerified=false이며 현재버전실행증거로 쓰지않는다. 저장실패롤백/복원거부는UNVERIFIED다. 이번합성실HTTP는 중지경로503시상태/버전유지→재시도200·직원403을확인했으나 unsigned관측보고에소급입력하지않는다. 모두관측도PARTIAL·전체회수/완전성/전환승인false. CLI exit0은경로/운영인수통과가아니다.


## 31차 합성 경로 검증 실행 수집기

`tools/gw_route_verify.py`는 새 소유 테스트DB에서 고정 시나리오를 직접 실행한다. 소유권을 확인한 로컬PG의 postgres 관리연결을 `FS_GW_ROUTE_VERIFY_ADMIN_URL` 환경에 비공개 주입한다. 기존 DB를 초기화하지 않고 새UUID *_test만 생성/마이그레이션/정리한다. 보고서 폴더는0700이어야 한다.

```sh
uv run --project backend python tools/gw_route_verify.py \
  --report work/route-verification/new-execution.json
```

현재 고정 검증은 직원연결중지 기록저장실패503/상태·버전불변→재시도200/직원업무403/현재정책진단과 거래취소/진행/저장점/다른원본 판정2개다. 임의명령·외부JUnit·수동PASS 입력을 받지 않는다. 실행번호/기준커밋과 backend/tools 실제소스지문/DB버전/시각/각시나리오결과를0600에 기록한다. 실행전후소스가 바뀌면BLOCKED다. 실패/건너뜀/누락/중복/비정상종료를 성공으로 바꾸지 않는다. 로그·JUnit은비공개임시폴더에서처리후정리하며 공개보고에원문/접속정보/계정/경로를넣지않는다.

성공도 합성 PARTIAL/exit0이며 ready=false다. 실패결과는BLOCKED/exit2, 환경/실행예외는exit1이고 예외시보고서가항상생성되지는않는다. 초기JUnit모듈명대조실패보고도보존했다. 기존파일덮어쓰기없음. 실제회사/기기의실행이나현재회사정책인수, 전체권한회수·누락없음·복원후거부검증이아니다. 보고서는unsigned이며제품ACCEPTANCE등록에사용하지않는다. 나머지경로/복원거부어댑터는후속이다.


## 32차 고정 실행 시나리오 V2 · 8개

31차수집기의 카탈로그 GW_SYNTHETIC_ROUTE_PROBES_V2는 기존2개에 MFA등록롤백·로그인요청발급롤백·비밀번호세션발급롤백·HR계정/권한변경·문서ACL롤백/기록·실격리복원후거부를더한8개다. 전체경로나모든권한조합의인수를뜻하지않는다. 문서제출은기록저장503시원문상태/버전/기록수불변→재시도제출/승인까지검사한다.

실복원검사를위해 기존관리연결외에 `GW_BACKUP_TEST_CONTAINER`와 `FS_GW_ROUTE_VERIFY_OWNER`(컨테이너factory-studio.owner라벨값)를설정한다. 수집기는컨테이너실행상태/라벨/PG포트매핑이관리URL의동일loopback대상인지확인한다. 컨테이너미설정은복원SKIPPED/BLOCKED, 불일치는실행전거부다. 실제운영컨테이너를지정하지않는다. 새원본시험DB와격리복원DB만사용하며기존preview/운영DB는초기화하지않는다.

전체8개PASSED/정상종료·소스불변시에만 `restoredAccessDenial=SYNTHETIC_SCENARIO_PASSED`를기록한다. 실패·건너뜀·코드변경에는UNVERIFIED를유지한다. 이는합성복원시나리오범위의통과이며전체revocationsReapplied/completenessConfirmed/ready=false와실회사인수미완료는그대로다. unsigned보고서는제품ACCEPTANCE등록용이아니다. 첫실패보고서도덮어쓰지않고새실행으로기록한다.


## 33차 고정 실행 시나리오 V3 · 12개

카탈로그 GW_SYNTHETIC_ROUTE_PROBES_V3는V2의8개에 연결취소·재개·역할부여·회수4개를더한다. 실패주입503때 S범위연결/직원버전·역할·권한버전/멱등영수증과기록수가유지되는지, 같은요청재시도후1회만기록되는지, 중복재시도가변경을늘리지않는지확인한다. 옛버전409·비권한403도원본불변을대조한다.

취소후본인수락/업무거부·재개후업무허용, 보안역할부여후보안이력허용/회수후거부·추가권한변경거부와마지막보안관리자보호를확인한다. 고정probe파일은미추적상태여도실코드지문에포함한다. 이번12개통과는지정합성시나리오의실행결과이며인증/HR/ACL전체분기·무누락/실회사인수가아니다. 기존PARTIAL/ready=false와실환경미확인4조건을유지한다. 수집기실행/비공개환경/소유컨테이너·DB정리규칙은32차와동일하다.


## 34차 고정 실행 시나리오 V4 · 23개

카탈로그 GW_SYNTHETIC_ROUTE_PROBES_V4는V3의12개에인증관련11개를더한다. OTP실패/잠금·요청만료/버전거부의기록대조, denied/expired/emergency기록실패롤백, 코드복구경합/제한세션·재등록/옛코드거부, 다른세션회수/코드재발급, 긴급문서만료, 긴급HTTP복구·현재역할/승인만료재확인, 로그아웃401을실행한다.

긴급복구는승인경합의단일성공·CSRF/Origin거부·업무세션우회금지·재등록/승인재사용거부를확인하고 새암호화기록과DB감사확정을대조한다. 역할이없거나승인이만료되면복구완료기록으로채우지않는다. 테스트준비용직접SQL의만료·권한설정은전체변경자동수집으로인정하지않는다. JUnit파라미터가다른결과도해당검사실행으로대체하지않는다.

## 35차 서명 인수 점검과 합성 결과의 경계

서명된 인수 일부 확인은 현재 BACKUP/RESTORE 원본만 참조한다. 이 문서의 고정23개 합성 실행 보고서는 계속 unsigned이며 인수 입력으로 등록하지 않는다. 새 계약/최신 등록 대조와 실행 명령은 [실회사 인수 절차 §10](GW_실회사_인수절차_10인_GW-READY-02.md)을 따른다. 서명을 추가해 전체 변경 수집·권한 회수·실회사 인수를 통과시키지 않는다.

## 55차 목록 신뢰 상태의 보존 경계

목록 발행 키의 정상 교체/회수는 [실회사 인수 절차 §29](GW_실회사_인수절차_10인_GW-READY-02.md)의 별도 로컬 보존 이력·현재 지문 CAS와 연결한다. 명시 revoke 뒤 과거 유효한 환경/승인을 되돌려도 차단한다. 이는 목록 키 상태의 로컬 후퇴 차단이며 인증/HR/ACL 전체 변경 무누락·실회사 권한 회수 또는 독립 외부 원장/WORM 인수를 통과시키지 않는다. 환경만 수정하고 영구 기록 절차를 생략하면 회수 절차가 완료된 것이 아니다. 실제 복원 PARTIAL·ready=false/최종4조건 UNVERIFIED를 유지한다.

## 56차 신뢰 원본 전달/복구의 경계

[실회사 인수 절차 §30](GW_실회사_인수절차_10인_GW-READY-02.md)은 별도로 확인한 최신 원장/지문과 남은 원본의 더 최신 회수·분기를 대조해 새 폴더에 신뢰 원본만 재구성한다. 손상 원본/실패 폴더를 보존하며 서버 사용 경로와 회사/키 권한을 자동 바꾸지 않는다. 완료 응답은 신뢰 원본 재구성이고 이 문서의 인증/HR/ACL 전체 경로·무누락/실회사 권한 회수 또는 독립 외부 보관의 인수 증거가 아니다. 실제 복원 PARTIAL·ready=false/최종4조건 UNVERIFIED 유지.


## 57차 서버 설정 차단의 화면 안내

운영 준비에서 고정된7종 차단 코드와 서버 담당자의 다음 조치를 제공한다(실회사 절차 §31). 원본 경로/키·예외 전문은 제공하지 않으며 직원 응답에는 서버 진단이 없다. GET 재점검은 현재 신뢰 설정·최신 근거를 다시 읽을 뿐 기록 수집/회수·복구를 실행하지 않는다. 보존/수신 미완료를 과거 성공으로 대신하지 않고 ready=false/미확인4조건·실제 복원 PARTIAL을 유지한다. 이 UI 변경이나 허용 코드 구분은 전체 경로의 누락 없는 수집/실제 권한 회수 인수 증거가 아니다.

## 58차 공통 계약과 전체 회수의 경계

[실회사 인수 절차 §32](GW_실회사_인수절차_10인_GW-READY-02.md)의12조건 계약/실행 어댑터는 기존 원본 검증기를 재사용하고 최신 등록부터 선택한다. 경로 검사·변경 관측·복원 재관측·목록/신뢰 회수는 전체 수집/회수 조건을 지원하는 일부 도구이며 GET에서 새로 실행하지 않는다. 실제 전경로 누락·직접SQL/재생 제외·독립 최신성·모든 회수 권한 거부 인수는 미확인이다. unsigned 합성 보고나 파일 자기 주장에 서명/체크를 더해 완료로 올리지 않는다. JOURNAL_COVERAGE는 LIVE_ENVIRONMENT/NOT_EXECUTED/UNVERIFIED, 실제 복원 PARTIAL·ready=false를 유지한다.

## 59차 권한 거부의 제한된 검토 목록

[실회사 인수 절차 §33](GW_실회사_인수절차_10인_GW-READY-02.md)의 선택형 실행 보고는 같은 읽기 거래의10인 구성/최신 원본/12조건을 대조한다. 권한 거부8영역은 기존 시험 참조와 미연결 확인을 표시하는 `SELECTED_REVOCATION_BOUNDARIES`이며 전수 경로 목록이 아니다. 인증 판별401·원본 HTTP 거부·복원/replay 제한 상태·격리와 실제 복원본의 새 인증 후 업무 권한 거부를 구분한다. 보고서 생성은 이 시험들을 실행하지 않고 unsigned 합성 결과를 가져오지도 않는다. 모든 검토 행 NOT_EXECUTED·coverageComplete/revocationsComplete=false다. 직접SQL/운영 도구·게시 대상/위임/채팅/일정·향후SSO·독립 최신성/실기기 검증은 별도다. 기존 복원PARTIAL·최종4조건 UNVERIFIED/ready=false 유지.
