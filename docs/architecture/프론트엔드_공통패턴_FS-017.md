# FS-017 프론트엔드 공통 패턴

> FS-017a 인계: 분할 지시 전 작성된 문서 초안이다. 공통 컴포넌트·P-01/P-02는 FS-017a 완료이며, P-03~P-07과 계약·재현 안내의 최종 확정은 FS-017b/c에서 수행한다.

이 문서는 antigravity가 반복 화면을 만들 때 쓰는 첫 구현 기준이다. 포털 P-01~P-07을 대상으로 확정했으며, 업무 API는 추가하지 않았다.

## 구조와 레이아웃

- `frontend/src/app/App.tsx`: React Router 경로, 포털 상단 헤더·본문·하단 안내, 로그인 필요 경계, 관리자 경계. 포털에 사이드바를 추가하지 않는다.
- `app/session.tsx`: 세션을 한 곳에서 관리한다. `useSession()`으로 `session`, `refresh`, `fail`, `busy`, `setBusy`를 사용한다. 토큰은 브라우저 메모리만 사용하며 인증 쿠키는 HttpOnly다.
- `shared/styles.css`: 백자·먹색·쪽빛, 12px 카드/8px 버튼, 4% 이내 그림자, 저채도 배지, 360px 재배치, 키보드 포커스·본문 바로가기·감소 모션.
- 각 화면 상단에 화면 ID 주석을 두고 `PageTitle`에 같은 ID를 준다. 이 ID가 맥락 도움말 경로가 된다.

## 재사용 컴포넌트

| 컴포넌트 | 사용법 |
|---|---|
| `PageTitle` | `id="P-06" title="내 공간"`, 화면별 도움말 버튼 포함 |
| `Field` | `label`, input 속성, `error` 전달. label/id와 오류 설명을 자동 연결 |
| `ErrorNotice` | `ApiError`를 전달. code/message/details 표시, references 건수를 생략하지 않음. `retry`는 동일 요청 재확인용 |
| `EmptyState` | `reason`, `to`, `action` 필수. 원인과 다음 행동 함께 제공 |
| `Loading` | `label`, 선택 `delay`. 게스트 복사는 `delay={1000}`으로 깜빡임 방지 |
| `SessionExpired` | 저장되지 않은 입력을 저장 완료로 오인하지 않도록 안내. 진입·공통 도움말 제공 |
| `Badge` | `tone=normal/warning/issue`, 의미를 children 텍스트로 반드시 표시 |
| `DataTable<T>` | 행·columns·caption·offset/limit/total·onPage 전달. 첫 열 고정, offset 페이지, 현재 페이지 열 정렬·CSV |
| `MarkdownContent` | 리포지토리 Markdown 표시, GFM 표·목록 지원, raw HTML 제외 |

표의 정렬·CSV는 **현재 페이지** 기준이다. FS-016 관리자 목록 API는 전역 정렬 인자를 지원하지 않아 서버의 id 내림차순 페이지 순서를 유지한다. 향후 업무 API가 정렬을 지원하면 별도 서버 정렬 제어를 붙인다. 현재 동작을 전역 정렬로 표기하지 않는다. CSV는 따옴표를 이스케이프하고 수식 시작 문자를 보호한다.

## API와 변경 요청

```tsx
const { session, fail } = useSession();
const keys = useRef(new MutationKeys());
const operation = `module:${moduleKey}:${enabled}`;
try {
  await api(`/workspace/modules/${moduleKey}`, {
    method: "PATCH", body: { enabled }, csrf: session?.csrfToken,
    key: keys.current.get(operation),
  });
  keys.current.complete(operation);
} catch (error) {
  // 인라인 ErrorNotice 표시. 401/410은 fail(error)로 전역 만료 처리.
}
```

`api`는 `/api/v1/core` 접두어, 동일 출처 쿠키, 오류 봉투를 공통 처리한다. 범위 키를 요청에 넣지 않는다. 멱등 키는 동작·본문 단위로 만들고 확인된 성공 후에만 폐기한다. 네트워크 불확실·5xx에서 재시도할 때 같은 키를 보존한다. 키 보존 범위는 현재 화면 인스턴스이며 새로고침 후 자동으로 변경 요청을 재전송하지 않는다. 세션·비밀번호·쿠키는 로컬 스토리지에 저장하지 않는다.

P-06의 서버 변경 성공과 후속 조회 실패를 구분한다. 후속 조회 실패 때문에 완료한 초기화 POST를 다시 실행하지 않는다. 초기화는 되돌릴 수 없음 확인 후 실행하며 처리 중 이동·중복 조작을 막는다. API를 통해 세션을 복구하면 CSRF 토큰도 함께 받는다. 만료·종료된 세션 응답에서는 서버가 만료 쿠키를 지운다.

## 정적 콘텐츠 계약

- 도움말 키: `portal/p-01`, `mes/m-01`, `erp/e-01`, `fems/f-01`, `common`. `content/help/**/*.md`를 빌드 시 포함한다.
- P-05는 전체 허브이며 각 화면 `PageTitle`의 도움말 진입이 맥락 문서로 연결된다.
- 카드 qms/wms/bems는 기존 문안을 그대로 읽는다. SCM에는 제목만 표시한다.
- 흐름 맵은 `version: 1`, `nodes`, `edges`. 노드 `id/label/module/kind/helpKey`, 연결 `from/to/label/kind`를 필수로 둔다. `kind=solution`은 구현 범위(실선), `card`는 설명 카드(점선)이며 현재 실제 구현 완료 상태를 뜻하지 않는다.
- FS-005a의 17개 노드·19개 연결을 유지하고 FS-013에 따라 master_data 소유를 erp로 정리했다. 학습 진행·채점 필드는 없다. SCM 노드는 원천 17개에 없으므로 임의 추가하지 않는다.
- Ajv 스키마 검사 외에 노드 ID 유일성·연결 참조·도움말 존재·QMS 우회 실선을 독립 테스트로 고정한다.
- 사용자 승인 임시 연결: 런처/업무 노드 → 기존 도움말. FS-018~020에서 해당 업무 화면으로 교체한다.

## 검증 추가 방식

`*.test.tsx`는 검증 항목별로 나눈다. 예: 모듈 토글 요청 헤더 / 초기화 확인 전 요청 금지 / 게스트 관리자 404를 각각 테스트한다. 브라우저 스모크는 실제 서버·별도 테스트 DB에 연결한다. `backend/tests/test_common.py`, `test_seed.py`는 antigravity 소유로 유지하며 FS-017 회귀는 `test_portal_session.py`에만 추가했다.
