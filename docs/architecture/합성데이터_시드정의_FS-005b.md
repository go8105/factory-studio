# FS-005b 합성 데이터·세대 시드 정의

> **대체됨 (2026-09-23).** 시드 기준본은 [FS-005g](합성데이터_시드정의_FS-005g.md)다. 이 문서는 단일 스키마·단일 에너지원·BOM 없음·학습 과정 전제의 이력으로 보존한다. 수량·규칙을 인용하지 않는다.

작성일: 2026-09-20. 상태: 정의 확정, 생성기 미구현.
기준: [FS-005a 차분 설계](../architecture/차분설계_게스트_ERP_프로세스맵_FS-005a.md), [MTS 전체 흐름 노드 정의서](MTS_전체흐름_노드정의서_FS-005a.md), [FS-004 학습 경로](../modules/learning/학습경로_수용기준_FS-004.md).
용도: 세대 생성기(`seed/`)의 요구사항 기준본. 실행 기반 구축(FS-009) 전에 확정해야 스키마와 학습 검증이 흔들리지 않는다.

---

## 1. 설계 전제

시드는 화면에 채울 예시 데이터가 아니라 **스키마·학습 수용 기준·게스트 진입 성능을 동시에 구속하는 제약**이다. 세 가지를 동시에 만족해야 한다.

| 요구 | 내용 |
|---|---|
| 재현성 | 같은 `seed_version`과 같은 기준일이면 항상 같은 데이터가 나온다 |
| 학습 가능성 | 각 과정의 시작점이 되는 **미완료 건**이 남아 있어야 한다 |
| 게스트 진입 속도 | 세대 하나를 수 초가 아니라 1~2초 안에 준비해야 한다 |

세 번째가 나머지 둘의 상한을 정한다. 전체 행 수가 커지면 게스트 진입이 무너지고, 그러면 포트폴리오로서 실패한다.

---

## 2. 시드 사업장

**소형 전자부품 양산 공장.** 커넥터·터미널류를 사출 → 조립 → 검사 3공정으로 만들어 박스·팔레트로 포장해 출하한다.

반도체 후공정(기존 문서의 예시)에서 바꾼 이유: 후공정은 수탁가공(MTO) 성격이 강해 판매계획을 기점으로 하는 MTS 흐름과 어긋난다. 양산형 부품은 계획생산·완제품 재고·팔레트 패킹이 모두 자연스럽다.

### 2.1 기준정보

| 구분 | 수량 | 내용 |
|---|---|---|
| 품목 | 6 | 완제품 3, 반제품 1, 원자재 2. 기준단위 EA |
| 공정 | 3 | `INJ` 사출 → `ASM` 조립 → `INS` 검사 |
| 설비 | 8 | 사출기 3, 조립기 3, 검사기 2 |
| 거래처 | 4 | 고객 3, 공급처 1 |
| 공정 경로 | 4 | 완제품 3종 × 게시본 1 + **미게시 1** (오류 시나리오용) |
| 계측기 | 9 | 설비별 제조 계측기 8 + 사업장 전체 계량기 1 |

설비·공정 허용 관계는 공정 유형과 설비 유형을 일치시킨다. 사출 공정에 검사기를 지정할 수 없다.

## 3. 시간축 규칙

**절대 날짜를 시드에 고정하지 않는다.** 고정하면 반년 뒤 심사자가 열었을 때 낡은 데이터가 뜬다. 매번 난수로 만들면 학습 검증 시나리오가 깨진다.

- 모든 시각을 **기준일 T로부터의 오프셋**으로 정의한다. T는 세대 생성 시각의 Asia/Seoul 자정이다.
- 오프셋은 `seed_version`에 고정된 상수다. 난수를 쓰지 않는다. 같은 버전·같은 T면 결과가 같다.
- 저장은 UTC, 표시는 Asia/Seoul.

| 데이터 | 기간 |
|---|---|
| 업무 데이터(계획·지시·실적·출하) | **T-60일 ~ T** |
| 계측 데이터 | **T-30일 ~ T** |

기간을 분리한 이유는 4.7에 있다. 판매계획 대비 실적 비교에는 2개월이 필요하지만, 계측을 60일로 늘리면 행 수가 두 배가 되어 게스트 진입 예산을 넘는다.

## 4. 데이터 구성

### 4.1 계획

| 대상 | 수량 | 상태 |
|---|---|---|
| 판매계획 | 2건 (전월 `T-1M`, 당월 `T`) | 전월 confirmed, 당월 confirmed |
| 판매계획 라인 | 6 (계획당 완제품 3종) | — |
| 생산계획 | 2건 | 전월 confirmed, 당월 confirmed |
| 생산계획 라인 | 18 (계획당 3품목 × 3주차) | — |

당월 계획은 실적이 아직 못 미치는 상태로 둔다. 계획 대비 실적 차이를 보여주는 것이 C2의 학습 포인트다.

### 4.2 작업지시와 LOT

작업지시 **30건**의 상태 분포:

| 상태 | 건수 | 용도 |
|---|---|---|
| completed | 18 | 완료 이력 |
| in_progress | 6 | 이어서 실행 가능 |
| released, LOT 미생성 | 3 | **C1 시작점** |
| released, LOT 생성만 | 2 | 공정 진입 시작점 |
| cancelled | 1 | 취소 이력 |

LOT은 **26건** (30 − 미생성 3 − 취소 1). 첫 버전은 1지시 = 1LOT이다.

### 4.3 공정 실행과 실적

| LOT 상태 | LOT 수 | 실행 | 확정 실적 |
|---|---|---|---|
| 3공정 완료 | 18 | 54 | 54 |
| 1공정만 완료 | 2 | 2 | 2 |
| 2공정 완료 | 2 | 4 | 4 |
| 1공정 완료 + 2공정 진행 중 | 2 | 4 | 2 |
| 생성만 (ready) | 2 | 0 | 0 |
| **합계** | **26** | **64** | **62** |

진행 중 실행 2건은 실적이 없다. **결과 부재와 양품 0을 구별**하는 설계를 시드에서 그대로 보여준다.

불량률은 품목·공정별로 0~3% 범위의 고정값을 쓴다. 난수를 쓰지 않는다.

### 4.4 패킹·입고

완료 18 LOT 중 전량 불량 1건을 제외한 **17 LOT**이 패킹 대상이다.

| 처리 | LOT 수 | 산출 |
|---|---|---|
| BOX → PALLET → 입고 완료 | 12 | BOX 24, PALLET 6, 입고 6 |
| BOX만 구성, PALLET 미구성 | 3 | BOX 6 — **C3 이어하기** |
| 미패킹 (확정 양품 보유) | 2 | — **C3 시작점** |

BOX **30**, PALLET **6**, 완제품 입고 **6**.

### 4.5 수주·출하·매출

| 대상 | 수량 | 분포 |
|---|---|---|
| 수주 | 10 | closed 4, shipping 2, open 4 |
| 수주 명세 | 18 | — |
| 출하지시 | 8 | shipped 4, open 4 — **open 4건이 출하 실습 대상** |
| 출하 | 4 | 확정 4 |
| 매출 | 4 | 출하당 1건 |

입고 6건 중 **2건은 미출하로 남긴다.** 출하 실습에 쓸 패킹 단위가 없으면 C3를 끝낼 수 없다.

수주 라인별 지시 누계는 수주수량 이하로 맞춘다. 초과 지시(AC-51)는 사용자가 직접 시도해서 거부를 확인하는 시나리오이지, 시드에 위반 데이터를 심는 것이 아니다.

### 4.6 계측

계측기 9대 × 24시간 × 30일 = **6,480행**. 여기서 누락 구간 6행을 빼면 **6,474행**.

**해상도는 1시간이다.** 분 단위는 쓰지 않는다.

| 해상도 | 행 수 | 판정 |
|---|---|---|
| 1분 × 30일 × 9대 | 388,800 | 게스트 진입 불가 |
| 15분 × 30일 × 9대 | 25,920 | 진입 지연. 심사자가 이탈 |
| **1시간 × 30일 × 9대** | **6,480** | 채택 |

원단위 학습의 목적은 기간·설비별 집계 조회와 계산 근거 확인이다. 분 단위 원시값이 필요하지 않다. 수집 파이프라인을 만들지 않기로 한 FS-005a 결정과도 일치한다.

값은 설비 유형별 기준 부하에 가동 시간대 계수를 곱한 고정 패턴으로 만든다. 난수를 쓰지 않는다.

### 4.7 에너지 검증 예시에 대한 제약

기존 문서의 검증 예시 `사업장 전체 450 = 제조 288 + 공용 132 + 미계측 잔여 30 kWh`는 **이번 시드에서 온전히 재현하지 않는다.**

공용 계측은 BEMS 소유인데 BEMS가 MAP_ONLY이기 때문이다. 시드는 사업장 전체 계량기와 제조 계측기 8대만 채우고, 화면에서는 `전체 − 제조 = 미계측 잔여`까지만 보여준다. 공용/미계측 분해는 BEMS 구현 시로 넘긴다.

BEMS 노드의 설명 카드에 이 분해 예시와 **중복 합산 방지가 설계 쟁점**이라는 점을 명시한다. 구현하지 않은 것을 구현한 것처럼 보이게 하지 않는다.

## 5. 오류·예외 시나리오 데이터

아래는 시드에 **의도적으로 심는다.** 없으면 해당 수용 기준을 검증할 수 없다.

| 시드 내용 | 대응 |
|---|---|
| 전량 불량 LOT 1건 | AC-42 전량 불량. 패킹 불가 확인 |
| 생산량 0인 설비·기간 (검사기 1대, 특정 3일) | 원단위 계산 불가 표시 |
| 계측 누락 6시간 (조립기 1대) | 집계 시 누락 구간 처리 |
| 미게시 공정 경로 1건 | 작업지시 생성 시 거부 |
| 취소된 작업지시 1건 | 취소 이력 표시 |
| 실적 없이 진행 중인 실행 2건 | 결과 부재와 양품 0의 구별 |
| 미출하 입고 2건 | 출하 실습 대상 |
| 지시 누계가 수주수량에 근접한 수주 1건 | 초과 지시 거부를 사용자가 직접 확인 |

## 6. 세대 생성 전략

### 6.1 총 규모

| 영역 | 행 수 |
|---|---|
| 기준정보 (품목·공정·설비·거래처·경로·계측기) | 약 40 |
| 계획 (판매·생산) | 28 |
| 생산 (지시·LOT·실행·실적) | 182 |
| 패킹·입고 | 72 |
| 수주·출하·매출 | 44 |
| 계측 | 6,474 |
| **합계** | **약 6,840행** |

**계측이 전체의 95%다.** 향후 규모를 늘릴 때 가장 먼저 검토할 지점이며, 여기에 해상도를 다시 올리자는 제안이 나오면 이 문서를 근거로 거부한다.

### 6.2 템플릿 복사

게스트가 들어올 때마다 생성 로직을 돌리지 않는다.

1. 배포 시 **템플릿 세대 1개**를 만들어 둔다.
2. 게스트·회원 공간 생성 시 `INSERT ... SELECT`로 템플릿 세대를 새 세대로 복사한다.
3. 복사 대상은 업무 데이터만이다. 계정·설정·학습 기록·프로세스 맵 콘텐츠는 복사하지 않는다.
4. 복사는 하나의 트랜잭션이다. 실패 시 부분 생성물을 남기지 않는다 (AC-46).
5. 복사 후 검증을 거쳐 `active_generation_id`를 전환한다. FS-006의 세대 전환 계약을 그대로 쓴다.

시간축 오프셋은 복사 시점에 T를 기준으로 재계산한다. 템플릿의 절대 시각을 그대로 복사하지 않는다.

### 6.3 성능 목표

| 항목 | 목표 |
|---|---|
| 세대 복사 완료 | 2초 이내 |
| 게스트 첫 화면 표시 | 3초 이내 |
| 동시 게스트 공간 상한 | 20 (AC-49) |

이 수치는 **목표이며 측정값이 아니다.** 실측은 FS-009 이후에 한다. 초과하면 계측 해상도를 4시간으로 낮추거나 계측 기간을 14일로 줄이는 것을 먼저 검토한다. 업무 데이터 축소는 학습 시나리오를 깨므로 마지막 수단이다.

### 6.4 게스트 진입 시 보이는 것

게스트는 들어오자마자 **이미 두 달치 이력이 쌓인 공장**을 본다. 빈 목록 화면을 보여주지 않는다.

- 판매계획·생산계획 2개월치, 완료된 생산 18건, 출하·매출 4건
- 진행 중인 작업 6건과 시작 대기 3건
- 30일치 에너지 조회 가능

C0(전체 둘러보기)은 업무 실행 없이 프로세스 맵 카드 열람만으로 진행되므로, 데이터 준비가 끝나기 전에도 시작할 수 있다.

## 7. 버전 관리

- `seed_version` 형식: `sv-<YYYYMMDD>-<n>` (예: `sv-20260920-1`).
- 시드 구성이 바뀌면 버전을 올린다. 기존 세대는 그대로 두고 새 세대부터 적용한다.
- 학습 콘텐츠(`course_version`)는 자신이 요구하는 최소 `seed_version`을 선언한다. 시드에 없는 데이터를 전제로 하는 과정이 게시되는 것을 막는다.
- 시드 변경으로 기존 학습 시나리오가 깨지면 **콘텐츠 버전도 함께 올린다.** 게시된 과정의 검증 조건은 불변이다.
- 시드 정의 변경 시 이 문서와 `seed/`의 구성 파일을 같은 작업에서 갱신한다.

## 8. 미확정 / 후속

- 품목 코드 체계와 실제 품목명은 생성기 구현 시 정한다. 실제 제품명·고객사명을 쓰지 않는다.
- 불량 사유 코드 목록은 QMS 도입 전까지 MES 내부 고정 목록으로 둔다.
- 단가·금액 규모는 ERP-1 구현 시 정한다. 세액 계산 정책은 단일 함수로 관리한다.
- 템플릿 세대의 배포·갱신 절차(마이그레이션과의 순서)는 FS-009에서 정한다.
- 성능 목표 실측과 조정은 FS-009 이후.
