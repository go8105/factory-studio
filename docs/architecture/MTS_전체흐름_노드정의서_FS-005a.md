# FS-005a MTS 전체 흐름 노드 정의서

작성일: 2026-09-20. 상태: 노드·연결 정의 확정, 화면·API 미구현.
기준: [FS-005a 차분 설계](../architecture/차분설계_게스트_ERP_프로세스맵_FS-005a.md), [FS-003 업무 카드](../modules/mes/첫업무카드_역할_범위_FS-003.md).
용도: `process_map.node` / `process_map.edge`의 콘텐츠 기준본.

---

## 1. 생산 방식 결정과 근거

**MTS(재고생산)** 를 기준 흐름으로 확정한다.

| 근거 | 내용 |
|---|---|
| 판매계획 기점 성립 | MTS는 수요예측 → 판매계획 → MPS가 자연스럽다. MTO는 수주가 기점이라 판매계획이 참고치에 머문다 |
| ERP 연결점 확보 | 흐름의 **시작(판매계획)과 끝(수주·출하·매출)** 양쪽에서 ERP가 등장한다. ERP가 덧붙인 모듈이 아니라 흐름의 골격이 된다 |
| WMS 확장 명분 | 완제품 재고가 필수로 존재하므로 WMS 도입 이유가 흐름 안에서 설명된다 |
| 학습 설명력 | 계획과 실적의 차이를 보여줄 수 있다 |

MTO 확장은 `mes.work_order.order_type` / `sales_order_line_id` 예약 컬럼으로 설계에만 남긴다. 이번 구현에서 `ORDER` 값은 거부한다.

## 2. 전체 흐름

```
[ERP] 거래처·품목 기준정보
        ↓
[ERP] 판매계획 수립  ──────────────┐
        ↓                          │ (계획 대비 실적 비교)
[MES] 생산계획(MPS)                │
        ↓                          │
[MES] 작업지시                     │
        ↓                          │
[MES] LOT 생성                     │
        ↓                          │
[MES] 공정 투입·실행               │
        ↓                          │
[MES] 실적 확정(양품/불량)         │
        ↓                          │
[QMS] 품질검사 ······ (MAP_ONLY)   │
        ↓                          │
[MES] 패킹(박스→팔레트)            │
        ↓                          │
[MES] 완제품 입고                  │
        ↓                          │
[WMS] 재고·비계획 입출고 ··· (MAP_ONLY)
        ↓                          │
[ERP] 수주                         │
        ↓                          │
[ERP] 출하지시                     │
        ↓                          │
[ERP] 출하                         │
        ↓                          │
[ERP] 매출 인식  ──────────────────┘

[FEMS] 에너지 기준정보·조회 ← 설비·공정·LOT 참조 (횡단)
[BEMS] 건물 에너지 ················ (MAP_ONLY)
```

### 3.1 노드 카드 상세

각 노드는 FS-003 업무 카드 규격을 따른다. 아래는 필수 항목 값이다.

---

**1. `master_data` 거래처·품목 기준정보**
- 목적: 이후 모든 업무가 참조할 대상을 등록한다
- 수행자: 기준정보 담당
- 시작 조건: 사업장·세대 준비 완료
- 입력: 거래처 코드/명/구분, 품목 코드/명/기준단위
- 산출물: `erp.partner`, `core.item`
- 다음 업무: 판매계획 수립
- 자주 발생하는 오류: 중복 코드, 단위 미지정
- 완료 기준: 판매계획에서 선택 가능한 거래처·품목이 존재한다

**2. `sales_plan` 판매계획 수립**
- 목적: 어떤 품목을 언제 얼마나 팔 것인지 정한다. 생산계획의 근거가 된다
- 수행자: 영업 계획 담당
- 시작 조건: 품목 기준정보 존재
- 입력: 대상 연월, 품목별 계획수량
- 산출물: `erp.sales_plan`, `erp.sales_plan_line`
- 다음 업무: 생산계획(MPS)
- 자주 발생하는 오류: 확정 후 라인 수정 시도, 음수 수량
- 완료 기준: 계획이 확정 상태이고 품목별 계획수량이 조회된다

**3. `production_plan` 생산계획(MPS)**
- 목적: 판매계획을 언제 얼마나 만들지로 바꾼다
- 수행자: 생산관리 담당
- 시작 조건: 확정된 판매계획 존재
- 입력: 근거 판매계획, 품목별·주차별 생산 계획수량
- 산출물: `mes.production_plan`, `mes.production_plan_line`
- 다음 업무: 작업지시
- 자주 발생하는 오류: 근거 판매계획 미지정, 계획 주차 누락
- 완료 기준: 작업지시로 전개 가능한 계획 라인이 존재한다
- 학습 포인트: **계획수량과 생산수량은 같지 않다.** 차이를 조회로 확인시킨다

**4. `work_order` 작업지시**
- 목적: 실제 현장에 지시할 단위로 계획을 쪼갠다
- 수행자: 생산관리 담당
- 시작 조건: 생산계획 라인 존재, 품목의 게시된 공정 경로 존재
- 입력: 품목, 경로 버전, 계획수량, 계획 시각
- 산출물: `mes.work_order` (`order_type = STOCK`)
- 다음 업무: LOT 생성
- 자주 발생하는 오류: 지시 품목과 경로 품목 불일치, 미게시 경로 선택
- 완료 기준: 실행 가능 상태의 작업지시가 존재한다

**5. `lot_issue` LOT 생성**
- 목적: 추적 단위를 만든다. 이후 모든 실적·에너지·출하가 LOT로 연결된다
- 수행자: 현장 담당
- 시작 조건: 실행 가능한 작업지시
- 입력: 작업지시
- 산출물: `mes.lot` (첫 버전은 1지시 = 1LOT)
- 다음 업무: 공정 투입·실행
- 자주 발생하는 오류: 중복 LOT 생성 요청
- 완료 기준: LOT 번호가 발번되고 공정 진입 가능 상태다
- 부속 기능: **바코드 발행** — `lot_no`를 코드로 출력한다. 별도 테이블을 만들지 않는다

**6. `operation_run` 공정 투입·실행**
- 목적: 경로 단계 순서대로 설비에서 작업을 수행한다
- 수행자: 현장 작업자
- 시작 조건: LOT 진행 가능, 해당 공정의 허용 설비 지정
- 입력: 경로 단계, 설비, 시작/종료 시각
- 산출물: `mes.operation_execution`
- 다음 업무: 실적 확정
- 자주 발생하는 오류: 선행 단계 미완료, 허용되지 않은 설비 선택, 시간 역전
- 완료 기준: 단계별 실행 기록이 존재한다

**7. `operation_result` 실적 확정**
- 목적: 얼마나 만들었고 얼마나 불량인지 확정한다
- 수행자: 현장 작업자
- 시작 조건: 해당 단계 실행 종료
- 입력: 투입수량, 양품수량, 불량수량, 불량사유
- 산출물: `mes.operation_result` (실행당 1건, 이후 직접 수정 금지)
- 다음 업무: 품질검사 → 패킹
- 자주 발생하는 오류: 투입 ≠ 양품 + 불량, 중복 확정 요청, 전량 불량
- 완료 기준: 확정 결과가 저장되고 양품수량이 패킹 가능 수량으로 집계된다

**8. `quality_inspection` 품질검사 — MAP_ONLY**
- 담당 영역: 검사 기준·결과 기록, 합격/불합격 판정, **LOT 보류**
- 연결: 실적 확정 결과를 입력으로 받고, 판정 결과가 패킹 진행 여부를 통제한다
- 미구현 사유: QMS 모듈은 후속 범위다
- 카드에 명시할 내용: 품질 보류는 **모듈 설정 변경으로 해제되지 않는다**는 정책이 이미 설계되어 있음을 밝힌다

**9. `packing` 패킹(박스/팔레트)**
- 목적: 출하 가능한 물리 단위로 묶는다
- 수행자: 포장 담당
- 시작 조건: 확정 양품수량 존재
- 입력: LOT, 담을 수량, 박스 단위 → 팔레트 단위
- 산출물: `mes.packing_unit`, `mes.packing_member`
- 다음 업무: 완제품 입고
- 자주 발생하는 오류: 양품수량 초과 담기, 박스를 박스에 담기, 순환 참조
- 완료 기준: 패킹 번호가 발번되고 담긴 수량이 LOT 잔여와 일치한다
- 부속 기능: **바코드 발행** — `packing_no` 출력
- 학습 포인트: LOT(추적 단위)과 패킹 단위(물리 단위)의 차이

**10. `fg_receipt` 완제품 입고**
- 목적: 만든 물건을 출하 가능한 재고로 확정한다
- 수행자: 창고 담당
- 시작 조건: 팔레트 하위 박스 패킹 완료
- 입력: 패킹 단위, 입고 시각
- 산출물: `mes.finished_goods_receipt`
- 다음 업무: 수주 / 출하지시
- 자주 발생하는 오류: 입고 후 구성 변경 시도
- 완료 기준: 해당 패킹 단위가 출하 대상으로 조회된다

**11. `inventory_move` 재고·비계획 입출고 — MAP_ONLY**
- 담당 영역: 창고 위치, 재고 이동 원장, 예약, **비계획 입출고**
- 연결: 완제품 입고와 출하 사이의 재고 상태를 소유한다
- 미구현 사유: WMS 후속 범위. 현재는 입고 이력과 출하 이력의 대사로 대체한다
- 카드에 명시할 내용: WMS 도입 시 **재고 원장 소유가 MES에서 WMS로 이관**된다

**12. `sales_order` 수주**
- 목적: 고객 주문을 받는다. MTS이므로 재고가 이미 있는 상태에서 발생한다
- 수행자: 영업 담당
- 시작 조건: 거래처·품목 존재
- 입력: 거래처, 수주일, 납기, 품목별 수량·단가
- 산출물: `erp.sales_order`, `erp.sales_order_line`
- 다음 업무: 출하지시
- 자주 발생하는 오류: 납기가 수주일보다 빠름, 단가 누락
- 완료 기준: 출하지시 가능한 수주 라인이 존재한다
- 학습 포인트: **MTS에서는 수주가 생산을 촉발하지 않는다.** MTO와의 차이를 여기서 설명한다

**13. `shipment_order` 출하지시**
- 목적: 어떤 수주 라인을 얼마나 내보낼지 지시한다
- 수행자: 영업/물류 담당
- 시작 조건: 수주 라인 존재
- 입력: 수주, 라인별 지시수량
- 산출물: `erp.shipment_order`, `erp.shipment_order_line`
- 다음 업무: 출하
- 자주 발생하는 오류: **수주수량 초과 지시**(거부), 분할 지시 누계 착오
- 완료 기준: 지시 누계가 수주수량 이하이고 출하 대기 상태다

**14. `shipment` 출하**
- 목적: 실제 물건을 내보낸다
- 수행자: 물류 담당
- 시작 조건: 출하지시 존재, 입고 완료된 패킹 단위 존재
- 입력: 출하지시, 패킹 단위, 출하수량, 출하 시각
- 산출물: `erp.shipment`, `erp.shipment_line`
- 다음 업무: 매출 인식
- 자주 발생하는 오류: **이미 출하된 패킹 단위 재사용**(거부), 미입고 패킹 선택
- 완료 기준: 출하가 확정되고 매출이 생성된다

**15. `sales_record` 매출 인식**
- 목적: 출하를 금액으로 확정한다
- 수행자: 시스템(출하 확정과 같은 트랜잭션)
- 시작 조건: 출하 확정
- 입력: 출하, 수주 단가
- 산출물: `erp.sales_record` (출하당 정확히 1건)
- 다음 업무: 흐름 종료. 판매계획 대비 실적 비교로 연결
- 자주 발생하는 오류: 요청 재전송으로 인한 중복 인식(차단)
- 완료 기준: 출하 1건당 매출 1건이 존재하고 금액이 수주 단가와 일치한다
- 학습 포인트: **매출은 출하 시점에 인식된다.** 수주 시점이 아님을 확인시킨다

**16. `energy_master` 에너지 기준정보·조회**
- 목적: 에너지 관리에 필요한 기준정보가 무엇이고 어떻게 등록·조회되는지 보여준다
- 수행자: 에너지 담당
- 시작 조건: 설비 기준정보 존재
- 입력: 계측기 등록(설비 연결, 부모/자식 관계, 소유 모듈), 요금제, 배출계수
- 산출물: 계측기 기준정보, 기간·설비별 사용량 조회, 생산 원단위
- 다음 업무: 건물 에너지 비교(MAP_ONLY)
- 자주 발생하는 오류: 부모 계량기와 하위 계측기 중복 합산, **생산량 0일 때 원단위 계산 불가**
- 완료 기준: 기간·설비를 선택해 사용량과 원단위 근거를 조회할 수 있다
- 구현 범위 제한: **계측 수집 파이프라인·알람 서버는 구현하지 않는다.** 계측값은 seed 생성기로 생성한다
- 학습 포인트: 원단위 = 에너지 사용량 ÷ 생산량. 분모가 0이면 계산 불가로 표시한다

**17. `building_energy` 건물 에너지 — MAP_ONLY**
- 담당 영역: 공용 계측, 환경 관측, 제조/공용/미계측 잔여의 경계
- 연결: FEMS와 계측 소유·집계 범위를 분리한다
- 미구현 사유: BEMS 후속 범위
- 카드에 명시할 내용: 사업장 전체 = 제조 + 공용 + 미계측 잔여. **중복 합산 방지가 설계 쟁점**임을 밝힌다

## 4. 연결(edge) 정의

| from | to | 연결 설명 |
|---|---|---|
| master_data | sales_plan | 품목이 있어야 계획을 세운다 |
| sales_plan | production_plan | 판매계획이 생산계획의 근거가 된다 |
| production_plan | work_order | 계획을 실행 단위로 전개한다 |
| work_order | lot_issue | 지시마다 추적 단위를 만든다 |
| lot_issue | operation_run | LOT이 경로를 따라 흐른다 |
| operation_run | operation_result | 실행 결과를 확정한다 |
| operation_result | quality_inspection | 확정 수량이 검사 대상이 된다 |
| quality_inspection | packing | 합격분만 포장한다 |
| operation_result | packing | (QMS 미구현 시 현재 경로) 확정 양품을 포장한다 |
| packing | fg_receipt | 포장 단위를 재고로 확정한다 |
| fg_receipt | inventory_move | 재고 상태를 원장이 관리한다 |
| master_data | sales_order | 거래처가 있어야 수주가 가능하다 |
| sales_order | shipment_order | 수주 라인을 출하 지시로 전개한다 |
| fg_receipt | shipment | 입고된 패킹 단위가 출하 대상이다 |
| shipment_order | shipment | 지시에 따라 출하한다 |
| shipment | sales_record | 출하 시점에 매출을 인식한다 |
| sales_record | sales_plan | 계획 대비 실적을 비교한다 (되돌아오는 연결) |
| operation_run | energy_master | 설비 가동 구간이 에너지 집계 대상이다 |
| energy_master | building_energy | 제조 에너지와 공용 에너지의 경계 |

`quality_inspection`이 `MAP_ONLY`인 동안 `operation_result → packing` 직결 경로를 활성 경로로 표시하고, 검사 경로는 점선으로 구분한다. QMS 구현 시 직결 경로를 비활성화한다.

## 5. 학습 경로 매핑

FS-004의 기존 7단계(생산 한 건과 에너지 이해)는 노드 4~7, 16을 사용한다. 전체 흐름 확대에 따라 과정을 분리한다.

| 과정 | 포함 노드 | 목표 |
|---|---|---|
| C1 생산 한 건 | 4~7 | 지시가 실적이 되는 과정을 이해한다 |
| C2 계획에서 지시까지 | 1~4 | 계획과 실행의 관계를 이해한다 |
| C3 만든 것을 내보내기 | 9, 10, 12~15 | 포장·재고·출하·매출의 연결을 이해한다 |
| C4 생산과 에너지 | 6, 7, 16 | 원단위와 집계 경계를 이해한다 |
| C0 전체 둘러보기 | 1~17 (읽기) | 프로세스 맵으로 전체 흐름을 조망한다. **게스트 기본 진입 과정** |

C0은 업무 실행 없이 카드 열람만으로 진행되므로 게스트가 3분 안에 완주할 수 있다. C1~C4는 실제 업무 실행과 서버 검증을 요구한다.

## 6. 미확정 / 후속

- 노드별 화면 라우트 키 매핑은 화면 설계(FS-008 개정) 범위다.
- C1~C4 과정의 단계·검증 조건·확인 질문은 FS-004 개정에서 확장한다. 현재 AC-01~34는 C1·C4 범위만 덮는다.
- 프로세스 맵의 시각 표현(레이아웃, 노드 상태 색상)은 UI 작업에서 정한다. 본 문서는 데이터 정의만 다룬다.
- 판매계획 대비 실적 비교 화면의 집계 기준(연월/주차)은 ERP-1 구현 시 확정한다.
