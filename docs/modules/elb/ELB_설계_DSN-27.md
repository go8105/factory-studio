## 0. ELB/MRO의 자리 — 사내 간접자재 "쇼핑"과 승인

**ELB/MRO = 사무용품·소모품·공구·안전용품 같은 간접자재를 직원이 카탈로그에서 골라 신청하고, 승인받아 구매로 넘기고, 받았는지 확인하는 솔루션.** 발주·매입·회계는 ERP, 재고로 두는 품목의 입고는 WMS가 한다(Q1).

| 영역 | 소유 | ELB와의 관계 |
|---|---|---|
| 간접자재 카탈로그·계약 단가·사내 신청·승인·수령 확인 | **ELB** | 이 문서 |
| 구매 요청 → 발주 → 매입 → 전표 | **ERP** | 승인된 신청을 ERP가 구매 요청(출처 ELB)으로 가져감 |
| 재고 품목(SUPPLY) 입고·재고 | **WMS** | 재고 품목은 WMS 입고, ELB는 상태만 조회 |
| 부서 예산 | **ERP**(DSN-11 F84) | ELB가 조회해 초과 경고(Q3) |
| 설비 예비품 구매 | **CMMS → ERP**(DSN-21) | ELB를 거치지 않는다 |

## 3. 기능 규칙 (범위 18)

공통: **ELB는 발주하지 않는다**(Q1) — 승인된 일반 신청을 ERP가 구매 요청(출처 ELB)으로 가져가 발주·매입·전표를 한다. 재고 품목은 WMS 입고. 신청 제출 후 명세 불변.

| 묶음 | 기능 ID | 규칙 |
|---|---|---|
| 카탈로그 (Q5) | F01~F04 | 품목(분류·규격·단위·재고 여부 — 재고는 WMS 품목 코드, 비재고는 비용 계정 코드), 계약 단가(공급처·최소 수량·유효기간, 장바구니 단가 = 유효 계약 중 최저), 표준 세트(부서 정기 묶음 → 한 번에 담기) |
| 신청·승인 (Q2) | F11~F13·F15 | 장바구니 → 신청서(부서·신청자·사유·희망일, 단가 스냅샷). 제출 시 필요한 단계 = 기준 금액 ≤ 합계인 사용 규칙(기본 부서장 0원, 관리부서 50만 원). 단계별 승인/반려(반려 의견 필수), 반려 시 새 신청서로 재신청, 승인 전 회수. 내 신청 현황 = 승인·ERP 구매 요청·발주·입고/수령 단계(ERP·WMS 조회) |
| 예산 (Q3) | F14 | 제출·승인 화면에 ERP 부서·비용 계정 월 예산 대비 실적 + 이번 합계, 초과면 경고만(차단 아님). 제출 시 결과 스냅샷 |
| 구매 연계 (Q1) | F21·F22 | 승인된 일반 신청 → ERP가 공급처별로 묶어 구매 요청(출처 ELB) |
| 긴급 구매 (Q6) | F23 | 법인카드로 먼저 산 것을 긴급 신청으로 사후 등록(ERP 카드 내역 1건 = 신청 1건, 승인 동일). 구매 요청은 만들지 않고 ERP 카드 내역의 비용 근거로 연결 |
| 수령 (Q4) | F31~F33 | 비재고 품목은 신청 부서가 수령 확인(누적 ≤ 신청 수량, 부분 수령, 이상 = 파손·오배송·부족 → 반품 요청). ERP가 읽어 매입 근거, 반품 처리는 ERP 구매 반품. 재고 품목은 WMS 입고 상태만 표시 |
| 분석 (Q5) | F41~F43 | 부서·분류·월별 간접비 지출, 품목 소비 추이·과다 사용 부서(전년 동월 대비), 계약 단가 vs 실제 매입 단가(ERP 매입 조회) |

## 6. 교차 조회

**ELB가 읽는 것**

| 제공 | 함수 | ELB 용도 |
|---|---|---|
| ERP | `budget_status(department, account, month)`(신규) · `elb_request_status(request_nos)`(신규: 구매 요청·발주·매입 단계) · `card_transactions(open=True)`(신규) · `purchase_prices(item_codes)`(신규) · `departments()`·`partners()` | 예산, 진행 추적, 긴급 연결, 단가 비교 |
| WMS | `inbound_status(item_codes, refs)`(신규) | 재고 품목 입고 상태 |

**ELB가 제공하는 것**

| 함수 | 돌려주는 것 | 쓰는 곳 |
|---|---|---|
| `approved_requests(since)` | 승인된 일반 신청(부서·품목·공급처·단가) | ERP 구매 요청(출처 ELB) |
| `receipts(since)` | 비재고 수령 확인·반품 요청 | ERP 매입 근거·구매 반품 |
| `emergency_requests(since)` | 긴급 신청 ↔ 카드 내역 | ERP 카드 비용 근거 |
| `monthly_summary(month)` | 부서별 간접비·승인 대기 | EIP |

> 넘길 것: **ERP** ELB 승인 신청 가져오기(구매 요청 출처 ELB — 이미 설계됨), 비재고 수령을 매입 근거로, 카드 내역 연결, `budget_status`·`elb_request_status`·`card_transactions`·`purchase_prices` 제공 · **WMS** `inbound_status` 제공. ROADMAP-01의 "ELB `purchase_receipts()` → WMS·ERP"는 Q1로 대체(발주·입고는 ERP·WMS).

> EIP DSN-28 반영(2026-10-05): 승인자 지정 `elb.approver`(부서장·관리부서 ↔ HR 사원 코드) 신설, 신청서·승인에 HR 사원 코드 칸. ELB는 `pending_tasks`·`lookup`을 제공한다.

## 7. 결정 질문 (하나씩)

| # | 질문 | 제안 |
|---|---|---|
| Q1 | **ELB 경계** — ELB는 카탈로그·신청·승인·수령 확인까지. 발주·매입·전표는 ERP(승인 신청 → ERP 구매 요청 출처 ELB), 재고 품목 입고는 WMS. ELB 자체 발주 없음 | 그대로 |
| Q2 | **승인 방식** — ELB 안에서 금액 기준 단계(기본: 부서장 1단계, 50만 원 초과 시 관리부서 2단계 — 금액·단계는 설정). GW 결재와 따로(GW는 문서 결재, ELB는 신청 승인) | 그대로 |

| Q4 | **비재고 품목 수령 확인** — 신청 부서가 ELB에서 수령(수량·이상)·부분 수령 확인 → ERP가 읽어 매입 근거로(재고 품목은 WMS 입고 그대로). 반품은 요청만, 처리는 ERP | 포함 |
| Q5 | **공급처 계약 단가·표준 세트·단가 비교** 포함 | 포함 |
| Q6 | **긴급 구매(법인카드 사후 등록)** — 카드로 먼저 산 간접자재를 신청서로 사후 등록, ERP 카드 사용 내역과 연결 | 포함 |
