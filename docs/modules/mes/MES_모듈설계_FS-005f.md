# FS-005f MES 모듈 공통 설계서

작성일: 2026-09-21. 상태: 설계 초안. 5장 제안은 메타데이터 미반영.
기준: [MES 참조 설계 검토 FS-003](MES참조설계_검토_FS-003.md), [첫 업무 카드 FS-003](첫업무카드_역할_범위_FS-003.md), [FS-005d 모듈·하위 모듈 구조](../../architecture/모듈_하위모듈_구조_FS-005d.md).
성격: MES를 **독립 솔루션**으로 성립시키기 위한 모듈 설계서. 4~5장이 핵심이다.

---

## 1. 이 모듈은 무엇인가

**계획에서 완제품 입고까지를 담당하는 생산 관리 솔루션이다.**

ERP나 FEMS를 꺼도 MES만으로 "무엇을 언제 얼마나 만들지 정하고, 지시하고, 공정을 돌리고, 실적을 확정하고, 포장해서 입고한다"가 성립해야 한다.

공유 마스터는 core가 소유한다. 설비·작업장·품목은 MES 화면에 보이지만 여기서 수정할 수 없다.

## 2. 하위 모듈

| 하위 모듈 | 소유 테이블 | 참조 |
|---|---|---|
| `mes_master` 기준정보 | 공정, 공정-설비 허용 | 설비, 작업장, 품목 |
| `routing` 표준공정 | 경로 버전, 경로 단계 | 품목, 공정 |
| `production_plan` 생산계획 | 생산계획, 생산계획 라인 | 품목 / **판매계획(선택)** |
| `work_order` 작업지시 | 작업지시, LOT | 품목, 경로 버전 |
| `execution` 생산실행 | 공정 실행, 공정 실적 | 설비, 경로 단계 |
| `packing` 포장·입고 | 패킹 단위, 패킹 구성, 완제품 입고 | LOT |
| `learning_link` 학습 연결 | 학습 바인딩 | 학습 시도 |

소유 14개. 모듈 경계 규칙 점검에서 **위반 0건**이다. ERP 판매계획은 선택 참조이므로 ERP를 꺼도 생산계획을 세울 수 있다.

## 3. 업무 규칙

| 규칙 | 내용 |
|---|---|
| 경로 버전 고정 | 작업지시 발행 시 적용 경로 버전을 고정한다. 이후 경로가 바뀌어도 진행 중 지시는 영향받지 않는다 |
| TX-10 패킹 | `Σ 담은 수량 ≤ 확정 양품수량`. 확정 실적 없는 LOT은 패킹 불가 |
| TX-11 완제품 입고 | PALLET 입고 시 하위 BOX가 모두 closed. 입고 후 구성 변경 금지 |
| 실적 확정 | 투입 = 양품 + 불량. 실행당 결과 1건. 확정 후 직접 수정 금지 |
| 다음 공정 투입 | 직전 공정의 양품이 다음 공정 투입 가능 수량이다 |
| 작업지시 양품 | **최종 공정의 양품**이다. 공정별 양품을 합산해 완제품 수량으로 쓰지 않는다 |
| 수율 | 투입 0이면 계산 불가로 표시한다. 0%로 오표시하지 않는다 |
| MTO 예약 | `order_type`은 `STOCK`만 허용. `ORDER`와 `sales_order_line_id`는 확장 예약 |

`mes.packing_unit`의 자기참조(BOX → PALLET)는 잠글 때 상위 먼저, 지울 때 하위 먼저다. 방향이 반대라는 점에 주의한다.

## 4. 참조 설계서 대비 격차

참조 설계서는 22테이블(시스템 7 · 기준정보 5 · 재고 5 · 생산 5)이다.

| 참조 영역 | 현재 | 판단 |
|---|---|---|
| 시스템·권한·코드 (7) | core가 담당 | **의도적 제외.** 중복이다 |
| 품목·분류·단위환산 | core 소유 | 제외 아님. 소유만 다르다 |
| 작업장·공정 | 작업장 core / 공정 mes | 책임 분리 적용됨 |
| 작업지시·공정실적 (5) | 소유 | 적용됨. LOT·경로·설비 연결로 오히려 확장 |
| 재고 (5) | 없음 | WMS로 미룸 |
| **BOM·자재** | **없음** | **격차.** 5장 참조 |
| 거래처·가격 | ERP 소유 | 적용됨 |

### 4.1 참조 검토에서 이미 반영한 것

FS-003 검토의 보완 항목 7개 중 6개는 반영됐다.

| 항목 | 상태 |
|---|---|
| LOT 독립 식별 + 공정 실행 연결 | 반영 |
| 경로·버전·단계 분리, 발행 시 버전 고정 | 반영 |
| 작업장과 설비 구분, 실행에 설비·시각 연결 | 반영 |
| 체험 공간·세대·모듈 상태를 키에 포함 | 반영 |
| 접근 로그와 업무 상태 변경 이력 분리 | 반영 (core.audit_event) |
| 계정·학습·설정의 초기화 보존 | 반영 |
| 실적 중복 방지 키, 진행 중 실행과 확정 결과 구분 | 반영 (요청 결과 + 실행/결과 분리) |

### 4.2 남은 구멍 — 자재

**지금 MES는 "무엇을 만들었는지"는 알지만 "무엇으로 만들었는지"는 모른다.**

공정 실적에 투입수량은 있지만 그게 **어떤 자재 몇 개인지**가 없다. 그래서 다음이 전부 불가능하다.

- 완제품 LOT에서 투입 자재 LOT으로 거슬러 올라가는 역추적
- 작업지시에 필요한 자재 소요량 산출
- 자재 실적 대비 이론 소요 비교 (로스율)

**LOT 추적은 MES의 정체성에 가까운 기능인데, 정방향(공정→완제품)만 되고 역방향(완제품→자재)이 안 됩니다.** 면접에서 가장 먼저 물어볼 지점이다.

## 5. 제안

### 5.1 넣기를 제안 — BOM·자재 투입 3테이블

**A. BOM (`bom` 하위 모듈 신설) — 2테이블**

`mes.bom_version`, `mes.bom_line`

품목별 자재 구성과 소요량. 경로(routing)가 "어떤 순서로 만드는가"라면 BOM은 "무엇으로 만드는가"다. 둘은 MES의 양대 기준정보이며 지금은 한쪽만 있다.

경로와 같은 규칙을 쓴다. **게시된 BOM 버전은 불변이고, 작업지시 발행 시 적용 버전을 고정한다.**

**B. 자재 투입 (`execution`에 추가) — 1테이블**

`mes.material_issue` — 공정 실행별 자재 LOT과 투입수량

이걸로 역추적이 성립한다. **재고 차감은 하지 않는다.** 투입 기록만 남기고 재고 원장은 WMS 소유다. 모듈 경계 규칙에 따라 WMS가 없어도 투입 기록은 성립해야 한다.

자재 LOT은 `mes.lot`을 그대로 쓴다. 구매 자재의 LOT은 WMS 도입 전까지 시드로 생성한다.

### 5.2 넣지 않기를 제안

| 영역 | 이유 |
|---|---|
| 재고 잔량·수불원장 | WMS 소유. 여기 넣으면 나중에 이관해야 한다 |
| 품질검사·보류 | QMS 소유 |
| 설비 보전·가동 이력 | 범위 밖. EAM 영역 |
| 시스템·권한·코드 | core 중복 |

### 5.3 신규 엔티티 목록

검증기가 읽는 기준 목록이다. **채택 결정 후에만 메타데이터에 반영한다.**

| 엔티티 | 하위 모듈 | 역할 |
|---|---|---|
| `mes.bom_version` | bom | 품목별 BOM 버전. 게시 후 불변 |
| `mes.bom_line` | bom | 자재 구성과 단위 소요량 |
| `mes.material_issue` | execution | 공정 실행별 자재 투입 기록 |

### 5.4 규모

| 구분 | 수 |
|---|---:|
| 현재 MES | 14 |
| BOM 2 + 자재 투입 1 | +3 |
| **MES 합계** | **17** |
| 전체 테이블 | 64 → **67** |

하위 모듈은 7개에서 **8개**가 된다 (`bom` 추가).

## 6. 화면 구성 (FS-008a 입력)

| 하위 모듈 | 주요 화면 |
|---|---|
| 기준정보 | 공정 목록·등록, 공정별 허용 설비, 설비·작업장·품목 조회(참조) |
| 표준공정 | 경로 목록, 경로 버전 작성·게시, 단계 순서 편집 |
| BOM | BOM 목록, 버전 작성·게시, 자재 구성 편집 |
| 생산계획 | 계획 목록, 품목·주차별 계획수량, 계획 확정, 지시 전개 |
| 작업지시 | 지시 목록, 지시 발행, LOT 발번, 바코드 출력 |
| 생산실행 | 공정 진행 현황, 투입·시작·종료, 자재 투입, 실적 확정 |
| 포장·입고 | 박스 구성, 팔레트 적재, 완제품 입고 |

## 7. 미확정 / 후속

- BOM·자재 투입 테이블의 컬럼별 타입·제약은 채택 결정 후 확정한다.
- 자재 소요량 대비 실적 비교(로스율)는 자재 투입 도입 후 조회 계산으로 처리한다. 별도 집계 테이블을 만들지 않는다.
- 재작업·반복 검사의 불량 중복 처리는 QMS와 함께 정한다.
- 작업지시 취소는 등록 상태에서만 허용한다. 발행 후 취소·생산 중단은 후속 정책이다.
- 다단계 BOM(반제품 → 완제품)은 1단계만 구현하고 확장 지점만 남긴다.
