## 구조 및 검증
26개 시트: 표지·설계규약·목차·테이블 정의 22개·공통코드. 시스템/권한 7개, 기준정보 5개, 재고 5개, 생산 5개 테이블이다. 상세 컬럼은 348개이며 목차의 테이블별 컬럼 수와 일치한다.
L/N열에 명시된 참조 테이블/컬럼의 존재를 확인했으며 누락 참조는 발견되지 않았다. 이는 FK 타입·삭제 정책·복합 키·실제 DDL 동작의 검증은 아니다. 실제 DB 접속·SQL 실행·Excel 재작성은 하지 않았다.

## 보완할 데이터
1. 작업지시의 LOT 문자열(M04 B31:Q31)만으로 끝내지 않고 독립 LOT 식별과 공정 실행의 연결을 추가한다. 첫 업무는 작업지시 1건/LOT 1건으로 제한하지만 데이터 책임은 분리한다.
2. 공정 종류의 표시순서(M02 B22:Q22)와 품목별 실제 공정 경로를 구분한다. 경로·버전·단계를 설계하고 작업지시 발행 시 적용 버전을 고정한다.
3. 작업장과 실제 설비를 구분한다. 공정 실행에 설비·시작/종료 시각을 연결해 FEMS 분석이 가능하게 한다.
4. 개인 체험 공간·데이터 세대·모듈 상태를 추가하고 업무 고유 키와 참조 관계에 해당 범위를 포함한다.
5. 접근 로그와 업무 상태 변경 이력을 구분한다. 누가 어떤 작업지시/공정에 대해 무엇을 변경했는지 남긴다.
6. 계정/학습 진도/콘텐츠/설정은 주간 업무 데이터 초기화에서 보존한다.
7. 실적 중복 처리 방지 키, 진행 중 실행, 확정 결과, 수정 이력을 상세 설계에서 구분한다.

## 그대로 강제하지 않을 규약
- 대문자/3글자 접두어와 CHAR(1) Y/N은 참고 문서의 선택이다. 새 프로젝트의 물리 명명과 boolean 표현은 FS-005/006에서 일관되게 결정하고 원본→신규 이름 대응을 남긴다.
- 단일 대리 PK를 사용하더라도 공간·세대가 다른 참조를 차단할 복합 UNIQUE/FK 설계를 배제하지 않는다.
- 공통 코드의 표시명·설명과 상태 전이 규칙은 구분한다. 화면에서 코드값을 추가했다고 새로운 업무 전이가 자동 허용되지 않는다.
- 원장의 수정/삭제 금지는 DB 권한과 업무 경계로 강제한다. MOD 컬럼이 없다는 사실만으로 불변성이 보장됐다고 판정하지 않는다.
- FK 인덱스·파티셔닝은 참조 무결성과 별도로 실제 조회/변경 패턴에 맞춰 검증한다. 월 10만 건을 무조건적인 분할 기준으로 사용하지 않는다.
- 기준정보는 과거 이력을 보존하면서 신규 사용을 막는 것과 기존 진행 업무를 중단하는 것을 구분한다.

## 상세 설계에서 해소할 사항
- M04 C10/C11 및 99.공통코드 F70/F73의 취소 조건은 'ORD 이전'과 '자재불출 발생 여부'의 관계를 명확히 해야 한다. 첫 사례는 등록 상태에서만 취소 허용, 발행 후 취소/생산 중단은 후속 정책으로 제한한다.
- I04 C8과 G17:G18의 NULL 가능한 로케이션/LOT를 포함한 UNIQUE는 실제 중복 허용 동작을 FS-005 이후 PostgreSQL에서 검증한다. 로케이션과 창고의 소속 일치도 필요하다.
- I04 Q26의 최종입고일을 FIFO 기준으로 삼는 정책은 여러 입고가 합쳐질 때 순서를 보존하는지 후속 WMS에서 검토한다.
- M05 Q22의 '전 공정 산출수량'과 Q24의 '다음 공정 투입 가능 양품'을 구분한다. 첫 사례는 다음 공정 투입=직전 공정 양품으로 정의한다.
- 작업지시 양품은 최종 공정 양품이다. 공정별 양품을 모두 합쳐 완제품 수량으로 표시하지 않는다. 재작업/반복 검사의 불량 중복은 후속 별도 정책으로 처리한다.
- 수율과 작업시간 저장은 원본 값과 계산값의 불일치 방지 정책이 필요하다. 0 투입은 수율 계산 불가이며 0%로 오표시하지 않는다.
