# FS-004 학습 경로 및 상세 수용 기준

작성일: 2026-09-20
상태: 설계 산출물 완료. 아래 테스트는 실행 전 명세이며 통과 결과가 아니다.
기준: [첫 업무 카드](../mes/첫업무카드_역할_범위_FS-003.md), 최신 개발 기준 및 상세 일정.

> **이 문서는 학습 과정 5개 중 C1·C4만 덮는다.** 개발기준 v1.1에서 과정이 C0~C4로 나뉘었으나,
> 아래 단계·검증 조건·확인 질문은 C1(생산 한 건)과 C4(생산과 에너지) 범위만 작성된 상태다.
>
> | 과정 | 범위 | 단계·검증 조건 |
> |---|---|---|
> | C0 전체 둘러보기 | 프로세스 맵 노드 1~17 열람 | **미작성** |
> | C1 생산 한 건 | 작업지시~실적 확정 | 작성됨 (이 문서) |
> | C2 계획에서 지시까지 | 기준정보~작업지시 | **미작성** |
> | C3 만든 것을 내보내기 | 패킹~매출 | **미작성** |
> | C4 생산과 에너지 | 공정·실적·FEMS | 작성됨 (이 문서) |
>
> C0·C2·C3의 단계·검증 조건·확인 질문은 FS-008a 이후 개정 범위다. 과정 정의는 개발기준 v1.1 4절을 따른다.

## 1. 과정과 적용 범위
과정 ID: MES-FOUNDATION-01, 콘텐츠 버전: 1.0.
목표: 학습자가 준비정보를 확인하고 작업지시→LOT→세 공정의 생산을 완료한 뒤 최종 수량과 다음 업무를 설명한다.
예상 안내 체험 시간: 10~15분. 실제 사용자 점검 전 목표치이며 확정 소요시간이 아니다.
선행 조건: 로그인, 본인 공간·활성 데이터 세대, MES 활성, 유효한 품목/경로/설비 예시.

핵심 과정은 MES만으로 완료된다. FEMS/BEMS 분석은 다음 과정이며 활성화 또는 아직 구현되지 않았다는 이유로 MES 완료를 막지 않는다. 첫 공개 전체 학습 흐름에는 이후 에너지 과정을 연결한다. QMS 정식 판정과 WMS 입고는 여기서 수행하지 않는다.

가상 단순 경로: 다이 접착 DA-01 → 와이어 본딩 WB-01 → 최종 검사 FT-01. 실제 반도체 공정 전체의 재현이 아니다.

## 2. 학습 단계
| 단계 ID | 화면/사용자 행동 | 도움말 핵심 | 서버가 확인할 완료 근거 | 다음 위치 |
|---|---|---|---|---|
| L01 | 학습 시작, 준비정보 확인 | 품목·EA·경로 버전·설비가 필요한 이유 | 준비정보 유효성 및 Q01 정답 | 작업지시 등록 |
| L02 | 1,000 EA 지시 등록·발행 | 계획과 실행 허용의 차이, 발행 후 고정 항목 | 본인/현재 세대의 발행 지시, 계획·경로 버전 | LOT 생성 |
| L03 | 지시에서 LOT 생성 | 지시는 계획, LOT는 추적할 생산 묶음 | 해당 지시의 LOT 1건, Q02 정답 | 다이 접착 |
| L04 | DA-01 시작·실적 입력·완료 | 시간·설비·양품·불량과 사유 | 투입 1,000/양품 995/불량 5의 확정 실행 | 와이어 본딩 |
| L05 | WB-01 시작·완료 | 이전 양품만 다음 공정에 투입 | 투입 995/양품 990/불량 5의 확정 실행 | 최종 검사 |
| L06 | FT-01 시작·완료 | 최종 검사 실적과 QMS 정식 판정의 구분 | 투입 990/양품 980/불량 10, LOT/지시 완료 | 결과 요약 |
| L07 | 결과 해석·다음 업무 확인 | 최종 양품, 누적 불량, 입고와 생산 완료의 차이 | 선행 단계 근거 + Q03/Q04/Q05 정답 | MES 완료, 에너지 학습 안내 |

고정 수량은 이 안내 과정의 과제 조건이다. 자유 탐색에서는 업무 규칙을 만족하는 다른 수량도 허용한다. 자유 탐색의 유효한 결과가 과제 수량과 다르면 업무 실패로 표시하지 않고 과제 조건 차이를 안내한다. 이미 확정된 실적을 과제에 맞추기 위해 몰래 수정하지 않는다.

## 3. 화면 및 이동 계약
- 홈에 '학습 시작/이어하기'와 개별 앱 아이콘을 제공한다.
- 업무 화면에 현재 단계/전체 단계, 목적, 준비물, 수행 순서, 자주 생기는 오류, 다음 업무를 보여준다. 긴 설명은 접을 수 있다.
- '다음'은 서버의 단계 검증 성공 후 열린다. 브라우저의 진행률 값을 수정해도 완료를 획득할 수 없다.
- '이전'은 설명·이력 조회이며 업무 상태를 역행시키지 않는다.
- 자유 탐색에서 같은 학습 시도에 연결된 업무를 수행한 경우 이어하기 시 서버가 근거를 재검증한다. 다른 작업지시를 임의로 완료 근거에 대입하지 않는다.
- 세션 만료 시 로그인으로 안내하고 재접속 후 확정 저장분으로 복구한다. 입력 중 미저장 값은 저장됐다고 표시하지 않는다.
- 네트워크 응답이 불명확하면 완료/실패를 단정하지 않고 해당 요청 결과를 조회한다. 재시도는 같은 요청 키를 사용한다.
- 준비정보/모듈 부족 시 해결 화면 링크와 이유를 표시한다. 준비 중 기능에는 실행 가능한 것처럼 보이는 링크를 만들지 않는다.
- 오류는 입력값과 수정할 필드를 안내한다. 내부 SQL·스택·타인 식별정보는 노출하지 않는다.
- 키보드로 핵심 동작을 수행할 수 있고, 360px 화면에서는 도움말/폼을 세로로 배치한다. 색상만으로 상태를 구분하지 않는다.

## 4. 이해 확인 질문과 채점
| ID | 질문 | 기대 답/판정 | 오답 피드백 |
|---|---|---|---|
| Q01 | 생산 1,000의 의미를 알려면 어떤 정보가 함께 필요한가? | 기준단위 EA | 개수·중량 등 단위를 먼저 확인해야 합니다. |
| Q02 | 작업지시와 LOT는 같은 개념인가? | 아니다. 계획/지시와 생산 추적 묶음 | 지시가 무엇을 얼마나 만들지 정하고 LOT가 생산 묶음을 추적합니다. |
| Q03 | 완제품 양품은 2,965와 980 중 무엇인가? | 980 EA | 각 공정 양품을 더하면 같은 제품을 여러 번 셉니다. |
| Q04 | 초기 1,000에서 최종 980이 된 이유는? | 재투입 없는 세 공정 불량 5+5+10=20 | 직전 양품만 다음 공정에 투입됩니다. |
| Q05 | 생산 완료이면 창고 입고도 완료인가? | 아니다. WMS 입고가 별도 | 생산실적과 재고 이동의 책임이 다릅니다. |

첫 과정은 선택형 질문으로 결정적으로 채점한다. AI 채점이나 장문의 자유서술 자동 판정을 도입하지 않는다. 오답은 설명 후 재시도 가능하며 업무 실적을 되돌리지 않는다. 최종 정답 여부와 시도 횟수·콘텐츠 버전을 보존한다.

## 5. 학습 기록과 업무 상태
과정 시도 상태: 진행 중 / 다시 준비 필요 / 완료.
단계 상태: 미시작 / 진행 중 / 완료. 선행 조건 차단과 모듈 비활성은 이유를 표시하는 가용 상태이며 완료 기록을 삭제하는 상태가 아니다.

시도에는 사용자/공간, course_key·콘텐츠 버전, 연결 업무·데이터 세대, 현재 단계, 단계 검증 결과, 질문 결과를 연결한다. 물리 테이블/필드는 FS-005에서 확정한다.
- 완료는 서버의 권위 있는 업무 상태와 답안을 검증한 결과다. 동일 검증 재요청으로 완료 기록을 중복 생성하지 않는다.
- 업무 저장과 학습 완료 저장의 경계는 명시한다. 학습 기록 실패 때문에 이미 성공한 생산을 다시 수행하지 않는다. 이어하기가 확정 업무로부터 미기록 진도를 복구한다.
- 완료된 단계의 요약 근거를 보존한다. 과거 세대의 업무 FK만 남기고 학습 기록을 잃지 않는다.
- 초기화 후 미완료 시도는 '다시 준비 필요'. 재시작은 새 세대의 새 시도이며 이전 일부 실습을 합쳐 새 과정 완료로 만들지 않는다.
- 과거 완료는 유지하지만 현재 세대의 업무 완료로 표시하지 않는다.
- 진행 중 시도는 콘텐츠 버전을 고정한다. 새 버전 게시가 기존 단계/질문을 묵시적으로 바꾸지 않는다.

| AC-29 | 진행 시도의 콘텐츠 v1, v2 게시 | 이어하기 | v1 기준 안내/채점 유지, 새 시도에 v2 적용 | API/DB |
| AC-30 | FEMS/BEMS 비활성 또는 미구현 | MES 과정 완료 | MES 완료 유지, 에너지 다음 경로의 필요 조건만 안내 | API/E2E |
| AC-31 | 업무 근거 없는 시도 | 브라우저 진도 조작/완료 API 호출 | 완료 거부, 근거 없는 완료 기록 없음 | API |
| AC-32 | 자유 탐색에서 유효한 다른 수량 완료 | 고정 과제 검증 | 업무 성공 유지, 과제 조건 차이 안내, 임의 수정 없음 | API/E2E |
| AC-33 | 키보드/360px 화면/오프라인 | 핵심 화면 사용·저장 시도 | 접근 가능한 조작과 읽을 수 있는 안내, 오프라인 저장 성공 오표시 없음 | E2E/수동 |
| AC-34 | 발행 지시/진행 생산 존재 | MES 비활성화 시도 | 진행 업무 정리 필요 안내·거부; 종결 업무만 있으면 비활성화해도 데이터/학습 보존 | API/DB |

## 7. 테스트 데이터와 자동화 연결
- 기준 seed: 공간 A/B, 각 공간 동일 표시 업무번호 사용 가능, 다른 내부 식별자. 유효/비활성 설비와 기준정보, 이전/현재 세대 제공.
- 기본 정상 시나리오의 수량은 L04~L06과 동일. 예외는 독립 fixture/트랜잭션으로 만들고 정상 데이터를 오염시키지 않는다.
- 시간은 제어 가능한 기준 시각으로 검증하며 테스트에 실제 수십 분 대기를 요구하지 않는다. 업무 시각과 테스트 실행 시각을 혼동하지 않는다.
- 규칙 검증은 수량·전이, PostgreSQL 검증은 원자성·제약·동시성, API 검증은 권한/모듈/세대, E2E는 학습 진입과 실행·복구를 담당한다.
- M1(MES 첫 실습)에서는 MES·학습·수동 초기화 관련 항목을 검증한다. 예약 초기화의 시간대·중복 실행·따라잡기는 FS-031에서 별도로 검증한다.
- 실제 테스트 작성 시 테스트명/경로와 AC ID를 연결하고 미실행/통과/실패 및 근거를 기록한다. 이 문서에 사전 통과 표시를 하지 않는다.

## 8. 상세 설계로 전달할 결정
FS-005: 공간/세대, 경로 버전, 작업지시↔LOT, 공정 실행↔실적, 요청 중복 키, 학습 시도/단계/답안/근거 요약의 관계.
FS-006: 상태 전이표·권한·잠금 순서·업무/학습 트랜잭션 경계·오류 코드.
FS-007: 위 결정을 Excel DB 설계서에 기록. 이번 단계에서는 물리 테이블을 생성하거나 참조 Excel을 변경하지 않는다.
