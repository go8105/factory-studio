# FS-004a 학습 과정 확장 — C0 · C2 · C3 및 설명 카드

작성일: 2026-09-21. 상태: 명세 작성 완료. 실행 전 명세이며 통과 결과가 아니다.
기준: [학습 경로 FS-004](학습경로_수용기준_FS-004.md), [MTS 전체 흐름 노드 정의서](../../architecture/MTS_전체흐름_노드정의서_FS-005a.md), [FS-005d 모듈·하위 모듈 구조](../../architecture/모듈_하위모듈_구조_FS-005d.md).
성격: FS-004를 **대체하지 않는 순증**이다. C1·C4의 기존 단계와 AC-01~34는 그대로 유효하다.

---

## 1. 무엇을 채우는가

개발기준 v1.1에서 학습 과정을 C0~C4로 나눴으나 **단계·검증 조건·확인 질문은 C1·C4만 작성돼 있었다.** 이 문서가 C0·C2·C3를 채우고, BOM·자재 투입 도입에 맞춰 C1을 개정한다.

| 과정 | 이전 | 이 문서 이후 |
|---|---|---|
| C0 전체 둘러보기 | 미작성 | **작성** |
| C1 생산 한 건 | 작성됨 | **개정** (자재 투입 단계 추가) |
| C2 계획에서 지시까지 | 미작성 | **작성** |
| C3 만든 것을 내보내기 | 미작성 | **작성** |
| C4 생산과 에너지 | 작성됨 | 유지 |

## 2. 공통 규칙

- 각 단계의 통과 판정은 **서버가 업무 상태를 조회해서** 내린다. 화면 클릭이나 자체 보고를 통과로 간주하지 않는다.
- 확인 질문은 선택형이며 **답을 틀려도 단계를 되돌리지 않는다.** 해설을 보여주고 다시 답하게 한다.
- 과정은 순서를 강제하지 않는다. C3를 먼저 열어도 되지만, 선행 데이터가 없으면 안내를 표시한다.
- 과정 콘텐츠 버전은 최소 요구 `seed_version`을 선언한다. 시드에 없는 데이터를 전제로 게시할 수 없다.
- **"계산 불가"는 오류가 아니다.** 생산량 0, 계수 없음, 모듈 비활성은 모두 정상 상태로 표시한다.

## 3. C0 전체 둘러보기

목표: 판매계획부터 매출까지 어떤 업무가 어떤 순서로 연결되는지 말할 수 있다.
대상: **게스트 기본 진입 과정.** 가입하지 않은 방문자가 첫 화면에서 바로 시작한다.
예상 소요: 3분. 업무 실행 없이 카드 열람만으로 진행한다.

| 단계 | 하는 일 | 통과 판정 |
|---|---|---|
| C0-1 | 프로세스 맵에서 전체 17개 노드를 본다 | 맵 화면 진입 기록 |
| C0-2 | 시작점(판매계획)과 끝점(매출) 카드를 연다 | 두 노드 카드 열람 기록 |
| C0-3 | 구현된 노드 하나를 골라 실제 화면으로 이동한다 | 해당 모듈 화면 진입 기록 |
| C0-4 | 준비 중 노드(품질검사·재고·건물 에너지) 중 하나를 연다 | 설명 카드 열람 기록 |
| C0-5 | 확인 질문 3개에 답한다 | 응답 저장 |

**확인 질문**

1. 매출은 언제 인식되는가 — 수주 시점 / **출하 시점** / 생산 완료 시점
2. 품질검사는 어느 업무 사이에 들어가는가 — 계획과 지시 사이 / **실적 확정과 포장 사이** / 출하 뒤
3. 이 시스템에서 지금 준비 중인 모듈은 몇 개인가 — 1개 / **3개** / 없음

C0-3은 **업무를 실행시키지 않는다.** 화면에 도착하는 것까지가 목표다. 게스트가 3분 안에 끝내야 하기 때문이다.

## 4. C1 생산 한 건 — 개정

BOM·자재 투입 도입으로 **단계 하나를 추가한다.** 기존 단계와 AC-01~34는 유지한다.

| 단계 | 하는 일 | 통과 판정 |
|---|---|---|
| (기존) | 준비 확인 → 작업지시 → LOT → 공정 실행 → 실적 확정 | FS-004 그대로 |
| **C1-신규** | 첫 공정 실행에 **자재를 투입**한다 | 해당 실행에 자재 투입 1건 이상 존재 |
| (기존) | 결과 요약과 다음 업무 | FS-004 그대로 |

자재 투입 단계는 **공정 실행 시작 이후, 실적 확정 이전**에 놓는다. 확정 후에는 투입을 추가할 수 없기 때문이다.

**추가 확인 질문**

- 이 완제품에 어떤 자재가 들어갔는지 어디서 확인하는가 — BOM / **자재 투입 기록** / 작업지시

BOM은 "무엇으로 만들 계획인가", 자재 투입은 "실제로 무엇을 썼는가"다. 이 구분이 C1의 새 학습 포인트다.

## 5. C2 계획에서 지시까지

목표: 계획수량과 생산수량이 왜 다른지, 계획이 어떻게 지시로 전개되는지 설명할 수 있다.
예상 소요: 10~15분.

| 단계 | 하는 일 | 통과 판정 |
|---|---|---|
| C2-1 | 품목과 공정 경로를 확인한다 | 게시된 경로 버전 조회 |
| C2-2 | 판매계획을 열어 품목별 계획수량을 본다 | 확정 상태 판매계획 조회 |
| C2-3 | 생산계획을 만들고 품목·주차별 수량을 넣는다 | 생산계획 라인 1건 이상 생성 |
| C2-4 | 생산계획을 확정한다 | 상태 draft → confirmed |
| C2-5 | 계획에서 작업지시를 전개한다 | 해당 계획을 근거로 한 지시 1건 이상 |
| C2-6 | 계획 대비 실적 차이를 조회한다 | 비교 화면 조회 기록 |
| C2-7 | 확인 질문 3개 | 응답 저장 |

**확인 질문**

1. 확정된 생산계획의 수량을 나중에 바꾸려면 — 그냥 수정한다 / **확정을 되돌릴 수 없으므로 새 계획을 만든다** / 작업지시에서 바꾼다
2. ERP를 사용하지 않으면 생산계획을 세울 수 없는가 — 그렇다 / **아니다. 판매계획 연결은 선택이다** / 판매계획을 직접 입력해야 한다
3. 작업지시 발행 시 고정되는 것은 — 계획수량만 / **적용 경로 버전과 BOM 버전** / 설비

**2번이 이 과정의 핵심이다.** 모듈 경계 규칙을 학습자가 직접 확인하는 지점이다. ERP 모듈을 꺼도 C2가 끝까지 진행돼야 한다.

**오류 시나리오**

| 시도 | 기대 |
|---|---|
| 미게시 경로로 작업지시 발행 | 거부. 게시 경로만 선택 가능함을 안내 |
| draft 상태 생산계획으로 지시 전개 | 거부. 확정 후 전개 가능함을 안내 |
| 음수 계획수량 입력 | 거부 |

## 6. C3 만든 것을 내보내기

목표: 포장·입고·출하·매출이 어떻게 연결되는지, 매출이 왜 출하 시점에 인식되는지 설명할 수 있다.
예상 소요: 10~15분.

| 단계 | 하는 일 | 통과 판정 |
|---|---|---|
| C3-1 | 확정 양품이 있는 LOT을 찾는다 | 패킹 가능 LOT 조회 |
| C3-2 | 박스를 만들고 LOT 수량을 담는다 | 패킹 구성 1건 이상 |
| C3-3 | 박스를 팔레트에 적재한다 | 상위 패킹 단위 연결 |
| C3-4 | 완제품으로 입고한다 | 입고 1건 생성, 패킹 상태 received |
| C3-5 | 수주를 등록한다 | 수주 라인 1건 이상 |
| C3-6 | 출하지시를 만든다 | 지시 누계가 수주수량 이하 |
| C3-7 | 출하를 확정한다 | 출하 확정 + **매출 1건 자동 생성** |
| C3-8 | 출하와 매출을 대사한다 | 대사 화면 조회 기록 |
| C3-9 | 확인 질문 3개 | 응답 저장 |

**확인 질문**

1. 매출은 언제 생기는가 — 수주 등록 시 / **출하 확정과 동시에** / 입고 시
2. 같은 팔레트를 두 번 출하하면 — 두 번 다 처리된다 / **두 번째가 거부된다** / 수량이 합쳐진다
3. MES를 사용하지 않는 회사도 이 출하 화면을 쓸 수 있는가 — 아니다 / **그렇다. 품목과 수량으로 출하한다** / 수주만 가능하다

**3번이 이 과정의 핵심이다.** 출하 독립화(FS-005e)를 학습자가 확인하는 지점이다.

**오류 시나리오**

| 시도 | 기대 |
|---|---|
| 확정 양품을 초과해 패킹 | 거부. 잔여 수량 안내 |
| 전량 불량 LOT을 패킹 | 거부. 양품 0임을 안내 |
| 입고 전 패킹 단위로 출하 | 거부. 입고 필요함을 안내 |
| 이미 출하된 패킹 단위 재사용 | 거부. 이중 출하 차단 안내 |
| 수주수량 초과 출하지시 | 거부. 잔여 지시 가능 수량 안내 |
| 출하 확정 요청 재전송 | 매출이 2건 생기지 않음 |

## 7. 준비 중 노드 설명 카드 본문

프로세스 맵의 `MAP_ONLY` 노드 3개다. **빈 화면 대신 이 내용을 보여준다.**
클릭했을 때 "준비 중입니다"만 뜨면 미완성으로 읽힌다. 역할·연결·설계 쟁점을 보여주면 설계된 확장 지점으로 읽힌다.

### 7.1 품질검사 (QMS)

**이 업무가 하는 일**
공정 실적으로 확정된 수량이 출하해도 되는 품질인지 판정한다. 검사 기준을 정의하고, 검사 결과를 기록하고, 합격·불합격을 판정하며, 문제가 있는 LOT을 보류시킨다.

**앞뒤 연결**
실적 확정에서 양품 수량을 받는다. 판정 결과가 포장 진행 여부를 통제한다. 현재는 QMS가 없어 **실적 확정 → 포장이 직접 연결**되어 있다.

**설계에서 이미 정해둔 것**
품질 보류는 **모듈 설정 변경으로 해제되지 않는다.** QMS를 꺼서 보류를 푸는 일이 없어야 한다. 이 정책은 QMS 구현 전에 이미 확정했다.

**왜 아직 없는가**
검사 기준은 업종마다 크게 다르다. 일반화한 검사 기준 모델을 먼저 설계해야 한다.

### 7.2 재고·비계획 입출고 (WMS)

**이 업무가 하는 일**
창고와 보관 위치를 정의하고, 재고 이동 원장을 관리하며, 출하 예약을 걸고, 계획에 없던 입출고(반품·폐기·조정·이동)를 처리한다.

**앞뒤 연결**
완제품 입고와 출하 사이의 재고 상태를 소유한다. 현재는 **완제품 입고 이력과 출하 이력의 대사**로 재고를 대신한다.

**설계에서 이미 정해둔 것**
WMS를 도입하면 **재고 원장의 소유가 MES에서 WMS로 이관된다.** 그리고 잔량은 파생값이고 수불원장이 원천이다. 잔량을 직접 수정하지 않는다.

**왜 아직 없는가**
재고 원장은 불변 원장 설계와 동시성 처리가 필요하다. 생산 흐름이 끝까지 동작한 뒤에 붙이는 것이 안전하다.

### 7.3 건물 에너지 (BEMS)

**이 업무가 하는 일**
공용 설비(조명·공조·사무동) 계측과 환경 관측을 담당한다. 제조 에너지와 공용 에너지의 경계를 나눈다.

**앞뒤 연결**
FEMS와 계측기를 공유하되 소유 모듈로 구분한다. 계측 기준정보는 core가 소유하므로 양쪽이 같은 마스터를 쓴다.

**설계 쟁점 — 중복 합산 방지**
사업장 전체는 이렇게 나뉜다.

```
사업장 전체 = 제조 + 공용 + 미계측 잔여
```

부모 계량기와 하위 채널을 함께 더하면 이중 집계가 된다. 지금은 **전체 − 제조 = 미계측 잔여**까지만 보여주고, 공용과 미계측의 분해는 BEMS 도입 시 처리한다.

**왜 아직 없는가**
공용 계측 데이터가 없으면 분해 자체가 성립하지 않는다. 계측 인프라가 먼저다.

## 8. 수용 기준 순증 (AC-81 ~ AC-96)

FS-006b의 AC-65~80에 이어서 부여한다.

| ID | 상황 | 기대 결과 |
|---|---|---|
| AC-81 | 가입하지 않은 방문자가 C0를 시작 | 로그인 요구 없이 진행. 5단계 완주 가능 |
| AC-82 | C0에서 준비 중 노드 선택 | 설명 카드 표시. 화면 이동 없음 |
| AC-83 | C0 완주 시간 측정 | 3분 이내 완주 가능 (실측으로 검증) |
| AC-84 | C1에서 확정 실적이 있는 실행에 자재 투입 시도 | 거부. 확정 후 변경 불가 안내 |
| AC-85 | C1 완주 후 완제품 LOT에서 자재 LOT 역추적 | 투입 자재 목록 조회 가능 |
| AC-86 | C2에서 ERP 모듈 비활성 상태로 생산계획 수립 | 정상 진행. 판매계획 칸은 비어 있음 |
| AC-87 | C2에서 draft 생산계획으로 지시 전개 | 거부. 확정 필요 안내 |
| AC-88 | C2에서 미게시 경로로 작업지시 발행 | 거부 |
| AC-89 | C2 완주 후 계획 대비 실적 조회 | 차이가 표시되고 근거를 확인할 수 있음 |
| AC-90 | C3에서 확정 양품 초과 패킹 | 거부. 잔여 수량 안내 |
| AC-91 | C3에서 입고 전 패킹 단위로 출하 시도 | 거부 |
| AC-92 | C3에서 MES 모듈 비활성 상태로 출하 | 정상 진행. 품목·수량으로 출하 |
| AC-93 | C3 출하 확정 요청 재전송 | 매출 1건 유지 |
| AC-94 | 과정을 순서 없이 열기 (C3 먼저) | 차단하지 않음. 선행 데이터 없으면 안내 표시 |
| AC-95 | 확인 질문 오답 | 단계를 되돌리지 않음. 해설 표시 후 재응답 |
| AC-96 | 시드에 없는 데이터를 전제한 과정 게시 시도 | 거부. 최소 seed_version 미달 |

AC-83은 **실측이 필요한 유일한 항목**이다. 나머지는 기능 검증이다.

## 9. 미확정 / 후속

- 각 단계의 안내 문구와 화면 위치는 FS-008a에서 확정한다. 이 문서는 무엇을 검증하는지만 정한다.
- 학습 콘텐츠 버전과 최소 `seed_version` 대응표는 시드 생성기 구현 시 작성한다.
- C0의 노드 카드 열람 기록을 어디에 남길지(학습 진도 vs 감사)는 구현 시 정한다. 게스트도 남겨야 하므로 세대 범위가 필요하다.
- C2의 계획 대비 실적 비교 집계 기준(연월/주차)은 ERP-1 구현 시 확정한다.
- 자재 투입 단계를 C1이 아니라 별도 과정으로 뺄지는 사용자 점검 후 재판단한다. C1이 길어지면 게스트 이탈이 늘 수 있다.
