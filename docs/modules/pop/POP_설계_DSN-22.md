# DSN-22 POP 현장 단말 설계 (신규)

작성: 2026-10-05 (Claude Code) · 상태: **1단계 — 기준표·결정 질문(범위 확인 대기)**. 3~6장은 범위 확정 뒤.
양식: [DSN-00](../../plan/기능기준표_DSN-00.md) · 방침: [ROADMAP-02](../../plan/전체설계우선_전환_ROADMAP-02.md) · 로드맵: [ROADMAP-01 §6-1](../../plan/로드맵_17개시스템_ROADMAP-01.md)(POP는 자기 스키마에 확정, MES가 가져오기)
넘겨받은 것: **MES DSN-12 Q1**(생산 스캔은 POP에만 — 공정 입고·작업 시작/완료·자재 투입·패킹·완제품 입고) · **WMS DSN-13 Q1**(창고 스캔은 POP — 입고·적치·피킹·불출·실사·이동) · MES 라벨 Code128/QR·USB 스캐너(MES Q3).

---

## 0. POP가 무엇이고 무엇이 아닌가

**POP = 생산·창고 현장의 단말 화면과 그 입력 원장.** 작업자가 바코드를 스캔하고 큰 버튼으로 입력한다. 확정한 입력은 POP 스키마에만 남고, **MES·WMS가 읽어 가져가 자기 규칙으로 다시 검증해 반영**한다(교차 쓰기 금지, FS-013 §6).

| 영역 | 소유 | POP와의 관계 |
|---|---|---|
| 스캔 시도·확정 입력(원장) | **POP** | 이 문서 |
| 작업지시·LOT·실행·실적·패킹 | **MES** | POP는 `pop_context`로 읽어 즉시 확인, MES가 POP 확정 입력을 가져감 |
| 재고·위치·LOT 수량 | **WMS** | 같은 방식 |
| 라벨·바코드 값 | **MES·WMS** | POP는 출력하지 않고 스캔만 |
| 작업자 인사 | **HR** | Q2 |

## 7. 결정 질문 (하나씩)

| # | 질문 | 제안 |
|---|---|---|
| Q1 | **MES·WMS 반영 시점** — POP는 확정 전에 `pop_context`(읽기)로 즉시 확인하고 확정한다. 가져가기는 (a) **MES·WMS가 자기 API가 불릴 때 미반영 POP 입력을 먼저 가져감**(지연 가져오기 — 교차 쓰기 없음, 배경 작업 없음, POP 화면은 몇 초 뒤 결과 표시) (b) MES·WMS 화면의 "가져오기" 버튼으로만 (c) POP 확정 요청 안에서 MES·WMS 쓰기 함수를 바로 호출(즉시 반영이지만 "조회 함수는 읽기만" 원칙 D9 예외 필요) | **(a)**. 원칙을 지키면서 체감은 즉시에 가깝다. POP는 결과를 MES·WMS 조회(`pop_results`)로 읽어 표시 |
| Q2 | **작업자** — (a) POP가 단말 사용자(작업자 코드·이름·역할 생산/창고)를 자체로 갖고, MES는 가져갈 때 같은 코드의 MES 작업자로 연결(없으면 거부) (b) POP는 MES 작업자를 조회로만 확인(창고 작업자도 MES에 등록) | **(a)**. 독립 솔루션 원칙(마스터 각자 소유, 중복 정상) |
| Q3 | **공정 검사 입력(초·중·종물)**을 POP 화면에서도 받는가(소유·판정은 MES, POP는 입력 → MES가 가져감) | 받는다 |
| Q4 | **호출(안돈)** — 자재·품질·보전·관리자 호출과 응답·완료를 POP 안에서만 관리(CMMS 신호로 넘기지 않음 — CMMS Q4와 같은 원칙) | 포함 |
| Q5 | **작업 일보·라인 현황판** 포함(POP 확정 입력 + MES 계획 조회로 계산, 저장 안 함) | 포함 |
| Q6 | 범위 확정 — 포함 22 + Q 4, 제외 3(오프라인·카메라 스캔·표준서 보기) | 제안대로 |
