작성: 2026-10-05 (Claude Code) · 상태: **설계 완료(2026-10-05) — 사용자 확인 대기.** 1단계(기준표·Q1~Q6 확정) + 2단계(3장 기능 규칙 · 4장 DB 7테이블 · 5장 화면 22 · 6장 교차 조회).
양식: [DSN-00](../../plan/기능기준표_DSN-00.md) · 방침: [ROADMAP-02](../../plan/전체설계우선_전환_ROADMAP-02.md) · 로드맵: [ROADMAP-01 §6-1](../../plan/로드맵_17개시스템_ROADMAP-01.md)(POP는 자기 스키마에 확정, MES가 가져오기)

## 0. POP가 무엇이고 무엇이 아닌가

**POP = 생산·창고 현장의 단말 화면과 그 입력 원장.** 작업자가 바코드를 스캔하고 큰 버튼으로 입력한다. 확정한 입력은 POP 스키마에만 남고, **MES·WMS가 읽어 가져가 자기 규칙으로 다시 검증해 반영**한다(교차 쓰기 금지, FS-013 §6).

| 영역 | 소유 | POP와의 관계 |
|---|---|---|
| 스캔 시도·확정 입력(원장) | **POP** | 이 문서 |
| 작업지시·LOT·실행·실적·패킹 | **MES** | POP는 `pop_context`로 읽어 즉시 확인, MES가 POP 확정 입력을 가져감 |
| 재고·위치·LOT 수량 | **WMS** | 같은 방식 |
| 라벨·바코드 값 | **MES·WMS** | POP는 출력하지 않고 스캔만 |
| 작업자 | **POP**(Q2 확정) | POP 자체 단말 사용자, HR 사원 코드는 스냅샷. MES는 같은 코드의 MES 작업자로 연결 |

## 3. 기능 규칙 (범위 26)

공통 흐름(모든 스캔 화면): **스캔 → 대상 확인(MES·WMS `pop_context` 읽기, 원장에 기록) → 필요한 값 입력(큰 버튼·숫자판) → 확정(다시 확인 후 저장)**. 확정 입력은 불변. **POP는 다른 스키마에 쓰지 않는다.**

| 묶음 | 기능 ID | 규칙 |
|---|---|---|
| 단말·작업자 (Q2) | F01~F03 | 단말(종류·모드·설치 위치 코드). 작업자 바코드 스캔 → 세션 시작(역할이 모드와 맞아야), 다른 작업자 스캔 = 교대. 단말당 열린 세션 1개. USB 스캐너는 키보드 입력 + Enter |
| 즉시 확인 | F31·F41 | 스캔마다 대상 종류(LOT·박스·팔레트·지시·작업자·설비·위치·자재 LOT)와 결과(OK·WARN·REJECT)를 원장에 기록. WARN(보류 LOT·SPC 이상·선입선출)은 사유를 보여 주고 진행 가능, REJECT(순서 위반·오투입·입수 초과·실사 잠금)는 확정 불가. 반영 솔루션이 꺼져 있으면 REJECT |
| 생산 입력 → MES | F11~F18 | 공정 입고(ARRIVE) · 시작(START: LOT+설비+작업자) · 완료(COMPLETE: 양품·불량 + 불량 코드별 명세) · 투입(ISSUE: 자재 LOT·수량) · 패킹(PACK: LOT/박스 → 박스/팔레트) · 완제품 입고(RECEIVE: 팔레트) · 비가동(DOWNTIME: 설비·사유·시작/종료) · 공정 검사(INSPECT: 시점·항목별 값, Q3) |
| 창고 입력 → WMS | F21~F26 | 입고 검수(RECEIVE: 예정 번호·품목·수량·LOT) · 적치(PUTAWAY: LOT/박스 + 위치) · 피킹(PICK: 지시 순서대로 위치·LOT·수량) · 불출(ISSUE: 요청 번호·LOT·수량) · 실사(COUNT: 위치별 품목·LOT·수량 명세) · 이동(MOVE: 출발·도착 위치) |
| 반영 (Q1) | F42·F43 | **지연 가져오기**: MES·WMS가 자기 API가 불릴 때 `confirmed_entries(since)`로 미반영분을 가져가 자기 규칙으로 재검증 → 반영 또는 거부(멱등 키 = 입력 번호). POP 화면은 `pop_results(entry_nos)`(MES·WMS 읽기)로 "반영됨/거부됨(사유)/대기" 표시. 배경 작업 없음 |
| 정정 | F44 | 취소 = CANCEL 입력(원 입력당 1건): 원 입력이 아직 반영 전이면 MES·WMS가 둘 다 건너뛰고, 이미 반영됐으면 CANCEL 거부("MES/WMS에서 정정"). 거부된 입력은 고쳐서 재제출(원 입력 참조) |
| 호출 (Q4) | F34 | 자재·품질·보전·관리자 호출(단말·종류당 진행 1건) → 확인(응답자) → 완료. POP 현황판·관리 화면에만 표시, 다른 솔루션으로 넘기지 않음 |
| 일보·현황판 (Q5) | F32·F33·F35 | 내 작업 목록 = MES 발행 지시·WMS 피킹/적치/불출 대기 조회. 작업 일보 = 작업자·일별 확정 입력 합계(반영 결과 포함). 라인 현황판 = 공정별 목표(MES 지시 수량) 대비 반영 실적·진행 비가동·진행 호출. 모두 조회 계산 |

## 6. 교차 조회

|---|---|---|
| `confirmed_entries(target_solution, since)` | 확정 입력 + 명세(입력 번호 = 멱등 키, CANCEL 포함) | MES·WMS 지연 가져오기(Q1) |
| `open_calls()` | 진행 호출 | EIP 요약(선택) |

> 넘길 것: **MES** `pop_results` 제공·가져오기 종류 DOWNTIME·INSPECT·CANCEL 처리, POP 작업자 코드 → MES 작업자 연결 · **WMS** `pop_results`·`pending_tasks` 제공·CANCEL 처리 · **DSN-90** 지연 가져오기 동시성(같은 입력을 두 요청이 동시에 가져갈 때 멱등 키로 1건만).
