# Factory Flow 간결 보드·총 관리자 사용자 관리 FLOW-03

2026-10-11. 사용자 전체 구현·main 반영·배포 승인. 구현 및 검증 진행.이번 사용자 Figma 디자인을 최종 UI 기준으로 반영했다.

## Figma 디자인 기준 변경 (사용자 최신 요청 우선)

이 절이 아래 초기 화면안보다 우선한다. 사용자 제공 폴더의 src/App.tsx 및 src/index.css를 확인했다. 참조 폴더는 수정하지 않았다. Figma 소스의 디자인 토큰·단색 SVG 라인 아이콘·256px 사이드바·64px 상단바·둥근 그룹 카드·행 간격·하위 업무 연결선·상태 배지·담당자 아바타·진행률 바를 기준으로 구현한다. 기존 검토 HTML의 사각 표 스타일은 최종 디자인이 아니다.

- 사이드바: 홈 / 내 업무 / 전체 솔루션, 즐겨찾기, 내 보드(+보드 추가), 하단 로그인 사용자. 최근 항목은 별도 더보기로 이동한다. 내 보드 목록에는 접근 가능한 보드만 표시한다. 펼친 상태가 기본이며 기존 요청대로 축소 시 아이콘·툴팁을 제공한다.
- 보드 상단: 경로·공유·검색·더보기, 제목·별·설명. 오른쪽 전체 업무 / 진행 중 / 완료 / 전체 진행률 카드 유지. 큰 상시 설정 폼만 제거한다.
- 메인 테이블 / 칸반 / 캘린더 / 간트 4개 탭을 상시 유지한다. 초기안의 ‘다른 보기 더보기 이동’ 제안은 취소한다.
- 도구줄: 새 업무, 업무 또는 담당자 검색, 내 업무만, 필터, 표시 중 개수. 필터·정렬·컬럼 표시 설정은 필터 팝오버에 제공한다.
- 기본 표시 컬럼: 업무명 / 담당자 / 상태 / 일정(기간) / 진행률. 중요도·설명은 선택 컬럼 및 업무 상세에서 제공한다. 사용자 컬럼은 오른쪽 컬럼 추가 버튼으로 추가한다. 컬럼 편집 버튼은 hover/focus 때 표시해 기본 화면을 복잡하게 만들지 않는다.
- 둥근 그룹 카드: 색상 막대·접기 버튼·클릭 편집 그룹명·개수·더보기. 각 행의 원형 +는 하위 업무 추가, 그룹 하단은 업무 추가, 모든 그룹 아래는 넓은 점선 ‘새 그룹 추가하기’ 버튼이다. 업무 이름 클릭은 이름 편집, 업데이트는 행 더보기/댓글 버튼으로 우측 패널을 연다.
- 화면의 체크 버튼은 완료 토글이다. 여러 항목 선택은 별도 선택 모드에서 제공해 완료와 혼동하지 않는다. 완료하면 DONE/진행률100; 해제하면 WAITING/0으로 명시적으로 복귀하고 기존 이력은 보존한다. 하위 업무가 있는 부모의 상태·진행률·기간은 기존 롤업을 유지하므로 직접 완료/수치 편집 대신 하위 업무 완료를 안내한다.
- 상태 선택은 ‘대기 / 진행 중 / 검토 / 완료’ 메뉴로 제공하고, 기존 BLOCKED(지연)·CANCELLED(취소)도 숨기거나 다른 의미로 바꾸지 않는다. 검토는 신규 REVIEW enum으로 기존 task DB CHECK/API/필터/칸반/집계에 추가한다. 기존 enum 데이터는 그대로 둔다. 부모 롤업은 유효한 미완료 자식이 모두 REVIEW면 REVIEW, 그 외 기존 집계 규칙을 유지한다. 사용자 자유 상태 컬럼은 이 기본 task 상태와 별개다.
- 요약은 실제 접근 가능한 보드의 보관·삭제·취소 제외 업무를 집계한다. 전체 업무·완료 개수는 상위+하위 행 수, 진행 중은 WORKING+REVIEW. 전체 진행률은 실행 단위인 하위 업무 없는 행의 평균(없으면0)으로 계산하여 부모·자식 진행률을 이중 가중하지 않는다. 필터의 표시 중 개수는 현재 표시되는 행 개수다. Figma 예제의 7/3/1/39%를 운영 숫자로 하드코딩하지 않는다.
- 공유는 기존 보드 멤버 권한 설정 패널을 연다. 공개 링크·외부 초대는 추가하지 않는다. 회사 구성원 조회 권한과 멤버 변경 OWNER 권한을 검증한다. 홈은 보드 목록, 내 업무는 로그인 계정 담당 업무, 전체 솔루션은 앱 런처로 연결한다.

### 참조 코드 동작 분석과 구현 보완

참조 코드는 합성 React 상태 시제품이다. 보드 추가/선택/즐겨찾기, 검색·내업무만, 그룹 추가/접기/이름 편집, 업무/하위 업무 추가·이름 편집, 상태 순환, 칸반이 동작한다. 홈/내업무/전체솔루션·공유·필터·행/그룹 더보기는 연결되지 않았다. 캘린더·간트는 EmptyView 안내만 표시한다. 모든 보드가 같은 groups/tasks 상태를 공유하며 새 보드 선택 후 독립 데이터가 없다. 비어 있는 업무 평균은 NaN이 될 수 있고, Escape는 수정값을 되돌리지 않는다.

제품에서는 기존 실제 보드별 API/회사 범위/멤버 권한/저장/4보기와 연결하고, 빈 집계0·독립 보드 데이터·Escape 취소·입력 실패 유지·그룹/아이템/컬럼 보관삭제복구를 구현한다. 참조 코드의 예제 계정·날짜·고정 배지·Date.now ID·상태 순환을 실제 저장 규칙으로 그대로 이식하지 않는다. Figma 빌드 전용 추적/오류 replay 플러그인은 제품에 이식하지 않는다.

## 확인 결과와 목표

기존 로그인 admin은 로컬·운영 모두 활성 플랫폼 ADMIN이다. 로컬 hugh-admin은 플랫폼 ADMIN이 아니며 회사의 work_role ADMIN이다. 운영에는 활성 회사가 0개다. 기존 사용자 관리 API는 플랫폼 ADMIN에게 모든 활성 회사의 사용자 관리 권한을 이미 부여한다. 따라서 운영 사용자 추가의 선행 조건은 회사 등록이다. 아이디 문자열로 권한을 주지 않고 현재 활성 계정·역할을 매 요청 검증한다.

사용자가 지정한 Monday 보드를 로그인된 브라우저에서 읽기 전용으로 확인했다. 왼쪽 즐겨찾기·최근 보드, 오른쪽 그룹별 표·아이템·하위 아이템·그룹 메뉴를 참고한다. 실제 보드와 계정은 수정하지 않았다. 검토 UI의 데이터는 합성 예제다. 기존 백자 F7F7F6, 카드 FFFFFF, 한지 E8E8E6, 먹색 1A1C1E, 쪽빛 1F2D3D, 청자 2D4442, 프로필 E2E3E5를 유지한다.

보드 구조 변경은 OWNER, 그룹·아이템·셀 변경은 EDITOR/OWNER, VIEWER는 조회만 가능하다. 회사 관리자 권한과 보드 참여 권한은 별개다. 플랫폼 ADMIN의 사용자 관리 권한을 Flow 전체 보드 공개 권한으로 확대하지 않는다. 게스트의 회사·계정 등록은 금지한다. 별표는 별 모양만 황토색이고 주변 배경은 기본색이다.

Excel 내보내기는 보드/그룹의 현재 조회 권한 내 표시 컬럼·행만 제공한다. CSV 우선 제공 시 버튼을 CSV로 명확히 표시하고 Excel로 표기하지 않는다. 실제 Excel 내보내기 구현은 후속 범위로 둔다. 다른 보드로 그룹 이동·복제, 수식·파일·자동화·외부 공유·AI·다단계 하위 아이템은 이번 구현 범위 밖이다. 날짜별 업무일지 FLOW-02b 8표는 별도 승인 범위를 유지한다.

## 데이터 모델

S=(workspace_id,generation_id). 신규 업무 FK는 같은 flow 스키마의 S+board_id+참조id를 사용한다. core.workspace/core.data_generation만 범위 앵커로 참조하며 업무 스키마 간 FK를 만들지 않는다. FK는 ON DELETE RESTRICT. 현재 적용 head flow_split을 수정하지 않고 새 revision을 추가한다.

### 신규 flow.work_column

| 컬럼 | 형식·NULL | 규칙 |
|---|---|---|
| id | bigint NOT NULL | PK, identity |
| workspace_id, generation_id | bigint NOT NULL | S 복합 범위 앵커 |
| board_id | bigint NOT NULL | 같은 S의 work_board FK |
| name | varchar(120) NOT NULL | trim 후 비어 있지 않음 |
| kind | varchar(16) NOT NULL | TEXT/NUMBER/DATE/STATUS/CHECKBOX/TIMELINE/BUILTIN |
| builtin_key | varchar(32) NULL | BUILTIN이면 필수, 그 외 NULL. assignee/status/timeline/priority/progress/description |
| position | integer NOT NULL | >=0, 정렬 동률 id. 순서 변경 시 보드 잠금 |
| width | integer NOT NULL | 80..600 px, 기본 160 |
| options | jsonb NOT NULL | 기본 {}, 객체 CHECK. STATUS labels=[{id,name,color,active}], 안정적인 id |
| archived_at, deleted_at | timestamptz NULL | 보관·휴지통. 영구 삭제는 제공하지 않음 |
| version | integer NOT NULL | 기본 1, >0, 낙관적 잠금 |
| created_at, updated_at | timestamptz NOT NULL | now() |

UK(S,board_id,id), UK(S,board_id,id,kind). builtin_key는 동일 보드에서 NULL을 제외하고 유일(삭제돼도 예약). board FK(S,board_id). BUILTIN 값은 기존 task/assignee 원장을 읽고 셀로 복제하지 않는다. 아이템명·체크박스 선택·댓글·행 메뉴는 고정 UI이며 지울 수 없다. 기본 상태의 의미/기존 enum은 유지하고 표시 이름만 설정한다.

### 신규 flow.work_cell

| 컬럼 | 형식·NULL | 규칙 |
|---|---|---|
| id | bigint NOT NULL | PK, identity |
| workspace_id, generation_id | bigint NOT NULL | S 범위 앵커 |
| board_id, task_id, column_id | bigint NOT NULL | 같은 S·보드의 task/column 참조 |
| kind | varchar(16) NOT NULL | 6개 사용자 컬럼 유형, BUILTIN 금지 |
| value | jsonb NOT NULL | TEXT 문자열, NUMBER 숫자, DATE 문자열, STATUS label id 문자열, CHECKBOX boolean, TIMELINE {start,end} |
| version | integer NOT NULL | 기본 1, >0 |
| created_at, updated_at | timestamptz NOT NULL | now() |

UK(S,task_id,column_id). task FK(S,board_id,task_id) 및 column FK(S,board_id,column_id,kind). 필요 시 기존 task에 동일 복합 UK 추가. JSON 종류·텍스트 길이(4000)·숫자 유한성은 DB CHECK와 입력 검증을 함께 적용한다. DATE는 실제 ISO 날짜, TIMELINE은 두 날짜 및 start<=end, STATUS는 해당 컬럼의 활성 label id를 SERVICE에서 검증한다. 유효한 실제 날짜/상태 옵션 존재는 단순 JSON CHECK만으로 보장되지 않는다. 빈 값은 셀 행 부재로 표현한다. 값이 존재한 컬럼의 유형 변경은 금지한다. 사용 중 상태 라벨 삭제는 막고 이름 변경·비활성화 또는 명시적 재배치를 제공한다.

### 기존 모델 변경·보존

- work_group에 archived_at/deleted_at nullable 추가. 그룹 삭제는 자식을 일괄 물리 삭제하지 않고 조회·집계·내 작업에서 부모 상태를 확인한다. 복구해도 개별 보관된 아이템은 보관 상태를 유지한다.
- 최근 보드·접힘·숨김은 기존 개인 view preference JSON에 버전 있는 키로 저장한다. 즐겨찾기는 기존 work_favorite 원장 유지. 구조적인 컬럼 보관·삭제와 개인 숨김을 구분한다.
- 모든 기존 보드에 기본 컬럼 정의만 추가한다. task·assignee·comment·event·receipt의 ID와 원문·기존 상태값은 변경하지 않는다. 구 API/URL/멱등 namespace 호환 유지.
- 그룹 복제는 같은 보드의 활성 아이템·하위 아이템·담당자 코드·사용자 셀을 새 ID로 복사한다. 댓글·기존 감사 이벤트·영수증은 복제하지 않는다. 새 복제 이벤트를 남긴다. 총 500개 아이템 초과는 요청을 거절한다.
- 휴지통·보관 복구 시 권한과 상위 보드의 활성 상태를 다시 검증한다. 영구 삭제 API는 없다. 세대 정리는 work_cell→work_column/기존 자식→task→group→board 순서를 반영한다. seed/copy/cleanup/module isolation 목록·메타데이터·통합 Excel·ERD를 구현과 함께 갱신한다.

## API·동시성

기존 /api/v1/flow/projects 계열을 확장한다. 상세 경로는 기존 router 이름을 유지하며 새 endpoint에 group archive/delete/restore/duplicate, column create/update/archive/delete/restore/reorder, cell batch update(max100)를 추가한다. 구조 변경은 보드 version과 그룹/컬럼 version, 셀 변경은 task/column/cell version을 전달한다. board→group/column→task/cell 순으로 잠그고 권한·세대·삭제 여부를 잠금 후 재검증한다. 신규 빈 셀의 동시 생성은 UK와 기대 version=0으로 충돌 검출한다. 409 응답 시 서버 값을 비교하고 재입력 안내, 자동 덮어쓰기 금지. CSRF·기존 mutation receipt 멱등 처리 유지. 그룹 복제는 전체 원자적이며 실패 시 0개 생성. 모든 새 쓰기 요청은 검증 실패 시 롤백한다.

기본/사용자 컬럼은 보드 상세에 함께 반환하고 셀은 현재 task 페이지 ID에 대해서만 조회한다. 하위 아이템은 펼칠 때 조회하고 페이지별 로딩. 그룹 요약은 서버 집계, 첫 화면 최대 100행·사용자 컬럼 최대 30개. 가상화 도입 시 키는 task id, 편집 중 행/포커스 유지. 키보드 Enter/Escape/Tab, 최소 44px 모바일 메뉴 버튼, 표는 내부 가로 스크롤을 제공한다.

## 회사 등록 계약 HR-USERS-02

POST /api/v1/hr/work/companies. 매 요청 활성 MEMBER+core ADMIN 재검증. 기존 관리 회사 목록은 전체 관리자에게 모든 활성 회사, 회사 관리자에게 자신의 관리 회사만 반환한다. frontend는 server capability(canCreateCompany/isPlatformAdmin)를 기준으로 버튼·제목을 표시하며 숨김만으로 보안 처리하지 않는다.

요청: companyName(1..120), initialAdmin {loginId,displayName,password,employeeCode}, timezone(첫 범위 Asia/Seoul), workStart(09:00 기본), dailyMinutes(480 기본), breakMinutes(60 기본), annualLeaveDays. 비밀번호 기준은 기존 사용자 생성과 동일하며 브라우저에서 가려 입력한다. 회사 생성 화면에 기본 근무 기준을 명시하여 확인 후 제출한다. 비밀번호는 저장 시 기존 해시만 보관하고 로그·응답·감사 JSON·멱등 원문에 넣지 않는다. 기존 사용자 mutation의 비밀값 HMAC 비교 방식을 재사용한다.

회사·공간·활성 세대·hr/gw/flow 모듈·최소 부서/직급/근무형태/정책·첫 회사 관리자 직원/계정/멤버십을 하나의 트랜잭션으로 만든다. 회사명 중복 판정은 trim+casefold를 기준으로 전역 생성 잠금 후 확인, 중복 로그인/사번은 기존 UK와 검증으로 409 처리한다. 기존 계정 권한을 임의 승격하거나 이름이 같은 회사를 덮어쓰지 않는다. 첫 회사 관리자는 회사 OWNER/HR ADMIN이며 core STAFF이고 core ADMIN을 부여하지 않는다. 플랫폼 admin을 근태 직원으로 자동 등록하지 않는다. 실패 시 생성 중간 상태를 남기지 않는다. 예제 helper의 공통 초기화만 재사용하고 hugh-D/hugh-admin을 하드코딩하지 않는다. 실제 운영 회사명·계정·비밀번호 입력은 배포 후 사용자가 웹에서 한다.
