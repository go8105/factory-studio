# DSN-30 HR 인사·급여 설계 (신규)

작성: 2026-10-05 (Claude Code) · 상태: **1단계 — 기준표·결정 질문(범위 확인 대기)**. 3~6장은 범위 확정 뒤.
양식: [DSN-00](../../plan/기능기준표_DSN-00.md) · 방침: [ROADMAP-02 D79](../../plan/전체설계우선_전환_ROADMAP-02.md)(사원 인사카드·발령·근태·급여 계산·급여대장, 4대보험·원천세 신고 제외, 주민번호·계좌 저장 안 함, ERP는 급여 결과를 읽어 급여 전표만) · 입력: [ERP DSN-11](../erp/ERP_보강설계_DSN-11.md) 영역 91·`payroll_runs(month)`, [EIP DSN-28](../eip/EIP_설계_DSN-28.md) Q3-1(사람 연결 = HR 사원 코드)

## 0. HR의 자리 — 사람 원천

앞선 설계에서 이미 정해진 것:

| 솔루션 | 사람 마스터 | HR과의 관계 |
|---|---|---|
| MES `worker`·POP `operator`·CMMS `technician` | 각자 소유(작업자 바코드·정비원 코드) | HR 사원 코드 스냅샷 |
| GW `person`·CRM `sales_rep`·ELB 신청·승인·`approver`·QMS CAPA·RWS `expert` | 각자 소유 | `hr_employee_code` 스냅샷(DSN-28 Q3-1) |
| ERP `department`·`employee` | ERP 자체(DSN-11 Q2, 중복 정상) | 급여 전표만 HR 결과를 읽음(F94) |
| EIP `person_link` | 로그인 사용자 ↔ HR 사원 코드 | 사람별 할 일 |
| core `holiday` | 공통 휴일 달력 | HR 근태가 날짜로 읽음 |

## 7. 결정 질문 (하나씩)

| # | 질문 | 제안 |
|---|---|---|
| Q1 | **사람 원천** — HR이 사원 코드·부서 코드를 발급하고 `employees()`·`departments()`로 제공한다. 각 솔루션은 "HR에서 가져오기"로 자기 사람 마스터를 만들고 코드를 스냅샷한다(자동 동기화 없음, 퇴직자는 조회 때 "퇴직" 표시). ERP·ELB 부서 코드도 HR에서 가져와 맞춘다(ERP 자체 부서 마스터는 유지) | 그대로 |
| Q2 | **일 근태 입력** — (a) 근무 형태와 휴일 달력으로 정상 근태를 자동 생성하고 예외(지각·결근·연장)만 고친다 (b) POP 단말 로그인(작업자 바코드)을 출퇴근으로 가져온다 | **(a)** — POP 세션은 공정 작업 단위라 출퇴근과 다르다 |
| Q3 | **휴가 승인** — (a) HR 안에서 부서장(HR 조직의 부서장 직책) 승인 (b) GW 전자결재로 올리고 HR이 결과를 가져온다 | **(a)** HR 자체 승인 |
| Q4 | **급여 계산 깊이** — 월급제. 기본급 + 고정 수당 + 근태 수당(연장·야간·휴일 = 통상시급 × 배율) − 공제(4대보험·소득세는 **합성 고정 비율**, 간이세액표 아님). 확정 후 불변, ERP에는 부서·항목별 합계만 제공 | 그대로 |
| Q5 | **상여·퇴직금** — 정기 상여(기본급 × 지급률, 지정 월) 포함, 퇴직금은 추계액만 조회 계산(지급·적립 회계 없음) | 둘 다 포함 |
| Q6 | **자격·교육 이력**(만료 경고 포함) 포함, **인사 평가**는 제외 | 자격·교육 포함, 평가 제외 |
| Q7 | **본인 조회** — EIP 사람 연결(로그인 사용자 ↔ 사원 코드)로 자기 급여명세서·잔여 연차·근태만 본다 | 포함 |
| Q8 | 범위 확정 — 포함 15 + Q 결과, 제외: 민감 정보, 4대보험·원천세 신고·연말정산(+ Q6 평가) | 제안대로 |
