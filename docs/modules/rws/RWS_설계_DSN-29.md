## 0. RWS의 자리 — CMMS·POP 호출과 무엇이 다른가

| 상황 | 소유 | RWS와의 관계 |
|---|---|---|
| 라인에서 지금 사람을 부른다(자재·품질·보전·관리자) | **POP 호출**(DSN-22 Q4, POP 안에서만) | 겹치지 않게 둔다 — Q2 |
| 설비를 고친다·예방보전한다(작업지시·부품·비용) | **CMMS** | 원격으로 못 고치면 "현장 출동 필요" → CMMS가 가져가 작업지시 — Q3 |
| 현장 사람이 **혼자 해결할 수 없어 원격 전문가의 안내를 받는다** | **RWS** | 이 문서. 전문가가 텍스트·단계 체크리스트로 안내하고, 현장이 결과·측정값을 입력 |
| 사람(사원) 원천 | **HR**(D79) | 전문가·요청자는 HR 사원 코드 스냅샷(EIP Q3-1과 같은 방식) |

## 3. 기능 규칙 (범위 17)

공통: **RWS는 안내와 기록만 한다** — 수리 실행은 CMMS, 라인 호출은 POP. 다른 솔루션 값은 코드 스냅샷, 다른 솔루션에는 쓰지 않는다. 사람은 HR 사원 코드(EIP Q3-1과 같은 방식).

| 묶음 | 기능 ID | 규칙 |
|---|---|---|
| 요청 (Q2·Q4) | F01~F03 | 직접 등록 또는 CMMS 작업지시·QMS 부적합(NCR) 번호로 가져오기(조회로 대상·증상 채움, 출처당 진행 요청 1건). 고객 현장은 CRM 고객사 코드 필수, 사내 담당자가 대신 등록. 접수 시 긴급도별 응답·해결 기한 스냅샷 |
| 배정 (Q7) | F11~F14 | 전문가 = 내부(HR 사원 코드)·외부(업체 코드), 단계 1~3, 분야·숙련도. 추천(분야 → 숙련도 → 진행 건수) 후 사람이 확정, 주 담당 1명. 해결 기한 초과·전문가 요청 시 상향 단계 +1 → 상위 단계 전문가 추가 배정. 기한 초과는 조회 표시 |
| 원격 안내 | F21~F23 | 텍스트 대화(추가만, 첫 전문가 메시지 = 첫 응답). 가이드 적용 시 게시 버전 단계를 복사, 현장이 단계마다 확인·OK/NG·측정값 입력(한계 밖이면 NG). 전문가가 측정 항목을 따로 요청 가능. 종료 후 입력 불가 |
| 가이드·지식 (Q5·Q6) | F31~F33 | 가이드는 코드별 버전, 승인 후 게시, 게시 후 불변·코드당 게시 1건. 완료 요청에서 지식 문서 작성, 새 요청 때 같은 설비·증상의 지식·완료 기록 추천 |
| 완료 (Q3·Q7) | F41~F43 | 완료 기록(원인·조치·현장 확인) 1건 = 요청 종료, 불변. **REMOTE_FIXED** → 해결, **FIELD_VISIT** → CMMS가 `field_visit_requests()`를 읽어 작업지시(출처 RWS_REQUEST) 생성. 종료 후 요청자 만족도 1~5 |
| 분석 | F44 | 요청 수·응답/해결 시간·기한 준수율·원격 해결률·분야·전문가별·만족도 평균(조회) |

## 6. 교차 조회

**RWS가 제공**

| 함수 | 돌려주는 것 | 쓰는 곳 |
|---|---|---|
| `field_visit_requests()` | FIELD_VISIT 완료 요청(설비·증상·원인·조치) | **CMMS "RWS에서 가져오기"** → 작업지시(source = RWS_REQUEST) |
| `monthly_summary(month)` | 요청 수·원격 해결률·평균 해결 시간·기한 준수율·만족도 | EIP |
| `pending_tasks(hr_employee_code)` | 배정된 진행 요청·기한 초과 | EIP 할 일 |
| `lookup(code)` | 요청 번호 → RW-03 | EIP 통합 검색 |

**RWS가 읽음**: CMMS `work_order(no)`·`failure_codes()`·`assets()` · QMS `ncr(no)` · CRM `accounts()` · MES 품목·작업지시 · HR `employees()`.

> 넘길 것(DSN-90): **CMMS** — 작업지시 출처 RWS_REQUEST(목표 DB 반영), "RWS에서 가져오기", `work_order(no)`·`failure_codes()` 제공 · **QMS** — `ncr(no)` 제공 · **POP** — 변경 없음(호출은 POP 안에서만).

## 7. 결정 질문 (하나씩)

| # | 질문 | 제안 |
|---|---|---|
| Q1 | **RWS의 정의** — "현장이 혼자 해결 못할 때 원격 전문가가 텍스트·단계 체크리스트로 안내하고 결과를 기록"으로 한정한다. 영상·AR·사진 첨부는 없다(ROADMAP-01 §6-5 재확인) | 그대로 |
| Q2 | **요청 출처** — 직접 등록 + CMMS 작업지시·QMS 부적합에서 "원격 지원 요청"(RWS가 출처 솔루션 조회로 채우고 코드 스냅샷, 교차 쓰기 없음). **POP 호출은 가져오지 않는다**(POP Q4 "호출은 POP 안에서만"을 유지) | 그대로 |
| Q3 | **원격 해결 실패** — RWS는 "현장 출동 필요"로 닫고, CMMS가 `field_visit_requests()`를 읽어 "RWS에서 가져오기"로 작업지시를 만든다(RWS가 CMMS에 직접 쓰지 않음) | 그대로 |
| Q4 | **고객 현장 원격 A/S** — CRM 고객사·출하 LOT 대상 요청 포함(요청은 사내 담당자가 대신 등록, 고객사 코드 스냅샷). CRM 고객 문의와는 별개 | 포함 |
| Q5 | **작업 가이드 소유** — RWS가 가이드(단계·주의·확인 항목, 게시 후 불변·새 버전)를 소유한다. CMMS 점검표(PM 정기 점검)·PLM 문서(도면 메타데이터)와는 별개 | 그대로 |
| Q6 | **지식화** — 완료한 요청을 지식 문서로 남기고, 새 요청 때 같은 설비·증상의 해결 사례를 추천 | 포함 |
| Q7 | **운영 관리** — 응답·해결 목표 시간(긴급도별)·단계 상향·만족도 | 모두 포함 |
| Q8 | 범위 확정 — 포함 8 + Q 결과, 제외: 사진·영상 첨부, 실시간 영상·AR | 제안대로 |
