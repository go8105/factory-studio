# 3D 공장 시연 — 공통 설계 (FS-3D-AI01)

사용자 승인 범위: 비전검사 설비 AI 설명 버튼 + 정상/불합격 증가/정지 세 시나리오.

- 업무 모듈이 아닌 합성 공간 체험. 업무 테이블·FK·학습 과정/채점 없음.
- 서버·프런트 공통 기준: `backend/src/fs/factory/scenarios.json`. 고정 직전/최근 10분 구간과 현재 애니메이션 누계를 구분한다.
- 정상: 2/100 → 2/100, 불합격 증가: 2/100 → 20/100(18%p 상승), 정지: 2/100 → 1/50(비율 동일, 검사 수량 감소). 고정 시간 구간 자료이며 실제 센서 기록이 아니다.
- 상태 전환은 현재 시연 검사 주기를 초기화. 정상은 50개당 1개 불합격, 증가 상황은 5개당 1개. 정지는 검사 주기·이송·조명을 정지. 설명 요청과 장면 이동은 독립.
- POST `/api/v1/factory/vision/explanation`는 기존 인증·CSRF 적용, 요청은 scenario enum 한 개만. 서버가 계산한 근거 + AI 설명/준비된 데모를 응답한다. 임의 프롬프트·업무 범위 ID·사용자 수치 입력 없음.
- 서버의 `OPENAI_API_KEY`가 있을 때만 Responses API의 `gpt-6-astra` 호출. 키는 프런트에 전달하지 않는다. `store:false`, 구조화 응답, 제한 시간·최대 토큰 사용. 확인된 사실과 가능성을 구분하며 설비 제어 권한 없음.
- AI 미설정·응답 실패·처리 중일 때 출처가 표시된 준비된 데모 설명. AI라고 가장하지 않는다. 401/410은 기존 세션 만료 처리, 403은 권한 오류 표시.
- 출력은 React 텍스트로 렌더링한다. 시나리오 변경 시 이전 요청 취소·응답 폐기. 설정된 실제 계측이나 MES 정보가 있다는 주장을 하지 않는다.
- 공개 고정 자료이므로 성공 응답은 모델/프롬프트 버전/시나리오별 프로세스 메모리에 공유 캐시. 프로세스 기동당 성공 호출 최대 3회. 동시 유료 요청 1개, 실패 후 60초 대기. 여러 워커/재시작이면 각각 새 캐시이므로 운영 비용 한도는 별도 계정 설정 필요.
- DB 쓰기가 없는 설명 조회라 업무 멱등 영수증을 만들지 않는다. 반복 유료 호출은 유한 캐시로 억제한다.

## 합성 이미지 검사실 (FS-VISION-LAB01)

사용자 승인: 합성 시나리오만 구현, C++ OpenCV 엔진·C# 통신·실장비는 후속.
- `/factory/vision-lab`: 정상/이물/조명 변화의 결정론적 160×100 회색조 이미지. 실제 촬영·AI 생성 이미지가 아님.
- 검사 영역(전체/중앙), 임계값, 최소 연결 면적을 조절. 브라우저에서 임계값 이진화와 4방향 연결 영역 검사를 실행한다. OpenCV를 사용했다고 표시하지 않는다.
- 원본/이진화·검출 상자, OK/NG, 영역 수·px², 정답 마스크 대비 오검출/미검출 픽셀 표시. ROI 외 결함 픽셀은 별도 표시해 제외로 인한 OK를 설명한다. 산업 정확도/실측 mm를 주장하지 않는다.
- 버전이 있는 InspectionRequest/InspectionResult 인터페이스를 순수 함수로 분리. 레시피와 결과 JSON 다운로드 제공. 변경 즉시 재계산, DB·서버·외부 AI 연결 없음.
- 큰 독립 화면에서 체험하고 3D 공장으로 복귀. 기존 합성 운전 시나리오와 AI 설명 데이터는 변경하지 않는다.
