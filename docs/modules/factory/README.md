# 3D 공장 시연 — 공통 설계 (FS-3D-AI01)

## 현재 도움말 기준 · 2026-10-12

합성 탐색·CNC/비전/검사실·가상 PLC 시연 기준이며 실설비·센서 데이터가 아니다. 실행 C++/AI는 서버 설정에 의존한다. 웹 브라우저 검사는 실장비 안전/검사 정확도 검증을 대신하지 않는다. [제품 도움말 구현 대조](../../agent/제품도움말_구현대조_HELP-01.md).

사용자 승인 범위: 비전검사 설비 AI 설명 버튼 + 정상/불합격 증가/정지 세 시나리오.

- 업무 모듈이 아닌 합성 공간 체험. 업무 테이블·FK·학습 과정/채점 없음.
- 서버·프런트 공통 기준: `backend/src/fs/factory/scenarios.json`. 고정 직전/최근 10분 구간과 현재 애니메이션 누계를 구분한다.
- 정상: 2/100 → 2/100, 불합격 증가: 2/100 → 20/100(18%p 상승), 정지: 2/100 → 1/50(비율 동일, 검사 수량 감소). 고정 시간 구간 자료이며 실제 센서 기록이 아니다.
- 상태 전환은 현재 시연 검사 주기를 초기화. 정상은 50개당 1개 불합격, 증가 상황은 5개당 1개. 정지는 검사 주기·이송·조명을 정지. 설명 요청과 장면 이동은 독립.
- POST `/api/v1/factory/vision/explanation`는 기존 인증·CSRF 적용, 요청은 scenario enum 한 개만. 서버가 계산한 근거 + AI 설명/준비된 데모를 응답한다. 임의 프롬프트·업무 범위 ID·사용자 수치 입력 없음.
- 서버의 `OPENAI_API_KEY`가 있을 때만 Responses API의 `gpt-6-astra` 호출. 키는 프런트에 전달하지 않는다. `store:false`, 구조화 응답, 제한 시간·최대 토큰 사용. 확인된 사실과 가능성을 구분하며 설비 제어 권한 없음.
- AI 미설정·응답 실패·처리 중일 때 출처가 표시된 준비된 데모 설명. AI라고 가장하지 않는다. 401/410은 기존 세션 만료 처리, 403은 권한 오류 표시.
- 출력은 React 텍스트로 렌더링한다. 시나리오 변경 시 이전 요청 취소·응답 폐기. 설정된 실제 계측이나 MES 정보가 있다는 주장을 하지 않는다.
- 공개 고정 자료이므로 성공 응답은 모델/프롬프트 버전/시나리오별 프로세스 메모리에 공유 캐시. 프로세스 기동당 성공 호출 최대 3회. 동시 유료 요청 1개, 실패 후 60초 대기. 여러 워커/재시작이면 각각 새 캐시이므로 운영 비용 한도는 별도 계정 설정 필요.
- DB 쓰기가 없는 설명 조회라 업무 멱등 영수증을 만들지 않는다. 반복 유료 호출은 유한 캐시로 억제한다.

## 합성 이미지 검사실 (FS-VISION-LAB01)

사용자 승인: 합성 시나리오만 구현, C++ OpenCV 엔진·C# 통신·실장비는 후속.
- `/factory/vision-lab`: 정상/이물/조명 변화의 결정론적 160×100 회색조 이미지. 실제 촬영·AI 생성 이미지가 아님.
- 검사 영역(전체/중앙), 임계값, 최소 연결 면적을 조절. 브라우저에서 임계값 이진화와 4방향 연결 영역 검사를 실행한다. OpenCV를 사용했다고 표시하지 않는다.
- 원본/이진화·검출 상자, OK/NG, 영역 수·px², 정답 마스크 대비 오검출/미검출 픽셀 표시. ROI 외 결함 픽셀은 별도 표시해 제외로 인한 OK를 설명한다. 산업 정확도/실측 mm를 주장하지 않는다.
- 버전이 있는 InspectionRequest/InspectionResult 인터페이스를 순수 함수로 분리. 레시피와 결과 JSON 다운로드 제공. 변경 즉시 재계산, DB·서버·외부 AI 연결 없음.
- 큰 독립 화면에서 체험하고 3D 공장으로 복귀. 기존 합성 운전 시나리오와 AI 설명 데이터는 변경하지 않는다.

## 연속 검사 모드 (FS-VISION-RUN01)

사용자 확인한 후속 범위: 연속 검사만. PLC/C++/C#/배포는 별도 후속.
- 기존 3종을 정상·이물·정상·조명 순서로 5회 반복(20회). 서로 다른 20장의 영상으로 표현하지 않는다.
- 시작 시 레시피와 투입 간격(200/500ms)을 고정. 다음 배치는 설정 변경 반영. 새 배치는 이전 기록 교체, JSON으로 보존 가능.
- 한 번에 한 검사만 실행. 시작 간격은 최소 목표 간격이며 처리 지연 시 밀린 프레임을 몰아서 실행하지 않는다.
- 일시정지는 진행 중 결과까지 반영한 뒤 대기, 종료/새 배치/화면 이탈은 이전 응답 무효화. 숨겨진 탭과 설정 모드 전환은 일시정지.
- 실행 기록 v1이 기존 검사 요청/결과 v1을 감싼다. runId/inspectionId/순번/시각/레시피 스냅샷/알고리즘 실행 ms 포함. 브라우저 합성 검사 전용.
- 완료 수·OK·NG·합격률·시간·샘플별 NG 및 정답 대비 픽셀 오류. 장애는 NG로 집계하지 않는다. 0건 비율/시간은 미정.
- NG 선택 시 당시 요청/결과를 사용해 원본/이진화·영역·판정 조건 재조회. 기록 최대 20건, 메모리만 사용.
- 검증: 결정론적 20회 집계, 정지/재개/중복 시작/종료 후 늦은 응답/장애/언마운트, 레시피 고정·JSON, 데스크톱/모바일 브라우저.

## 가상 PLC 핸드셰이크 (FS-VISION-PLC01)

사용자 후속 진행 승인: 연속 검사에 선택형 가상 PLC 모드 추가. 브라우저 내부 모의 프로토콜이며 실제 PLC 통신/안전 인터락이 아니다.
- Ready → Trigger ON/Busy → 결과+Done(Busy OFF) → PLC 확인/Trigger OFF → Ready. 결과는 확인까지 래치, OK/NG 상호 배타적. Recipe_ID는 배치 고정 레시피를 뜻하는 RUN_SNAPSHOT.
- 검사 응답 제한 300ms, 확인 응답 제한 1000ms. 정상 응답에는 시각화용 80ms, 자동 확인에는 120ms 지연. 알고리즘 ms에 이 지연을 포함하지 않는다.
- 다음 검사 지연(450ms)/다음 결과 확인 누락, 수동 결과 확인, 중복 트리거 입력을 테스트한다. 주입은 1회 소비, 오류 후 잔여 배치는 중단.
- 오류는 Interlock ON/Ready OFF, 신규 트리거 차단. 타임아웃 이후 늦은 결과 폐기. 검사 타임아웃은 결과 없음, 확인 타임아웃은 당시 결과/Done 보존. 명시적 PLC 리셋 후 새 배치로 복구, 자동 재개 없음.
- 연속 검사 누계는 PLC 확인까지 완료된 거래만 반영. 확인 실패한 검사 결과는 PLC 패널에 보존하되 배치 OK/NG에는 더하지 않는다. 장애는 제품 NG가 아니다.
- 배치 종료·화면 이탈은 진행 거래 취소 및 타이머 해제, 오류 래치는 리셋 전 유지. 일시정지/탭 숨김은 진행 거래를 마무리하고 다음 투입 보류.
- 상태·신호 스냅샷/요청 ID/이벤트 로그(최근 200건) JSON 포함. 새 배치 시작 시 지난 로그 교체, 리셋은 로그 유지. 기존 검사 v1과 직접 실행 모드는 유지.

## C++ OpenCV 검사 코어 (FS-VISION-CORE01)

사용자 후속 진행 승인. 독립 C++17 라이브러리/CLI에서 기존 합성 요청 v1 또는 검사실 다운로드 {request,result}를 읽고 결과 v1을 출력한다. source만 synthetic-opencv-cpp-v1로 명시한다.
- 기존 결정론적 160×100 샘플 생성, `< threshold`, 4방향 연결, 연결 픽셀 수 `>= minArea`, ROI와 영역 밖 정답, 좌표/면적/순서를 웹과 동일하게 맞춘다. OpenCV compare + connectedComponentsWithStats(CCL_SAUF), contourArea 사용 안 함.
- stdin/파일 1개 JSON 또는 --ndjson(요청당 한 줄). 성공 stdout 결과 JSON/exit0, 잘못된 입력 오류 JSON/exit2. 입력 문서/줄 최대 64KiB. 빌드/진단은 JSON stdout에 섞지 않는다.
- CMake, OpenCV core/imgproc, nlohmann-json. 기본 설치 라이브러리 탐색, 선택형 고정 버전·해시 다운로드 빌드. 빌드 산출물은 work/에 둔다.
- 원본 TS 엔진을 직접 실행하는 비교 스크립트로 경계값·ROI·샘플 조합과 정답/오검출/미검출/제외 픽셀 일치를 검증한다. C++ 단위/CLI 오류 검증 포함.
- 웹/서버/PLC와 실행 연결, 실제 이미지 파일/카메라/실장비/C#·운영 배포는 이번 범위 밖이다.

## 웹 C++ 호출·사용자 참고 문서 (FS-VISION-CONNECT01)

사용자 요청: C++ 호출 연결과 도움말 집필, 운영 배포는 사용자가 직접 수행.
- 인증/CSRF POST `/api/v1/factory/vision/inspect`에 `{requestId,request}` 전달. 서버 환경 VISION_CORE_EXECUTABLE의 절대 경로만 shell 없이 실행. 클라이언트 경로/명령 입력 없음.
- C++ `--timed`는 `{result,inspectionMs}`를 반환하며 기본 CLI v1 출력은 유지. 서버 입력·출력 타입/범위/출처/판정 일관성 검증, 2초 제한, 동시 4개/프로세스, 출력 각 1MiB. 미설정/과부하/실패/초과 오류는 각각 503/429/502/504. 자동 대체 없음.
- 단건은 기존 브라우저 결과 아래 별도 C++ 검사·결과·JSON. 조건 변경/모드 이동/언마운트는 취소·늦은 결과 폐기. 연속 검사는 배치 시작 전 엔진 선택, 실행 중 잠금. PLC 내부 엔진도 동일 선택 사용, 취소/실패 시 HTTP abort.
- 처리 시간은 C++ 함수 내부 steady_clock, 통신/프로세스 기동/PLC 대기 제외. 브라우저는 3초 제한. 서버는 연결 취소 즉시 종료를 보장하지 않으나 2초 이내 제한하며 결과는 클라이언트에서 무효화.
- 도움말 `content/help/portal/vision-lab.md`: 사용자 참고 문서/포털 트리·검색·검사실 왕복, 설정/20회 배치/PLC 장애·복구/JSON/출처·한계·전체 흐름 설명.
- 실제 C++ 브라우저 검증은 모의 인증·실제 API/바이너리의 로컬 5187 테스트 서버 사용. 테스트 인증 우회는 tests/에만 두며 운영 앱에 포함하지 않음. 배포/push 없음.

## 로봇 연동 CNC 가공 셀 (FS-FACTORY-CNC01)

사용자 2단계 진행 요청 범위: 첫 설비를 로봇/CNC로 교체하고 한 소재의 정상 운전·정지·복구를 구현한다. [상태·화면·검증 계약](../../agent/로봇CNC가공셀_FS-FACTORY-CNC01.md).

- 단일 상태 머신이 패널과 소재·그리퍼·문·주축을 구동. 단계 순서는 기획 기준을 따른다. 시작당 한 개, 중복 시작과 중복 완료 차단.
- 주축은 모의 문 닫힘·고정·퇴피 조건에서만 가동. 오류 해제 후 명시적 재개. 중간 종료 소재는 별도 보류 수량.
- 탭 숨김 일시정지, 외관/전역 정지/그래픽 대기 진행 차단, 언마운트 정리. 상태는 메모리 전용.
- CNC 수량과 기존 비전 시연·C++·MES 실적·재고는 아직 연결하지 않는다. 실제 절삭 해석·안전 제어·실장비 연동 없음.
- CNC 패널에서 `/help/portal/cnc-cell` 사용자 참고 문서로 이동한다.

## WMS 트럭 도착 연결 (FS-026)

- `/factory`의 트럭 입고 패널에서 WMS 입고 예정을 선택한다. 외부 진입·정차 시연 후 WMS 도착 API의 성공을 확인한다. 애니메이션은 실제 GPS·배송 추적이 아니다.
- 트럭 도착은 재고를 변경하지 않는다. W-08에서 합격·격리·부족 검수를 확정해야 원장을 만든다. CNC 합성 소재와 WMS 품목/수량은 자동 연결하지 않는다.
- 시연 중 선택 잠금, 일시정지/숨김/화면 이탈 정리, 통신 실패 재조회/재시도, 서버 도착 상태 복원. 선택한 예정의 품목과 기본단위 수량을 표시한다.
- 업무 데이터는 기존 인증·공간/세대 범위의 WMS API로만 조회/변경한다. 3D 전용 재고나 별도 DB 테이블은 만들지 않는다.
- 사용자 참고 문서 `/help/portal/wms-flow`, [통합 구현·검증 기록](../../agent/WMS확장_화면트럭통합_FS-026.md).
