# DSN-28 EIP 통합 정보 포털 설계 (신규)

작성: 2026-10-05 (Claude Code) · 상태: **1단계 — 기준표·결정 질문(범위 확인 대기)**. 3~6장은 범위 확정 뒤.
양식: [DSN-00](../../plan/기능기준표_DSN-00.md) · 방침: [ROADMAP-02](../../plan/전체설계우선_전환_ROADMAP-02.md) · 로드맵: [ROADMAP-01 §6-3](../../plan/로드맵_17개시스템_ROADMAP-01.md)(EIP = 전사 요약 대시보드·공지, GW = 전자결재·게시판, 포털 = 인증·앱 런처)
입력: 각 솔루션 설계 6장의 **`monthly_summary(month)`**(ERP·FEMS·BEMS·SPC·CMMS·POP·TMS·PLM·CRM·SCM·ELB 등).

---

## 0. EIP의 자리 — 포털·GW와 무엇이 다른가

| 영역 | 소유 | EIP와의 관계 |
|---|---|---|
| 로그인·앱 런처·흐름 맵·휴일 달력 | **포털(core)** | EIP는 런처 안의 한 솔루션 |
| 전자결재·게시판(**공지 포함**, 운영 중) | **GW** | 공지를 EIP가 다시 만들면 두 벌 → **GW 공지를 읽어 표시**(Q1) |
| 전사 요약·KPI·목표 대비·할 일 모음·경영 보고 | **EIP** | 이 문서 |
| 각 지표의 원천 값 | 각 솔루션 | EIP는 `monthly_summary` 등 조회로만 읽는다(저장은 확정 보고서 스냅샷만) |

로드맵 §6-3의 "EIP 공지"는 GW 공지 게시판이 이미 운영 중이라 **표시로 바꾸는 것**을 Q1에서 묻는다.

## 7. 결정 질문 (하나씩)

| # | 질문 | 제안 |
|---|---|---|
| Q1 | **공지** — GW 공지 게시판(운영 중)을 EIP가 읽어 표시하고, EIP 자체 공지·배너는 두지 않는다(로드맵 §6-3의 "EIP 공지"를 "GW 공지 표시"로 바꿈) | 그대로 |
| Q2 | **KPI** — KPI 정의(코드·이름·출처 솔루션·요약 지표 키·단위·좋은 방향)와 월 목표를 EIP 테이블로(시드 16개 정도), 실적은 각 솔루션 `monthly_summary`에서 읽어 비교 | 그대로 |
| Q3 | **할 일 모음 단위** — (a) 공간 전체 건수(체험 공간 하나 = 회사 하나, 솔루션마다 사람 개념이 달라 "나"를 묶기 어렵다) (b) 사람별(솔루션마다 사람 코드 연결 필요) | **(a)** 공간 단위 건수 + 바로가기 |
| Q4 | **월간 경영 보고서·경영 의견** 포함(확정 스냅샷, 재작성은 새 버전) | 포함 |
| Q5 | **위젯 배치 개인화** — 제외하고 고정 배치(FS-008b에서 core 대시보드 배치를 없앤 결정과 맞춤) | 제외 |
| Q6 | **통합 번호 검색** — 각 솔루션이 `lookup(code)`(번호 → 대상 종류·화면 경로)를 제공해야 한다. 포함하면 18개 솔루션 모두에 조회 함수 1개씩 추가 | 포함(조회 함수 1개씩, 개발 때 함께) |
| Q7 | 범위 확정 — 포함 9 + Q 결과, 제외: 외부 BI 연동(+ Q5 위젯 개인화) | 제안대로 |
