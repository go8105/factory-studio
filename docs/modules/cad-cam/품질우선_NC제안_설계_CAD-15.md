# CAD-15 품질 우선 NC 검토 제안 계약

2026-10-08. 사용자 CAD-10 권장안 및 CAD-14 결과 확인 후 다음 진행 승인. 이번은 CAD-15 한 ID. 기존 공통 설계/NC·소재·시간 모델을 재사용하며 CAD-16/17·DB·운영 배포는 제외한다.

## 의도와 제약

품질1·소비2. 외부 NC의 정삭/열/칩 배출 의도와 실제 공차/Ra는 추론하지 않는다. 원본·절삭/급속 경로·F/S/T·쿨런트·주축/교환/종료 순서는 보존한다. 초기 제안은 **모달 변화 없는 단독 G4 대기**의 사용자 확인된 최소 유지 시간에 대한 시나리오다. 검토용 비교만 제공하고 NC 편집/자동 적용/장비 실행 파일 출력은 제공하지 않는다. [LinuxCNC G4](https://linuxcnc.org/docs/html/gcode/g-code.html#gcode:g4)는 P초 동안 축이 움직이지 않고 주축/쿨런트는 유지하는 명령이다. 대기 축 정지는 공정상 안전/품질 보증이 아니다.

## 입력/판정

1. 완전 해석 NC·동일 SHA-256 소재 결과·현재 CAD-14 전체 시간/kWh 계산 필수. 부분/미정 합계·급속 소재 접촉은 비교 차단.
2. 사용자 품질 기준/근거와 허용 최대 잔삭 높이·과절삭 깊이(mm), 목표 STEP 격자 체적 오차(%) 상한을 빈칸 없이 입력한다. 결과가 상한을 초과하면 모든 후보 차단한다. 이 수치는 셀 중심 근사 형상 기준이며 실제 공차/Ra 판정이 아니다.
3. 최대12개 대기를 사용자가 선택한다. 각 행의 공정 목적/최소 시간 근거·최소 유지 초와 열/냉각/칩/정삭 영향 검토 확인이 필요하다. 최소시간은0 이상 원래 시간 이하. 미선택은 그대로 보존. 0초 삭제 가정도 명시 확인 없이는 산정하지 않는다. 개별 후보 및 확인된 전체 조합 후보를 비교한다. 같은 행 중복 입력과 설정 변화 혼합 대기는 거부한다.
4. 남은 실기계·홀더/지그·공정 위험을 별도로 검토했다는 사용자 확인이 필요하다. UI는 ‘사용자 조건 충족 / 실제 품질·안전 미검증’으로 표시한다. 품질 가정 미확인 후보를 에너지 순위로 추천하지 않는다.
5. 후보 소비는 CAD-14와 동일 전체 장비 전력 범위·불변 구간 + 확인된 대기 시간으로 독립 합산한다. 기준 모델은 변경하지 않는다. 같은 상태 전력을 재사용하는 가정과 대기 전체 평균 kW 일정 가정을 명시한다. 예상 시간 차이·소비 범위·대기에서 줄어드는 에너지 범위를 표시한다.
6. 추가 비교 여유(kWh)는 빈칸 미정이며 사용자가 근거와 함께0 이상 입력한다. 후보 최대 + 추가 여유 < 원본 최소일 때만 ‘입력 범위에서 소비 감소 후보’로 분류한다. 범위 겹침·경계 같음·추가 여유 미정이면 ‘우열 판단 불가’. 이는 통계적 불확실성/절감 보증이 아니며 실측 정확도로 승격하지 않는다. 에너지 후보 간 범위가 겹치면 단일 최적 후보를 선언하지 않는다.

## 화면/이력/검증

에너지 분석 완료 → 대기 목록 생성(미확인 기본) → 품질/비교 여유·행 근거 입력 → 시나리오 비교. 대기가 없거나 혼합 상태만 있으면 이유를 표시한다. 목적이 불명인 비절삭/보조 소비는 별도 안내로 남기며 자동 최적화하지 않는다. 행 선택은 원본 코드/경로에 연결한다. 표/근거/차단 이유·원문 해시·입력·비교 결과는 분석 JSON에 포함, 고객 파일/기록은 메모리만·서버 전송 없음.

NC·소재·장비·상태 전력·품질 입력 변경은 제안 결과 무효화. 에너지 변경은 행 목록/검토 근거도 새로 준비하도록 한다. 대기 목록200행 페이지·선택12개·비교13후보 상한. 검증은 독립 kWh 합계/원본 불변·품질/미정/근거 차단·범위겹침/경계·목록/선택 상한·실제 UI 행 연결/무효화/모바일과 합성 예제. 실 장비/공정/정확도·NC 다운로드 재열기/운영 배포는 미검증으로 남긴다.
