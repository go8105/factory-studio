# CAD-V01 · Hey Hugh-D NC 에너지 음성 발표 데모 제안

2026-10-08 사용자 답변 반영. 발표 PC는 **Windows**, **일반 브라우저(내장 브라우저 아님)**, 대상은 **NC 에너지 개선 제안**으로 확정했다. 이전 Mac/E1 제안은 이 문서로 대체한다. 발표 브라우저는 **Google Chrome**으로 확정했다. 아래는 구현할 전체 흐름의 제안이며 음성/후보 자동 재생 **구현 미착수**다. CAD-17을 자동 착수하지 않는다.

## 기획 의도 검토

진입은 `/cad-cam?view=nc`. 사용자가 NC 파일과 소재/STEP·공구/좌표·장비·품질 기준을 준비하고 현재 분석을 완료한다. 발표자는 음성 켜기/마이크 허용 후 다음을 말한다.

1. **“헤이 휴디 / Hey Hugh-D”** → 휴디 패널이 활성화되고 “네, 무엇을 도와드릴까요?”라고 응답.
2. **“현재 가공 시뮬레이션에서 최적안 제안해줘”** → 현재 NC의 품질 조건을 먼저 확인하고 에너지 시나리오를 비교, 번호가 붙은 후보·시간/kWh 범위·감소량·근거/판정 표시.
3. **“2번으로 가공 실행해줘”** → 현재 표시된2번을 검토 시나리오로 선택하고, **예상 시간·소비 비교와 해당 시간 모델에 따른 NC 경로 재생** 시작. 화면에 ‘시나리오 재생’과 후보 번호를 표시한다.
4. **“시뮬레이션 멈춰”** → 현재 위치에서 일시정지. “마이크 꺼”는 음성 대기를 종료.

기계 동작·NC 파일 실행/수정/출력으로 연결하지 않는다. 발표 문장은 “2번 시나리오로 시뮬레이션 실행해줘”를 제안한다.

## 현재 구현과 새로 필요한 것

| 항목 | 현재 상태 | CAD-V01 제안 |
|---|---|---|
| 품질 우선 NC 에너지 비교 | CAD-15 구현 | 기존 `compareProposals`와 입력/차단 기준 재사용 |
| 개선 범위 | 확인된 단독 G4 대기의 최소 유지 시간 | 범위 유지; 경로 재배열/F·S 최적화로 소개하지 않음 |
| 후보 | 최대12개 대기 개별+조합, 최대13후보 | 현재 표시 순서의1~13번호·안정적인 후보 ID·입력 revision 부여 |
| NC 경로 표시 | 원본 행·3D 경로 구간 선택 | 후보 선택·시간 모델 기반 자동 재생/정지/진행률 추가 |
| 음성/호출어 | 없음 | 브라우저 한국어 인식·호출어/명령 상태·응답 음성 추가 |

확인 코드: `src/nc-review.js`, `nc-proposal-review.js`, `nc-proposals.js`, `nc-viewer.js`. 현재 카드에는 번호 선택/재생 핸들러가 없으므로 버튼 이름만 음성으로 누르는 연결로 완료할 수 없다.

## 예상 문제점·제약

- SpeechRecognition은 지원이 제한된다. 확정된 Windows Google Chrome에서 한국어 인식·마이크·네트워크를 실증해야 한다. 현재 작업용 Mac/내장 브라우저 시험을 Windows 실음성 성공으로 기록하지 않는다. [MDN SpeechRecognition](https://developer.mozilla.org/en-US/docs/Web/API/SpeechRecognition).
- `continuous`는 OS 수준 항상 호출어 대기/백그라운드 동작 보장이 아니다. 사용자가 마이크를 시작하고 열린 페이지에서만 대기한다. 권한 거절/네트워크/서비스 종료는 표시하고 무한 재시도하지 않는다. [MDN continuous](https://developer.mozilla.org/en-US/docs/Web/API/SpeechRecognition/continuous).
- 호출어는 이번 데모에서 인식 문장의 “헤이 휴디 / hey hugh d” 일치로 감지한다. 전용 오프라인 호출어 모델이나 한국어 로컬 인식팩 지원을 실증한 것으로 주장하지 않는다. [MDN processLocally](https://developer.mozilla.org/en-US/docs/Web/API/SpeechRecognition/processLocally).
- 브라우저 음성 서비스가 원격 처리할 수 있다. 시작 UI에 이를 알리고 녹음/인식문장은 Git·DB·localStorage에 저장하지 않는다. NC 원문/품질 근거/고객 파일을 음성 서비스나 별도 LLM에 보내지 않는다. 화면 발화/마지막 명령은 메모리만 사용한다.
- 현재 에너지 제안은 [CAD-15](품질우선_NC제안_설계_CAD-15.md)의 품질/공정 근거와 전체 분석이 필수다. 음성이 확인 체크를 대신하거나 대기 목적·최소 유지 시간을 임의 입력하지 않는다. 범위 겹침/추가 여유 미정은 ‘우열 판단 불가’, 조건 부족은 ‘제안 차단’으로 응답한다. 유일한 최적안이 없는데 자동1등을 만들지 않는다.
- 품질 검토를 통과한 후보가 실제 에너지 감소를 보증하지 않는다. 후보 경로는 원본과 같고 확인된 G4 시간만 바뀐다. 형상 제거 결과는 동일하며, 재생에서 대기시간·누적시간/kWh 차이를 보여준다. 가공 순서를 바꾸는 연출은 하지 않는다.
- 인식 중복/잘못된 번호/계산 대기/입력 변경/TTS 자기 음성 재인식은 완료 발화 실행·중복 차단·응답 중 인식 중단·호출 후30초 명령 창·현재 후보/입력 revision 확인으로 방지한다.

## 질문과 확정 사항

- **확정:** Windows PC, Google Chrome 일반 브라우저, NC 에너지 제안. Mac/E1을 다시 묻거나 기본 대상으로 사용하지 않는다.
- **검토할 전체 흐름:** NC 후보 번호 선택·시간/에너지 재생과 음성 제어를 함께 구현하는 CAD-V01 범위.
- 확정된 발표 환경에서, NC 후보 자동 재생을 포함한 위 전체 흐름을 구현 대상으로 제시한다. 음성 인식 성공은 실제 Windows 발화 리허설 전에는 미검증이다.

## 권장안과 구현 계약 제안

- 한 ID CAD-V01: **NC 후보 선택·시간/에너지 경로 재생 + 음성 제어**를 함께 구현한다. E1과 관리자 비누 기능을 변경하지 않는다. 브라우저 Web Speech 우선, 추가 유료 API/서버 STT·키/DB 변경 없음. 실제 인식 실패 시 원인을 확인한 후 별도 STT 방식 재제안.
- 음성 상태: 꺼짐 → 호출 대기 → 응답 → 명령 듣기 → 제안 계산 → 후보 준비 → 시나리오 재생. 마이크 종료/탭 비활성화/페이지 이동 시 인식 중단. 재생 중에도 별도 정지 버튼 제공.
- 명령 파서/상태 머신/NC 검토 명령 API를 분리한다. 기존 비교 로직은 버튼과 음성이 공유한다. 제안 입력이 준비되지 않았으면 필요한 항목을 안내하며 자동으로 합성/확인 값을 채우지 않는다.
- 번호는 현재 report의 표시 순서에 고정한다. 후보 스냅샷에 NC/소재/STEP/장비/품질의 revision과 근거를 연결한다. 입력 변경 시 선택·번호·재생을 즉시 무효화한다. 없는 번호/차단된 후보/과거 번호는 실행하지 않는다. 우열 판단 불가 후보는 그 판정을 표시한 검토 재생만 허용하며 권장 최적안으로 승격하지 않는다.
- 재생 타임라인: CAD-14 상태 행의 이동/이벤트 시간은 유지, 해당 후보의 G4만 확인된 제안 초로 대체한다. 진행률·현재 행·공구 위치·원본/후보 총시간·누적 kWh 범위 표시. 대기/주축/교환 이벤트에는 실제 축 이동을 꾸며내지 않는다. 이동은 검토용 보간이며 실기계 look-ahead/실측 정확도는 아니다.
- 발표 예제: 합성 대기 검토 NC와 장비/품질 기준을 **명시적 발표 예제 버튼**으로 준비한다. 실제 고객 NC 입력을 덮어쓰거나 합성 기준을 자동 검토 완료로 적용하지 않는다. 최소2개 확인된 대기를 갖는 합성 파일로2번 후보 시연이 가능하도록 한다. 실제 데이터가 없는 예시는 항상 합성 표시.
- 실패 대비로 버튼과 명시적인 텍스트 명령 테스트 입력을 제공한다. 텍스트 테스트를 실제 음성 성공으로 표시하지 않는다. 후보 소비 범위를 서로 비교해 개선 순위가 판정되지 않는 예제도 확인한다.
- 완료 조건: 후보 시간/kWh 합계·원본 불변·번호/revision·정지/취소·중복/오인식/권한 거절·미정/품질 차단 회귀시험, 실제 후보 선택/원본 대비 재생/PC·모바일 UI, 전체 테스트/build·비누 자산 격리, Windows 브라우저 호출→제안→2번→정지 실발화 리허설. Windows 실음성 미실행은 별도 명시한다.

발표용 문장: “헤이 휴디” → “현재 NC의 에너지 최적안 제안해줘” → “2번 시나리오로 시뮬레이션 실행해줘” → “시뮬레이션 멈춰”.
