# CAD-V01 · Hey Hugh-D 음성 발표 데모 제안

2026-10-08 사용자 추가 요청. CAD-16 완료와 별도로 기획을 검토한 제안이며 **음성 구현 미착수**다. CAD-17 검증 범위를 자동으로 음성 개발로 바꾸지 않는다. 발표 브라우저와 제어 대상은 사용자에게 질문 중이다.

## 기획 의도 검토

발표자가 마이크를 켠 뒤 “Hey Hugh-D / 헤이 휴디”라고 부르면 응답 상태로 전환한다. “현재 가공 시뮬레이션에서 최적안 제안해줘” → 기존 E1의 품질 우선 경로 제안 계산 → 번호가 붙은 실제 후보 표시 → “2번으로 가공 실행해줘” → 현재 2번 후보 적용·소재 제거 시뮬레이션 재생. “멈춰 / 정지”는 재생 일시정지. CNC 장비나 NC 파일 실행 기능이 아니다.

현재 후보는 2개(원래 방문 순서/가까운 방문 순서)이며 절삭·마무리·깊이/안전 조건을 보존한다. 장비 정보가 없으면 이동거리/이송 시간만 말하고 실제 소비 kWh 절감으로 소개하지 않는다. 품질 기준을 통과한 후보끼리 소비/비절삭 효율을 비교하는 기존 정책을 유지한다.

## 예상 문제점·제약

- 웹 SpeechRecognition은 브라우저 지원이 제한된다. 생성자가 있다는 것만으로 실제 인식 성공을 뜻하지 않는다. **발표에 사용할 Chrome·한국어·마이크·네트워크에서 실음성 시험이 먼저**다. 내장 브라우저/Chromium 파생 제품은 Chrome과 동등한 음성 서비스가 있다고 가정하지 않는다. [MDN SpeechRecognition](https://developer.mozilla.org/en-US/docs/Web/API/SpeechRecognition).
- 지속 인식은 `continuous` 설정이지 OS 수준 항상 호출어 대기/백그라운드 동작 보장이 아니다. 사용자가 마이크를 시작하고 페이지를 연 상태에서만 데모한다. 자동 종료·권한 거절·네트워크 오류는 화면에 표시하고 무한 재시도하지 않는다. [MDN continuous](https://developer.mozilla.org/en-US/docs/Web/API/SpeechRecognition/continuous).
- 호출어는 이번 데모에서 인식된 문장의 “헤이 휴디 / hey hugh d” 일치로 감지한다. 별도 오프라인 호출어 엔진/전용 음성 모델을 만든 것으로 발표하지 않는다. 한국어 로컬 음성팩 설치·지원 여부를 실증하기 전 `processLocally`를 사용한 완전 오프라인을 약속하지 않는다. [MDN processLocally](https://developer.mozilla.org/en-US/docs/Web/API/SpeechRecognition/processLocally), [Web Speech on-device explainer](https://github.com/WebAudio/web-speech-api/blob/main/explainers/on-device-speech-recognition.md).
- 브라우저 음성 서비스가 원격 처리할 수 있다. 마이크 시작 UI에 이를 안내하며 음성/문장 기록은 Git·DB·localStorage에 저장하지 않는다. 발화 인식 상태와 마지막 명령은 화면/메모리에서만 표시한다. 이 안내는 서비스를 선택하는 데 필요한 정보다.
- 발표장 소음·발음·TTS의 자기 음성 재인식·인식 결과 중복·계산 대기·후보 변경으로 틀린 번호 실행이 가능하다. 완료 발화만 실행, 중복 차단, 응답 중 인식 중단, 호출 후30초 명령 창, 현재 후보/설계/공구 revision 재검증, 1개 실행 큐가 필요하다.

## 질문

1. 발표 환경은 Mac Chrome / Codex 내장 브라우저 / 다른 PC 중 어디인가?
2. 제어 대상은 E1 경로 후보 적용+소재 제거 재생인가, NC 에너지 제안인가?

미답이면 구현 제안의 기본은 **Mac Chrome + E1 웹 시뮬레이션**이며, 실제 음성 지원/품질은 미검증이다.

## 권장안과 구현 계약 제안

- 모듈 공통 설계 추가 후 한 작업 ID CAD-V01로 구현한다. 브라우저 Web Speech 우선(유료 API/서버 음성 엔드포인트·키/DB 변경 없음). 한국어 서비스가 실제로 실패하면 원인을 먼저 실증해 별도 STT 방식을 다시 제안한다.
- 화면: `휴디 음성 켜기` → 브라우저 마이크 허용 → `호출 대기` → 호출어 감지/“네, 무엇을 도와드릴까요?” → `명령 듣기` → `경로 계산 중` → `1번·2번 후보` → “2번 실행” → `2번 시뮬레이션 재생 중`. 마이크 끄기·정지 버튼을 항상 제공한다.
- 상태 머신과 명령 파서를 분리한다. 자유 대화 LLM이 버튼을 임의로 클릭하게 하지 않는다. 허용 명령: 호출/현재 경로 제안/유효 후보1·2 실행/시뮬레이션 정지/마이크 종료. 미인식은 실행 없이 예문을 안내한다.
- 미확정 스케치/전문 창 편집 중에는 제안/후보 적용을 차단한다. 계산 중의 번호, 없는 번호, 무효 후보, 입력이 바뀐 후보는 실행하지 않는다. “2번”은 현재 표시 순서와 후보 ID를 묶어 해석한다. 새 계산은 이전 번호를 무효화한다.
- 클릭 버튼과 음성은 같은 기존 제안/적용/재생 핸들러를 공유한다. 공개 E1에만 연결하고 관리자 비누 화면을 확장하지 않는다. iframe 마이크 정책/HTTPS 또는 localhost/권한은 실제 발표 환경에서 검증한다.
- 실패 대비로 같은 버튼과 **명시적인 텍스트 명령 테스트 입력**을 제공한다. 텍스트를 실제 음성 성공으로 보여주지 않는다. 발표 전 실제 음성 인식으로 호출→제안→2번→정지를 반복 리허설한다.
- 완료 조건: 순수 명령/상태 회귀시험, 실제 마이크(사용자 발화 또는 동석 리허설) 결과, 중복/잘못된 번호/계산 중/미확정 편집/후보 무효화/권한 거절/탭 비활성화/자기 음성 차단, PC/모바일 UI, 기존 CAD/비누 자산 격리. 실음성 미실행이면 그 사실을 별도로 남긴다.

발표용 권장 문장: “헤이 휴디” → “현재 가공 시뮬레이션의 최적 경로 제안해줘” → “2번으로 시뮬레이션 실행해줘” → “시뮬레이션 멈춰”.
