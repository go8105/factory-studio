# CAD-10 NC 분석·에너지 예측·설계 편집 고도화 분석

2026-10-07. 사용자 조사/분석 요청에 따른 제안 문서. **제품 구현·새 라이브러리 설치·DB 변경·NC 생성·실기계 시험은 이번에 하지 않는다.** CAD-09의 품질1·소비 에너지2 순위를 이어간다. 장비/컨트롤러와 실측 가능 여부는 미정이다. 기존 CNC 우선·비누 심화 후속·사진 없이 파일명/기록 원칙을 유지한다.

## 기획 의도 검토

목표는 ① CNC 프로그램과 CAD를 불러와 경로·가공 결과를 이해하고 소비 에너지를 예측/비교하는 작업실, ② 그리는 중 실수와 치수/피처 변경을 편하게 복구하는 CAD 편집기다. 두 입력을 같은 화면에 겹쳐 보이되 의미와 원본은 분리해야 한다.

**NC는 기계 명령이다. NC 단독으로 원래 스케치·구속·돌출 이력·설계 의도를 일반적으로 복원할 수 없다는 것이 이 분석의 결론이다.** 공구 경로는 해석할 수 있고, 소재·공구·좌표계가 있으면 가공 후 형상을 근사할 수 있다. 설계 목표 형상을 비교하려면 별도의 CAD 모델이 필요하다. [LinuxCNC 명령 명세](https://linuxcnc.org/docs/html/gcode/g-code.html), [Autodesk 제조 시뮬레이션 구성](https://help.autodesk.com/view/fusion360/ENU/?contextId=MFG-REF-SIMULATION)을 근거로 제품 경계를 정했다.

NC 행의 제안 순서는 **최우선: 한 컨트롤러 프로필의 3축 밀링 부분집합**이다. 나머지는 표에 명시된 단계다. [replicad Import API](https://replicad.pages.dev/docs/api/)와 설치된 타입 선언에서 STEP 가져오기 존재를 확인했지만 실제 외부 파일 호환성을 보증하지 않는다.

## 예상 문제점/제약

### NC는 좌표를 정규식으로 읽는 것만으로 충분하지 않다

단위·절대/증분·활성 평면·원호 중심 모드·이송 모드·작업 원점·공구 보정·주축 상태를 이어서 해석해야 한다. 축 생략은 이전 상태를 따른다. G1은 소재에 닿지 않는 이송일 수도 있으므로 ‘G1 = 절삭’으로 에너지를 분류하면 안 된다. [LinuxCNC 명세](https://linuxcnc.org/docs/html/gcode/g-code.html).

초기 제안은 XYZ·G0/G1·G17 XY 원호 G2/G3(I/J 및 R)·G20/21·G90/91·G91.1·G94·G4·F/S/T·M3/4/5·M6·M7/8/9·M2/30, 선택한 G54와 입력된 설정이다. G40/G49/G80의 취소 상태도 처리한다. 원호 전체 원/반원·R부호·단위 변환·모달 생략 시험이 필요하다. 헬릭스·G18/19는 별도 해석 시험 뒤 확장한다.

G43/H·G41/42/D, G53/G28, 다른 작업 좌표, 고정 사이클·매크로·G93/G95·사용자 M코드 등은 초기 미지원으로 **행 번호와 이유를 표시하고 완전 해석/전체 시간·kWh 제안을 막는다.** 관성적으로 무시하고 다음 좌표를 정상 경로처럼 연결하면 안 된다. G04 P의 시간 단위와 M코드 의미도 컨트롤러 프로필로 정한다. 실제 NC에서 빈도가 높은 G43·G28·G81 계열은 두 번째 컨트롤러 단계의 우선 대상이다. 일부 성공 구간은 ‘부분 해석’으로만 표시한다.

NC에 없는 시작 XYZ/원점 보정·장비 좌표·공구 길이/직경을 0이나 주석 추측으로 확정하지 않는다. 프로필에 명시된 기본 모드와 사용자가 제공한 초기 설정을 구분한다. M0/M1의 작업자 대기는 조건/시간 없으면 미정이며 M1 실행 여부도 설정이다.

G0의 실제 축 이동 형태도 장비에 따라 다르다. Haas는 각 축의 동시 종료가 보장되지 않는 급속을 설명한다. 따라서 XYZ 끝점을 직선으로 이은 뷰어를 실기계 충돌 검증으로 표시할 수 없다. [Haas G00](https://www.haascnc.com/service/codes-settings.type%3Dgcode.machine%3Dmill.value%3DG00.html).

### 현재 높이장 시뮬레이터의 적용 경계

단일 상면·평 엔드밀과 좌표 정합을 검증한 작업은 기존 소재 제거를 재사용할 수 있다. 임의 NC를 E1 모델로 변환해서 실행하면 안 된다. 여러 공구의 직경/형상·측면/언더컷·회전축·홀더/고정구는 별도 제거/충돌 표현이 필요하다. 목표 STEP/STL 겹쳐보기와 정확한 과절삭/잔삭 비교는 다른 완료 기준이다.

초기 ‘NC 검토’ 화면은 코드/경로/상태부터 제공하고, 제거 지원 조건 충족 때만 제거 화면을 연다. 그 외는 경로 조회 전용으로 표시한다. 수직 공구의 볼/불 엔드밀과 일반 3축은 높이장 확장 또는 voxel/SDF 실증이 필요하며 기존 shader/격자에 UI만 추가해서 해결되지 않는다.

### 소비 에너지 예측의 신뢰 수준

| 수준 | 필요한 입력 | 보여줄 결과 |
|---|---|---|
| 정보 부족 | NC만·장비/초기 좌표 미정 | 해석 가능한 명령/경로. 전체 시간·kWh는 산정 불가 또는 명시된 부분 결과 |
| 입력 가정 모델 | 장비 이동 속도/가속·상태별 전력·이벤트 시간, 소재/공구/제거 또는 절삭 전력 근거 | 가정에 따른 시간·kWh 시나리오/범위. 검증 정확도% 없음 |
| 장비 실측 보정 | 해당 장비의 시간 동기 전력·공정 데이터·도구/소재 조건 | 보정된 예상 범위·검증셋 오차·보정 날짜/범위 |

**명판 정격kW × 전체 시간으로 소비 에너지를 확정하지 않는다.** 주축 ON 무부하·실제 절삭·축 이동·쿨런트·대기·교환·가감속을 구분한다. NIST 연구는 기계/환경 불확실성과 장비 데이터 기반 보정을 다루며, 특정 장비의 모델을 모든 CNC에 일반화하지 않는다. [NIST 연구](https://www.nist.gov/publications/towards-generalized-energy-prediction-model-machine-tools).

제안 계산 경계는 장비 전체 전기다. `E_kWh = Σ(P_segment_kW × Δt_seconds / 3600)`. 상태 모델은 `P_base + P_spindle_no_load(rpm) + P_axis(v,a) + P_aux + P_cut/η`로 나누되, base 측정에 이미 포함된 펌프/축 소비를 중복 합산하지 않는다. 상태별 **전체 장비 전력 측정 모델**과 **분해 모델** 중 하나를 택해 사용한다.

절삭 항의 초기 물리식 `Pc = ae × ap × vf × kc / (60 × 10^6)` kW는 순 절삭 동력이다. ae/ap/vf/kc의 단위와 실제 접촉·소재 조건을 입력해야 하며, 선삭·탭 가공에 밀링 식을 그대로 쓰지 않는다. [Sandvik 공식](https://cdn.sandvik.coromant.com/files/sitecollectiondocuments/services/metal-cutting-e-learning/formulas-and-definitions/formulas-and-deinitions-for-milling-metric-enu.pdf).

선분 길이/F는 등속 시간일 뿐이다. 축별 속도/가속·블렌딩·주축 가속·교환/정지 이벤트가 필요하다. 초기 독립 구간 가감속 가정은 명시하고 컨트롤러 look-ahead 재현으로 부르지 않는다. 계측 없이 ‘오차±5%’ 같은 숫자를 정하지 않는다. 시나리오 범위와 통계적 신뢰구간을 구분한다.

### 품질 우선 제안의 범위

CAD-09는 우리가 만든 래스터/정삭 단계의 의도를 알고 순서를 비교한다. 외부 NC는 같은 구간이 황삭/정삭/스프링패스/칩 배출인지 알 수 없으므로 **기존 래스터 순서 변경기를 그대로 적용하지 않는다.**

초기 NC 제안은 근거 있는 비절삭/대기/보조 소비 구간의 ‘검토 후보’와 에너지 시나리오다. G04 대기는 공정 목적이 있을 수 있고, 쿨런트/주축 정지는 공구/열/재시동 영향이 있으므로 자동 삭제/정지하지 않는다. 소재 접촉을 입증한 뒤에만 공중 이송 개선을 검토한다. 최종 정삭과 접촉 구간은 초기 제안에서 유지한다.

후속 이송 최적화는 목표 공차/Ra·칩 두께·절삭력·공구 처짐·주축/장비 부하·허용 가감속과 제조사 절삭조건이 있어야 한다. VERICUT 문서도 칩 두께/힘/동력/처짐 등의 제한과 소재·장비·공구 설정을 다룬다. 이는 방향의 참고이며 동일 알고리즘/성능이나 전력 절감 보장은 아니다. [VERICUT Optimize Control](https://help.vericut.com/4_vericut_help/90.01_optimize_control_window).

판정은 **해석 완전성/안전 → 목표 품질 조건 → 예상kWh** 순이다. 목표 품질/전력 모델이 없으면 해당 제안 수준을 낮추고 이유를 표시한다. 개선량이 예측 불확실성보다 작으면 ‘우열 판단 불가’로 처리한다. 실제 NC 재출력은 컨트롤러/post 검증·재해석 비교·실장비 절차를 갖춘 별도 단계다.

### 편집 도구는 원본 데이터 구조부터 확장

E1 단일 닫힌 프로파일에서 단순 자르기를 하면 열린 윤곽·영역 분할·구속 참조가 깨진다. 선/원호 엔티티 ID, 여러 와이어·영역/섬, 구속 연결을 먼저 설계해야 한다. [Fusion Trim/Extend 안내](https://help.autodesk.com/cloudhelp/ENU/Fusion-Sketch/files/SKT-TRIM-EXTEND.htm)는 사용자 흐름의 참고이지 현재 데이터 구조의 지원 증거가 아니다.

E2 치수 변경 후 OCCT 면/모서리 순번이 바뀔 수 있다. 직접 선택 편집은 표시용 삼각형 인덱스 대신 피처 의미/참조·선택 결과와 재계산 유효성을 관리해야 한다. 참조 손실은 임의의 다른 면에 적용하지 말고 재선택 요청으로 처리한다. 범용 위상 이름 추적은 별도 어려운 과제다.

1. 첫 대상: 3축 밀링인가, 선반인가? 컨트롤러/FANUC·Haas·Siemens 등의 구체 계열과 CAM post를 알 수 있는가? 현재 사용자에게 질문했으며 미답변 상태로 3축 밀링 부분집합을 제안한다.
2. 장비별 주축/축 이동·대기·쿨런트 전력을 직접 측정할 수 있는가? 불가하면 사용자가 입력한 가정 시나리오부터 시작한다.
3. 첫 목표는 분석/제안까지인가, 변경 NC를 장비에 넣는 출력까지인가? 현재 요청은 조사·분석이며, 첫 제품 범위는 분석/검토 제안으로 제안한다. 실제 출력은 별도 계약이다.

질문이 미정이어도 본 분석은 완료한다. 구현 전에 컨트롤러·지원 코드·완료 범위를 포함한 전체 설계를 확인한다.

## 권장안

### 화면/데이터 흐름

```mermaid
flowchart LR
  A[NC 원본 + 컨트롤러 프로필] --> B[Worker 상태 해석 / 행별 진단]
  B --> C[공통 경로·이벤트 모델]
  D[소재·공구·원점 / 목표 CAD] --> E[정합 및 지원 범위 검사]
  C --> E
  E --> F[경로 / 지원 조건 내 소재 제거]
  C --> G[장비 시간·전력 모델]
  F --> G
  G --> H[근거·범위가 있는 소비 예상]
  H --> I[안전·품질 검사 후 개선 시나리오 비교]
```

NC 원본은 변경하지 않는다. 중간 모델은 source file hash/행·블록, 해석 전후 모드, 원호 원본, 공구/T/H/D, 원점, 이동/주축/쿨런트/대기 이벤트·진단을 연결한다. CAD는 자체 피처 원본 또는 가져온 참조 바디로 별도 보관한다. 소재/공구/좌표/장비 전력/품질 조건은 각각 버전과 출처를 갖는다. 하나가 바뀌면 분석/제안을 미검증으로 전환한다.

화면은 ‘파일/입력 상태 → 코드·3D 경로 동기 선택 → 공구/원점·소재 → 시간/전력 그래프 → 후보 근거/비교’로 구성한다. 그래프 구간을 고르면 해당 NC 행과 공구가 강조된다. 데이터 부족/미지원은 숫자 대신 이유를 보여준다.

브라우저 File API·Worker·Three.js·기존 커널을 재사용한다. 고객 NC를 저장소/로그/외부 AI로 보내지 않고 합성 NC로 시험한다. 초기 로컬 파일 읽기, 분석 JSON/보고서 다운로드를 제안한다. 브라우저가 임의 폴더에 파일을 자동 저장할 수 있다고 표시하지 않는다. 서버 보관/FEMS 연결은 별도 설계이며 다른 솔루션의 테이블/FK를 공유하지 않는다.

초기 성능 상한 후보는 2MiB/50,000블록/표시500,000점·30초 취소다. **검증 전 확정 수치가 아니다.** 원호는 해석 원본을 유지하고 표시만 분할/단순화한다. 해석 실패 상태를 축소된 표시 경로로 감추지 않는다. 1천/1만/5만 블록 합성군에서 시간·메모리·취소 응답을 실측해 상한을 확정한다.

### 작업 순서와 완료 기준 — 아직 미착수

| 제안 ID | 범위 | 완료 기준 |
|---|---|---|
| CAD-11 | E1/E2 공통 편집 명령·실행 취소 | Ctrl/⌘Z·ShiftZ·CtrlY, 그리는 중 한 점 취소/다시 실행, Esc 현재 조작 취소, Delete 선택 삭제, 입력 필드 native undo 보존. 드래그/변경 적용 1회=이력1회. 실패·취소는 이력/저장에 없음. 새 편집이면 redo 초기화 |
| CAD-12 | NC 해석기·3D 경로 읽기 | 컨트롤러 프로필/모달 상태·원본 행 동기화, 초기 XYZ/단위/원점 명시, 직선/원호/주축/이벤트 합성 oracle, 미지원 전체 분석 차단, 상한/Worker 취소 |
| CAD-13 | 공구·소재·원점·목표 STEP 참조 | 실제 공구/T/H/D 연결·좌표 정합, STEP 참조 표시 실증, 지원 공구/상면 조건 내 제거·급속 소재 접촉/과절삭/잔삭 시험. 정합 전 형상 비교 차단 |
| CAD-14 | 시간·소비 모델과 근거 UI | 상태별 시간/전력 입력·단위/중복 방지, 구간/전체kWh 독립 합산, 입력 미정 차단, 가정/계측 구분·검증군과 별도 실측 보정 |
| CAD-15 | 품질1·소비2 개선 제안 | 원본/후보 근거·제약·예상범위, 안전/품질 미달 후보 차단, 불확실성보다 작은 차이 동등/판단 불가. 초기 NC 자동 재배열/실행 파일 출력 없음 |
| CAD-16 | 전문 스케치/직접 편집 | 엔티티/와이어/구속 명세 먼저. 다중선택·점 드래그·선/원호 연속 작성·측정/치수·move/copy/rotate/mirror → trim/extend/offset·섬 순. 면 선택·국소 필렛/모따기는 참조 유효성 실증 뒤 |
| CAD-17 | 컨트롤러 전용 NC 출력 | 확정 post·공구/보정·블록 의미 보존, 내보낸 파일 재해석/원본 비교·장비별 검증, 실제 장비 시험을 디지털 시험과 구분 |

우선 CAD-11로 즉각적인 실수 복구를 개선하고 CAD-12로 NC 입력 기반을 만든다. CAD-13/14가 있어야 에너지 예상에 근거가 생긴다. CAD-15는 그 다음이다. 스플라인·로프트/스윕·범용 구속·조립·선반/5축은 이 표의 첫 공개 범위가 아니라 후속 설계다. 기존 E3 비누 조립은 CNC 우선 결정에 따라 보류한다.

### 편집 명령 계약의 핵심

- 우선순위: 입력 필드 자체 undo → 진행 중 스케치/도구 조작 → 확정 설계 이력. 점 추가/닫기/원호 3점 단계를 draft 이력으로 기록한다. 클릭한 점만 되돌릴 때 이전 확정 부품을 날리지 않는다.
- E1/E2에서 같은 키와 안내를 제공한다. 선택/카메라 이동은 설계 undo 이력에 넣지 않는다. 키 반복·IME 조합·contenteditable·iframe 포커스·Windows/Mac modifier를 시험한다.
- 계산 중 Esc는 Worker 작업 취소/직전 정상 모델 유지. 치수 편집 취소는 마지막 확정 치수 복원. 삭제는 후속 피처 참조를 검사하고 영향 목록을 보여주며 성공 후 하나의 명령으로 확정한다.
- 단축키 도움말과 각 버튼 툴팁, 조작 중 ‘마지막 점 취소/확정/취소’를 노출한다. 선택 삭제/복제/화면 맞춤/저장 등 자주 쓰는 명령부터 통일한다. Fusion의 명령과 단축키 흐름을 참고한다. [Autodesk 단축키](https://www.autodesk.com/shortcuts/fusion-360).
