# CAD-17 FANUC 검토용 NC 출력 계약

2026-10-10 사용자 CAD-17 진행·FANUC 계열 선택, 장비/시리즈 미정으로 **검토용 출력·UI·파일 재검증** 진행 승인. 이 제한 범위 구현 완료. 실제 장비용 post는 미완료이며 장비 확정 뒤 별도 검증한다.

## 지원과 출력 규칙

- 출력 post `fanuc-mill-review-v1`, 입력은 기존 LinuxCNC 숫자 리터럴 부분집합 또는 FANUC 검토용 부분집합. 3축 G54·G17·증분 I/J 원호만, H/D·다른 원점·사이클·매크로·선반·장비별 M코드 미지원. E1/E2 형상에서 새 CAM을 생성하는 기능이 아니다.
- `%`, `O0001~O7999`, ASCII 대문자/CRLF, `.review.nc`. 기종 미정 경고를 파일 주석·UI·검증 JSON에 표시한다. 프로그램 번호1~7999는 이 검토용 범위의 제한이며 실제 장비 범위를 보증하지 않는다.
- LinuxCNC G4 P초 → 검토용 FANUC G4 P밀리초 정수(0~99999999). 밀리초보다 세밀한 값/범위 초과는 반올림·절삭하지 않고 차단한다. 원본 주석을 제외하고 G91.1 명령은 고정 증분 I/J 가정으로 생략한다. F/S/T·이동/원호·주축·냉각·보정 해제·기존 종료 명령의 의미는 보존한다.
- 새 초기화·퇴피·공구 교환 이동을 넣지 않는다. 초기 G54 XYZ/단위·기본 모달 상태와 공구표는 외부 조건이다. H/D 미지원이므로 길이/지름 보정된 실제 장비 가공 프로그램으로 승인할 수 없다.
- [Autodesk 공개 FANUC post](https://cam.autodesk.com/posts/post.php?name=fanuc)의 프로그램 번호/ASCII 및 onDwell 밀리초 규칙을 참고했다(조회2026-10-10). 원본 코드를 복사하거나 Autodesk 전체 post를 설치하지 않았다. [LinuxCNC G-code 명세](https://linuxcnc.org/docs/html/gcode/g-code.html), [FANUC 0i-MF Plus](https://www.fanucamerica.com/products/cnc/0i-mf-plus). 제품 소개는 특정 장비 명세의 대체가 아니다.

## 검증·무효화

- 원본 해시/재해석 대조 → 현재 소재/시간소비/품질 설정으로 후보 재계산 → 출력 생성 → FANUC 검토용 어댑터로 재해석 → 원본 행 대응표로 이동/원호·모달 상태·비대기 이벤트·변경 G4 시간을 대조한다.
- 후보0은 원본 의미 보존, 후보1~13은 현재 확인된 단독 G4의 최소시간/품질 조건을 충족해야 한다. 원본 덮어쓰기·자동 최적 후보 적용·실 CNC 실행 없음.
- 원본 오류/미종료/종료 뒤 숨은 실행 코드·해시/분석 변조·미지원 명령/혼합 대기 후보·불확정 품질·밀리초 정밀도 초과는 차단한다. 원본2MiB·50,000행·500,000점, 출력 Worker30초/수동 취소.
- 입력·외부 분석/선택 변경·탭 비활성 시 검증/저장을 무효화한다. 완료 순간과 다운로드 순간에 현재 설정과 snapshot을 다시 비교한다.
- 검증 JSON에는 post/기종미정/machineReady=false·초기조건·원본/출력해시·변경행·출력→원본행맵·제약이 있다. NC 원문/서버 저장/DB 변경 없음.

## 사용자 흐름

NC 화면 결과 패널의 **NC 파일 출력 · FANUC 검토용** → 프로그램 번호/원본 또는 후보 번호 → 환경 조건 확인 → 검증·미리보기 → 파일·검증 JSON 다운로드. 다시 열 때 입력 프로필 **FANUC 검토용** 선택. 예제 버튼은 초 단위 LinuxCNC 프로필로 복귀한다. 휴디는 검토 재생만 수행한다.
