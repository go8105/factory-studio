# CAD-17 FANUC 출력 설계·검증 기반 (진행 중)

2026-10-10 사용자 CAD-17 진행 승인 및 **출력 대상 FANUC 계열** 답변. 구체 시리즈/장비 모델 확인 질문 대기. CAD-17 전체 완료가 아니다.

FANUC 대상 post는 시리즈·장비 매뉴얼에 맞춰 별도 확정한다. 아래 LinuxCNC 부분집합 코드는 기존 해석기에 기반한 내부 검증 초안이며 FANUC 출력으로 노출하지 않는다. 현재 제품 NC 화면에는 연결하지 않았다.

공식 참고: [FANUC 0i-MF Plus](https://www.fanucamerica.com/products/cnc/0i-mf-plus), [컨트롤러 목록](https://www.fanucamerica.com/products/cnc). 제품 소개만으로 해당 장비의 G/M 코드·대기 단위·공구 보정 규칙을 확정하지 않는다.

- 고정 post: `linuxcnc-mill-subset-v1`. FANUC/선반/범용 post 변환, E1/E2 형상에서 새 CAM 생성은 포함하지 않는다. 지원 NC 원본 또는 CAD-15 확인된 단독 G4 후보를 `.ngc`로 출력한다.
- 원본 행·주석·줄바꿈·F/S/T·G54·보정 해제·주축/냉각/종료 명령을 보존한다. 후보는 선택 행의 P 숫자만 변경한다. G4 P는 초 단위(공식 https://linuxcnc.org/docs/html/gcode/g-code.html).
- 원본 해시 재검증, 원본 재해석, 최신 소재/에너지/품질 설정으로 후보 재계산 후 출력 재해석. 이동·원호·상태·비대기 이벤트·각 블록 상태 보존, 선택 대기만 목표 초로 변했는지 비교한다. 해석 오류/미종료/실행 뒤 숨은 코드/혼합 대기/미지원 프로필/오래된 입력/차이 발생은 출력 차단.
- 출력 파일은 초기 G54 XYZ/단위·해석기 기본 상태를 전제로 한다. 기계의 실제 원점·공구표·보정·초기 모달 상태는 자동 확인하지 않는다. H/D 보정은 기존과 같이 차단한다. 자동 초기화/퇴피/공구교환 이동을 삽입하지 않는다.
- UI 초안(제품 미연결): 분석 결과 아래 NC 출력. 원본(0) 또는 현재 후보 번호 입력 → 검증/미리보기 → 별도 다운로드. 환경 조건 확인 체크박스·프로필·변경 행·해시·초기 조건/검증 JSON 다운로드. 음성은 검토 재생만 수행하며 파일 출력/기계 실행을 하지 않는다.
- Worker 30초/원본 2MiB·50,000행·500,000점 상한 유지, 종료/입력 변경 시 무효화. 문서 필드에는 NC 원문을 넣지 않고 파일 해시·초기 설정·변경 행·제약만 넣는다. 서버 전송/DB 변경 없음.
- 검증: 실제 반환 파일 재해석·원본/후보 보존, 인치/상대좌표/원호/댓글·CRLF·중복P/미지원/해시·최신 후보 차단 회귀, 브라우저 파일 수신/다시 열기/입력 변경/모바일. 실제 LinuxCNC interpreter·CNC 장비/실측 품질·절감은 별도 미검증.

- FANUC 시리즈/장비명 및 매뉴얼 기반으로 프로그램 번호·대기 단위·모달 초기화·공구/H/D·종료 규칙 확정 → FANUC post/대응 재해석 어댑터 → UI 연결/파일 수신 검증 순서. LinuxCNC 파일을 FANUC로 이름만 바꿔 출력하지 않는다.
