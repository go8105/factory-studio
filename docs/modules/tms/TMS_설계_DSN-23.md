작성: 2026-10-05 (Claude Code) · 상태: **설계 완료(2026-10-05) — 사용자 확인 대기.** 1단계(기준표·Q1~Q7 확정) + 2단계(3장 기능 규칙 · 4장 DB 10테이블 · 5장 화면 14 · 6장 교차 조회).
양식: [DSN-00](../../plan/기능기준표_DSN-00.md) · 방침: [ROADMAP-02](../../plan/전체설계우선_전환_ROADMAP-02.md) · 로드맵: [ROADMAP-01](../../plan/로드맵_17개시스템_ROADMAP-01.md) 4번(ERP 출하지시를 읽고 배송 결과 `deliveries()`를 ERP에 제공, FS-026 트럭 도착과 경계)
넘겨받은 것: **WMS DSN-13** 출고장 피킹 완료 → 배차(WMS는 출하 확정까지) · ERP 출하지시·출하(DSN-11 F14).

## 0. TMS의 자리 — 출하 흐름에서 어디를 맡는가

지금 출하 흐름: ERP 출하지시 → WMS 출고 예약 → **피킹 확정(출고장 위치)** → ERP 출하 확정 → WMS 출고 반영. **차량·배송은 어디에도 없다.**

TMS = **피킹이 끝난 출하를 차량에 배정(배차)하고, 상차 → 출발 → 배송 완료까지 기록하고, 운임을 계산하는 솔루션.**

| 영역 | 소유 | TMS와의 관계 |
|---|---|---|
| 출하지시·출하 확정·매출 | **ERP** | TMS는 출하지시를 읽고, 상차·배송 결과를 ERP가 읽는다(Q1) |
| 출고 예약·피킹·출고장 재고 | **WMS** | TMS는 피킹 완료를 읽어 배차 대상으로 |
| 입고 차량 운송(조달 물류) | **TMS**(Q6 확정) | TMS가 운송 계획·게이트 도착을 기록, WMS 입고 예정은 검수 그대로 두고 차량·도착은 TMS를 읽어 채움(수동도 유지) |
| 납품처 주소 | **ERP** 거래처 상세(DSN-11 F02) | 코드·주소 스냅샷 |
| 운송비 회계 | **ERP** | 용차 운임 정산을 ERP가 읽어 직접 매입(Q5) |

## 3. 기능 규칙 (범위 20)

공통: **TMS는 ERP·WMS를 바꾸지 않는다**(Q1) — 출하지시·피킹·발주·입고 예정은 조회로 읽고 번호 스냅샷으로 남기며, 상차·배송·정산 결과는 ERP·WMS가 TMS 조회로 읽는다.

| 묶음 | 기능 ID | 규칙 |
|---|---|---|
| 기준 (Q2) | F01~F05 | 차량(자차/용차 — 용차는 운송사 필수, 톤수·적재 중량·용적), 운송사(ERP 거래처 코드), 기사(이름·연락처 합성), 배송지(ERP 거래처 코드·주소 스냅샷·권역·하차 조건), 권역, 운임표(권역 × 톤수, 기본·경유지·대기, 적용일 이력) |
| 배차 (Q1·Q3) | F11~F14 | 배차 대상 = ERP 확정 출하지시 중 WMS 피킹 완료분. 사람이 차량에 배정·방문 순서 지정(출하지시당 살아 있는 배송 1건, 실패 후 재배차 가능). 적재율 = 방문 중량(MES 품목 단위 중량 × 수량)·용적 합 ÷ 차량 한도 — 초과면 경고. 상차 지시서·경로표 인쇄 |
| 실행 (Q1·Q4) | F21~F25 | 상차 확인(방문별) → 모든 방문 상차 = 배차 LOADED(ERP는 이를 읽어 출하 확정 대기) → 출발 → 기사 화면(현장 단말 패턴 K)에서 도착·인수(인수자 이름)·부분 인수·실패(부재·거부·파손·기타) → 운행 완료. 실패·부분은 ERP 판매 반품 후보로 표시 |
| 조달 운송 (Q6) | F41 | 방향 INBOUND 배차: 공급처 상차지(배송지 표 공용) → 공장. 방문은 ERP 발주·WMS 입고 예정 번호. 게이트 도착 시각을 WMS가 읽어 입고 예정의 차량·도착 칸을 채움(3D 공장 입고 트럭도 이 값) |
| 운임·비용 (Q5·Q7) | F31~F33 | 운행 완료 시 운임 행 생성: BASE(권역·톤수) + EXTRA_STOP × 경유지 수 + WAITING(입력 시간). 자차 운행비(유류·통행료) 기록. 용차 운송사 월 정산 = 그 달 완료 배차 비용 합, 확정 1건 → ERP 직접 매입 |
| 현황·지표 | F51·F52 | 현황판(오늘 배차·진행·완료·실패). 정시 배송률(약속일 대비)·평균 리드타임(피킹 완료 → 인수)·평균 적재율·매출 대비 운송비 — 조회 계산 |

## 6. 교차 조회

**TMS가 읽는 것**

| 제공 | 함수 | TMS 용도 |
|---|---|---|
| ERP | `open_shipment_orders()`(ROADMAP-01) · `purchase_orders(open=True)`(DSN-11) · `partners()` | 배차 대상, 조달 운송, 배송지·운송사 |
| WMS | `picked_shipments()`(신규) · 입고 예정 조회 `inbound_notices(open=True)`(신규) | 피킹 완료 출하지시, 조달 방문 |
| MES | `items()`(있음, 단위 중량 포함) | 적재율 |

**TMS가 제공하는 것**

| 함수 | 돌려주는 것 | 쓰는 곳 |
|---|---|---|
| `loaded_shipments(since)` | 상차 완료된 출하지시 번호·차량·시각 | ERP 출하 확정 대기(Q1) |
| `deliveries(since)` | 배송 결과(인수·부분·실패, 인수자·시각·사유) | ERP 납품 확인·반품 후보 |
| `inbound_arrivals(since)` | 조달 차량 게이트 도착(입고 예정 번호·차량·시각) | WMS 입고 예정 차량·도착(Q6) |
| `carrier_settlements(month)` | 확정 운송사 정산 | ERP 직접 매입(Q5) |
| `monthly_summary(month)` | 배송 건수·정시율·운송비 | EIP |

> 넘길 것: **ERP** 출하 확정 대기 목록(TMS 상차 완료)·납품 확인·운송비 매입 · **WMS** `picked_shipments`·`inbound_notices` 제공, 입고 예정 차량·도착을 TMS에서 채움 · **MES** `items()`에 단위 중량 포함 확인.

## 7. 결정 질문 (하나씩)

| # | 질문 | 제안 |

| Q1 | **출하 흐름에서 TMS의 경계** — 배차 대상 = ERP 확정 출하지시 중 WMS 피킹 완료분(조회). TMS는 배차·상차·배송을 기록하고, **ERP는 TMS 상차 완료를 읽어 "출하 확정 대기"로 보여 주고 사람이 ERP에서 출하 확정**(TMS가 ERP를 바꾸지 않음). ERP는 배송 완료도 읽어 납품 확인 표시 | 그대로 |
| Q2 | **차량** — 자차와 용차(운송사) 둘 다. 용차는 운송사·운임 정산 대상 | 둘 다 |
| Q3 | **배차 방식** — 사람이 출하를 차량에 배정·순서 지정, 적재율(중량·부피)은 품목 단위 중량(MES 품목 조회)으로 계산해 초과 경고. 자동 최적화 제외 | 그대로 |
| Q4 | **배송 완료 입력** — (a) 기사 모바일 화면(현장 단말 패턴 K 재사용, TMS 소유) (b) 사무실에서 대신 입력만 | **(a)**. 인수자 이름·시각, 실패 사유. 서명·사진 제외 |
| Q5 | **운임·정산** — 운임표(권역 × 톤수) + 추가 요금(경유지·대기)으로 배차별 운임, 용차 운송사 월 정산서 확정 → ERP가 읽어 직접 매입 | 포함 |
| Q6 | **조달 운송(입고 차량)** — WMS 입고 예정의 차량·도착을 그대로 두고 TMS는 출하 운송만 | 출하만(WMS 유지) |
| Q7 | **자차 운행 비용**(유류비·통행료 기록) 포함 여부와 범위 확정 — 포함 17 + Q, 제외 4(자동 최적화·서명/사진·GPS·3D 출차) | 운행 비용 포함, 제안대로 |
