작성: 2026-10-05 (Claude Code) · 상태: **1단계 — 기준표·결정 질문(범위 확인 대기)**. 3~6장은 범위 확정 뒤.
양식: [DSN-00](../../plan/기능기준표_DSN-00.md) · 방침: [ROADMAP-02](../../plan/전체설계우선_전환_ROADMAP-02.md) · 로드맵: [ROADMAP-01](../../plan/로드맵_17개시스템_ROADMAP-01.md) 4번(ERP 출하지시를 읽고 배송 결과 `deliveries()`를 ERP에 제공, FS-026 트럭 도착과 경계)
넘겨받은 것: **WMS DSN-13** 출고장 피킹 완료 → 배차(WMS는 출하 확정까지) · ERP 출하지시·출하(DSN-11 F14).

## 0. TMS의 자리 — 출하 흐름에서 어디를 맡는가

지금 출하 흐름: ERP 출하지시 → WMS 출고 예약 → **피킹 확정(출고장 위치)** → ERP 출하 확정 → WMS 출고 반영. **차량·배송은 어디에도 없다.**

TMS = **피킹이 끝난 출하를 차량에 배정(배차)하고, 상차 → 출발 → 배송 완료까지 기록하고, 운임을 계산하는 솔루션.**

| 영역 | 소유 | TMS와의 관계 |
|---|---|---|
| 출하지시·출하 확정·매출 | **ERP** | TMS는 출하지시를 읽고, 상차·배송 결과를 ERP가 읽는다(Q1) |
| 출고 예약·피킹·출고장 재고 | **WMS** | TMS는 피킹 완료를 읽어 배차 대상으로 |
| 입고 차량 도착(조달 물류) | **WMS**(FS-026 트럭 도착) | Q6 |
| 납품처 주소 | **ERP** 거래처 상세(DSN-11 F02) | 코드·주소 스냅샷 |
| 운송비 회계 | **ERP** | 용차 운임 정산을 ERP가 읽어 직접 매입(Q5) |

## 7. 결정 질문 (하나씩)

| # | 질문 | 제안 |
|---|---|---|
| Q1 | **출하 흐름에서 TMS의 경계** — 배차 대상 = ERP 확정 출하지시 중 WMS 피킹 완료분(조회). TMS는 배차·상차·배송을 기록하고, **ERP는 TMS 상차 완료를 읽어 "출하 확정 대기"로 보여 주고 사람이 ERP에서 출하 확정**(TMS가 ERP를 바꾸지 않음). ERP는 배송 완료도 읽어 납품 확인 표시 | 그대로 |
| Q2 | **차량** — 자차와 용차(운송사) 둘 다. 용차는 운송사·운임 정산 대상 | 둘 다 |
| Q3 | **배차 방식** — 사람이 출하를 차량에 배정·순서 지정, 적재율(중량·부피)은 품목 단위 중량(MES 품목 조회)으로 계산해 초과 경고. 자동 최적화 제외 | 그대로 |
| Q4 | **배송 완료 입력** — (a) 기사 모바일 화면(현장 단말 패턴 K 재사용, TMS 소유) (b) 사무실에서 대신 입력만 | **(a)**. 인수자 이름·시각, 실패 사유. 서명·사진 제외 |
| Q5 | **운임·정산** — 운임표(권역 × 톤수) + 추가 요금(경유지·대기)으로 배차별 운임, 용차 운송사 월 정산서 확정 → ERP가 읽어 직접 매입 | 포함 |
| Q6 | **조달 운송(입고 차량)** — WMS 입고 예정의 차량·도착을 그대로 두고 TMS는 출하 운송만 | 출하만(WMS 유지) |
| Q7 | **자차 운행 비용**(유류비·통행료 기록) 포함 여부와 범위 확정 — 포함 17 + Q, 제외 4(자동 최적화·서명/사진·GPS·3D 출차) | 운행 비용 포함, 제안대로 |
