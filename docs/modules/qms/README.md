# QMS — 품질 관리

## 현재 기준 (2026-09-30, ROADMAP-01)

- 상태: **운영 · 동결** — 6화면(Q-01~06). 기능 추가는 [로드맵](../../plan/로드맵_17개시스템_ROADMAP-01.md)의 "살 붙이기" 단계에서만 한다. 다른 솔루션이 요청하는 **조회 함수 추가는 동결 중에도 허용**한다.
- 설계: [QMS 모듈 설계서](QMS_모듈설계_FS-023.md) · [결정서 FS-023](../../plan/QMS도입_교차조회_결정_FS-023.md)
- 읽는 조회: MES `inspectable_lots`·`lot_snapshot`·`items`

### 제공 조회 함수 (`backend/src/fs/qms/interface.py`)

| 함수 | 돌려주는 것 | 쓰는 곳 |
|---|---|---|
| `held_lot_nos()` | 활성 보류 LOT 번호 | MES |
| `latest_results(lot_nos)` | LOT별 마지막 확정 판정 | MES |

모든 함수의 앞 두 인자는 `(connection, scoped)`이고, 이 솔루션이 꺼져 있으면 `None`을 돌려준다.

## 메모

- 설계 승인 전에는 `schema.json`·마이그레이션·제품 코드를 만들지 않는다. 승인 후 FS-023a(메타데이터) → b(API·화면) → c(시드·도움말·통합 검증).
- MES 데이터는 **읽기 전용 조회 인터페이스**로만 읽고, 값은 코드 문자열·스냅샷으로 저장한다(FS-023 D9·D11).
- 품질 보류는 QMS 기록·MES 배지 표시까지다. MES 패킹을 막지 않는다(FS-023 D10).

## 규칙

이 폴더에 모듈 공통 설계서가 없으면 해당 모듈은 개발 착수 대상이 아니다.
설계를 먼저 확정하고 사용자 확인을 받은 뒤 구현에 들어간다.

기준정보(품목 등)는 각 솔루션이 독립 소유한다(FS-013 D1). QMS는 품목 마스터를 두지 않고 MES 조회 또는 직접 입력한 코드를 스냅샷으로 보관한다.

전체 현황은 [현재 기획과 진행 현황](../../plan/현재기획_진행현황.md)을 본다.
