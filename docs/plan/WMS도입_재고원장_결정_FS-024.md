# FS-024 WMS 도입과 재고 원장 결정서

상태: **확정 — 사용자 승인 2026-09-27**(6장 2문항 + 모듈 설계 13장 4문항 모두 권장안). 메타데이터·마이그레이션은 전체 설계 확인 뒤 FS-024a에서 적용.
성격: [FS-013](독립솔루션_전환결정_FS-013.md)·[FS-023](QMS도입_교차조회_결정_FS-023.md)의 범위를 넓히는 결정서. 교차 조회 규칙(D9·X1~X6·R6)은 그대로 따른다.

## 1. 배경

MES·ERP·FEMS·QMS가 구현·배포됐다(2026-09-27). 그런데 **재고를 소유한 솔루션이 없다.**

| 지금 | 동작 | 근거 |
|---|---|---|
| MES 자재 투입 | 기록만. 차감 없음 | `mes/execution.py` "재고 원장은 WMS 소유", 갭 M-G01 |
| MES 완제품 입고 | 팔레트 상태를 `received`로. 재고 조회 화면 없음 | `mes/packing.py` `receive` |
| MES 패킹 `shipped` | 앱 코드가 바꾸지 않는다(시드만) | FS-013으로 ERP↔MES FK 제거 |
| ERP 출하 | 재고 확인 없이 확정. `packing_no`는 손으로 적는 문자열 | `erp/shipping.py`, 갭 E-G04 |
| ERP 매입 | 전표만. 입고·검수 없음("그 앞은 WMS 범위") | `erp/purchases.py`, FS-013 §153 |

기존 문서의 방향은 일치한다. **재고는 원장(이동 기록)이 원천이고 잔량은 파생값**이며(FS-004a §7.2), 도입하면 원장 소유가 WMS로 간다(WMS README, 노드정의서 11번).

## 2. 결정

| # | 항목 | 결정 |
|---|---|---|
| **D13** | WMS 범위 | **WMS를 구현 솔루션에 넣는다.** 1차는 **완제품과 원자재의 재고 원장**: 창고·위치, 원천 반영(MES 입고·MES 투입·ERP 출하·ERP 매입), 조정, 창고 간 이동, 재고 현황·원장 조회. **예약·실사·피킹·구매발주·입고검수는 제외.** 설명 카드는 BEMS·SCM 2종으로 줄인다 |
| **D14** | 원장 소유와 반영 | **재고 원장은 WMS만 쓴다.** WMS는 MES·ERP의 **확정된** 기록을 읽기 전용 조회 인터페이스(D9)로 읽어, 사용자가 **"반영"을 눌렀을 때** 원장 전표로 만든다. 원천 1건 = 전표 1건이며 `source_key`로 두 번 반영하지 않는다. 원천이 나중에 취소되면(ERP 매입 취소) 되돌림 전표를 남긴다. **MES·ERP 데이터는 바꾸지 않는다** |
| **D15** | 재고 부족 | **음수 재고를 허용하고 표시만 한다.** ERP 출하·MES 투입을 막지 않는다(D10과 같은 이유 — 막으려면 ERP·MES가 WMS에 의존한다). 음수가 된 품목·위치는 대시보드와 현황에 경고 배지로 보인다 |
| **D16** | 추적 단위 | **완제품은 LOT 단위, 원자재는 품목 수량**으로 추적한다(시드에 원자재 LOT이 없다). 창고는 **원자재 창고·완제품 창고 2개**, 창고마다 **위치 1단계**. 원천 반영은 창고별 기본 위치로 들어오고 이동 전표로 옮긴다 |
| **D17** | 가용 수량 | **예약 테이블을 두지 않는다.** 완제품 가용 = 현재고 − ERP 미출하 출하지시 수량을 **조회할 때 계산**만 한다. ERP가 꺼져 있으면 가용은 "계산 불가" |

D12(독립 동작)는 WMS에도 적용한다. MES·ERP를 꺼도 WMS는 **수동 전표(기초·조정·이동)만으로** 동작하고, 반영 화면은 "원천 솔루션 꺼짐"으로 안내한다. 반대로 WMS를 꺼도 MES·ERP는 그대로다.

### D14 보충 — 왜 "읽어 와서 반영"인가

- **쓰기를 열지 않는다.** "MES 투입 때 차감"을 MES 트랜잭션 안에서 하려면 MES가 WMS에 쓰거나 WMS를 호출해야 한다. 이는 D9(읽기 전용)를 깨고 잠금 순서가 스키마를 넘는다.
- **자동이 아니라 버튼인 이유.** 원천 화면을 열 때마다 자동 반영하면 여러 사용자가 동시에 같은 원천을 반영하는 경합을 늘 처리해야 한다. 버튼 반영은 "무엇이 아직 안 들어왔는지"가 화면에 보여 교차 조회를 시연하기에도 낫다. 경합은 `source_key` 부분 유니크 인덱스로 막는다(두 번째 요청은 "이미 반영됨").
- **실제 운영이라면** 이 자리는 시스템 간 이벤트·메시지 연계이며, 반영 버튼은 "미처리 이벤트 수동 처리"에 해당한다. 도움말에 이 경계를 적는다.

### D15 보충 — 음수를 허용하는 이유

잔량 확인을 하려면 전표 확정 때 같은 품목·위치 행을 잠가야 하고, 원천 반영은 거부될 수 있어야 한다. 그러면 "MES·ERP에서는 확정됐는데 WMS에는 못 들어온 기록"이 생기고 두 솔루션의 수량이 영구히 어긋난다. 1차는 **원천 기록을 그대로 받아들이고 차이를 드러내는 것**을 택한다. 음수를 해소하는 방법은 조정 전표(실물 확인 후)다.

## 3. 교차 조회 인터페이스 (D9 규칙 X1~X6 그대로)

| 제공 | 함수(새로 공개) | 용도 |
|---|---|---|
| MES `fs/mes/interface.py` | `finished_goods_receipts(scope)` · `completed_material_issues(scope)` · `items(scope, item_type=None)` 확장 | 완제품 입고, 자재 투입(완료된 공정 실행만 — 실행 중에는 투입을 지울 수 있다), 품목 가져오기 |
| ERP `fs/erp/interface.py` (**새 파일**) | `confirmed_shipments(scope)` · `purchase_receipts(scope)` · `open_shipment_qty(scope)` | 출하 차감, 매입 입고(확정·취소 포함), 가용 수량 |

ERP가 인터페이스를 공개하는 것은 처음이다. ERP는 WMS를 읽지 않는다(재고 확인을 하지 않으므로 D15와 일치).

격리 검사: R1·R5에 `wms` 추가, R6(다른 솔루션은 `interface`만 import) 그대로.

## 5. 하지 않는 것

- 출하·투입을 재고로 **막는 것**(D15). ERP·MES에서 WMS 재고를 보여 주는 것도 1차 제외(ERP·MES 변경 없음).
- 예약·할당·피킹·실사(재고 조사)·구매발주·입고검수·원가(이동평균·선입선출 금액).
- 원자재 LOT·유효기간·시리얼.
- MES 패킹 상태(`shipped`) 갱신 — MES 데이터이므로 WMS가 바꾸지 않는다.
- QMS 보류·폐기 판정의 자동 반영. 폐기는 사용자가 조정 전표(사유 SCRAP)로 남긴다.
