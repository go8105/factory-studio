# 정밀 부품 공장 — 제품·공정 컨셉

작업 ID: FS-FACTORY-CONCEPT01 / 작성: 2026-09-28
상태: 1단계 기획 기준 정리 완료. 사용자 요청한 개발 순서의 첫 단계이며 아래 화면·설비·업무 기능의 구현 완료를 뜻하지 않는다.

## 1. 제품과 체험의 정의

- 제품명: **Factory Studio**.
- 체험 부제: **입고부터 출하까지, 제조 운영 시뮬레이터**.
- 공장명: **정밀 부품 가공 공장**.
- 제품: **설비용 알루미늄 마운팅 블록**. 직육면체 소재에 상면 포켓과 체결 구멍을 가공한 합성 예시 제품.
- 산업 맥락: 이차전지·반도체 생산설비 등에 쓰이는 정밀 부품의 제조 업무를 설명한다. 배터리 셀 제조나 웨이퍼 제조 공정, 실제 납품 실적을 뜻하지 않는다.
- 생산 방식: 기존 MTS(재고생산) 원칙 유지. 생산계획에서 작업지시를 만들고, 출하 요구 수량에 맞춰 완제품을 할당한다. 수주가 직접 생산을 발생시키는 MTO 전환은 이번 범위가 아니다.
- 사용자 체험 목표: 작업지시 실행, 소재 확인, 설비 운전, 검사 결과 확인, 불량 격리, 출하 가능 수량 확인.
- 체험 안내는 정적 도움말로 제공한다. 학습 점수·진도·과정 DB를 추가하지 않는다.

## 3. 공정과 물류 흐름

입고 예정 → 트럭 도착 → 하역·수량 검수 → 소재 LOT 등록·창고 적치 → 작업지시별 소재 할당·불출 → 로봇 투입 → CNC 가공 → 로봇 배출 → 비전검사 → OK 포장 / NG 격리 → 완제품 입고 → 출하 할당·확정 → 상차·배송 관제.

소재: 알루미늄 사각 블록(개). 부자재: 포장 상자·완충재(개). 소재 한 개에서 제품 한 개를 만드는 단순 모델로 시작한다. 절삭칩 회수·중량 수율·원가·공구 수명은 제외한다. 포장 단위별 부자재 소요량은 WMS/BOM 상세 설계에서 정한다.

트럭 도착은 재고 확정이 아니다. 검수 확정 시 사용 가능 재고로 전환한다. NG 제품은 출하 가능 재고에 포함하지 않는다. 장애는 제품 NG로 집계하지 않는다.

## 4. 2단계 CNC 셀 구현 기준

정상 순서: 준비 → 소재 집기 → 투입 → 로봇 퇴피 → 소재 고정 확인 → 문 닫힘 확인 → 가공 → 주축 정지 확인 → 문 열기 → 고정 해제 → 로봇 배출 → 검사 대기 위치 인계.

- 로봇: 베이스·관절·그리퍼가 있는 형상. 소재가 그리퍼/지그/이송 위치 중 하나에만 존재하도록 관리.
- CNC: 밀폐형 장비 외형, 문, 지그, 주축의 동작 표시. 가공 완료 시 원소재에서 포켓·구멍 있는 형상으로 전환. 실제 절삭 물리·CAM·G-code 해석은 구현하지 않는다.
- 상태가 애니메이션과 패널을 함께 구동한다. 애니메이션 완료만으로 업무 재고를 변경하지 않는다.
- 모의 인터락: 로봇 퇴피·고정·문 닫힘 조건이 모두 만족해야 가공 시작. 문 열림 중 주축 가동 차단. 실제 안전 제어 인증을 뜻하지 않는다.
- 사용자 조작: 시작, 일시정지, 재개, 종료, 모의 설비 오류, 오류 해제 후 명시적 복구.
- 일시정지는 진행 위치와 소재 소유 위치를 유지한다. 오류는 신규 투입을 차단한다. 초기화 시 진행 소재의 처리 상태를 표시하며 완료 수에 더하지 않는다.
- 1인칭 이동·설비 선택·키오스크·비전검사실 진입 유지. 장비 크기가 바뀌면 충돌 영역과 카메라를 함께 검증한다.
- 2단계 완료 기준: 정상 1주기 소재 중복 없음, 가공 전후 형상 구분, 정지 중 이동 없음, 재개 후 중복 완료 없음, 오류 중 신규 가공 차단, 데스크톱·모바일 패널 사용 가능.

## 5. 대표 시나리오와 수량 기준

표준 시연은 생산계획과 작업지시 100개로 시작한다. 정상 시나리오는 합격 100개를 출하한다. 불량 시나리오 예시는 완료 100 = OK 95 + NG 5, 출하 가능 95개, 출하 요구 대비 부족 5개다. 부족분이 자동 생성되거나 불량이 자동 양품으로 바뀌지 않는다. 추가 생산은 별도 작업지시로 표현한다.

예외 체험: 소재 부족이면 생산 대기, CNC 오류면 원인 확인 후 재개, 검사 시간 초과면 검사 오류로 분리, NG면 당시 레시피·이미지 확인 후 격리, 배송 지연이면 영향 출하 건과 도착 예정 시간 표시.

위 수량은 후속 통합 시연용 예시다. 기존 검사실 20회 배치·합성 샘플 결과를 95/5에 맞춰 조작하지 않는다. 기존 3D 시나리오의 고정 통계와 신규 생산 실적도 섞지 않는다.

## 6. 기존 구현과 연결 경계

- 현재 3D: 조립 → 검사 → 포장. 기존 MES 시드: 소형 전자부품 사출 → 조립 → 검사. 신규 정밀 부품 컨셉은 3D 체험의 후속 기준이며 현재 업무 시드를 변경한 상태가 아니다.
- 기존 MES·ERP·FEMS는 독립 소유 유지. 업무 스키마 간 FK 없음. core는 업무 마스터를 소유하지 않는다.
- WMS는 현재 설명 카드 단계. 3단계에서 공통 설계·재고 원장·입출고 확정·예약·중복 방지·취소 규칙과 DB 변경 산출물을 먼저 정의한다. MES 자재 투입 기록 자체를 재고 차감으로 간주하지 않는다.
- 전체 자동 운전은 후속 조정 계층과 모듈별 API/이벤트 계약으로 연결한다. 코드 문자열 참조와 추적 ID, 재시도/중복 처리, 실패 후 복구를 설계해야 한다. 단일 공유 업무 DB나 스키마 간 직접 쓰기로 우회하지 않는다.
- 새 공정과 MES를 연결할 때 별도 품목·공정·경로·설비 코드를 정의한다. 기존 확정 실적·시드 코드 일괄 변경 금지. 기존 예시 보존 및 신규 시나리오 추가 방식은 3~4단계 상세 설계에서 결정한다.
- C++ 검사는 현재 합성 이미지 기반이다. 가공 형상에서 실제 카메라 영상이 생성되거나 치수 정확도가 검증된 것으로 표현하지 않는다. 통합 시 제품 ID·검사 요청 ID·레시피 버전·결과를 연결하고 출처를 표시한다.
- 지도는 모의 위치·ETA를 명시. 실제 GPS/운송사 연결은 범위 밖.
- JSON은 버전이 있는 시나리오 백업/복원으로 시작. 설정·허용된 합성 업무 데이터만 포함하고 인증정보 제외. 검증·복원 미리보기·실패 시 원상 유지가 필요하며 운영 DB 백업을 대체하지 않는다.
