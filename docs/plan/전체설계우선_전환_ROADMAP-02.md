# ROADMAP-02 — 전체 설계 우선 전환

작성: 2026-10-03 (Claude Code) · 상태: **확정 — 사용자 승인 2026-10-03**(D75~D78 하나씩 확정)
대체: [ROADMAP-01](로드맵_17개시스템_ROADMAP-01.md)의 **진행 방식**(하나씩 설계·개발·동결)을 대체한다. 17개 목록·분야·교차 조회 규칙(ROADMAP-01 §2·§3·§4)은 그대로 쓴다.

## 1. 배경

솔루션을 하나씩 끝까지 만들고 동결하다 보니 솔루션마다 기능이 얕다. 예: ERP 27테이블은 기초등록·영업·구매·출하·매출/매입 전표까지이고, 회계 장부·결산·원가·자금·부가세는 거의 없다. 사용자 기준: **"이카운트만큼은 아니어도 어느 정도는 되어야 한다."** 또 솔루션 사이 흐름(수주 → 생산 → 품질 → 출하 → 회계)은 한꺼번에 설계해야 어긋나지 않는다.

## 4. 제약·주의

- **분량**: 기준표에서 "어디까지"를 먼저 정해야 끝난다. 고급 기능은 목록에만 두고 범위 밖으로 표시할 수 있다.
- **이미 적용한 마이그레이션은 고치지 않는다.** 기존 테이블을 크게 바꾸면 개발 때 변경 마이그레이션이 많아진다. 합성 데이터뿐이라 운영 DB를 새로 만드는 선택지가 있다(배포절차 4-3) — DSN-99에서 정한다.
- **실행 없는 검증의 한계**: 설계 단계에서는 검증기·ERD·빈 DB DDL·흐름 시나리오까지만 확인된다. 동작 확인은 개발 후.
- 이카운트 화면은 로그인이 필요해 Claude가 직접 열지 않는다. 공개 정보와 일반 실무 기준으로 만들고, 사용자가 캡처를 주면 반영한다.
- 불변 규칙(AGENTS §3: 범위 키 S, 업무 스키마 간 FK 금지, 달력 문자열, 확정 데이터 불변)은 목표 설계에도 그대로 적용한다.
