# DSN-01 — 솔루션이 "전체 구성"이 될 때 무게 대응

작성: 2026-10-05 (Claude Code) · 상태: **확정 — 사용자 승인 2026-10-05(S1~S4 모두 제안대로)**
배경: ROADMAP-02로 17개 솔루션을 경량이 아니라 전체 구성으로 설계한다(예: ERP 기능 72개 중 57개 범위, 테이블 27 → 약 55~65). 사용자 우려: 코드가 매우 무거워지고, 지금도 배포에 40~50분이 걸린다.

## 3. 제안

### A. 테스트·CI — 34분 → 목표 10분 이내 (가장 효과 큼)

1. **필요한 솔루션 시드만 복사**: `guest_space`가 테스트 파일의 솔루션 시드만 복사한다(ERP 테스트 → core + erp 시드). 교차 조회 테스트만 여러 솔루션을 지정한다. 스키마가 이미 솔루션별로 나뉘어 있어 구조상 가능하다.
2. **읽기 전용 테스트는 게스트 공유**: 조회만 하는 테스트는 파일 단위로 게스트 하나를 같이 쓴다. 쓰기 테스트만 새 게스트.
3. **병렬 실행**(pytest-xdist): CI 러너 4코어, 작업자마다 DB 분리.
4. **변경 범위 선택 실행**: push 때는 바뀐 솔루션 + 공통(core·common) 테스트만, 배포 전·야간에 전체.

### B. 게스트 데이터 — 솔루션을 처음 열 때 복사(지연 복사)

게스트를 만들 때 core만 복사하고, **솔루션을 처음 열 때 그 솔루션 시드만 복사**한다. 게스트 생성은 1초대로 유지되고, 둘러보지 않는 솔루션의 행은 만들지 않는다. 독립 솔루션 구조(FS-013)와 맞는다. 교차 조회는 꺼진/아직 복사 안 된 솔루션을 "꺼짐"과 같게 다루면 된다(이미 `None` 규칙이 있다).

> **구현(W0-1, 2026-10-05):** `core.workspace_module.seeded_generation_id`(그 솔루션 시드를 복사한 세대)·`core.data_generation.template_generation_id`(원천 템플릿). 솔루션 라우터 의존성 `fs.common.scope.seed_ready(모듈)`이 요청 트랜잭션 **전에** 공간 잠금 → 다시 확인 → `seed.copy.copy_module_seed` → 표시. 게스트 생성·회원 생성·세대 초기화는 core(모듈 행)만. 교차 조회 `interface.enabled()`는 `module_available`(켜짐 **그리고** 활성 세대에 복사됨)만 True. 세대가 바뀌면 표시가 자동 무효. 테스트도 쓰는 솔루션 시드만 복사한다(A1).

### C. 코드 — 화면마다 손으로 만들지 않고 "패턴 + 정의"로

이카운트 분석에서 화면은 사실상 4종이다: **마스터 목록 + 등록 팝업**, **전표 입력(머리 + 라인 + 합계 + 확정)**, **기간 조회·현황**, **진행 단계 관리**. 우리 UI-02 패턴(D·L·S·P·V·W)과 거의 같다.

- 프런트: 4종을 공통 컴포넌트로 만들고, 솔루션 화면은 **컬럼·필드·버튼 정의(설정 객체)**만 쓴다. 특수 화면(3D, 관리도, 결재 진행)만 손으로 만든다.
- 백엔드: 마스터 CRUD·전표 상태 전이(작성 → 확정 → 취소/역분개)·멱등·낙관적 잠금을 공통 엔진으로. 솔루션은 검증 규칙과 계산만 쓴다.
- 단순 마스터(코드·이름·사용중단 수준)는 `schema-target.json` 메타데이터에서 API·화면 정의를 생성할 수 있다(선택).
- 기대 효과: 화면당 코드가 지금의 1/3~1/5. 25~35만 줄 추정을 10~15만 줄 수준으로.

### D. 런타임 구조 — 지금 방식(모듈러 모놀리스) 유지

솔루션별 서버 분리(마이크로서비스)는 1 vCPU · 2GB에 맞지 않고 운영이 무거워진다. **한 서버·한 DB·스키마 분리** 구조를 유지한다. 대신:
- 프런트: 솔루션별 코드 분할 유지(지금도 그렇다). 공통 패턴 컴포넌트는 한 번만 내려받는다.
- 백엔드: 꺼진 솔루션은 라우터를 등록해도 비용이 거의 없다. 필요하면 솔루션별 지연 import.
- DB: 모든 업무 인덱스 선두에 범위 키 S(이미 규칙). 측정값·이력처럼 큰 테이블은 설계 단계에서 보존 기간을 정한다.

### E. 배포 — 한 줄 스크립트

맥북에서 `tools/deploy.sh` 하나: CI 통과 확인 → 같은 커밋으로 빌드 → rsync → 서버 pull·sync·migrate·(필요 시)템플릿·재시작 → 운영 확인(curl). 사용자는 한 번 실행한다(Claude의 SSH는 권한 검사가 막는다). 사람 손 단계가 없어져 실수(예: 2026-10-04 프런트 업로드 누락)가 사라진다.

## 4. 설계 단계(DSN)에 지금 반영할 것

1. **화면 목록에 패턴 코드를 반드시 적는다**(DSN-00 5장). "특수 화면"은 따로 표시해 수를 관리한다.
2. **시드 예산**: 솔루션별 시드 행 수 상한을 설계 문서에 적는다(예: 솔루션당 3,000행, 측정값형은 별도 협의).
3. **전표형 업무는 같은 상태 모델**(작성 → 확정 → 취소/역분개)로 설계해 공통 엔진에 맞춘다.
4. 교차 조회는 "그 솔루션 시드가 아직 없음"도 `None`으로 처리되게 계약을 적는다.
