# 회사 공동 출퇴근·휴가 PWA — HR-TIME-01

2026-10-10. 상태: 상세 구현 전 설계 확인 대상. 사용자 확정: 회사 공동 사용, 버튼 출퇴근, 1시간 단위 시간차. 이번 문서는 계획이며 실제 회사용 기능이나 DB를 구현한 결과가 아니다.

## 화면과 접근

- 모바일 PWA 시작 화면은 ‘내 근무’. 오늘 출근/퇴근 버튼, 기록된 서버 시각, 근무 상태, 월별 기록, 휴가 잔여와 신청 내역을 제공한다. 웹과 같은 계정/API를 사용한다.
- HR에 ‘내 근무’와 ‘근무 체험’ 진입을 추가하고 GW에도 바로가기를 제공한다. 별도 근태 제품을 중복 소유하지 않는다.
- 실제 화면/API는 활성 회원 + 회사 소속 + 활성 사원 연결이 모두 있어야 사용 가능. 가입만으로 다른 회사 기록에 접근할 수 없다. 회사 미소속 회원은 연결 안내를 본다.
- 게스트는 웹의 ‘근무 체험’만 이용한다. 합성 직원 선택과 가상 출퇴근/신청/승인을 분명히 표시한다. 실제 회사 데이터를 체험 템플릿·초기화·복사 대상으로 포함하지 않는다.

## 회사와 권한

현재 회원 인증은 개인 MEMBER 공간만 조회한다. 공동 사용 전에 core의 회사 공간·멤버십·현재 공간 선택/검증을 구현해야 한다. 기존 GW 공유공간 설계를 참조하되, 회사 근태의 사원 연결과 승인 권한은 HR에서 소유한다. core→HR 업무 FK 금지 및 기존 S=(workspace_id,generation_id) 격리를 유지한다.

| 역할 | 권한 |
|---|---|
| 직원 | 본인 출퇴근·기록 조회·휴가/시간차/출장/정정 신청 |
| 승인 담당자 | 명시적으로 배정된 소속 직원 신청 승인·반려 |
| 근태 관리자 | 회사 근태 조회·정정 처리·월 마감, 권한 범위 명시 |
| 회사 소유자 | 회사 구성원 초대·역할 배정·계정 연결 관리 |

회사 관리자라는 이유만으로 승인자 권한을 자동 부여하지 않는다. 신청자가 자기 신청을 승인할 수 없다. 사용자 입력 employeeId/personId를 신뢰하지 않고 서버에서 활성 계정 연결로 본인을 결정한다. 회사 탈퇴·사원 비활성·권한 회수 시 이후 요청을 즉시 차단한다.

## 버튼 출퇴근

- 출근/퇴근 실제 기록 시각은 서버 UTC 타임스탬프, 표시·근무일은 회사 시간대(초기 Asia/Seoul). 위치/QR/Wi-Fi 검증은 첫 범위에 없다.
- 날짜별 합계를 먼저 생성하는 기존 AUTO 근태와 실제 기록을 구분한다. AUTO의 예정 시각을 실제 출근으로 취급하지 않는다.
- 열린 근무 세션당 출근 1회, 퇴근 1회. 중복 클릭/응답 유실 재시도는 멱등 키와 DB 잠금/제약으로 같은 결과를 반환한다. 퇴근만 단독 제출·동시 열린 근무 생성은 거부한다.
- 야간 근무는 출근 근무일에 연결하며 자정 뒤 퇴근을 지원한다. 열린 근무가 남으면 새 출근 대신 정정/확인을 안내한다.
- 출퇴근 누락·시간 정정은 사유와 요청자·처리자·원래 값·수정 값을 이력으로 보관한다. 월 마감 후 직접 수정 금지, 정정/재마감 절차 적용.
- 지각·조퇴·근무시간 산정에는 승인된 시간차와 회사 근무표/휴게시간을 반영한다. 출근~퇴근 경과시간을 그대로 급여 인정시간으로 확정하지 않는다.

## 휴가·시간차·출장

기존 HR 연차/반차 승인과 잔여 조회를 확장한다. 첫 범위는 연차, 오전 반차, 오후 반차, 시간차, 출장이다.

- 시간차는 날짜 + 시작/종료 시간으로 신청한다. 사용 길이는 60분의 정수 배수, 근무시간 안의 실제 유급 근무 분만 차감한다. 점심/휴게시간·휴일 제외, 중복 신청 방지, 남은 시간 초과 거부.
- 잔여는 정수 분 단위로 정확히 계산하고 UI에 일/시간을 병기한다. 기본 예시 1일=480분, 오전/오후 반차=240분. 실제 회사 일 근로시간/반차 구간을 설정으로 확정하며 직원에게 적용 기준을 표시한다. 1시간=0.125일 같은 고정값을 모든 회사에 강제하지 않는다.
- 신청→승인/반려→취소 흐름. 승인/취소/중복승인 경합에서 잔여 차감·반환은 정확히 한 번. 승인된 휴가/시간차의 근무일 겹침과 월 마감을 확인한다.
- 기존 반차 승인에서 일 근태 clock_in/out을 NULL로 바꾸는 처리는 실제 출퇴근 기록을 지우지 않도록 변경한다. 실제 이벤트와 근태 요약을 분리하고 승인 전후 기록을 보존한다.
- 출장은 기간·행선지·업무 목적·승인 담당자로 신청하며 연차를 차감하지 않는다. 출장 중 버튼 출퇴근 기록 가능. 첫 범위에서 출장 경비 지급/ERP 확정은 수행하지 않는다.

## PWA

HTTPS, manifest, 앱 아이콘, 앱 시작 경로와 설치 안내를 제공한다. 홈 화면 실행 후 회원 세션 및 회사 연결을 서버로 확인한다. 로그인 화면/로그아웃도 앱 내부에서 이용 가능.

정적 앱 셸만 서비스 워커 캐시 대상으로 삼는다. 근태·개인정보·인증 API는 캐시하지 않는다. 오프라인에서는 현재 상태를 명확히 알리고 실제 출퇴근을 제출하지 않는다. 재연결 후 사용자가 다시 기록한다. 업데이트/로그아웃 시 이전 회사 응답이나 사용자 기록이 남지 않도록 처리한다. 설치 유도 및 iPhone/Android 실제 설치 검증은 별도 체크한다.

## 구현 순서와 검증

1. 회사 공간·멤버십·사원 연결·권한: 서로 다른 회원 2명과 다른 회사로 실제 격리 검증. 기존 개인/게스트 회귀.
2. 실제 출퇴근 원장/근무 세션·근태 집계·정정: 중복/동시/자정/퇴근누락/마감 검증.
3. 시간차·휴가·출장 신청/승인: 1시간/2시간·휴게시간·부족잔여·동시승인·승인취소·반차기록보존 검증.
4. 내 근무 모바일 웹·HR/GW 바로가기·별도 합성 체험: 게스트 실제API403, 위조 사원/회사403, 체험 실제데이터 유출0 검증.
5. PWA 설치·오프라인·로그아웃·버전 업데이트 검증 후 main 반영·운영 출시 판단.

새 revision/schema/DB설계서.xlsx/모듈 ERD는 실제 구현 단계에서 함께 갱신한다. 이번 문서로 기존 migration을 수정하거나 실제 회사 모드를 활성화하지 않는다.

## 첫 운영 전 회사 설정

회사명/관리자 계정/직원 목록과 사원 연결, 근무시간·휴게시간·승인자, 시간차/반차 정책, 기록 보존기간을 실제 운영 적용 전에 확정한다. 개발 검증에는 합성 회사·직원과 위 예시 근무표를 사용한다. 시간차 지원은 회사 설정 가능한 제품 기능이며 특정 회사에서의 사용 권리를 법률상 확정하는 설명이 아니다.
