## 1. 이 제품은 무엇인가

**하나의 포털에서 MES·ERP·FEMS를 각각 독립된 전문 솔루션으로 보여주는 제조 업무 플랫폼이다.**

각 솔루션은 자기 대시보드·메뉴·업무 흐름을 갖는 완결된 제품이고, 포털은 로그인과 진입만 담당한다. 세 솔루션이 어떻게 이어지는지는 정적 흐름 맵과 도움말로 설명한다.

**최종 목적은 이직 시 제출할 포트폴리오다.** 이 목적이 아래 모든 결정을 지배한다.

| 함의 | 내용 |
|---|---|
| 평가자 | 채용 담당자·기술 면접관. 3~5분 안에 판단한다 |
| 회원가입 | 요구하면 안 된다. 게스트 즉시 체험이 필수다 |
| 잘 만든 결과 | 한 솔루션이 대시보드부터 업무 완결까지 동작하고 설계 근거를 설명할 수 있는 것 |
| 치명적 실패 | "준비 중" 남발, 빈 화면, 가입 강제 |

실제 운영 데이터는 절대 들어오지 않는다. 합성 데이터만 사용한다.

**2026-09-22 방향 전환.** 이전 기획은 학습 과정(C0~C4)이 중심인 통합 업무 포털(EIP)이었다. 현재는 독립 솔루션 전시가 중심이고 학습은 도움말로 축소됐다. 이전 전제로 쓰인 문서를 인용할 때 주의한다.

## 3. 세 솔루션의 업무 범위

### MES
```
기준정보(품목·설비·사업장·공정) → 표준공정·경로 → BOM
  → 생산계획(MPS) → 작업지시 → LOT → 공정 투입·실행(자재 투입)
  → 실적 확정 → 패킹(박스→팔레트) → 완제품 입고
```

### ERP
```
기준정보(거래처·품목·단가) → 견적 → 판매계획 → 수주
  → 출하지시 → 출하 → 매출 인식
  → 매출채권 → 수금·소명
  → 매입 전표 → 매입채무 → 지급·소명
  → 세금계산서 발급확인 / 분개 미리보기(읽기 전용)
```

### FEMS
```
기준정보(에너지원·계측기·채널·설비) → 계측값 조회
  → 설비별 배분 → 원단위·기준선 → 목표 대비 실적 → 요금 산정
```

솔루션 간 연결은 **FK가 아니라 코드 문자열과 설명 카드**로 표현한다. 세 솔루션의 전체 흐름도는 정적 파일로 포털에 둔다.

### 도움말·업무 안내 (학습 대체)

- 화면별 맥락 도움말과 업무 흐름 안내 문서만 둔다. 진도·채점·이어하기는 없다.
- 원천 문안은 `modules/learning/학습경로_수용기준_FS-004.md`와 `학습과정확장_FS-004a.md`의 **업무 설명 문장**에서 가져온다. 과정 구조·검증 조건·확인 질문은 폐기했다.

### FS-008b 확정 규칙

- 배분량 quantity와 unit, 관측/배분의 채널 단위 포함 복합 FK 유지. owner_module 3개 제거.
- 품목 TAXABLE/ZERO/EXEMPT. 과세율 10% 상수이며 마스터 없음.
- 결제조건·채권/채무 만기는 nullable. 조건 없음으로 거래 확정을 막지 않음. NULL 만기는 만기 미설정 그룹이며 연체 아님.
- 매출 만기는 인식일+N 계산만 허용. 매입은 수기 만기 우선, 없으면 매입일+N, 조건도 없으면 NULL. 확정 시 채무로 복사. 확정 후 불변·소급 금지.
- 설비 동시 점유·패킹 한도·세션 종료 후 게스트 회수는 SERVICE 정책, 실제 동작 미검증.

### ERP 회계 확정 규칙

- 채권은 매출 인식, 채무는 매입 확정과 같은 트랜잭션에서 파생한다. 수기 원장 생성 없음.
- 잔액=원금−SUM(소명액), 상태는 OPEN/PARTIAL/CLOSED로 조회 파생. 잔액·상태·합계 캐시 저장 없음.
- 수금/지급 확정은 금액 고정이다. **확정 이후에도 소명 추가·취소 허용**. 취소는 물리 DELETE이며 core.audit_event가 이력을 보존한다.
- 7단계 잠금은 채권·채무→수금·지급→소명. receivable.id 다음 receipt.id 오름차순이며 지급도 대응 순서다.
- 잠금 후 소명 합계를 새로 계산하여 수금/지급액·채권/채무 원금 양쪽 한도를 SERVICE 정책으로 검사한다.
- 매출 취소는 소명 0행을 전제로 발급대기 세금계산서를 함께 삭제한다. 발급완료이면 취소 금지. 매입 취소는 소명 조건만 적용한다.
- tax_invoice는 매출 전용 최대 1건, 발급대기/발급완료 두 상태. 선발행·명세·월합계·국세청 연동 없음.
- 미리보기는 4거래 유형·7계정·10규칙만. 수금은 receipt_apply 1행, 지급은 payment_apply 1행당 분개 1세트다.
