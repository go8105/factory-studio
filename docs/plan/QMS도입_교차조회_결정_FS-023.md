# FS-023 QMS 도입과 읽기 전용 교차 조회 결정서

작성일: 2026-09-27 (Claude Code)
상태: **제안 — 사용자 승인 대기.** 승인 전에는 `schema.json`·마이그레이션·제품 코드를 바꾸지 않는다.
성격: [FS-013 독립 솔루션 전환 결정서](독립솔루션_전환결정_FS-013.md)의 **범위와 경계 규칙을 일부 바꾸는 결정서.** 충돌하는 부분은 승인 후 이 문서가 우선한다.
관련: [QMS 모듈 설계서](../modules/qms/QMS_모듈설계_FS-023.md) · [QMS 화면 설계](../ui/화면설계_QMS_FS-023.md)

## 1. 배경

MES·ERP·FEMS 1차 범위(47화면 + 포털)가 구현·배포됐다(2026-09-27). 다음 모듈로 사용자가 **QMS를 먼저, 다른 솔루션 데이터는 읽기 전용 조회로** 진행하기로 했다(2026-09-27 대화).

기존 결정과 부딪히는 곳은 두 군데다.

| 기존 | 내용 | 부딪히는 이유 |
|---|---|---|
| 제품 결정표 "설명 카드만" | QMS·WMS·BEMS·SCM은 포털 설명 카드로만 둔다(FS-013 / FS-008a Q2) | QMS를 구현하면 이 목록에서 빠진다 |
| FS-013 D1 | 솔루션 간 경계는 **공통 인증만 공유**. 업무 DB·API·마스터는 독립 | QMS가 MES LOT을 골라 검사하려면 MES 데이터를 읽어야 한다 |

## 2. 결정

| # | 항목 | 결정 |
|---|---|---|
| **D8** | QMS 범위 | **QMS를 구현 솔루션에 넣는다.** 1차는 LOT 단위 **출하 전 최종검사**만 한다(수입검사·공정검사·SPC 제외). 설명 카드는 WMS·BEMS·SCM 3종으로 줄인다 |
| **D9** | 교차 조회 | **다른 솔루션의 데이터를 읽기 전용으로 조회할 수 있다.** 쓰기·스키마 간 FK·다른 스키마 테이블의 직접 SQL 참조는 계속 금지한다. 조회는 제공 솔루션이 공개한 **조회 인터페이스**로만 한다(3장) |
| **D10** | 보류의 효력 | **QMS 보류는 QMS 안에서 기록·표시만 한다.** MES 패킹을 막지 않는다. MES는 조회 인터페이스로 보류 여부를 읽어 **안내 배지**로만 보여 준다 |
| **D11** | 조회 값의 보관 | 조회해 온 값(LOT 번호·품목 코드·수량)은 **코드 문자열·스냅샷으로 복사해 저장**한다. 원본이 나중에 바뀌어도 QMS 기록은 그대로다(기존 "코드 문자열 보관" 규칙과 같다) |
| **D12** | 독립 동작 | **제공 솔루션을 꺼도 QMS는 동작한다.** MES가 꺼져 있으면 조회 대신 LOT·품목 코드를 직접 입력한다. 반대로 QMS를 꺼도 MES는 그대로이며 배지만 사라진다 |

### D9 보충 — 왜 "읽기 전용 인터페이스"인가

- **DB 결합을 만들지 않는다.** FK나 스키마를 넘는 SQL JOIN은 세대 복사·정리 순서와 격리 검사(FS-013 6장)를 무너뜨린다. 인터페이스는 같은 API 서버 안의 **함수 호출**이며 결과는 값(스냅샷)으로만 넘어간다.
- **제공자가 계약을 소유한다.** MES 내부 테이블이 바뀌어도 `fs/mes/interface.py`의 함수 시그니처가 유지되면 QMS는 영향받지 않는다. 실제 운영이라면 이 자리가 시스템 간 API·메시지 인터페이스다.
- **쓰기를 열지 않는다.** 한 솔루션이 다른 솔루션의 상태를 바꾸기 시작하면 트랜잭션·잠금 순서가 스키마를 넘고, 독립 솔루션이라는 설명이 성립하지 않는다.

### D10 보충 — 보류가 패킹을 막지 않는 이유

막으려면 MES 패킹 트랜잭션(TX-10) 안에서 QMS 상태를 확인해야 한다. 이는 MES가 QMS에 **의존**하게 만들고(QMS를 끄면 MES 규칙이 바뀐다), 잠금 순서가 스키마를 넘는다. 1차는 "보류 중인 LOT이 패킹 목록에 **보류 배지**로 보인다"까지로 하고, 실제 통제는 운영 연계 과제로 남긴다. 포털 설명과 도움말에 이 경계를 명시한다.

## 3. 조회 인터페이스 규칙 (D9 구현 규칙)

| # | 규칙 |
|---|---|
| X1 | 제공 솔루션은 `backend/src/fs/<솔루션>/interface.py`에 **읽기 전용 함수**만 공개한다. 반환은 dict/list(값)이며 ORM 객체·커서를 넘기지 않는다 |
| X2 | 소비 솔루션은 다른 솔루션의 `interface.py`만 import한다. `repository.py`·`service.py`·테이블을 직접 쓰지 않는다 |
| X3 | 인터페이스 함수는 호출자의 범위 키 `S`로만 조회한다. 다른 공간·세대 데이터는 보이지 않는다 |
| X4 | 제공 솔루션이 꺼져 있으면(`workspace_module.enabled = false`) 인터페이스는 `None`을 돌려주고, 소비 쪽은 기능을 줄여 동작한다(D12) |
| X5 | 인터페이스 호출은 소비 요청의 트랜잭션 안에서 **읽기만** 한다. 제공 스키마 행을 잠그지 않는다(`FOR UPDATE` 금지) |
| X6 | 조회 결과를 저장할 때는 코드·수량을 스냅샷 컬럼에 복사한다(D11). 제공 솔루션 id를 저장하지 않는다 |

### 격리 검사 확장 (FS-013 6장에 추가)

| # | 규칙 | 위반 시 |
|---|---|---|
| R1 | 업무 스키마 간 FK 0건 — **`qms`를 업무 스키마 목록에 추가** | 오류 |
| R5 | `qms`도 자체 범위 키 보유 | 오류 |
| **R6 (신규)** | `fs/<A>/` 코드가 `fs/<B>/`를 import할 때는 `fs/<B>/interface`만 허용 | 오류 (`tools/audit_schema_isolation.py` 또는 별도 import 검사) |

## 5. 하지 않는 것

- 보류로 MES 패킹·ERP 출하를 **막는 것**(D10).
- 수입검사(구매 자재)·공정 중 검사·SPC 관리도·측정기 검교정·고객 클레임·CAPA.
- QMS 전용 품목 마스터. 품목은 MES 조회 또는 코드 직접 입력으로 스냅샷만 보관한다.
- WMS. 재고 원장 이관은 WMS 설계에서 따로 결정한다.

## 6. 승인 요청 사항

1. D8~D12를 확정해도 되는가.
2. 1차 범위(출하 전 최종검사 · 6화면 · 6테이블)가 적절한가.
3. 승인되면 다음 작업 ID를 **FS-023a(메타데이터·Excel·ERD 반영 + 격리 검사 R6)** → **FS-023b(API·화면 구현)** → **FS-023c(시드·도움말·흐름 맵·통합 검증)** 로 나눈다.
