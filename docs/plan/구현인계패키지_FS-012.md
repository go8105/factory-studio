## 4. 반드시 지킬 것

### 4-1. 설계 불변 규칙 (AGENTS §3)

- 범위 키는 `S = (workspace_id, generation_id)`. 모든 업무 FK는 `(S, 참조id)` 복합 참조
- **업무 스키마 간 FK 0건.** core 참조는 `workspace`·`data_generation` 앵커만
- **`erp/`가 `mes/`를 import 하지 않는다.** FK 규칙의 코드 계층 대응물
- 연·월·주차는 정수가 아니라 문자열(`'YYYY-MM'`, `'YYYY-Www'`) + CHECK
- 참조 삭제는 RESTRICT
- 환산계수(PRIMARY)와 배출계수(EMISSION)를 섞지 않는다
- 확정·게시된 데이터는 변경하지 않는다. 재산정은 새 버전

### 4-2. 저장하지 않기로 한 것

**추가하고 싶어지는 순간이 반드시 온다. 그때 이 목록을 본다.**

| 대상 | 이유 |
|---|---|
| 채권·채무 **잔액** 컬럼 | 원금 − Σ소명액으로 산출. 진실이 두 곳이 되면 어긋났을 때 판정 불가 |
| 채권·채무 **상태** 컬럼 | 잔액에서 파생 |
| 견적 **최신 여부** 플래그 | `MAX(revision_no)`로 파생 |
| 분개 **결과·전표·총계정원장** | 미리보기는 계산만 |
| 배출량·요금 **산출 결과** | 조회 시 계산 |
| 1차에너지 **환산 결과** | 조회 시 계산 |

성능을 이유로 캐시 컬럼을 추가하지 않는다. **실측 후 병목이 증명되면 그때 다시 판단한다.**

### 4-3. 범위 밖

결산·재무제표·원가계산·고정자산·예산 / 구매발주·입고검수 / 대손·역분개·선수금·외화·전자세금계산서 연동 / 품질검사(QMS)·재고원장(WMS)·건물에너지(BEMS)·공급망(SCM) / 계측 수집 파이프라인·MQTT·알람 서버 / LOT 분할 생산 / 설비 상태·가동률 / 학습 과정·진도·채점

**이 목록은 "못 만든 것"이 아니라 "안 만들기로 한 것"이다.** 화면에 제외 사유를 안내한다. 감추면 결함으로, 적으면 범위 판단으로 읽힌다.

## 5. 검증 방법

### 5-1. 매 작업마다

```
npm run db:validate                        메타데이터 정합성
python3 tools/audit_schema_isolation.py    R1~R5 격리
python3 -m unittest discover -s tools      변환 회귀
pytest                                     백엔드 테스트
```

스키마를 바꾸면 **같은 작업에서** `schema.json` · `DB설계서.xlsx` · ERD를 함께 갱신한다(AGENTS §4).

### 5-2. SERVICE 정책 7건 (FS-021)

DB가 막아주지 않으므로 전부 통합 테스트로 검증한다.

| 정책 | 검증 방법 |
|---|---|
| **범위 격리** | 다른 공간의 자원 ID로 요청 → 404. **최우선** |
| Σ소명액 ≤ 수금액·채권 원금 | 초과 요청 409 + 아무것도 저장 안 됨 |
| 배정 합계 ≤ 계획·수주 수량 | 동일 |
| 패킹 수량 ≤ LOT 양품 | 동일 |
| 설비 동시 점유 금지 | **동시 요청 주입.** 하나만 성공 |
| 매출 취소 조건 | 소명 존재 시 거부 / 발급완료 세금계산서 시 거부 |
| 멱등키 | 같은 키 재요청 = 같은 응답 / 다른 본문 = 422 / 24시간 초과 = 422 |

**순차 호출로는 잠금이 동작하는지 알 수 없다.** 동시성 주입이 없으면 이 검증은 통과해도 의미가 없다.

### 5-3. 실측해야 하는 것

설계 내내 목표값만 있고 측정한 적이 없다.

| 항목 | 목표 | 상태 |
|---|---|---|
| 게스트 세대 복사 | 2초 | 미측정. `statement_timeout 10초` 부족 우려 |
| 첫 화면 표시 | 3초 | 미측정 |
| 동시 게스트 | 20명 | 미측정 |

**FS-015에서 복사 시간을 먼저 재고, 목표를 못 맞추면 그때 대책을 논의한다.** 미리 비동기 큐를 만들지 않는다.

## 6. 세션 운영 규칙

- **작업 ID 하나씩.** 결과를 보고하고 사용자 확인을 기다린다. 확인 전 다음 ID를 시작하지 않는다.
- 기획·방향 제시에 바로 착수하지 않는다. 누락·모순·리스크를 먼저 역질문한다.
- 답변은 **[기획 의도 검토] → [예상 문제점/제약] → [질문] → [권장안]** 순서.
- **미실행 검증을 완료로 표시하지 않는다.** 무엇을 검증했고 무엇을 하지 않았는지 명시한다.
- 없는 라이브러리·기능을 있는 것처럼 제안하지 않는다.
- 문서 용어는 '제언'·'권고' 대신 **'제안'**으로 통일한다.
- 복잡한 계산 로직(잔액 산출·1차에너지 환산·분개 적용·배분 방법)에는 **한글 주석**을 단다.
- 사용자가 수정한 UI 파일을 임의로 덮어쓰지 않는다.
- **작업이 끝나면 `plan/현재기획_진행현황.md`와 `progress.md`를 함께 갱신한다.** 갱신하지 않은 작업은 완료가 아니다.

### 공개 배포 시 대비할 것

게스트 체험이 있으므로 누구나 공간을 생성할 수 있다.

- **게스트 공간 전역 상한**이 이미 설계에 있다(FS-006b). 실제 수치를 여기서 정한다
- 만료 게스트 회수 배치가 돌아야 한다. 안 돌면 디스크가 찬다
- 게스트 생성에 레이트 리밋. IP 단위 정도면 충분하다
- HTTPS 필수. 세션 쿠키가 `Secure`다
- **백업은 하지 않는다.** 합성 데이터뿐이고 유실돼도 시드로 재생성된다
