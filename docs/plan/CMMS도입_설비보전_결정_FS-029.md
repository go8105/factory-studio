## 1. 배경

| 지금 | 상태 |
|---|---|
| 설비 정보 | MES 설비 8대(사출 INJ-01~03, 조립 ASM-01~03, 검사 INS-01~02)와 공정·설비 연결만 있다. **고장·정지·보전 기록은 어디에도 없다** |
| 경보 | BEMS가 환경 경보(구역·센서 단위, 발생 → 확인 → 해제)를 만든다. 확인 뒤 "누가 무엇을 고쳤는가"는 남지 않는다. FEMS에는 경보가 없다 |
| 품질 신호 | SPC가 설비 코드가 붙은 이상 기록을 만든다(예: LT-0017 · INJ-02 사출 추세). 원인이 설비라면 이어 받을 곳이 없다 |
| 공조기 | BEMS 공조기 2대(AHU-OFF·AHU-PRD)는 운전 상태만 있고 점검 이력은 없다 |

CMMS는 이 신호들을 **보전 작업지시**로 받아 고장 접수 → 작업 → 완료까지 기록하고, 설비별 MTBF·MTTR·예방보전 준수율을 보여 준다. "경보가 울렸다"에서 "정비했다"로 이어지는 흐름이 SPC·BEMS 다음 솔루션으로 가장 짧다(로드맵 §2).

## 2. 결정

| # | 항목 | 결정 |
|---|---|---|
| **D45** | CMMS 범위 | **CMMS를 구현 솔루션에 넣는다(스키마 `cmms`, 모듈 키 `cmms`, 화면 접두어 `C`).** 1차는 ① 설비 대장 ② 예방보전(PM) 계획·주기 도래 작업지시 ③ 고장 접수·작업지시(접수 → 진행 → 완료) ④ 작업 기록(작업 시간·원인·조치·사용 부품) ⑤ 예비품 목록과 사용 기록 ⑥ 지표 MTBF·MTTR·PM 준수율 |
| **D46** | 설비 대장 소유 | **설비 대장은 CMMS가 소유한다**(FS-013 D1). 출처는 `MES`(설비 코드 스냅샷) · `BEMS`(공조기 코드 스냅샷) · `CMMS`(직접 등록, 예: 공용 압축기). MES·BEMS에서 **가져오기**로 등록하고, 원천이 바뀌어도 대장은 그대로 둔다(스냅샷) |
| **D47** | 작업지시 상태 | `REQUESTED`(접수) → `IN_PROGRESS`(작업 시작) → `COMPLETED`(완료) 또는 `CANCELLED`(취소, 사유). 완료에는 원인 분류(마모·윤활·전기·설정·외부·기타)와 조치 내용이 필요하고, **완료·취소 뒤 불변**이다. 고장(BM) 작업지시에는 설비 정지 시작(고장 시각)·정지 종료(복구 시각)를 기록한다 |
| **D48** | 신호 → 작업지시 | 신호를 **읽기 전용 조회로 받아 작업지시로 전환**한다. 출처는 ① BEMS 경보(발생·확인 상태) ② SPC 이상(원인 분류가 설비이거나 미조치인 것, 설비 코드 포함) ③ 수동 접수. 원천 코드(경보 id·이상 id)를 스냅샷으로 남겨 같은 신호의 중복 전환을 막는다. **CMMS는 BEMS 경보·SPC 이상의 상태를 바꾸지 않는다**(확인·조치는 각 솔루션에서) |
| **D49** | 예방보전(PM) | 설비별 PM 계획: 점검 항목·주기(일 단위)·마지막 수행일. **주기 도래(업무 기준일 ≥ 다음 예정일) 계획은 사람이 "작업지시 생성"을 눌러 만든다**(자동 생성 작업 없음 — 배경 작업·시계 없이 결정적). PM 작업지시를 완료하면 마지막 수행일이 갱신된다 |
| **D50** | 예비품 | 예비품 목록(코드·이름·단위·안전 재고)과 **작업지시별 사용 기록**만 둔다. 재고 원장은 만들지 않는다(재고는 WMS 소유 — FS-024 D13). 안전 재고 미만 표시는 "사용 누적 기준 참고값"이다. **WMS 재고 조회·ELB 구매 요청은 하지 않는다**(로드맵 §6-4: ELB/MRO 사이클에서) |
| **D51** | 지표 | 조회할 때 계산한다. **MTBF** = 기간 가동 시간 ÷ 고장 건수, **MTTR** = 고장 정지 시간 합 ÷ 고장 건수(완료된 BM만), **PM 준수율** = 기한 안 완료 PM ÷ 기한 도래 PM. 가동 시간은 1차에서 "기간 × 24h − 정지 시간"(교대·계획 정지 없음) |
| **D52** | MES 연계 | CMMS는 진행 중 고장 작업지시가 있는 설비 코드를 **조회로만** 내놓는다. MES 공정 실행·설비 화면에 **"보전 중" 배지**만 표시하고, MES 실행을 막지 않는다(QMS 보류·SPC 이상과 같은 방식). MES는 동결 상태지만 이 배지는 이웃 변경이다 |

### D48 보충 — 왜 "전환"인가

경보·이상이 생길 때마다 작업지시가 자동으로 생기면, 진동처럼 반복되는 경보가 작업지시를 쌓는다. 실제 보전 현장도 보전 담당이 신호를 보고 접수 여부를 정한다. 그래서 CMMS는 **"전환 대기 신호"** 목록을 보여 주고 사람이 작업지시로 바꾼다. 한 신호는 한 번만 전환된다.

## 3. 교차 조회 인터페이스 (D9 규칙 그대로)

| 제공 | 함수 | 용도 |
|---|---|---|
| MES `fs/mes/interface.py` **(추가)** | `equipment()` → `[{equipmentCode, name, equipmentType, locationCode, isActive}]` | 설비 대장 가져오기 |
| BEMS `fs/bems/interface.py` **(신규 파일)** | `enabled()` · `hvac_units()` → `[{code, name, zoneCode}]` · `active_alarms()` → `[{alarmId, zoneCode, metric, severity, status, raisedAt, peakValue}]`(해제 전) | 공조기 대장 가져오기, 전환 대기 신호 |
| SPC `fs/spc/interface.py` **(추가)** | `equipment_signals()` → `[{signalId, equipmentCode, lotNo, characteristic, rule, status, detectedAt}]`(미조치 + 원인 "설비" 조치 완료 최근 30일) | 전환 대기 신호 |
| CMMS `fs/cmms/interface.py` **(신규)** | `enabled()` · `equipment_in_maintenance(codes)` → 진행 중 고장 작업지시가 있는 설비 코드 집합 | MES "보전 중" 배지 |

MES·BEMS·SPC는 동결 상태지만 조회 함수 추가는 허용한다(로드맵 §3). 각 README "제공 조회 함수" 표를 같은 커밋에서 갱신한다. 제공 솔루션이 꺼져 있으면 그 출처만 비고 CMMS는 그대로 동작한다.

## 5. 하지 않는 것

- 설비 IoT·PLC 연동, 진동·온도 센서 실시간 감시, 예지보전(AI·상태 기반).
- 작업자 배정·근무 일정·작업 허가(LOTO)·안전 점검표.
- 예비품 재고 원장·발주·입고(WMS·ELB/MRO 영역), 외주 보전 계약·비용 정산.
- 작업지시 자동 생성(배경 작업), 알림 발송.
- 교대·계획 정지를 반영한 가동 시간, OEE.
- MES 실행을 막는 설비 잠금.

## 6. 승인 요청 사항

1. D45~D52를 확정해도 되는가.
2. **신호 출처에 SPC 이상을 넣는 것**(D48 ②) — SPC → CMMS → MES로 세 솔루션이 이어지는 시연이 생긴다(예: LT-0017 INJ-02 사출 추세 → "INJ-02 냉각수 유량 점검" 고장 작업지시 → MES "보전 중"). 넣지 않으면 BEMS 경보·수동 접수만 남는다.
3. **예비품은 CMMS 안의 목록·사용 기록까지**(D50) — WMS 재고 조회·구매 요청은 ELB/MRO(로드맵 8번)에서 붙인다.
4. **MES "보전 중" 배지**(D52)를 이 사이클에 넣어도 되는가(MES는 동결 상태).
