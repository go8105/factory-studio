# FS-022 배포 절차서 — Vultr VM · Nginx (도메인 전 IP 단계 → 도메인·HTTPS 단계)

작성일: 2026-09-26 · 작성 Claude Code · 기준 main (FS-021 + 3D 공장 고도화 통합)

이 문서는 **사람이 서버에서 직접 실행하는 절차**다. Claude Code는 서버에 접속하지 않는다(사용자 결정 2026-09-26). 명령은 Ubuntu 24.04 LTS 기준이며, 다른 배포판이면 패키지 명령만 바꾼다.

도메인이 아직 없으므로 두 단계로 나눈다.

| 단계 | 접속 | 목적 |
|---|---|---|
| **A. IP 단계**(지금) | `http://<서버IP>` | 서버에서 앱 전체가 뜨는지 확인. 본인·지인만 접속 |
| **B. 도메인 단계**(도메인 구매 후) | `https://<도메인>` | 공개. HTTPS와 Secure 쿠키 |

> **A 단계는 공개 운영이 아니다.** HTTPS가 없어 세션 쿠키의 `Secure`를 끄고(`COOKIE_SECURE=false`) 운영한다. 주소를 널리 공유하지 않고, B 단계에서 반드시 되돌린다(FS-012 §7 "HTTPS 필수").

---

## 0. 구성 한눈에

```
브라우저 ──80/443──▶ Nginx ─┬─ /            → /srv/factory-studio/frontend/dist (정적, SPA)
                            └─ /api/        → 127.0.0.1:8000 uvicorn (systemd: factory-studio-api)
                                                    │
                                                    └─▶ PostgreSQL 18 (Docker, 127.0.0.1:55432)
타이머: factory-studio-cleanup.timer (15분마다 만료 게스트 회수)
```

- DB 포트와 API 포트는 **127.0.0.1에만** 연다. 밖에서는 80/443만 보인다.
- 백업은 하지 않는다. 합성 데이터뿐이고 시드로 다시 만든다(FS-012 §7).

## 1. 서버 준비 (A·B 공통, 한 번)

```bash
sudo apt update && sudo apt -y upgrade
sudo apt -y install git nginx ufw curl ca-certificates
# 방화벽: SSH·HTTP·HTTPS만
sudo ufw allow OpenSSH && sudo ufw allow 'Nginx Full' && sudo ufw --force enable
```

Docker(DB용):

```bash
curl -fsSL https://get.docker.com | sudo sh
sudo usermod -aG docker $USER   # 다시 로그인해야 적용
```

Node 24와 uv(파이썬 도구):

```bash
curl -fsSL https://deb.nodesource.com/setup_24.x | sudo -E bash - && sudo apt -y install nodejs
curl -LsSf https://astral.sh/uv/install.sh | sh   # ~/.local/bin/uv
node --version   # v24.x 확인
```

앱 전용 사용자와 폴더:

```bash
sudo useradd --system --create-home --home-dir /srv/factory-studio --shell /usr/sbin/nologin factory
sudo -u factory git clone https://github.com/go8105/factory-studio.git /srv/factory-studio/app
```

> 저장소가 비공개면 배포 키(읽기 전용 deploy key)를 `factory` 사용자에 등록한 뒤 SSH 주소로 clone한다.

## 2. 환경 변수 파일

`/srv/factory-studio/app/.env` (소유자 factory, 권한 600). **값은 서버에서 새로 만든다. 로컬 .env를 복사하지 않는다.**

```bash
cd /srv/factory-studio/app
sudo -u factory tee .env >/dev/null <<EOF
POSTGRES_PASSWORD=$(openssl rand -hex 24)
POSTGRES_PORT=55432
SESSION_SECRET=$(openssl rand -base64 48 | tr -d '\n')
GUEST_LIMIT=20
COOKIE_SECURE=false
EOF
# DATABASE_URL은 위 비밀번호로 만든다
PW=$(sudo -u factory grep ^POSTGRES_PASSWORD= .env | cut -d= -f2)
echo "DATABASE_URL=postgresql+psycopg://factory_studio:${PW}@127.0.0.1:55432/factory_studio" | sudo -u factory tee -a .env >/dev/null
sudo chmod 600 .env
```

- `COOKIE_SECURE=false`는 **A 단계에서만**. B 단계 5-3에서 줄을 지운다(기본값 true).
- `FS_TODAY`는 **넣지 않는다**(테스트용 날짜 고정). 운영은 실제 오늘(Asia/Seoul) 기준이다.
- `GUEST_LIMIT=20`은 FS-021 실측 기준(동시 20명 성공, 같은 순간 몰리면 생성 대기 최대 약 14초).

## 3. DB·백엔드

DB 기동:

```bash
cd /srv/factory-studio/app
sudo -u factory docker compose --env-file .env up -d db
sudo -u factory docker compose ps   # db healthy 확인
```

> `factory` 사용자가 docker를 쓰려면 `sudo usermod -aG docker factory` 후 적용. 또는 compose 명령만 관리자 계정으로 실행해도 된다(데이터 볼륨은 docker가 관리).

의존성 설치·마이그레이션·템플릿 시드:

```bash
cd /srv/factory-studio/app
UV=/srv/factory-studio/.local/bin/uv   # factory 사용자에 uv를 설치했다면. 아니면 관리자 uv 경로
sudo -u factory $UV sync --project backend --frozen
sudo -u factory $UV run --project backend --env-file .env alembic -c backend/alembic.ini upgrade head
sudo -u factory $UV run --project backend --env-file .env python -m seed.cli template --date $(TZ=Asia/Seoul date +%F)
```

- 템플릿은 **한 번만** 만든다. 다시 만들 때는 DB를 비우고(`docker compose down -v` 후 3장 반복) 실행한다.
- 게스트 공간은 템플릿을 복사할 때 날짜를 그날 기준으로 옮긴다.

API 서비스 `/etc/systemd/system/factory-studio-api.service`:

```ini
[Unit]
Description=Factory Studio API
After=network-online.target docker.service
Wants=network-online.target

[Service]
User=factory
WorkingDirectory=/srv/factory-studio/app
ExecStart=/srv/factory-studio/.local/bin/uv run --project backend --env-file .env uvicorn fs.main:app --host 127.0.0.1 --port 8000 --proxy-headers --forwarded-allow-ips=127.0.0.1
Restart=on-failure
RestartSec=3

[Install]
WantedBy=multi-user.target
```

```bash
sudo systemctl daemon-reload && sudo systemctl enable --now factory-studio-api
curl -s -o /dev/null -w '%{http_code}\n' http://127.0.0.1:8000/api/v1/core/sessions/current   # 401이면 정상(세션 없음)
```

만료 게스트 회수 타이머(안 돌면 디스크가 찬다, FS-012 §7):

`/etc/systemd/system/factory-studio-cleanup.service`

```ini
[Unit]
Description=Factory Studio expired guest cleanup

[Service]
Type=oneshot
User=factory
WorkingDirectory=/srv/factory-studio/app
ExecStart=/srv/factory-studio/.local/bin/uv run --project backend --env-file .env python -m fs.core.cleanup
```

`/etc/systemd/system/factory-studio-cleanup.timer`

```ini
[Unit]
Description=Run Factory Studio cleanup every 15 minutes

[Timer]
OnBootSec=5min
OnUnitActiveSec=15min

[Install]
WantedBy=timers.target
```

```bash
sudo systemctl daemon-reload && sudo systemctl enable --now factory-studio-cleanup.timer
sudo systemctl start factory-studio-cleanup && journalctl -u factory-studio-cleanup -n 5   # cleaned_guest_workspaces=0
```

## 4. 프런트 빌드와 Nginx (A 단계: IP, HTTP)

```bash
cd /srv/factory-studio/app
sudo -u factory npm --prefix frontend ci
sudo -u factory npm --prefix frontend run build   # frontend/dist 생성
```

`/etc/nginx/sites-available/factory-studio`:

```nginx
# 게스트 생성 레이트 리밋: IP당 분당 6회(FS-012 §7 "IP 단위 정도면 충분")
limit_req_zone $binary_remote_addr zone=guest_create:10m rate=6r/m;

server {
    listen 80 default_server;
    server_name _;

    root /srv/factory-studio/app/frontend/dist;
    index index.html;

    # 해시가 붙은 빌드 파일은 오래 캐시, 3D 모델은 하루
    location /assets/ { expires 30d; add_header Cache-Control "public, immutable"; }
    location /models/ { expires 1d; }

    location = /api/v1/core/guest-sessions {
        limit_req zone=guest_create burst=3 nodelay;
        limit_req_status 429;
        proxy_pass http://127.0.0.1:8000;
        include /etc/nginx/proxy_params;
    }
    location /api/ {
        proxy_pass http://127.0.0.1:8000;
        include /etc/nginx/proxy_params;
        proxy_read_timeout 60s;
    }
    # SPA: 모르는 경로는 index.html (React Router)
    location / { try_files $uri /index.html; }

    client_max_body_size 1m;
}
```

```bash
sudo ln -sf /etc/nginx/sites-available/factory-studio /etc/nginx/sites-enabled/factory-studio
sudo rm -f /etc/nginx/sites-enabled/default
sudo nginx -t && sudo systemctl reload nginx
sudo chmod o+x /srv/factory-studio /srv/factory-studio/app /srv/factory-studio/app/frontend   # nginx가 dist를 읽도록
```

### A 단계 확인 (FS-012 완료 조건: 게스트 진입 → 세 솔루션 진입)

브라우저에서 `http://<서버IP>`:

1. "가입 없이 둘러보기" → 앱 런처가 뜬다(첫 화면 3초 이내 목표, FS-021 로컬 실측 약 1초).
2. 런처에서 **FEMS·MES·ERP**를 각각 연다 → 각 대시보드에 시드 숫자가 보인다.
3. `/factory` 3D 공장이 열리고 외관↔내부 전환이 된다.
4. ERP 견적 한 건 만들기 → 새로고침 후에도 남아 있다(세션 쿠키가 HTTP에서 유지되는지 = `COOKIE_SECURE=false` 확인).
5. 서버에서 `journalctl -u factory-studio-api -n 50`에 500 오류가 없다.

## 5. B 단계: 도메인 연결과 HTTPS (도메인 구매 후)

5-1. DNS: 도메인 관리 화면에서 `A 레코드 @ → <서버IP>`(필요하면 `www`도). 전파 확인 `dig +short <도메인>`.

5-2. Nginx `server_name _;` → `server_name <도메인> www.<도메인>;` 로 바꾸고 `sudo nginx -t && sudo systemctl reload nginx`.

5-3. 인증서(Let's Encrypt, certbot이 443 블록과 80→443 리다이렉트를 추가):

```bash
sudo apt -y install certbot python3-certbot-nginx
sudo certbot --nginx -d <도메인> -d www.<도메인> --redirect -m <이메일> --agree-tos
sudo systemctl list-timers | grep certbot   # 자동 갱신 타이머 확인
```

5-4. **Secure 쿠키 되돌리기**: `.env`에서 `COOKIE_SECURE=false` 줄을 지우고 `sudo systemctl restart factory-studio-api`. 브라우저 개발자 도구에서 `fs_session` 쿠키에 Secure·HttpOnly가 붙었는지 확인.

5-5. 4장 확인 1~5를 `https://<도메인>`에서 다시 한다. `http://`로 접속하면 https로 넘어가야 한다.

## 6. 업데이트 배포 (main에 새 커밋이 들어온 뒤)

```bash
cd /srv/factory-studio/app
sudo -u factory git pull --ff-only
sudo -u factory $UV sync --project backend --frozen
sudo -u factory $UV run --project backend --env-file .env alembic -c backend/alembic.ini upgrade head
sudo -u factory npm --prefix frontend ci && sudo -u factory npm --prefix frontend run build
sudo systemctl restart factory-studio-api
```

- 스키마가 바뀐 배포(새 마이그레이션)는 게스트 데이터가 예전 템플릿 복사본이다. 필요하면 DB를 비우고 3장 시드부터 다시 한다(합성 데이터, 백업 없음).
- 되돌리기: `git checkout <이전 커밋>` 후 같은 절차. 마이그레이션을 되돌려야 하면 DB를 비우고 다시 만든다.

## 7. 운영 점검

| 무엇 | 명령 |
|---|---|
| API 상태·로그 | `systemctl status factory-studio-api` · `journalctl -u factory-studio-api -f` |
| 회수 타이머 | `systemctl list-timers | grep factory` · `journalctl -u factory-studio-cleanup -n 20` |
| 게스트 수 | `docker compose exec db psql -U factory_studio -d factory_studio -c "select count(*) from core.workspace where workspace_kind='GUEST'"` |
| 디스크 | `df -h` · `docker system df` |
| Nginx | `sudo tail -f /var/log/nginx/access.log /var/log/nginx/error.log` |

## 8. 이 절차서가 하지 않은 것

- 서버 접속·실행 자체(사용자 결정). 명령은 검토했지만 **실제 Vultr VM에서 실행해 보지 않았다.**
- 도메인 구매·DNS(B 단계는 도메인이 생긴 뒤).
- 컨테이너 이미지로 앱을 묶는 것(Dockerfile). 지금은 DB만 컨테이너, 앱은 systemd. 필요해지면 후속 작업으로 제안한다.
- 모니터링·알림, 보안 점검(FS-012 §8 미해결 항목).
