# FS-022 배포 절차서 — Vultr VM · Nginx (이지스 공존판)

작성일: 2026-09-26 · 원본 작성 Claude Code · 공존 수정 Claude (chat) · 보완 Claude Code(apt upgrade 제외·맥북 빌드 기본·uv --frozen·스왑) · 기준 main (FS-021 + 3D 공장 고도화 통합)

이 문서는 **사람이 서버에서 직접 실행하는 절차**다. Claude Code는 서버에 접속하지 않는다(사용자 결정 2026-09-26).

**대상 서버는 이지스(AI 비서)가 이미 운영 중인 Vultr 서버 `158.247.236.136`이다**(secretary-ai-server, 서울, 1 vCPU · RAM 2GB · SSD 55GB · Ubuntu 24.04, Vultr 자동 백업 꺼짐 — 2026-09-26 콘솔 확인). 모든 단계의 목표는 "FS를 올리되 이지스는 한 번도 멈추지 않는 것"이다. 각 장 끝의 **이지스 생존 확인**을 건너뛰지 않는다.

| 단계 | 접속 | 목적 |
|---|---|---|
| **A. IP 단계**(지금) | `http://158.247.236.136:8080` | FS 전체가 뜨는지 확인. 본인·지인만 접속 |
| **B. 도메인 단계**(도메인 구매 후) | `https://fs.<도메인>` | 공개. HTTPS와 Secure 쿠키 |

> **A 단계는 공개 운영이 아니다.** HTTPS가 없어 `COOKIE_SECURE=false`로 운영한다. B 단계에서 반드시 되돌린다(FS-012 §7 "HTTPS 필수").

## 0. 구성 한눈에 (공존 후)

```
                     ┌─ :80   (기존 default 사이트) → /var/www/html/office.html        [이지스, 변경 없음]
브라우저 ─▶ Nginx ───┤
                     └─ :8080 (factory-studio 사이트) ─┬─ /      → frontend/dist (SPA)  [FS]
                                                       └─ /api/  → 127.0.0.1:8021 uvicorn

브라우저 ─▶ :8000 secretary-api (이지스, 외부 직접 호출 — 이번엔 유지, 후속 작업에서 닫음)

PostgreSQL 16 (호스트, :5432, secretary DB)      [이지스]
PostgreSQL 18 (Docker, 127.0.0.1:55432)           [FS]
Tailscale(100.72.70.64) + Syncthing              [이지스 문서 동기화]
```

### 포트 배정

| 포트 | 주인 | 외부 공개 | 비고 |
|---|---|---|---|
| 80 | 이지스 office.html | O | 기존 그대로 |
| 8000 | 이지스 secretary-api | O (임시) | office.html이 직접 호출. 닫는 건 별도 작업 |
| **8080** | **FS Nginx** | O (A 단계만) | B 단계에서 서브도메인 :443으로 이동 후 닫음 |
| **8021** | **FS uvicorn** | X (127.0.0.1) | 원본의 8000에서 변경 — 이지스와 충돌 |
| 5432 | 이지스 PostgreSQL | X | |
| 55432 | FS PostgreSQL(Docker) | X (127.0.0.1) | compose 바인드 확인 필수(3장) |
| 8384 / 22000 | Syncthing | Tailscale 경유 | ufw에서 tailscale0 허용 |

### 원본 대비 변경점

| 원본 | 공존판 | 이유 |
|---|---|---|
| uvicorn `:8000` | `:8021` | 이지스 secretary-api가 8000 사용 |
| Nginx `listen 80 default_server`, default 사이트 삭제 | `listen 8080`, **default 삭제 안 함** | 이지스 office.html이 default 사이트 |
| ufw: SSH·HTTP·HTTPS만 | + 8000(임시), 8080, tailscale0 | 켜는 순간 이지스·Syncthing이 끊기지 않도록 |
| uv 경로 `/srv/factory-studio/.local/bin/uv` | `/usr/local/bin/uv` | 관리자 설치 uv는 `/root` 아래라 factory가 못 읽음 |
| `sudo -u factory` | `sudo -u factory -H` | HOME이 root로 남아 uv 캐시가 `/root`로 가는 것 방지 |
| `docker compose`를 factory로 실행 | root로 실행 | docker 그룹은 root와 동급 권한. factory에 줄 이유가 없음 |
| `apt update && apt upgrade` | `apt update`만 | 전체 업그레이드가 이지스 nginx·PostgreSQL 16을 재시작할 수 있음. FS에 필요한 것은 설치뿐 |
| 서버에서 Vite 빌드 | **맥북에서 빌드 → `dist`만 rsync**(서버에 Node 불필요) | RAM 2GB·1 vCPU에서 3D 번들 빌드는 메모리를 크게 써 이지스가 OOM으로 죽을 수 있음 |
| systemd `uv run` | `uv run --frozen` | 서비스 시작 때 잠금 파일·가상환경을 다시 맞추지 않게 |

## 0-1. 사전 점검 (필수, 결과가 기준에 못 미치면 멈춘다)

**Vultr 콘솔에서 스냅샷부터 찍는다.** 이지스(회사 메일 포함) 운영 서버이므로 되돌릴 지점이 없으면 시작하지 않는다.

```bash

ss -tlnp | grep -E ':(80|443|8000|8021|8080|5432|55432|8384|22000)\b'

systemctl list-units --type=service | grep -i sync
```

| 확인 항목 | 통과 기준 | 미달 시 |
|---|---|---|
| RAM (`free -h` total) | **2GB 이상** | 1GB면 멈춘다. 요금제 상향 또는 0-3의 경량안 선택 |
| RAM 여유 (`free -h` available) | **900MB 이상** | 이지스가 이미 많이 쓰고 있다. FS(Docker·PG18·uvicorn) 약 500~700MB를 더 쓴다. 미달이면 요금제 상향 |
| 스왑 (`swapon --show`) | 1GB 이상 있음 | 없으면 0-2에서 2GB 스왑 파일을 만든다(OOM 시 이지스가 먼저 죽지 않게 하는 안전판) |
| 디스크 여유 | 10GB 이상 | Docker 이미지·node_modules·빌드 산출물 |
| 8021·8080·55432 | 비어 있음 | 사용 중인 프로세스 확인 후 포트 재배정 |
| sites-enabled | `default`만 있음 | 다른 사이트가 있으면 80/8080 중복 여부 확인 |
| ufw | `inactive` 예상 | 이미 active면 기존 규칙을 기록해 두고 1장에서 추가만 한다 |
| 이지스 서비스 | 모두 `active` | 먼저 이지스부터 정상화 |
| `getent hosts` | 3줄 모두 IP가 나옴 | Tailscale MagicDNS 문제(9/20 기록). `tailscale set --accept-dns=false` 후 재확인 |

**이지스 생존 기준선**(이후 장마다 같은 명령으로 비교):

## 0-2. 스왑 파일 (0-1에서 스왑이 없을 때만)


## 0-3. RAM 1GB일 때의 경량안 (2GB 이상이면 건너뛴다)

1GB에서 Docker 데몬 + PG18 + uvicorn 2개 + Vite 빌드는 OOM으로 **이지스 프로세스가 죽을 수 있다.** 선택지:

| 안 | 내용 | 대가 |
|---|---|---|
| **1 (제안)** | Vultr 요금제 2GB로 상향 (스냅샷 후). 디스크는 되돌릴 수 없음 | 월 비용 증가 |
| 2 | (이제 기본 절차) 프런트 빌드를 맥북에서 하고 `dist`만 rsync (4-1) | 배포 절차가 맥북 의존 |
| 3 | Docker 없이 기존 호스트 PostgreSQL 16에 `factory_studio` DB·계정 추가 | PG18 전용 문법·기능을 쓰는지 먼저 확인해야 함 |

## 1. 서버 준비 (한 번)

```bash
sudo apt update
sudo apt -y install git nginx ufw curl ca-certificates rsync
```

> **`apt upgrade`는 하지 않는다.** 전체 업그레이드는 이지스의 nginx·PostgreSQL 16을 재시작할 수 있다. 보안 업데이트는 이지스 점검 시간에 따로 한다(이 절차의 범위 밖).

**방화벽** — 규칙을 모두 넣은 뒤 마지막에 enable한다(순서 바꾸면 SSH가 끊길 수 있음).

```bash
sudo ufw allow OpenSSH
sudo ufw allow 'Nginx Full'          # 80, 443
sudo ufw allow 8080/tcp              # FS A 단계
sudo ufw allow 8000/tcp              # 이지스 API — office.html 직접 호출 유지(임시)
sudo ufw allow in on tailscale0      # Syncthing·Tailscale 경유 접속
sudo ufw allow 41641/udp             # Tailscale 직접 연결(없으면 릴레이로 느려짐)
sudo ufw --force enable
sudo ufw status numbered
```

Docker(FS DB용):

```bash
curl -fsSL https://get.docker.com | sudo sh
docker --version
```

> Docker는 iptables 규칙을 직접 추가하며, **Docker가 공개한 포트는 ufw 규칙을 우회한다.** 그래서 3장에서 DB 포트가 127.0.0.1에만 바인드되는지 반드시 확인한다.

uv (**모든 사용자가 쓰는 경로**에 설치). **Node는 서버에 설치하지 않는다** — 프런트는 맥북에서 빌드한다(4-1):

앱 전용 사용자와 폴더:

## 2. 환경 변수 파일

`/srv/factory-studio/app/.env` (소유자 factory, 권한 600). **값은 서버에서 새로 만든다. 로컬 .env를 복사하지 않는다**(이지스에서 rsync로 서버 .env가 덮인 사고와 같은 이유).

```bash
cd /srv/factory-studio/app
sudo -u factory -H tee .env >/dev/null <<EOF
POSTGRES_PASSWORD=$(openssl rand -hex 24)
POSTGRES_PORT=55432
SESSION_SECRET=$(openssl rand -base64 48 | tr -d '\n')
GUEST_LIMIT=20
COOKIE_SECURE=false
EOF
PW=$(sudo -u factory grep ^POSTGRES_PASSWORD= .env | cut -d= -f2)
echo "DATABASE_URL=postgresql+psycopg://factory_studio:${PW}@127.0.0.1:55432/factory_studio" | sudo -u factory -H tee -a .env >/dev/null
sudo chmod 600 .env
```

- `COOKIE_SECURE=false`는 **A 단계에서만**. B 단계 5-4에서 줄을 지운다(기본값 true).
- `FS_TODAY`는 넣지 않는다(테스트용 날짜 고정).
- `GUEST_LIMIT=20`은 FS-021 실측 기준.
- 참고: 쿠키는 포트를 구분하지 않으므로 `fs_session` 쿠키가 같은 IP의 이지스(:80, :8000) 요청에도 실린다. 이지스는 쿠키를 쓰지 않아 동작에는 영향 없음. B 단계에서 서브도메인으로 분리되면 사라진다.

## 3. DB·백엔드

**DB 포트 바인드부터 확인** (기동 전):

```bash
cd /srv/factory-studio/app
sudo docker compose --env-file .env config | grep -A4 'ports:'
```

출력의 `host_ip`가 `127.0.0.1`이어야 한다. 없거나 `0.0.0.0`이면 **기동하지 말고** compose 파일의 포트를 `"127.0.0.1:${POSTGRES_PORT}:5432"`로 고친 뒤(저장소에 커밋) 진행한다.

DB 기동:

```bash
sudo docker compose --env-file .env up -d db
sudo docker compose ps                        # db healthy
ss -tlnp | grep 55432                         # 127.0.0.1:55432 만 보여야 함
```

의존성 설치·마이그레이션·템플릿 시드:

```bash
cd /srv/factory-studio/app
UV=/usr/local/bin/uv
sudo -u factory -H $UV sync --project backend --frozen
sudo -u factory -H $UV run --project backend --env-file .env alembic -c backend/alembic.ini upgrade head
sudo -u factory -H $UV run --project backend --env-file .env python -m seed.cli template --date $(TZ=Asia/Seoul date +%F)
```

- 템플릿은 **한 번만** 만든다. 다시 만들 때는 `sudo docker compose down -v` 후 3장을 반복한다.
- `down -v`는 **FS 컨테이너 볼륨만** 지운다. 이지스의 호스트 PostgreSQL과는 무관하다.

API 서비스 `/etc/systemd/system/factory-studio-api.service`:

```ini
[Unit]
Description=Factory Studio API
After=network-online.target docker.service
Wants=network-online.target

[Service]
User=factory
Environment=HOME=/srv/factory-studio
WorkingDirectory=/srv/factory-studio/app
ExecStart=/usr/local/bin/uv run --frozen --project backend --env-file .env uvicorn fs.main:app --host 127.0.0.1 --port 8021 --proxy-headers --forwarded-allow-ips=127.0.0.1
Restart=on-failure
RestartSec=3

[Install]
WantedBy=multi-user.target
```

```bash
sudo systemctl daemon-reload && sudo systemctl enable --now factory-studio-api
curl -s -o /dev/null -w '%{http_code}\n' http://127.0.0.1:8021/api/v1/core/sessions/current   # 401이면 정상
```

> 반드시 **8021**로 확인한다. 8000으로 요청하면 이지스 API가 응답해 잘못된 판단을 하게 된다.

## 4. 프런트 빌드와 Nginx (A 단계: :8080, HTTP)

### 4-1. 빌드 (맥북, 기본)

서버(RAM 2GB·1 vCPU)에서는 빌드하지 않는다. 맥북 `~/projects/factory-studio`에서, **서버와 같은 커밋**으로 빌드해 `dist`만 보낸다.

```bash
# 맥북
cd ~/projects/factory-studio
git fetch && git switch --detach origin/main      # 또는 서버에 올린 커밋
git rev-parse --short HEAD                        # 서버: sudo -u factory -H git -C /srv/factory-studio/app rev-parse --short HEAD 와 같아야 함
npm --prefix frontend ci && npm --prefix frontend run build
rsync -avz --delete frontend/dist/ root@158.247.236.136:/srv/factory-studio/app/frontend/dist/
ssh root@158.247.236.136 "chown -R factory:factory /srv/factory-studio/app/frontend/dist"
git switch -                                      # 원래 작업 브랜치로
```

> 맥북에는 다른 작업 브랜치가 열려 있을 수 있다. 커밋하지 않은 변경이 있으면 `git switch --detach`가 거부된다 — 그때는 `git worktree add ../fs-build origin/main`으로 별도 폴더에서 빌드한다.

### 4-1 대안. 서버에서 빌드 (RAM 여유가 충분할 때만, 권장하지 않음)

Node 24를 설치해야 하고(`curl -fsSL https://deb.nodesource.com/setup_24.x | sudo -E bash - && sudo apt -y install nodejs`), 빌드 중 다른 창에서 `free -h`를 지켜본다. 스왑이 급증하면 즉시 Ctrl+C.

```bash
cd /srv/factory-studio/app
sudo -u factory -H npm --prefix frontend ci
sudo -u factory -H npm --prefix frontend run build
```

### 4-2. Nginx 사이트 추가 (기존 default 유지)

`/etc/nginx/sites-available/factory-studio`:

```nginx
# 게스트 생성 레이트 리밋: IP당 분당 6회(FS-012 §7)
limit_req_zone $binary_remote_addr zone=guest_create:10m rate=6r/m;

server {
    # 이지스 default 사이트(:80)와 겹치지 않도록 8080. default_server 지정하지 않음
    listen 8080;
    server_name _;

    root /srv/factory-studio/app/frontend/dist;
    index index.html;

    location /assets/ { expires 30d; add_header Cache-Control "public, immutable"; }
    location /models/ { expires 1d; }

    location = /api/v1/core/guest-sessions {
        limit_req zone=guest_create burst=3 nodelay;
        limit_req_status 429;
        proxy_pass http://127.0.0.1:8021;
        include /etc/nginx/proxy_params;
    }
    location /api/ {
        proxy_pass http://127.0.0.1:8021;
        include /etc/nginx/proxy_params;
        proxy_read_timeout 60s;
    }
    location / { try_files $uri /index.html; }

    client_max_body_size 1m;
}
```

```bash
sudo ln -sf /etc/nginx/sites-available/factory-studio /etc/nginx/sites-enabled/factory-studio
# 원본의 "rm sites-enabled/default"는 실행하지 않는다 — 이지스 office.html이 여기 있음
sudo chmod o+x /srv/factory-studio /srv/factory-studio/app /srv/factory-studio/app/frontend
sudo nginx -t && sudo systemctl reload nginx
ss -tlnp | grep nginx          # :80 과 :8080 둘 다 보여야 함
```

> `nginx -t`가 실패하면 reload하지 않는다. reload 전 실패는 이지스에 영향이 없다.

### A 단계 확인

**먼저 이지스**: 기준선 명령 + 브라우저 `http://158.247.236.136/office.html` 정상.

그다음 FS, 브라우저에서 `http://158.247.236.136:8080`:

1. "가입 없이 둘러보기" → 앱 런처(3초 이내 목표).
2. FEMS·MES·ERP 각각 진입 → 시드 숫자 표시.
3. `/factory` 3D 공장, 외관↔내부 전환.
4. ERP 견적 한 건 → 새로고침 후 유지(`COOKIE_SECURE=false` 확인).
5. `journalctl -u factory-studio-api -n 50`에 500 없음.
6. `free -h` — 게스트 몇 명 생성 후에도 스왑이 안정적인지.

## 5. B 단계: 서브도메인과 HTTPS (도메인 구매 후)

도메인 하나에 서브도메인으로 나눈다(스택찬 연동 때 계획한 `aegis.` 과 같은 도메인 사용).

5-1. DNS: `A fs → 158.247.236.136`. Cloudflare를 쓰면 **프록시 끄기(DNS only)**. 전파 확인 `dig +short fs.<도메인>`.

5-2. FS 사이트를 80으로 옮긴다. `listen 8080;` → `listen 80;`, `server_name _;` → `server_name fs.<도메인>;`.
이름 기반이라 이지스 default 사이트(IP 접속)와 공존한다.

```bash
sudo nginx -t && sudo systemctl reload nginx
```

5-3. 인증서:

```bash
sudo apt -y install certbot python3-certbot-nginx
sudo certbot --nginx -d fs.<도메인> --redirect -m <이메일> --agree-tos
sudo systemctl list-timers | grep certbot
```

> certbot은 `server_name fs.<도메인>` 블록만 고친다. 실행 후 `grep -n 'listen\|server_name' /etc/nginx/sites-enabled/default`로 이지스 사이트가 그대로인지 확인.

5-4. **Secure 쿠키 되돌리기**: `.env`에서 `COOKIE_SECURE=false` 줄 삭제 → `sudo systemctl restart factory-studio-api` → 개발자 도구에서 `fs_session`에 Secure·HttpOnly 확인.

5-5. 8080 닫기: `sudo ufw delete allow 8080/tcp`.

5-6. 4장 확인 1~6을 `https://fs.<도메인>`에서 반복. `http://`는 https로 넘어가야 한다. 이지스 생존 확인도 다시.

## 6. 업데이트 배포

```bash
cd /srv/factory-studio/app
UV=/usr/local/bin/uv
sudo -u factory -H git pull --ff-only
sudo -u factory -H $UV sync --project backend --frozen
sudo -u factory -H $UV run --project backend --env-file .env alembic -c backend/alembic.ini upgrade head
sudo systemctl restart factory-studio-api
# 프런트: 맥북에서 4-1(같은 커밋으로 빌드 → rsync)
```

- `systemctl restart`는 **factory-studio-api만** 대상으로 한다. 이지스 배포 명령(`systemctl restart secretary-api secretary-scheduler`)과 섞지 않는다.
- 스키마가 바뀐 배포는 필요하면 `sudo docker compose down -v` 후 3장 시드부터(합성 데이터, 백업 없음).
- 되돌리기: `git checkout <이전 커밋>` 후 같은 절차.

## 8. FS만 걷어내기 (이지스 영향 없이)

문제가 생겨 FS를 서버에서 빼야 할 때:

```bash
sudo systemctl disable --now factory-studio-api factory-studio-cleanup.timer
sudo rm /etc/systemd/system/factory-studio-{api,cleanup}.service /etc/systemd/system/factory-studio-cleanup.timer
sudo systemctl daemon-reload
sudo rm /etc/nginx/sites-enabled/factory-studio && sudo nginx -t && sudo systemctl reload nginx
cd /srv/factory-studio/app && sudo docker compose down -v
sudo ufw delete allow 8080/tcp
```

그래도 불안정하면 0-1에서 찍은 스냅샷으로 복원한다(단, 스냅샷 이후 이지스가 받은 메일·DB 변경은 사라진다).

## 9. 이 절차서가 하지 않은 것

- 서버 접속·실행 자체(사용자 결정). **실제 서버에서 실행해 보지 않았다.**
- 이지스 :8000 외부 차단. office.html의 API 호출을 Nginx `/api/` 프록시로 바꾸는 작업이 선행돼야 하므로 별도 작업으로 제안한다. 지금은 인증 없는 이지스 API가 계속 인터넷에 열려 있다는 점을 인지할 것.
- root 비밀번호 SSH 로그인을 키 인증으로 바꾸는 것(두 서비스가 한 서버에 올라가므로 우선순위를 올리는 것을 제안).
- 도메인 구매·DNS, Dockerfile화, 모니터링·알림(FS-012 §8 미해결 항목).
