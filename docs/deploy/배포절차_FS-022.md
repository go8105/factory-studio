## 2. Cloudflare 설정 (계정 소유자가 대시보드에서)

1. **DNS → 레코드**: `A` `eip` → `158.247.236.136`, **프록시 켜짐**. (`fs`도 같은 값 — 서버가 eip로 301)
2. **SSL/TLS → 개요**: 암호화 모드 **Full (strict)**.
3. **SSL/TLS → 원본 서버 → 인증서 만들기 → "내 개인 키와 CSR 사용"**: 4-5에서 서버가 만든 CSR을 붙여 넣는다. 호스트 `*.hugh-d.com`, `hugh-d.com`, 15년. 받은 원본 인증서(PEM, 공개 정보)를 서버에 둔다. **비밀키는 서버에서 만들고 밖으로 내보내지 않는다.**
4. (제안) **SSL/TLS → 엣지 인증서 → Always Use HTTPS** 켜기. 끄면 `http://aegis.hugh-d.com`·`http://hugh-d.com` 방문자가 Cloudflare를 거쳐 서버 :80 default 사이트(이지스 office.html)로 간다.

> 이 서버의 다른 레코드(`hugh-d.com`·`www`·`aegis`)도 같은 IP를 가리키지만 서버에 사이트가 없어 https는 525가 된다(의도). 새 서비스를 올릴 때 그 이름의 server 블록만 추가한다.

## 5. Nginx 사이트 (이지스 default 사이트는 그대로)

방문자 IP 복원 스니펫(FS 사이트에서만 include — Cloudflare 경유가 아니면 이지스에 영향 없음). 게스트 생성 레이트 리밋이 방문자별로 걸리게 하는 데 필요하다.

```bash
{ echo "# Cloudflare IP ranges — $(date -u +%F) https://www.cloudflare.com/ips/"
  for ip in $(curl -fsS https://www.cloudflare.com/ips-v4) $(curl -fsS https://www.cloudflare.com/ips-v6); do echo "set_real_ip_from $ip;"; done
  echo "real_ip_header CF-Connecting-IP;"; } > /etc/nginx/snippets/cloudflare-realip.conf
```

`/etc/nginx/sites-available/factory-studio` (서버에 적용된 그대로):

```nginx
# Factory Studio (EIP) — https://eip.hugh-d.com, Cloudflare 프록시 + Origin CA (Full strict)
# 이지스 default 사이트(:80, IP 접속)는 건드리지 않는다.
limit_req_zone $binary_remote_addr zone=fs_guest_create:10m rate=6r/m;

server {
    listen 80;
    listen [::]:80;
    server_name eip.hugh-d.com fs.hugh-d.com;
    return 301 https://eip.hugh-d.com$request_uri;
}

# 443 기본 서버: 사이트가 없는 이름(hugh-d.com·www·aegis 등)은 TLS 연결을 거절한다.
# FS가 엉뚱한 주소로 노출되지 않게 한다. 새 서비스는 자기 server 블록만 추가하면 된다.
server {
    listen 443 ssl default_server;
    listen [::]:443 ssl default_server;
    server_name _;
    ssl_reject_handshake on;
}

# 예전 주소 fs.hugh-d.com → eip.hugh-d.com
server {
    listen 443 ssl;
    listen [::]:443 ssl;
    server_name fs.hugh-d.com;
    ssl_certificate     /etc/ssl/cloudflare/hugh-d.com.pem;
    ssl_certificate_key /etc/ssl/cloudflare/hugh-d.com.key;
    return 301 https://eip.hugh-d.com$request_uri;
}

server {
    listen 443 ssl http2;
    listen [::]:443 ssl http2;
    server_name eip.hugh-d.com;

    ssl_certificate     /etc/ssl/cloudflare/hugh-d.com.pem;
    ssl_certificate_key /etc/ssl/cloudflare/hugh-d.com.key;
    ssl_protocols TLSv1.2 TLSv1.3;

    include /etc/nginx/snippets/cloudflare-realip.conf;

    root /srv/factory-studio/app/frontend/dist;
    index index.html;

    location /assets/ { expires 30d; add_header Cache-Control "public, immutable"; }
    location /models/ { expires 1d; }

    location = /api/v1/core/guest-sessions {
        limit_req zone=fs_guest_create burst=3 nodelay;
        limit_req_status 429;
        proxy_pass http://127.0.0.1:8021;
        include /etc/nginx/proxy_params;
    }
    location /api/ {
        proxy_pass http://127.0.0.1:8021;
        include /etc/nginx/proxy_params;
        proxy_read_timeout 60s;
    }
    location / { try_files $uri /index.html; }

    client_max_body_size 1m;
}
```

- Nginx 1.24는 `http2 on;`을 모른다(1.25.1부터). `listen 443 ssl http2;`를 쓴다.

```bash
ln -sf /etc/nginx/sites-available/factory-studio /etc/nginx/sites-enabled/factory-studio
chmod o+x /srv/factory-studio /srv/factory-studio/app /srv/factory-studio/app/frontend
nginx -t                      # 실패하면 링크를 지우고 멈춘다(실행 중인 Nginx는 영향 없음)

```

### 8-1. C++ 비전 검사 엔진 (FS-VISION-CONNECT01, 2026-09-27 추가)

서버(1 vCPU·2GB, 이지스 공존)에서는 OpenCV를 컴파일하지 않는다. Ubuntu 24.04의 apt `nlohmann-json3-dev`(3.11)는 요구 버전(3.12)보다 낮고 서버에 Node가 없어 CMake 설정도 멈춘다. **맥 Docker(linux/amd64 Ubuntu 24.04)에서 OpenCV를 정적으로 넣어 빌드하고 실행 파일만 복사한다.**

```bash

native/inspection_core/build-linux.sh          # QEMU 에뮬레이션에서 gcc가 죽으면 JOBS=1(기본)로 다시 실행
ssh root@158.247.236.136 'uname -m'            # x86_64 확인
```

## 12. 2026-09-27 추가 작업 (후속 제안 적용)

### 12-1. 443을 Cloudflare IP로만 허용

```bash

```

### 12-2. 이지스 → https://aegis.hugh-d.com (Cloudflare Access)

1. Cloudflare Zero Trust(무료) → Access → Applications → Self-hosted `aegis.hugh-d.com`, 정책 **Allow · Emails = 본인** (로그인: One-time PIN).
2. office.html(secretary-ai `91baa61`): https에서는 API를 같은 도메인 `/api`로 부른다(http IP·file:은 기존 :8000).
3. Nginx `/etc/nginx/sites-available/aegis`(enabled): `aegis.hugh-d.com` 80→443 이동, 443은 Origin CA 인증서·real-IP 스니펫, `root /var/www/html; index office.html;`, `location /api/ { proxy_pass http://127.0.0.1:8000/; }`(접두어 제거).

## CAD-03 비누 POC 관리자 자산 배포 (2026-10-05 · 실행 전 체크)

CAD 일반 편집기만 frontend/dist/cad-cam-app에 포함한다. 비누 설계/메시/ZIP은 **웹 루트 밖** `backend/private-assets/soap-poc`에 빌드된다.
`cd frontend && npm ci && npm run build`가 두 산출물을 생성하고 공개 자산 누출 검사를 수행한다.
배포 시 frontend/dist뿐 아니라 backend 코드와 `backend/private-assets/soap-poc/`도 해당 backend 위치에 복사하고 API를 재시작해야 한다.
private-assets에 Nginx alias/정적 공개 경로를 만들지 않는다. API `/api/v1/cad/admin/soap-poc/{파일}`만 사용하며 MEMBER+ADMIN을 매 요청 확인한다.

이전 공개 산출물(`cad-cam-app/soap-poc.html`, `cad-cam-app/soap-poc/`, 과거 soap JS/CSS)이 서버에 남지 않도록 **새 dist로 교체**한다. 기존 디렉터리에 파일만 덧붙이는 배포는 피한다.
과거 공개 배포/캐시가 있었다면 이전 POC URL의 CDN 캐시도 무효화한다. 이미 내려받은 사본을 회수하는 기능은 아니다.
배포 후 비로그인401, 일반 회원/게스트403, 관리자200·Cache-Control private,no-store 및 공개 디렉터리에 POC 부재를 확인한다.
모의 로그인 fixture는 테스트 전용이며 운영 uvicorn 대상에 사용하지 않는다. 이 절차를 적었다고 운영 반영/검증이 완료된 것은 아니다.
