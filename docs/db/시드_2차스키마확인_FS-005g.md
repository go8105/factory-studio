대상: `schema.json v0.9.1 / FS-008c`, 71테이블·712컬럼·161 FK·제약/정책 526개.

## 1. 결론과 판정 범위

**문서에 명시된 값만으로 확정할 수 있는 CHECK 위반은 발견하지 못했다.**
이는 시드 전체 통과 판정이 아니다. 실제 시드 행이 없으며, 필요한 사유·시각·코드 일부가
문서에 명시되지 않아 그 값의 충족 여부는 확정할 수 없다. 아래에 누락과 조건부 실패를 분리했다.

확인된 가정 차이:
- 목표 EQUIPMENT 분기는 site_id를 NULL로 제한하지 않는다. “대상 둘 중 하나만 NOT NULL”과 다르다.
- BOX/PALLET 부모·구성·입고의 타입별 제한은 SERVICE 정책이며 일반 CHECK가 아니다.
- 견적 6상태와 수주 상태는 states에 있지만 해당 상태 CHECK는 없다.
- 매입 cancelled 분기는 confirmed_at의 NULL 여부와 취소·확정 시각의 선후를 CHECK로 제한하지 않는다.

**스키마 수정 방안은 제안하지 않는다.** 미정 값과 판정은 설계 세션의 검토 입력으로 남긴다.
1-C 역시 미적용이다.

### 4.1 작업지시·LOT·실행 — FS-005g 4.2

### 4.2 패킹 — FS-005g 4.7

- BOX 30·PALLET 6의 타입은 C261 허용값이며 open/closed/received/shipped는 C299 허용값이다.
- W03 BOX 1 closed·1 open은 상태 CHECK와 충돌하지 않는다. W01·W02 BOX closed도 허용된다.
- PL-0001/0003/0004/0005 shipped, PL-0002/0006 received는 C299를 만족한다.
- 생산 수량 절반 배정은 C100 970/970, C200 961/960, T300 491/491로 모두 양수(C267).
  구성 1행씩 두 BOX에 나누므로 UK(S,packing_unit_id,lot_id)와 충돌하는 것으로 명시된 행은 없다.
- PALLET별 4 BOX가 두 LOT의 양품을 담으면 표의 3,880/3,842/1,964와 일치한다.
  LOT별 합계 한도는 CHECK가 아니라 SERVICE C268이다.
- BOX 부모는 nullable인 단일 parent_packing_unit_id로 0~1개다. 자기참조 금지 C262가 있지만,
  부모가 PALLET인지와 PALLET 부모가 없는지는 SERVICE C263이다.
- packing_member는 BOX에만 연결하는 SERVICE C304, 입고는 PALLET만·하위 BOX closed·BOX 상태 closed 유지라는 SERVICE C305다.
  본문은 구성 30개를 BOX 기준으로 정의하므로 명시된 구조에서 이 정책과의 충돌은 보이지 않는다.
- **입고 6행의 status는 confirmed만 허용(C300)**이다. PALLET의 received/shipped를 입고 행에 넣으면 실패한다.
  4.7 표는 PALLET 상태를 적었으며 입고 행의 실제 status는 따로 명시하지 않았다.
  다만 schema.json의 입고 status 기본값은 confirmed이므로 생략하고 기본값을 사용하면 C300을 충족한다.

따라서 BOX/PALLET 관계까지 DB CHECK가 보장한다는 판정은 할 수 없다. 서비스 실행도 검증하지 않았다.

### 4.3 생산량 27행 — FS-005g 5.6

- 행 수 18+2+4+2+1=27. 모든 정의 구간은 1/2/3일의 양의 반개구간으로 C402를 만족한다.
- W06 검사 0은 C403 `production_qty >= 0`에서 허용된다. 분모 0 처리는 SERVICE C409다.
- W04 검사 source_key는 번호 매핑상 `MES:LT-0016:INS`다. 같은 키에 v1=1,904, v2=1,940을 두는 것은
  두 수량 모두 비음수이고 버전 1/2≥1이며 C401의 버전 포함 UK에 충돌하지 않는다.
- 설비·품목·구간이 같은 두 개정본 자체를 막는 별도 UK는 없다. 최신 confirmed 버전만 집계하는 것은 C407 정책이다.
- **27행 모두 status=confirmed이므로 confirmed_at NOT NULL이 필수(C406)**다.
  5.6 컬럼 표에는 confirmed_at 배정이 없고, W04 v2 확정 시각도 없다.
  4.4의 MES 실적 확정 시각을 FEMS confirmed_at으로 복사한다고 명시되어 있지도 않다.
  따라서 확정 시각 충족 여부는 미확정이며, NULL이면 해당 27행이 C406에 걸린다.
- 코드·단위는 MES:…/품목코드/EA로 비어 있지 않아 C405와 충돌하지 않는다.

1,904라는 오입력은 정정 시나리오이며 수량 CHECK 위반은 아니다. MES 결과와 같은 양품이어야 한다는 DB FK/CHECK도 없다.

### 4.4 견적 개정·수주·출하지시 — FS-005g 6.1~6.2

- Q-0002 r1/r2는 같은 quote_no와 다른 revision_no=1/2이므로 C354 UK와 C355를 만족한다.
  명세 line_no UK는 quotation_id별(C360)이어서 각 개정본의 2행을 독립 보유할 수 있다.
- 견적 상태 목록 draft/confirmed/sent/accepted/rejected/cancelled는 states에 존재한다.
  6.1의 최종 accepted/sent/rejected/draft는 그 목록과 일치하나 이를 검사하는 status CHECK는 없다.
- 견적 valid_until은 NULL이거나 quoted_on 이상이어야 한다(C356). 6.1에는 해당 날짜가 없어 확정 판정 불가.
  quote_qty>0(C361)는 명세별 수량이 표에 없어 전수 대조 불가다. discount_rate 0~100(C362)은
  컬럼 기본값이 0이므로 생략 시 충족한다. 별도 할인율 값을 넣는지는 본문에 명시되지 않았다.
- 수주 due_on≥ordered_on(C223). 이미 출하된 SO-0001~0004는 출하−3일≥출하−10일로 충족한다.
  SO-0005~0010은 수주일 범위만 있고 출하일·납기 값이 정해져 있지 않아 같은 대조를 완료할 수 없다.
- 수주 명세 order_qty>0(C227), 출하지시 명세 order_qty>0(C234).
  표에 주어진 수량은 모두 양수. 행 번호·각 명세 실제 키가 없는 부분의 UK는 확정 검사 불가다.
- 출하지시 8건은 shipped/open으로 C301 허용값이다. **비취소 행의 cancel_reason은 반드시 NULL(C302)**이다.
  cancelled 행이 생기면 비공백 사유가 필요하다. 현 시드의 출하지시에는 cancelled 행이 없다.
- 수주 상태 open/shipping/closed/cancelled는 states에만 있으며 DB 상태 CHECK는 없다.
- Q-0002 r1 sent를 보존하고 r2 accepted를 수주가 참조하는 구조를 막는 CHECK/UK는 확인되지 않았다.

### 4.5 회계 — FS-005g 6.3~6.4, 특히 PI-0006

- RC-0001/0002, PM-0001/0002는 confirmed_at NOT NULL, RC-0003/PM-0003 draft는 confirmed_at NULL이어야 한다(C458·479).
  일자는 적혀 있지만 confirmed_at의 구체 시각은 문서에 없다. confirmed 일자만으로 컬럼이 채워졌다고 간주하지 않았다.
- TI-0001/0003 issued는 비공백 approval_no와 issued_on 모두 필수(C499). TI-0001은 합성 승인번호라는 설명이 있고
  TI-0003은 번호가 명시되지 않았다. 실제 번호 값·서로 중복 없음(C498 UK_PARTIAL)은 생성 전에는 확인 불가다.
  TI-0002 pending은 두 필드가 모두 NULL이어야 한다.
- PI-0006은 status=cancelled, cancelled_at=d−29, cancel_reason='수량 오입력'이면 C428 취소 분기를 만족할 수 있다.
  **취소 분기는 confirmed_at을 검사하지 않는다.** 따라서 확정 시각을 보존해도 CHECK 위반이 아니며,
  confirmed_at=NULL이나 취소 시각<확정 시각도 이 CHECK만으로는 거부하지 않는다. 이는 허용 식의 사실이며 변경 제안이 아니다.
- PI-0006 공급가액: 100×3,500 + 3×180,000 = 890,000, 세액 89,000, 합계 979,000.
  모두 비음수이고 합계 일치(C427). 두 명세도 수량·단가가 양수이고 합계 조건(C434)에 맞는 구성이 가능하다.
  PY-0005 원금 979,000 보존은 C449 amount≥0과 충돌하지 않는다.
- PI-0006에 지급 소명은 정의되어 있지 않다. 취소 시 소명 0건·원금 보존·유효 조회 제외는 SERVICE C429·450·451이며 DB CHECK가 아니다.
- receivable/payable에는 상태·취소 플래그·확정 시각 컬럼이 없다. 표의 OPEN/PARTIAL/CLOSED는 C443·451에 따른 조회 파생이다.

## 5. 나머지 4~6장 CHECK 대조 범위

- MES 품목 유형 finished/semi_finished/raw, 단위 EA/KG/BOX, 공간 workcenter는 실제 CHECK 허용값이다.
  경로 draft/published도 허용된다. published_at은 published 경로에서 필수(C163)지만 구체 시각은 미지정이다.
- BOM 수량>0·로스율 0≤값<100(C384·385), 자재 투입량>0(C390)과 제시된 양수 산식은 충돌하지 않는다.
- 실적의 input=output=good+defect·EA 정수·양수 투입(C126~129)은 4.5의 산식과 일치한다.
  W06 985=0+985이며 불량 사유가 있다(C130). 사유는 S-6에서 이미 추가된 값이다.
- FEMS 채널 11개의 CUMULATIVE·양수 multiplier와 kWh/Nm3/m3는 확인한 CHECK와 충돌하지 않는다.
  계수 PRIMARY/EMISSION·양수 값, tariff의 양수 사용 단가, 계측 invalid/0 및 배분 estimated는 각 CHECK의 허용 범위다.
- 5.5 ITEM 기준선은 item_code NOT NULL·equipment_id NULL 조건을 받아야 한다(C348).
  기준선 값은 >0(C349)이어야 하나 4행의 실제 값은 없다.
  T300 confirmed와 draft 2행이 **같은 baseline_code를 쓰면 C346 UK(S,baseline_code)에 충돌**한다.
  본문은 두 코드 값을 명시하지 않아 실제 충돌 여부는 확정 불가다. 기준선에는 version_no 컬럼이 없다.
- 목표/계수/요금/기준선의 달력 문자열은 지정 정규식 형식이어야 한다. T에 따라 파생시키는 설계이며 실제 생성값은 없다.
- ERP 표의 매출 공급가액·세액·합계 4건은 모두 비음수·합계 일치(C248·417).
  수금·지급 및 소명액도 양수이다(C457·478·464·485). 금액·통화·요청 키 등 미기재 컬럼까지 검사한 결과는 아니다.

여기서 산식과 CHECK의 정적 대조만 했다. 실제 행 7,469개 생성·INSERT·SQL CHECK 평가·FK/UK 전수 실행 검증은 하지 않았다.

## 6. 설계 세션에 남기는 미확정 값

아래는 사실 확인에 필요한 질문이며 스키마 변경 제안이 아니다.

1. X01의 비공백 cancel_reason, 완료 지시/LOT의 completion_reason, 지시의 released_at/started_at/completed_at 배정은 무엇인가?
2. FEMS production_record 27행의 confirmed_at 및 W04 v2 확정 시각은 무엇인가?
3. 수금·지급 confirmed_at, issued 세금계산서 승인번호 실제 값은 무엇인가? 입고 status는 기존 기본값 confirmed이며 별도 지정을 하더라도 이 값만 허용된다.

빈 부분에 임의 값을 넣지 않았고, 미지정 값을 NULL로 단정하여 위반이라고 보고하지 않았다.
