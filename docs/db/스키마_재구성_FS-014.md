## 재배치와 부속 제약

FS-013 §3.2 각 행의 ○만 복제한다. 마스터의 컬럼·키·상태·코드목록·인덱스를 함께 복제하고
모든 FK를 동일 업무 스키마로 재지정한다. 범위 앵커만 core에 남는다.
learning 6, process_map 3, mes.learning_binding 1, bems 2와 부속 메타데이터를 삭제한다.

- `fems.energy_allocation.execution_id` 컬럼·FK·실행별 조건부 UK·선택 MES 정책 삭제.
  설비별 조건부 UK는 조건 없는 UK로 전환하여 배분 중복을 차단한다.
- `mes.production_plan.sales_plan_id` → nullable `sales_plan_code varchar(40)`.
  기존 ERP `plan_code` 길이를 따른다. ERP 판매계획 존재·확정 상태를 강제하지 않는다.
- `erp.shipment_line.packing_unit_id` → nullable `packing_no varchar(40)`.
  기존 MES `packing_no` 길이를 따른다. ERP 내부 패킹 번호 중복 방지 UK_PARTIAL은 보존하되
  MES 입고·패킹 상태·품목 조회를 강제하던 정책을 삭제한다. ERP 자체 품목·수량 검증은 유지한다.
- FS-013 §3.5에 따라 `fems.energy_baseline.item_id` → nullable `item_code varchar(40)`.
  품목 FK를 제거하고 ITEM/EQUIPMENT 대상 CHECK도 코드에 맞게 바꾼다.
  명시된 업무 간 FK 3개 외에, FEMS가 품목 마스터를 두지 않으므로 이 core 품목 FK도 제거한다.
- 선택 코드의 빈 문자열은 CHECK로 금지한다. 코드 존재 여부는 강제하지 않는다.
- `workspace_module`은 core/mes/erp/fems만 허용. 플랫폼 역할 목록은 owner/guest/admin으로 정리한다.
  인증 구조나 솔루션별 업무권한 테이블은 추가하지 않는다.
- FEMS 단독 소유로 meter와 meter_channel의 owner_module은 fems만 허용한다.
  기존 복합키 형태를 보존하기 위해 컬럼을 유지한다.

## fems.production_record 설계 근거

입력 단위는 **설비·품목 코드·수량 단위·생산 시간 구간별 양품 생산량**이다.
MES 설치나 품목 마스터 없이 FEMS에서 입력할 수 있다. 에너지와 생산량의 단위를 분리한다.

| 컬럼 | 타입 | 의미 |
|---|---|---|
| id | bigint identity | 기존 테이블과 같은 PK |
| workspace_id, generation_id | bigint NOT NULL | S 범위 및 core.data_generation 복합 앵커 |
| source_key | varchar(100) | 원천 기록 키. 재입력·개정 식별 |
| version_no | integer | 기록 개정 번호. 연·월·주차가 아님 |
| equipment_id | bigint | (S, equipment_id) → fems.equipment |
| item_code | varchar(40) | 독립 품목 코드, 외부 FK 없음 |
| period_start, period_end | timestamptz | [시작, 종료) 반개구간. 에너지 배분과 같은 시간 기준 |
| production_qty | numeric(18,3) | 기존 생산 수량 정밀도. 양품 생산량, 0 허용 |
| unit | varchar(10) | 생산량 단위. 기존 수량 단위 길이 |
| status | varchar(20) | draft / confirmed |
| confirmed_at | timestamptz nullable | 확정 상태와 CHECK로 일치 |
| created_at | timestamptz | now() |

PK(id), UK(S,id), UK(S,source_key,version_no). 모든 참조 삭제는 RESTRICT.
CHECK: 양의 시간 구간, 생산량≥0, 버전≥1, 키·품목·단위 공백 금지, 상태·확정시각 일치.
별도 연·월·주차 컬럼을 만들지 않고 구간 시각을 기준으로 한다.

서비스 정책(실행 구현 아님):
- confirmed 행은 수정·삭제 금지(세대 정리 예외). 수정은 같은 source_key의 새 버전이다.
- 집계는 원천 키별 최신 **확정** 버전만 사용한다. 새 draft가 기존 확정분을 숨기지 않는다.
- 같은 원천 키의 설비·품목·단위는 고정한다. 최신 확정 기록끼리 동일 설비·품목·단위의 구간 중복을 거부한다.
- 에너지와 동일 구간만 비교한다. 부분 구간 비례 배분이나 여러 공정의 같은 생산량 중복 합산은 하지 않는다.
- 품목·단위가 다르면 자동 합산하지 않는다. 공장 전체 분모의 대표 공정 선정은 별도 업무 규칙이 필요하다.
- 생산량 0이면 원단위는 계산 불가로 표시한다. 0 원단위로 대체하지 않는다.
- 에너지원 간 합산은 PRIMARY 환산 후 수행하고 EMISSION은 배출량에만 사용한다.

기존 `target_week`, 요금·단가 종료월, 기준선 시작·종료월의 누락된 형식 CHECK 5개도 보완했다.
월은 YYYY-MM, 주차는 YYYY-W01~W53이며 실제 ISO 53주 존재 여부는 서비스 검증 대상이다.

## 실행·검증 계약

`python3 tools/apply_fs013.py --check`는 쓰기 없이 후보를 검증한다.
`python3 tools/apply_fs013.py`는 검증 통과 시에만 입력 바이트의 SHA256 이름으로
`docs/db/schema-metadata/backups/`에 백업하고 원자적 파일 교체를 수행한다.
입력 버전·테이블 수·구조가 다르거나 결과 격리·참조 검증에 실패하면 중단한다.
이미 유효한 FS-014면 파일·백업·변경이력 추가 없이 종료한다.
이는 메타데이터 변환 도구이며 물리 DB 마이그레이션이 아니다.

`audit_schema_isolation.py`는 R1~R5 위반 시 종료 코드 1을 반환한다.
R5는 각 업무 테이블에서 NOT NULL 범위 키 보유를 검사한다.
일반 검증기는 FK 대상 키·컬럼·타입·RESTRICT·복합 범위·세대 앵커와 현재 엔티티 목록을 검사한다.
이전 설계 문서의 폐기 엔티티 목록 대신 아래 현재 목록을 기준으로 사용한다.
