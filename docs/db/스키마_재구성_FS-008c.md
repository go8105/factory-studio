# FS-008c — fems.meter CHECK 잔재 제거

2026-09-23 / v0.9.0 → v0.9.1 / task FS-008c / DB 미적용.
근거: FS-005g 10.3 D-A·D-B 및 사용자 수정 지시. 시드 정의 본문은 변경하지 않았다.

## 1. 결함 원인과 조치

| 항목 | 원인 | 조치 |
|---|---|---|
| D-A | FS-005c에서 채널로 이관한 measurement_kind·unit을 meter CHECK가 계속 참조했다. 값 목록도 이전 코드였다 | 해당 CHECK 1개 삭제. meter_channel로 옮기지 않음 |
| D-B | scope_kind에 factory/common/site_total과 factory/site_total CHECK가 중복됐다 | 넓은 CHECK 1개 삭제, 기존 `scope_kind IN ('factory','site_total')` 그대로 유지. 실제 허용 집합 불변 |

변경 전 D-A:
```sql
(measurement_kind IN ('cumulative_energy','interval_energy') AND unit = 'kWh') OR (measurement_kind = 'instant_power' AND unit = 'kW')
```
위 식은 결함 기록이며 실행 SQL/DDL이 아니다.

테이블·컬럼·FK·코드 목록·상태·SERVICE 정책·채널 제약은 전부 변경하지 않았다.
메타데이터에서는 위 2개 CHECK 삭제, version/task/date 갱신, change_log 1행 추가만 수행했다.

## 3. 채널 조사와 설계 세션에 남기는 질문

현재 `fems.meter_channel`의 CHECK는 정확히 아래 두 개다.

1. `measurement_kind IN ('CUMULATIVE','INSTANT')` — 측정 종류 제한.
2. `multiplier > 0` — 배수 양수.

**단위 값 CHECK와 측정 종류·단위 조합 CHECK는 없다.** 따라서 D-A와 같은 조합 CHECK가
채널에 이미 존재한다고 볼 수 없다. 이번에는 채널을 변경하지 않았다.

설계 질문: 채널의 측정 종류·단위 조합 제한이 필요한지, 필요하다면 어떤 조합을 허용할지는
설계 세션에서 판단할 항목이다. 이 보고서는 제약 신설이나 허용값을 제안·적용하지 않는다.

사용자 지시에서 **1-C는 별도 승인 항목이지만 본문 정의가 없었다.** 1-C는 미적용이다.
검증기의 일반 expression 파싱은 추가하지 않았다. 향후 별도 작업을 위해 1-C의 정확한 범위 확인이 필요하다.
