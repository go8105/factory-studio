# FS-008b — 화면 설계 반영 스키마 수정

2026-09-22 / v0.8.0 → v0.9.0 / 메타데이터 설계 / DB·서비스 미적용.
FS-013을 아키텍처 전제로 유지하고 FS-008a 54화면에서 발견한 갭을 반영했다.
만기 nullable·매입 수기 우선·owner_module 3개 삭제는 사용자 확인 후 적용했다.

## 2. A-1 배분량과 단위 / B-1 소유 모듈 잔재

- energy_allocation.kwh → quantity, numeric(20,6), NOT NULL, CHECK quantity >= 0.
- unit은 meter_channel.unit과 동일한 varchar(10), NOT NULL. 기본값을 kWh로 두지 않는다.
- 기간 배분은 CUMULATIVE 채널만 SERVICE 정책으로 허용한다. 전력 kWh, 가스 Nm3(표시 Nm³), 용수 m3(표시 m³) 등 채널에 저장된 단위를 그대로 쓴다. kW 순간 채널은 기간 배분에 사용하지 않는다.
- 에너지원 간 합산은 PRIMARY 환산 후에만 한다. EMISSION은 배출량 산출용이다. quantity는 환산량이 아니다.
- 확정 배분은 변경하지 않으며 재산정은 새 method_version을 사용한다.

### 키 교체와 순서

사전 조사에서 meter_channel에는 `(S,id,unit)` UK가 없었다.
기존 `(S,id,owner_module,unit)` UK를 **먼저 `(S,id,unit)` UK로 교체**한 후 FK를 구성한다.
이는 메타데이터 후보 안의 구성 순서이며 실제 ALTER/DDL 수행이 아니다. 파일은 전체 원자 교체한다.

| 대상 | 변경 |
|---|---|
| fems.meter | owner_module 컬럼·CHECK·(S,id,owner_module) UK 삭제. 기존 (S,id) UK 유지 |
| fems.meter_channel | owner_module 컬럼·CHECK·소유 일치 SERVICE 정책 삭제. owner 포함 UK를 (S,id,unit)으로 교체 |
| fems.energy_reading | owner_module 컬럼·CHECK 삭제. FK와 인덱스를 (S,meter_channel_id,unit)으로 변경 |
| fems.energy_allocation | 기존 채널 FK와 인덱스에도 unit 추가 |

두 FK 모두 `(S,meter_channel_id,unit) → fems.meter_channel(S,id,unit)`, 삭제/변경 RESTRICT이다.
기존 채널 `(S,id)` 및 `(S,meter_id,channel_code)` UK는 유지한다.
BEMS 테이블은 없고 세 owner_module의 CHECK 값은 모두 소문자 'fems'였다. 구분할 다른 소유 모듈은 없다.
관측 또는 배분이 있는 채널의 에너지원·측정 종류·단위 변경은 SERVICE 정책으로 금지한다.

### kwh 참조 조사 건수

현재 schema.json의 소문자 식별자 `kwh` 참조는 **2곳을 찾아 2곳 수정**했다.
① 컬럼 정의 ② CHECK 표현식. 이를 참조하는 UK·인덱스·FK·정책은 **0건**이었다.
`apply_alloc_uk.py`·`apply_fems_alloc_fix.py`도 조사했으나 kwh 참조는 없다.
과거 조건부 UK는 이미 FS-014에서 설비·채널·기간·방법·버전 UK로 대체돼 있고 이번에도 유지한다.
Excel·ERD의 파생 표시는 재생성한다. 과거 설계의 kwh 기록과 FS-008a의 원래 갭 설명은
변경 이력이므로 보존하고 처리 결과를 붙인다. 물리 단위 kWh를 quantity로 일괄 치환하지 않는다.

## 3. A-2 과세구분

`erp.item.tax_category varchar(20) NOT NULL`을 추가하고 CHECK로 TAXABLE/ ZERO/ EXEMPT만 허용한다.
암묵 기본값 없이 품목 등록 시 선택한다. 각각 과세/영세/면세이며 세율은 10%/0%/0%다.
**부가세율 10%가 상수로 고정되어 있으며 세율 마스터가 없다.** 영세와 면세는 구분을 보존한다.

확정 시 매출은 출하→출하지시→수주 명세의 품목, 매입은 매입 명세의 품목을 기준으로 계산한다.
공급가액은 세액 별도이며 명세별 공급가액×세율을 KRW 1원 단위 사사오입한 후 합산한다.
이는 서비스 구현 정책이며 DB CHECK에 세무 계산을 구현한 것이 아니다.
확정 공급가액·세액은 이후 품목 과세구분 변경으로 재계산하지 않는다.
법정 세무 적합성, 전자세금계산서 연동, 0원 매출 발급 정책은 이번에 검증·구현하지 않았다.

## 4. A-3 nullable 만기 스냅샷

사전 조사 결과 receivable/payable/purchase_invoice의 due_date는 **이미 date nullable로 존재**했다.
중복 컬럼을 추가하지 않고 산출·우선순위·불변 정책을 보완했다. FS-008a의 “컬럼 없음”은 갭 표에서 정정한다.

- partner.payment_term_days: integer, nullable, 기본값 없음, CHECK payment_term_days >= 0.
  NULL은 미설정, 0은 당일, 양수는 기준일 이후 N일이다. 달력 기간 키가 아니라 일수이므로 정수다.
- receivable.due_date: 매출 확정 시 recognized_at의 Asia/Seoul 날짜+N을 저장한다.
  결제조건이 NULL이면 만기 NULL로 생성하며 매출 확정을 막지 않는다. 수기 입력 경로 없음.
- purchase_invoice.due_date: **draft에서 사용자가 입력한 값 최우선 → 비어 있으면 확정 시 invoice_date+N → N도 없으면 NULL**.
  결과를 payable.due_date에 NULL까지 동일하게 복사한다. 확정 후 매입일·만기 변경 금지.
- receivable/payable의 만기와 원금은 확정 후 불변이다. 이후 거래처 조건을 채우거나 바꾸어도 소급하지 않는다.
- 만기 NULL은 연령분석의 **만기 미설정** 그룹으로 분리하며 연체로 분류하지 않는다.

모두 SERVICE 정책이다. 원천 확정 트랜잭션에서 조건을 일관되게 읽고 만기 확정과 원장 생성을 함께 커밋한다.
매출 수기 만기 경로, 잔액·상태 캐시, 연령분석 화면/API는 추가하지 않았다.

## 5. A-4 삭제와 C SERVICE 정책

core.dashboard_layout 1개와 소속 제약 5개·workspace FK 1개를 삭제했다. 유입 FK는 없었다.
포털은 아이콘 런처, 솔루션 대시보드는 고정 배치이므로 저장할 위젯 배열이 없다.
기존 역사 문서에는 삭제 사실과 본 문서 링크를 남겼으며 활성 Excel·ERD에서는 제거했다.

| 정책 | 보장 방법과 한계 |
|---|---|
| C-1 설비 동시 점유 | 시작/종료/설비 변경을 동일 S 공간 잠금으로 직렬화. 잠금 후 동일 equipment_id의 ended_at IS NULL 실행이 있으면 새 시작 거부. 검사·INSERT·감사·요청 결과는 같은 트랜잭션. 공간 잠금 완화 시 설비별 직렬화를 먼저 설계해야 함 |
| C-2 패킹 한도 | 공간→세대→작업지시→LOT(id 오름차순)→패킹 단위→구성. 부모 잠금 후 최종 확정 양품 및 최신 구성 합계를 재조회. 추가/변경 후 SUM(packed_qty)≤양품, 초과 시 전체 롤백. 삭제도 같은 잠금. BOX를 PALLET 포장했다고 중복 합산하지 않음 |
| C-3 게스트 만료 | expires_at 도달만으로 활성 작업을 중단하지 않음. 세션 종료 및 진행 요청 없음 확인 후 TX-12 회수. guest_pool→공간 잠금 안에서 조건 재확인 후 기존 자식→부모 삭제와 job_run 기록 |

C-1·C-2는 직접 DB 쓰기를 보호하지 않는다. 여러 행의 합계를 일반 CHECK로 표현하지 않았다.
C-3 세션 생존·종료 판정은 서비스 책임이며 브라우저 종료 이벤트만으로 단정하지 않는다.
세션 판정의 상세 타임아웃·인증 계약은 FS-010에서 정하며 이번에는 테이블·API를 만들지 않는다.
TX-12의 “잠금을 먼저 얻으면 회수 우선” 문장은 활성 세션을 보호하도록 정정했다.

## 6. D 유지 결정과 갭 처리

- D-1 작업지시:LOT=1:1은 의도. 기존 (S,work_order_id) UK 유지.
- D-2 work_order.bom_version_id nullable 유지. BOM 없으면 자재 투입 기준 소요량 기본값 없음.
- D-3 견적은 같은 quote_no에서 revision_no를 올려 새 행 누적. 이전 행 보존.
  활성은 **같은 S·quote_no별 MAX(revision_no)**로 파생. 최신 플래그를 만들지 않는다.
  sales_order.quotation_id는 특정 개정 행을 계속 참조한다.
- D-4 workspace_module 유지. 앱 on/off는 모듈 독립성 시연 수단이다.

FS-008a 네 문서는 본문을 다시 쓰지 않고 갭 목록·종합 목록에 처리 결과를 표기했다.
적용: G-01/02/05, E-G01/02, P-G01/05, M-G07/08.
해소(설계 결정): M-G04/05, E-G03, P-G06. 기존 화면 안내 항목은 기존 해소 범위를 표시한다.
보류: M-G06 설비 상태, G-08 대표 공정, E-G07 0원 발급, P-G03 정적 파일 경로(FS-011), P-G04 SCM 문안.
코드 자동완성 등 화면 안내로 완화하는 갭은 DB 무결성 보장으로 과장하지 않는다.
