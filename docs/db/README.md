# DB 설계서 — FS-007 / 007a / 007b

상태: **v0.3.0 설계 초안.** 실제 PostgreSQL 생성·마이그레이션 적용·카탈로그 대사는 아직 수행하지 않았다.

## 기준 파일

- `schema-metadata/schema.json` — 설명 메타데이터 **기준본**. 모든 산출물이 이 파일에서 생성된다.
- `DB설계서.xlsx` — 메타데이터에서 생성한 **모듈별 31시트**. 목차에서 모듈을 선택하고 각 모듈은 테이블/컬럼/관계/규칙 네 시트로 나뉜다. 내부 링크 172개로 목차와 모듈을 오간다.
- `validation-report.json` — 정적 검사 결과와 기준본 SHA-256. 테이블 수·스키마별 분포는 이 파일을 기준으로 본다.
- `FS-007b_변경_검증.md` — 이번 판의 변경 내용과 실제 수행한 검증 범위.
- `../architecture/erd/EIP_모듈별_ERD.html` — 외부 라이브러리 없이 열리는 모듈별 관계 탐색기. Mermaid 원본 8종이 같은 폴더에 있다.

외래키 113개, 제약·인덱스·서비스 정책 375개. **54개 전체가 첫 개발 단계의 구현 범위라는 뜻은 아니다.** QMS/WMS는 아직 별도 테이블 설계가 없다.

M1은 첫 MES 학습 실습, M2는 생산·에너지 통합 학습, M3는 전체 흐름·ERP 단계다. 상세 일정에 따라 기능별로 도입한다.

## 설계 원칙

- bigint identity 기본키와 공간·세대 복합 참조키를 병행한다. 업무 데이터가 다른 사용자 공간이나 세대를 참조하지 않도록 한다.
- 계정·설정·학습 기록·프로세스 맵 콘텐츠를 보존하고 세대별 실습 데이터를 교체한다. 참조 삭제는 RESTRICT로 설계하며 구세대 정리는 자식부터 수행한다.
- 시각은 timestamptz, 수량·계측값·금액은 numeric, 논리값은 boolean을 사용한다. 화면 시간은 한국 시간으로 표시한다.
- 연·월·주차 같은 기간 식별자는 정수가 아니라 문자열(`'YYYY-MM'`, `'YYYY-Www'`)로 저장하고 CHECK로 형식을 강제한다.
- 공유 테이블은 소유 모듈에 한 번만 정의한다. `core.item`을 ERP/MES가 참조해도 명세를 복제하지 않는다.
- SERVICE/DB_POLICY는 구현해야 할 정책이다. SQL CHECK만으로 강제되는 제약으로 해석하지 않는다. 게시 불변성·동시성·권한은 실제 서비스와 DB에서 별도로 검증한다.
- UK_PARTIAL은 조건부 유니크 인덱스다. 일반 UNIQUE 제약과 구분한다.
- 원본 MES 설계서(`../references/`)는 참고 사본이며 새 설계서로 덮어쓰지 않는다.

## 실행 환경

도구는 일반 Node와 Python만 사용한다. 사설 번들 런타임 의존은 FS-007a에서 제거했다.

```
npm install            # exceljs 설치 (최초 1회)
npm run db:validate    # = python3 tools/validate_db_design.py
npm run db:build       # = node tools/build_db_design.mjs
```

Node 18 이상, Python 3.9 이상이 필요하다. `tools/build_erd.py`와 `tools/add_db_links.py`는 ERD와 Excel 내부 링크 생성에 쓴다.

## 갱신 절차

1. 메타데이터와 관련 업무 설계를 함께 수정한다. 새 테이블은 해당 설계 문서의 엔티티 표에도 함께 올린다. 검증기가 설계 문서와 메타데이터의 테이블 집합 일치를 검사한다.
2. `npm run db:validate`를 실행한다.
3. `npm run db:build`로 Excel과 `work/db-design/previews/`의 시트별 미리보기를 재생성한다. ERD를 바꿨다면 `tools/build_erd.py`도 함께 실행한다.
4. Excel을 재개방해 행 수·컬럼 정의·내부 링크·표시 상태를 검토한다.
5. 구현 단계부터 새 migration revision, 적용 결과, 실제 DB 대사 결과도 기록한다. 이 생성기는 DDL 생성기나 DB 동기화 도구가 아니다.

## 미반영 제안

`../architecture/FEMS_공통설계_FS-005c.md`는 FEMS를 다중 에너지원 구조(전력·가스·유량 등, core +2 / fems +4)로 확장하는 제안이며 **v0.3.0에 반영되어 있지 않다.** 현재 FEMS 2테이블은 사실상 전력 전용이다. 채택하려면 메타데이터·Excel·ERD·시드 정의를 함께 재생성해야 한다.

## 검증 범위

설계 문서 엔티티 목록 일치, 컬럼 유일성, 외래키 타입·참조 고유키·공간/세대 일치, 삭제 정책을 정적으로 검사했다. Excel은 31시트 1,191행을 생성 원본과 대사하고 시트 상단을 시각 확인했다. ERD는 9개 보기 생성과 FK 113개 표시를 검사했다.

실제 PostgreSQL 구문·트리거·경합·권한 테스트, 브라우저 상호작용, Excel 네이티브 앱 검증은 미실행이다. 상세는 `FS-007b_변경_검증.md`를 본다.
