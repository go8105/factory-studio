# Factory Studio — 모듈형 제조·에너지 체험 플랫폼

2026-09-20 · 설계 개정 및 UI 시제품 · 제품 구현 미착수

## 제품 및 공개 범위
React·TypeScript·Vite, FastAPI, PostgreSQL의 단일 저장소·모듈형 모놀리스를 유지한다. 하나의 가상 소형 전자부품 양산 사업장에서 개인별 체험 공간과 게스트 임시 공간을 제공한다. 기존 회사 파일과 서버에 의존하지 않는다.

첫 공개: 공통 기반, 모듈 라이브러리, 선택형 **MES/FEMS/ERP**, 프로세스 맵, 게스트 즉시 체험, 관리자 진도 대시보드, 정해진 위젯의 선택·배치, 학습 과정 C0~C4, 데이터 격리 및 초기화, 재현 가능한 로컬 실행과 공개 배포.
ERP는 ERP-1(거래처·판매계획·수주·출하지시·출하·매출)로 한정한다.
두 번째 공개: QMS/WMS와 품질·재고 통합, BEMS 공용 에너지.
세 번째 공개: ERP-2·3 — 매입매출·채권채무·기초회계. 편입 여부는 ERP-1 완료 후 재판단한다.
후속: 모의 세금계산서 고도화와 외부 테스트 연동, PWA/Web Push, 사용자 정의 필드·화면.
실제 세금계산서 발행은 별도 운영 환경 및 준비 조건을 만족한 이후에만 활성화한다.

## 데이터 책임과 의존성
| 소유 모듈 | 소유 데이터 | 의존성/규칙 |
|---|---|---|
| core | 계정, 권한, 체험 공간, 사업장·공간, 품목·단위, 설비·계측기 식별정보, 모듈 설정, 대시보드 배치, 감사 기록 | 상시 활성. 품목은 업무별 확장 속성을 분리 |
| mes | 공정 경로, 작업지시, LOT, 공정 실행, 생산·양품·불량 실적, 생산계획, 패킹 단위, 완제품 입고 | core 필수 |
| fems | 제조 계측 기준정보, 계측값, 제조 에너지 집계, 생산 배분 규칙 | core 필수. MES 없이 독립 계측 조회 가능. 수집 파이프라인·알람 서버는 미구현이며 계측값은 seed로 생성 |
| bems | 건물 계측값, 환경 관측값, 공용 에너지 집계 | **준비 중.** FEMS와 계측 소유·집계 범위 분리 |
| qms | 검사 기준·결과, 품질 판정 | 후속. LOT 품질 연계는 MES 필요 |
| wms | 창고 위치, 재고 이동 원장, 예약 | 후속. 생산 LOT 연계는 MES와 명시적 계약 |
| erp | 거래처, 판매계획, 수주, 출하지시, 출하, 매출 | **구현 대상(ERP-1).** core 필수. 출하는 mes의 패킹 단위를 참조하며 재고 원장은 WMS 도입 시 이관 |
| process_map | 맵 버전, 노드, 연결, 업무 카드 | 콘텐츠. 세대 축 없음. 업무 테이블에 FK를 걸지 않는다 |
| learning | 학습 콘텐츠, 안정적인 학습 ID, 학습 완료 기록 | 업무 데이터 세대와 분리 |

core 계측기 등록정보에 관측값 소유 모듈과 계측 범위를 명시한다. 같은 관측값을 FEMS/BEMS가 각각 적재하지 않는다. 통합 집계는 부모 계량기와 하위 계측기를 중복 합산하지 않는다.
사업장 전체 계측 450 = 제조 288 + 공용 132 + 미계측 잔여 30 kWh의 검증 예시를 사용한다.
다만 **이번 시드는 이 예시를 온전히 재현하지 않는다.** 공용 계측은 BEMS 소유이고 BEMS가 준비 중이므로, 전체 − 제조 = 미계측 잔여까지만 보여주고 분해는 BEMS 설명 카드에 기재한다. 상세는 [시드 정의](architecture/합성데이터_시드정의_FS-005b.md) 4.7을 따른다.

## 모듈 및 화면 정책
- 코드에 등록된 내부 모듈만 제공한다. 모듈은 id, version, required_dependencies, optional_integrations, 메뉴, 권한, 위젯을 선언한다.
- 코드 설치와 DB 마이그레이션은 배포 단위이다. 사용자 활성화는 체험 공간 설정 변경이며 테이블 생성·삭제를 하지 않는다.
- 상태는 준비 중/비활성/활성으로 표시한다. 준비 중 모듈은 활성화할 수 없다.
- 활성화 전 필수 의존성을 검사한다. 추가로 켜야 할 모듈이 있다면 영향을 제시하고 함께 적용한다.
- 비활성화 전 의존 모듈·진행 업무·미처리 작업을 검사한다. 충돌 시 변경을 거부하고 이유를 표시한다. 보류 LOT의 품질 제약은 모듈 설정 변경으로 해제하지 않는다.
- 비활성화는 데이터를 보존한다. 모듈 메뉴, API 진입, 관련 예약 작업, 위젯에 같은 설정을 적용한다.
- API 접근은 권한, 체험 공간, 활성 모듈, 활성 데이터 세대를 서버에서 검사한다. 내부 함수도 같은 업무 경계를 지킨다.
- 모듈 설정 변경과 업무 실행 간 경쟁을 막도록 설정 버전 재검증/잠금 정책을 구현 시 확정한다.
- 위젯은 사전 개발된 목록에서 선택한다. 배치는 사용자별로 저장하며 권한을 부여하는 수단이 아니다.
- 모듈이 꺼져 위젯이 숨겨져도 기존 배치 선호를 보존한다. 다시 켜면 복구한다.
- MES+FEMS가 활성화될 때만 생산 원단위 위젯을 제공한다. 생산량 0은 계산 불가로 표시한다.
- 초기화 시 계정·학습 기록·콘텐츠·모듈 선택·화면 배치는 보존하고 업무 예시 세대만 바꾼다.
- 주간 초기화는 월요일 04:00 Asia/Seoul. 초기화 작업은 비활성 모듈의 체험 데이터도 참조 정합성을 유지하도록 처리한다.

## 권장 개발 순서와 완료 기준
1. R01~R04: 문서 기반 요구사항, 역할, 데이터 책임, 공통 ERD, 활성화 정책과 수용 기준 확정. 본 문서는 초안이며 ERD·상세 권한표는 아직 미작성.
2. R05~R07 확장: 실행 기반, 로그인·격리, 모듈 등록·활성화 API, 권한 기반 메뉴, 위젯 등록과 배치 저장.
3. R08~R10: 합성 데이터, 초기화·실패 복구·보존 설정 검증.
4. R11~R20: MES/FEMS/BEMS. 개발 순서는 실행 필수 의존성을 의미하지 않는다.
5. R30의 핵심 학습 흐름, R32 문서화, R33~R36의 첫 공개 범위 검증·배포를 앞당긴다. R31 PWA는 후속.
6. R21~R29, E01~E04는 후속 버전으로 진행한다. 별도 범위별로 R33~R36 검증을 반복한다.

추가 검증: 다른 사용자의 설정·업무 접근 차단, 비활성 모듈 API 차단, 필수 의존성 위반 거부, 비활성화 후 재활성화 데이터 유지, 초기화 후 설정 유지, 구버전 세대 요청 차단, 위젯 권한 우회 차단.
기존 16주 추정은 위 범위 변경을 반영해 단계 종료 시 다시 산정한다. 현재 단계에서 새로운 납기를 확정하지 않는다.

## UI 시제품
`../prototypes/factory-studio.html`은 자체 포함 HTML 시제품이다. 실제 API·인증·DB·주간 초기화·영구 저장을 구현한 결과가 아니다.

구조: 첫 진입은 최신 Odoo 참고 이미지처럼 여백 있는 독립 아이콘과 짧은 이름으로 구성한 앱 런처. 테마와 색상은 후속 UI 작업에서 조정한다. 상단 공통 브랜드·사업장, 중앙 앱 아이콘 그리드, 모듈 검색, 하단 통합 대시보드·모듈 관리 진입을 제공한다. 앱을 선택하면 해당 업무 화면과 내부 내비게이션을 표시한다. 브랜드 또는 모든 앱으로 런처에 복귀한다. 화면 진입 방식만 변경하며 모듈 간 데이터 연결과 기존 업무 정책은 유지한다.

아이콘은 ERP/MES/WMS/QMS/FEMS/BEMS의 기존 범위에 맞춘다. 참고 이미지의 SCM/PLM/CRM은 이번 범위에 추가하지 않는다. 미구현 모듈은 준비 중으로 표시하고 사용 중으로 오표시하지 않는다. 비활성 모듈 아이콘은 활성화 설정으로 연결한다.
체험: 모듈 라이브러리에서 에너지 구성을 선택 → 대시보드에서 생산 영역이 사라지는 것 확인 → MES 활성화 → 원단위 위젯 등장 → 생산 화면에서 공정 시작/완료 → 대시보드 편집에서 위젯 숨김/표시·순서 변경.
동작 범위: 모듈 토글, 프리셋, 메뉴 전환, 위젯 선택, 역순 배치, LOT의 제한된 상태 전이. 새로 열면 초기화되며 설정 저장과 자유로운 드래그 배치는 미구현.
모든 수치는 가상 예시이며 공정 버튼은 두 번째 LOT 상태만 변경한다. 완료 LOT 기준 에너지 집계는 고정 예시다.

## 배포 및 미결정 사항
MacBook의 CPU/메모리/도구 버전은 실제 개발 착수 시 확인한다. Linux 배포는 Compose와 기존 서버 웹 서버 구성을 확인한 후 결정한다. 기존 AI 비서는 변경하지 않는다.
Vultr 사양·OS·배포 방식·도메인 정보는 배포 단계에서 확인한다. 비밀정보는 문서나 저장소에 기록하지 않는다.
다음 설계 산출물: 공통 ERD, 필드·키·시간·단위 규칙, 권한표, 업무 상태 전이표, 검증용 시나리오.
