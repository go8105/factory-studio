## 설계 결과

회사 1개·부서 1개·총 10명(관리자 1명, 직원 9명)을 기본으로 정했다. 기존 GW 회사 인증·권한을 유지하면서 미완료였던 MFA, 계정 복구, 선택형 SSO, 운영 기준·백업·복원·보관 검토와 역할별 화면을 설계했다. [전체 설계](../modules/gw/실사용_보안운영_UI_통합설계_GW-READY-01.md), [DB/API 계약](../modules/gw/보안운영_DB_API_GW-READY-01.md), [GitHub 비교 근거](../modules/gw/GitHub조사_적용근거_GW-READY-01.md), [제안 ERD](../modules/gw/review/ERD_제안.md), [제안 DB Excel](../modules/gw/review/GW-READY-01_제안DB.xlsx)을 함께 검토한다.

기본안은 비밀번호+인증 앱, 일회용 복구 코드 8개, 외부 SSO 선택 사용이다. RPO 60분·RTO 240분·백업 간격 30분, 문서 보관 검토 36개월·감사 기록 12개월·백업 30일은 제안 초기값이다. 실제 달성 수치나 법정 보존 적합성을 뜻하지 않는다. 관리자 비밀번호 재설정만으로 MFA를 우회하지 않으며, 응급 복구도 별도 증명·감사 절차를 거친다.

## 네 가지 UI 기준과 확인 범위

| 기준 | 설계 및 시제품 확인 |
|---|---|
| 직관성 | 내 업무/내 계정 보안과 관리자 회사 시작 안내/운영 준비를 분리. 다음 행동과 미완료 원인을 표시 |
| 유효성 | 오류 위치와 해결 행동, 값 유지, 중복·충돌·권한 회수·실패 상태 계약. 시제품에서 입력 오류와 복구 동선 확인 |
| 학습성 | 단계별 시작 안내, 정적 도움말, 같은 명칭과 닫기 동작. 별도 학습 DB 없음 |
| 유연성 | 390px 메뉴, 키보드 이동, 미저장 계속 편집, 제안 운영 기준 변경. 실기기·보조기기 검증은 후속 |

[검토용 화면과 재현 절차](../../prototypes/gw-readiness/README.md). Chrome 데스크톱 11개 화면·390px 6개 화면, 입력 오류/값 유지·모달 계속 편집 포커스·메뉴·직원 검토 경계·건너뛰기 링크를 검사했다. 페이지 오류 0·외부 요청 0·검사한 화면의 가로 넘침 0. 계속 편집 포커스 문제를 수정 후 재검사했다. 시제품의 권한 선택기는 검토 도구이며 실제 계정 가장 기능이 아니다.

Node 문법·Prettier·신규 Python 도구 Ruff 검사 통과. 제안 메타데이터 검사는 신규 9표/기존 2표 확장/제안 FK 19건 오류 0. Excel 9개 시트 렌더 확인·오류 셀 0 및 저장 파일 시트 구조를 확인했다. 현재 제품 schema0.27/210표·기존 DB Excel·migration은 변경하지 않았다. 제품 전체 회귀는 이번 정적 설계 작업에서 재실행하지 않았으며 이전 결과는 GW-COMPANY-05를 따른다.

## 남은 작업과 반영 범위

실제 TOTP·SSO·계정 복구·서명 증거·암호화 백업·복원·정책 저장·제품 UI 구현 및 실제 회사/기기 인수는 남아 있다. 시제품 저장은 메모리 내 검토값 변경이며 새로고침하면 사라진다. 로그인·실제 저장·백업을 수행하지 않는다.

작업 브랜치는 codex/gw-company-01, 기준 로컬 main은 2be292e이다. 이번 설계는 브랜치에만 커밋하며 로컬 main·origin/main·실서버에는 적용하지 않는다. 전체 설계 확인 후 GW-READY-02 하나의 작업 ID에서 A 인증 → B 복구/선택형 SSO → C 운영 정책/준비 판정 → D 백업·복원 → E 실제 제품 UI·검증·문서·로컬 main 반영 순서로 구현한다. 내부 A~E마다 설계 승인을 반복하지 않는다. 원격 push/배포는 현재 사용자 요청 범위가 아니다.

AGENTS.md §2에 따라 이번 신규 보안·운영 범위의 전체 설계 확인이 제품 개발 착수 조건이다. 실제 환경 인수에는 운영 담당·배포 환경·인증 앱/공급자·복원 대상이 필요하며 소프트웨어만으로 인수 완료를 선언하지 않는다.
