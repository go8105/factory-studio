# CAD-05 CNC 우선 윤곽 커널 실증

2026-10-06. 사용자가 CNC 우선·기록/설계파일 위치 연결·main push를 승인했다. 이번은 고도화 E0의 CNC 계산 실증이며 편집기 자유 스케치 버튼이 추가된 단계는 아니다. 비누 심화는 후속으로 보류했다.

## 실행 결과

기존 manifold-3d 3.5.4 WASM으로 비직사각형 평면 영역을 만들고 공구 반경+0.05mm만큼 안쪽으로 offset했다. 스캔선과 경계의 교점은 짝별로 분리해 섬/오목 윤곽을 건너는 절삭선을 만들지 않는다. 각 절삭 구간 전후에는 수직 퇴피·안전 높이 XY·수직 진입을 별도로 둔다. 공구가 들어갈 영역이 없으면 절삭 경로0개다.

커널 offset 결과를 그대로 신뢰하지 않고 원래 선분까지의 거리·even/odd 내부 판정으로 경로를 0.25mm 이하 간격으로 독립 검사했다. 원래 영역 돌출체의 상태와 면적×높이 체적도 검사했다.

| 경우 | 공구 지름 mm | 중심 영역 수 | 검사점 | 최소 원본 경계 여유 mm |
|---|---:|---:|---:|---:|
| L자 홈 | 6 | 1 | 2775 | 3.04917 |
| 섬이 있는 홈 | 6 | 1 | 5415 | 3.04909 |
| 폭4mm 목으로 연결된 홈 | 6 | 2 | 2718 | 3.04909 |
| 폭8mm 홈/과대 공구 | 12 | 0 | 0 | 해당 없음 |

총10908 검사점, 영역간 이동의 Z검사 통과. 최초 빈 영역 decompose()를 그대로 세어 1로 오판한 검증이 실패했다. 빈 component를 제외하도록 보정한 뒤 과대 공구0개를 확인했다.

Node24.21.0 로컬 단일 실행: WASM541470bytes(압축 전), 초기화8.03ms, 각 경우 약8.95/5.28/2.27/0.15ms. 계산시간에는 독립 검사/돌출 검사도 포함한다. 브라우저 다운로드·worker 초기화·저사양 기기 성능은 측정하지 않았으며 일반 성능 약속으로 사용하지 않는다. 설치 package 라이선스는 Apache-2.0이며 WASM과 의존성 고지 검토는 브라우저 배포 단계에서 수행한다.

## 검증과 제약

prototype32테스트, frontend 타입/빌드·공개/보호 자산 분리 통과. 연구노트 실제 합성 관리자 브라우저에서 폴더/파일 참조 저장과 기존 기록 호환 확인. DB 변경/실제 DB 인증·장비/슬라이서·연속 공구 충돌·절삭력/홀더·3축/NC·전체 포켓 제거량은 미검증이다.

현재 경로는 1개 깊이의 수평 절삭 구간이며 별도 윤곽 마무리·완전 제거/잔삭 증명·가공 순서 최적화·진입 방식 선택을 하지 않는다. 수직 진입은 해당 공구가 가능한 가정이다. Node 실증이며 일반 편집기의 rect/circle 제한은 아직 유지된다. OCCT/STEP/셸/필렛 실증은 CNC 우선 결정에 따라 후속 정밀 CAD 단계로 옮겼다.

## 연구노트와 다음 단계

사진 업로드 없이 설계 폴더·파일명 입력을 추가했다. 참조 문자열 저장이며 디스크 파일 생성/존재 확인 기능은 아니다. 구 기록·백업은 읽을 수 있고 필드는 JSON에도 유지된다. 미래 POC-04부터 버전 폴더/이름을 사용하며 기존01~03 파일은 보존한다.

다음 CAD-06은 선/닫힌 폴리라인·원호/슬롯·기본 치수·스냅과 원본 JSON v2, 형상/경로 worker 연결이다. 첫 연결은 오목 홈과 섬/좁은 통로 실패를 정확히 표시하는 2.5D CNC 범위로 한다. E0 결과만으로 사용자 입력 검증·전체 CAM이 끝났다고 표시하지 않는다. 프로젝트 AGENTS.md의 작업 ID별 보고/확인 규칙에 따라 이번 CAD-05 결과 보고 후 다음 ID를 시작한다.
