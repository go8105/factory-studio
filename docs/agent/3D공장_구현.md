## 사용자 승인과 범위

사용자가 승인한 권장안: 단순화한 입체 모형, 전체 조감도와 3인칭 이동. 일반 조립 → 비전검사 → 포장 설비로 구성한다. 상단 앱 런처 바로 오른쪽 **3D 공장** 메뉴, `/factory` 경로. 기존 세션 보호와 포털 레이아웃 안에서 열며 API·DB·업무 상태 변경은 없다.

- 1층 현장사무실: 책상·노트북으로 일하는 직원 1명, 바코드 프린터와 출력 라벨.
- 생산 현장: 연결된 설비 3대·이송 제품, 키오스크 3대, 비전검사 카메라·링 조명, 작업 통로·상태등. 직원 1명이 생산 라인 주변을 순회하며 멈춘다.
- 2층 사무실: 책상/노트북/의자 2조, 근무 직원 2명. 계단과 난간.
- 사용자: 노란 조끼의 별도 캐릭터. WASD·방향키·화면 이동 버튼, 설비/책상/벽 충돌, 계단 오르내리기. 대각선 속도 정규화, 지연 프레임 이동량 제한, 포커스 이탈 시 입력 해제.
- 전체 / 1층 / 2층 선택, 조감도 회전·확대, 시점 초기화, Esc 조감도 복귀. 걷기에서 층 선택은 해당 층 시작 위치로 이동한다.
- 시연 일시정지·재생, reduced-motion 기본 정지, 그래픽 연결 손실/렌더링 오류 안내와 재시도, DOM 공간/공정 설명.
- 외부 모델·텍스처·폰트 다운로드 없이 기본 도형으로 제작. 경량 스타일의 합성 시연이며 실제 설비와 연동하지 않는다. 본격 물리엔진·사람 간 충돌·실사 모델은 범위 밖.

## 파일과 의존성

- `frontend/src/factory/Factory.tsx`: 화면·조작·오류 안내.
- `Scene.tsx`: 건물·설비·인물·시연·카메라. `world.ts`: 공정 설명과 이동/충돌 규칙. `Factory.css`: 전용 스타일.
- App.tsx: lazy route와 메뉴 1개. 기존 MES/ERP/FEMS 및 공통 CSS 변경 없음.
- `three@0.186.1`: WebGL 장면·도형·재질.
- `@react-three/fiber@9.8.1`: React 19 장면 구성·렌더 루프.
- `@react-three/drei@10.7.8`: 카메라 OrbitControls·Html 라벨.
- 개발용 `@types/three@0.186.0`: 타입 검사. package-lock에 버전 고정.
- 3D 화면과 장면은 lazy load. Three.js를 포함한 3D 청크는 크기 경고가 있으며 런처 진입 시 로드하지 않는다. R3F 내부 THREE.Clock 사용 중단 예고는 남아 있다(실행 오류 없음).

- 새 단위/화면 테스트 16개: 시작점·설비/책상/경계 충돌·계단 상하 이동/측면 추락 방지·속도, 시연 표시·걷기·Esc·일시정지·층·공정 선택. 검증별 개별 테스트.
- 독립 Playwright 7개: 실제 WebGL 렌더 오류, 메뉴 위치, 이동에 따른 실제 화면 변화, 2층 선택, 공정 설명, 360px 가로 스크롤, context loss 안내.
- `playwright.factory.config.ts`는 **5186만** 사용하며 모든 API를 모의 응답한다. backend/DB 없이 재현한다. 기존 `tools/run_portal_smoke.py`·8000·5173·스모크 DB는 사용하지 않았다.
- 사전 렌더링에서 조감도·1층·걷기·2층·360px 스크린샷을 직접 확인. 큰 라벨·버튼 대비·모바일 카메라 거리 보정 후 최종 2층/360px 화면도 직접 확인했다.
- 초기 단위 테스트의 부동소수점 exact 비교 1건 실패(exit 1)는 근사 비교로 수정했다. 편집 스크립트의 잘못된 상대 경로 호출 1건을 바로잡았고, 그때 실행한 중간 검사 묶음은 중단(exit 130) 후 최종 코드로 재실행했다.
- backend pytest·DB 검증·공용 포털 스모크·Safari/실기기 성능 측정·원격 CI는 **미실행**. 기존 업무 기능 통합 스모크는 사용자 지시에 따라 Claude Code가 수행한다.
