# CAD-V01 · 휴디 NC 에너지 발표 데모

2026-10-08. 사용자 전체 흐름 승인, 발표 환경은 최신 요청에 따라 **맥북 Google Chrome**이다. [계약](../modules/cad-cam/음성발표데모_제안_CAD-V01.md). 제품 기능 구현·로컬 검증 완료. **실제 마이크 발화 리허설은 미검증**이며 발표 준비 완료로 간주하지 않는다.

## 구현

- NC 화면에 휴디 패널을 추가했다. 마이크 시작 → 호출어 → 30초 명령 창 → 기존 품질 우선 비교 → 번호 선택·검토 시나리오 재생. 중간 인식 결과는 실행하지 않으며 같은 최종 결과 중복은 차단한다.
- “헤이 휴디”, “Hey Hugh-D”, “현재 가공 시뮬레이션에서 최적안 제안해줘”, “2번으로 가공 실행해줘”, “두 번째 시뮬레이션 실행해줘”, “시뮬레이션 멈춰”, “마이크 꺼” 지원. 번호 없는 실행·부정 명령·없는 후보·차단 후보는 실행하지 않는다.
- 후보 번호/ID/revision·선택 표시, CAD-14 이동/이벤트 시간과 후보 G4 변경만 반영한 타임라인, 원본/후보 총시간·kWh 범위·후보 누적 kWh·현재 NC 행·공구 위치·진행률, 1/10/50배·일시정지/계속 재생.
- NC 원문·이동·F/S/T·쿨런트·형상은 그대로다. NC 출력/실장비 연결이 아닌 검토 재생이다. 품질/공정 근거를 음성이 자동 확인하지 않는다. 우열 판단 불가 후보는 검토용으로만 재생한다.
- TTS 중 인식을 중단해 자기 응답 재실행을 막는다. 탭 비활성화/페이지 이동 시 마이크 종료·재생 정지. 서비스 반복 종료는 5회에서 중단한다. 권한 거절/마이크 없음/네트워크 오류 안내와 버튼·명시적 텍스트 테스트 대안 제공.
- 인식 문장은 메모리만 사용하고 저장하지 않는다. 브라우저 원격 인식 가능성을 마이크 시작 전에 표시한다. NC 원문을 별도 음성/LLM API에 전송하지 않는다. 추가 API/키/DB 변경 없음. NC iframe에만 microphone 정책 명시.

## 발표 준비 순서

로그인 후 `/cad-cam?view=nc`에서 다음을 준비한다. 기본 입력을 자동 검토 완료로 바꾸지 않는다.

1. **휴디 발표 예제 NC (합성)** → **경로 해석**.
2. **STEP 예제** → 읽기 완료 확인 → STEP 정합/단일 상면 두 항목 확인 → **소재 검토 실행**. 예제 공구 T1·지름4·날15, 소재20×20×8, 목표 상면Z5.
3. **합성 장비 값 채우기** → **시간·에너지 계산**.
4. **품질 우선 개선 제안** 펼치기 → **합성 검토 기준 채우기**. 이 버튼은 실측·실공정 검토가 아닌 예제 가정을 명시적으로 채운다.
5. **음성 켜기 · 마이크 허용** → Chrome 사이트 권한과 macOS의 Chrome 마이크 권한을 허용한다. HTTPS 운영 또는 localhost에서 사용한다. 인터넷 연결이 필요할 수 있다.
6. “헤이 휴디” → 응답이 끝난 뒤 “현재 가공 시뮬레이션에서 최적안 제안해줘”.
7. 응답 후 “3번 시뮬레이션 실행해줘” → “시뮬레이션 멈춰”. 임의 번호 선택 시연은 “2번 시뮬레이션 실행해줘”도 가능하지만 이 예제의2번은 우열 판단 불가다.
8. 종료 시 **마이크 끄기**. 실패하면 버튼을 사용하며 실제 음성 성공으로 소개하지 않는다.

## 검증 결과

- CAD 전체 **141개**, 프런트 전체 **545개/67파일** 통과. 음성 어댑터 테스트는 모의 SpeechRecognition/TTS이며 실제 음성 서비스 성공을 뜻하지 않는다. 첫 프런트 전체 실행의 ERP 단가 테스트1건은 시간 초과; 단독12개 재실행과 전체 maxWorkers=2 재실행 모두 통과.
- 첫 CAD 테스트는 이 checkout의 미설치 패키지로 실패했다. `npm --prefix prototypes/cad-cam ci` 후 전체 재실행 통과. 음성 어댑터의 DOM 시험용 jsdom을 prototype 개발 의존성으로 고정하고 lockfile을 갱신했다. 실행 앱에 추가되는 라이브러리는 아니다.
- 실제 맥북 Chrome UI: 합성 NC·STEP·소재·시간/에너지 계산 →3후보 → 버튼2번/텍스트 “두 번째” 선택·공구 재생 → 정지 →99번 차단 → 장비 입력 변경에 후보/재생/계속 버튼 무효화 확인. Factory Studio 공개 CAD 빌드와 모의 게스트 포털의 iframe에서도 제안→텍스트3번→재생/정지를 확인했다. 마이크 정책·게스트 비누 탭 비노출 확인. [포털 화면](assets/cad-v01/factory-chrome-nc.jpg), [독립 NC 화면](assets/cad-v01/chrome-nc-demo.jpg), [390px viewport](assets/cad-v01/chrome-nc-mobile.jpg): 내용 폭375px, 가로 넘침 없음.
- 예제 원본 **1113.680초 / 0.228874–0.381228 kWh**. 2번 **823.680초 / 0.188597–0.308728 kWh**, 우열 판단 불가. 3번 조합 **233.680초 / 0.106652–0.161228 kWh**, 입력 범위에서 소비 감소 후보. 합성 모델이며 실측 절감 보증이 아니다.
- 전체 프런트 빌드·공개 CAD/비공개 비누 자산 격리·포맷·diff 검사 실행. 기존 큰3D 청크 경고 유지. 실제 인증/서버 권한·실 CNC·실측 품질/에너지·실제 마이크/TTS 발화·운영 배포 미검증/미실행. DB 작업은 이 ID 범위 밖이며 병행 MES 변경을 수정하거나 검증 완료로 간주하지 않는다.
