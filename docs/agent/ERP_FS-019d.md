# FS-019d 완료 보고 — E-07 매출 · E-08 세금계산서 (ERP 11/18)

작성일: 2026-09-26 · 브랜치 `fs-019d-erp-revenue` (main `22055ef` FS-019c 위) · 작업자 Claude Code

## 결정 반영

- **E-G07 (사용자 2026-09-26): 0원 매출 세금계산서 발급 금지.** 0원 매출 자체는 성립(출하·매출·채권 생성)하고, 계산서 생성·발급에서 409 `ZERO_AMOUNT_SALE`. 화면은 발급 대상 목록에서 0원 매출을 빼고 안내 문구를 둔다.
- 매출 인식(TX-09)은 019c에서 출하 확정과 함께 구현했다. 019d는 조회·취소와 세금계산서다.

## API (구현: `erp/revenue.py` — TX-09와 같은 파일)

계약 요약은 FS-010 §8 "매출·세금계산서 (FS-019d)".

| 항목 | 규칙 |
|---|---|
| 매출 조회 | 금액·소명액·계산서 상태와 **취소 막힘 이유를 서버가 파생**(`cancelBlockedReason`). 화면은 이 값으로 버튼을 끄고 툴팁을 쓴다 — 조건 계산이 두 곳에 있지 않다 |
| 매출 취소 | 잠금 순서 매출(6) → 세금계산서(6) → 채권(7). 잠근 뒤 조건 재확인: 이미 취소 / 발급완료 / 소명 있음이면 409. 발급대기 계산서는 같은 트랜잭션에서 삭제. 채권 원금은 남기고, 출하는 되돌리지 않음(FS-014b) |
| 계산서 | 매출당 1건, pending → issued 한 방향. 발급일 ≥ 매출일(Asia/Seoul), 승인번호 공간 내 유일. 취소 매출·0원 매출 거부 |

019e의 소명 등록은 채권을 먼저 잠그므로, 매출 취소가 채권을 잠그는 이 순서로 "소명과 취소가 동시에 통과"가 막힌다(019e 동시성 테스트에서 함께 확인 예정).
