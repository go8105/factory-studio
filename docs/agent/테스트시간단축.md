## 변경

- `backend/tests/conftest.py`의 `guest_template`은 FEMS 테스트 묶음에 필요한 템플릿을 세션당 한 번 생성한다.
- `guest_space`는 매 테스트마다 실제 `POST /api/v1/core/guest-sessions`로 새 공간·세대를 받는다. 쿠키·CSRF·멱등 처리는 실제 API를 통한다.
- `FS_TODAY=2026-09-24`, `GUEST_LIMIT=10000`, 합성 SESSION_SECRET은 function fixture 안에서 설정하고 복원한다. 외부 실행 환경에는 CI의 네 변수만 전달한다.
- 13개 `test_fems_*.py`의 `fems`는 `guest_space`를 반환하는 adapter로 바꿨다. 기존 두 값/세 값 unpack 형식을 보존했다. 테스트 함수 261개와 비-fixture 보조 함수는 AST 동일, 파라미터화도 그대로다.
- FK 정렬은 세션당 한 번 계산한다. 각 테스트의 finally에서 모든 게스트(보조 클라이언트 포함)의 업무 데이터 → 영수증·감사·작업·모듈 → active 세대 포인터 해제 → 세대 → 공간 순서로 삭제한다. 초기화로 남은 이전 세대도 지운다. 템플릿과 시퀀스는 테스트 사이에 유지한다.
- 세션 종료 시 템플릿의 모든 업무 테이블 및 core 공간·세대·모듈 내용 해시를 시작 시점과 비교한다. 게스트 잔여 공간 0도 검사한다.
- 새 의존성 없음. 업무 코드·seed 생성기·schema.json·마이그레이션 변경 없음.

## 기존 전체 DB fixture와 수명 분리

`test_common.py`, `test_seed.py`는 원본 그대로 전체 DB TRUNCATE와 자체 템플릿 생성을 수행한다. `test_seed_targets.py`, `test_portal_session.py`도 기존 `clean_database`를 유지한다.

`pytest_collection_modifyitems`는 `guest_template`에 의존하지 않는 테스트를 먼저, 의존하는 테스트를 마지막에 안정 정렬한다. 명령줄에서 파일 순서를 섞어도 전체 DB fixture의 teardown이 끝난 뒤 공유 템플릿이 시작된다. 각 묶음 안의 순서는 보존한다. `guest_template`과 `clean_database`/`common_env`/`seed_env`를 한 테스트에서 섞으면 수집 오류를 낸다.

따라서 “세션당 한 번”은 **공유 FEMS 템플릿** 기준이다. 시드 결정성·공통 인증 검증에 필요한 독립 템플릿 생성까지 없앤 것은 아니다. 앞으로 MES/ERP API 테스트도 `guest_space`의 `(client, created, engine)`을 사용할 수 있다. 전체 DB를 바꾸는 테스트에는 이 fixture를 쓰지 않는다. 동일 DB의 병렬 pytest 실행은 지원하지 않는다.

## SQL 변경 범위 확인

FEMS의 직접 INSERT/UPDATE/DELETE는 allocations, billing, dashboard, emissions, targets에 있으며, 모두 게스트 응답의 `workspaceId`·`generationId`를 `:w`·`:g`로 바인딩한다. 템플릿을 직접 수정하는 FEMS 테스트는 발견하지 않았다. energy_source/equipment의 직접 SQL은 초기화 뒤 세대 검증용 SELECT이며 그대로 뒀다.
