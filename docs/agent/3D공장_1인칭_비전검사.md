# 1인칭 비전검사 체험 (FS-3D-FP01)

2026-09-27 · Codex · `codex/factory-building` · 기준 `d3eaf31`.

## 요청과 범위

사용자가 승인한 첫 데모: 웹에서 1인칭으로 공장과 비전검사 설비를 둘러보고, 작업자 1명과 설비 상태·값 확인까지 체험한다. 기존 Blender 건물·생산라인을 재사용한다. VR 기기, 실데이터 수집, 홍보영상, 업무 DB 변경은 범위 밖이다.

## 구현

- `/factory`의 **1인칭 비전검사 체험** 버튼. 눈높이 1.68m, 시야각 62도. 비전검사 전면의 안전 위치에서 시작한다.
- 드래그/터치 시선 회전, WASD/방향키 또는 화면 이동 버튼. 시선 기준 이동, 기존 벽·설비·계단 충돌 재사용, 작업자 충돌 추가.
- 설비 직접 클릭/탭 또는 중앙 표적의 E 키/상태 확인 버튼. 7m 이내의 가장 가까운 보이는 표면만 선택해 벽 너머 선택을 방지한다. 드래그 이동은 클릭에서 제외한다.
- 데스크톱은 장면 옆 상세 패널, 900px 이하에서는 장면 아래 패널. 상세 닫기 후 탐색 포커스 복귀. 몰입 화면의 키보드 순환, Esc 종료, 배경 스크롤 복원.
- 비전검사 상태·판정·검사/불합격/합격 수량·링 조명과 주기 6초/노출 8ms 시연 설정 표시. 기존 정지·이상 시연과 동기화한다.
- 데이터는 브라우저 합성 시뮬레이션. 노출시간은 고정 시연 설정으로 실제 카메라에서 읽은 값이 아니다. 실제 MES/FEMS 레코드 매핑이나 저장은 없다. 다른 두 공정은 설명만 제공하고 미연결 상태를 표시한다.
- 1인칭에서는 지붕과 외벽을 닫은 실내, 검사 구역 조명·천장 지지대·바닥 안전선·매트, 작업복/조끼/안전모/안전화/태블릿을 갖춘 고정 작업자 1명. 머리의 작은 점검 동작은 시연 일시정지와 함께 멈춘다.
- 외부 모델·텍스처·새 의존성 없이 코드로 작업자 제작. 기존 블록 인물보다 세부 형상이 늘었지만 **실사 인물·사진 수준의 공장 완성을 뜻하지 않는다**. 후속 사실감 개선에는 고품질 리깅 인물과 표면 텍스처가 필요하다.

## 파일

- `frontend/src/factory/FirstPerson.tsx`: 시선, 카메라, 충돌 이동, 표면 선택.
- `InspectionZone.tsx`: 작업자·구역 디테일.
- `Factory.tsx` / `Factory.css`: 체험 진입·조작·상세 패널.
- `Scene.tsx` / `Building.tsx`: 모드별 장면·외피.
- `world.ts` / `world.test.ts`: 시선 기준 이동·작업자 충돌 및 테스트.
- `frontend/e2e/factory.spec.ts`: 클릭/E 선택, 드래그, 이동, 상태 패널, 모바일, 기존 기능 회귀.

## 재현

전용 `factory-studio-codex`에서 Node 24 PATH를 지정한다.

```sh
npm --prefix frontend run typecheck
npm --prefix frontend run lint
npm --prefix frontend run format:check
npm --prefix frontend run build
npm --prefix frontend test -- --maxWorkers=2
npm --prefix frontend run test:factory-browser
```

브라우저 검증은 5186·모의 API만 사용한다. 공용 8000/5173 및 스모크 DB는 사용하지 않는다. 통합 담당자는 현재 main의 공통 UI 변경과 충돌을 검토한 뒤 반영한다. 본 브랜치는 과거 ERP 작업도 포함하므로 브랜치 전체를 무조건 병합하지 않고 3D 관련 커밋의 포함 여부를 먼저 확인한다.

## 검증 결과

- Node 24.21.0: typecheck, lint, format:check, build 모두 exit 0.
- Vitest 36파일 / 348개 통과, `--maxWorkers=2`로 실행.
- 독립 Chromium: 기존 회귀 10개 통과. 새 1인칭 테스트 3개는 최종 분리 실행에서 모두 통과(1.9분, exit 0). 초기 전체 실행의 1인칭 복합 테스트는 60초 제한 초과였으며, 선택/직접 클릭·이동 테스트로 분리해 재검증했다.
- 1440×900 및 390×844 검사 화면, 기존 360px 공장 화면의 스크린샷 확인. 직접 클릭/E 선택, 드래그 선택 방지, 상태 패널, 시점 초기화, 실제 카메라 이동, 종료 확인.
- 기존 Three.Clock deprecation 및 500kB 초과 번들 경고는 남는다. 공장 장면은 지연 로딩한다.
- backend/DB/공용 스모크, 배포, 실제 기기 FPS, Safari, WebXR는 이번 작업에서 검증하지 않는다.
