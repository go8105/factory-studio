# FS-019e 완료 보고 — E-09 매출채권 현황 · E-10 수금 등록·소명 (ERP 13/18)

작성일: 2026-09-26 · 브랜치 `fs-019e-erp-receipts` (main `40efad7` FS-019d 위) · 작업자 Claude Code

## API (구현: `erp/receipts.py`)

계약 요약은 FS-010 §8 "매출채권·수금·소명 (FS-019e)".

| 항목 | 규칙 (FS-014b) |
|---|---|
| 잔액·상태 | 원금 − Σ소명, OPEN/PARTIAL/CLOSED(원금 0은 CLOSED)를 **조회 때만** 계산(`RECEIVABLE_SQL` 한 곳). 취소 매출 채권은 제외 |
| 수금 | draft에서만 수정·삭제, 확정 시 `confirmed_at`, 이후 금액·거래처·일자 불변 |
| 소명 추가 | 잠금: 매출(6) → 채권(7, id 오름차순) → 수금(7). 잠근 뒤 최신 합계로 Σ소명 ≤ 채권 원금, Σ소명 ≤ 수금액. 한 줄이라도 넘으면 전체 롤백 + 어느 채권/수금인지와 남은 금액. 과입금(미소명 잔여)은 허용. 같은 거래처·확정 수금·미취소 매출만 |
| 소명 취소 | 채권 → 수금 → 소명 잠금, 물리 DELETE + `core.audit_event` 같은 트랜잭션 |
| FIFO | 매출일 오래된 순 제안만, 저장 없음 |

019d 매출 취소는 매출 → 계산서 → 채권 순서로 잠그고, 소명 추가는 매출 → 채권 순서로 잠근다. 같은 순서라 "취소와 소명이 둘 다 통과"하지 않는다(테스트로 확인).

## 화면

- `Receivables.tsx` E-09: 거래처·상태 필터, 원금·소명액·잔액·상태·만기(없으면 "미설정"), 행 펼침 소명 이력, 합계 행(서버 값의 합). 연령분석 미제공 사유(E-G02) 안내.
- `Receipts.tsx` E-10: 수금 목록(소명·미소명), 등록·확정·삭제(draft), 소명 패널: "수금액 = 소명 + 미소명" 등식, 대상 채권별 소명액 입력, **FIFO로 채우기(제안만)**, 소명 저장, 한도 초과는 어느 채권·남은 잔액을 풀어 씀, 소명 이력과 2단계 소명 취소(감사 기록 안내).
- 도움말 e-09·e-10을 실제 동작에 맞게 고쳤다.
