## 3. 발견한 결함과 수정 — AC-63

- **증상**: 게스트 만료는 인증 단계(공간 잠금 전)에서만 봤다. 잠금을 기다리는 사이 만료되면 쓰기가 통과했다(FS-006b §4.2 위반).
- **수정**: `common/scope.py` `_scope`가 잠금 뒤 같은 트랜잭션에서 `expires_at <= clock_timestamp()`를 다시 보고 410 `WORKSPACE_EXPIRED`. 읽기·쓰기 모두 이 함수를 지난다.
- **확인**: 수정 전 코드에서 `test_ac63_expiry_is_rechecked_after_workspace_lock`를 돌리면 쓰기가 201로 성공해 실패함을 확인했고, 수정 후 통과.

- `statement_timeout`이 설정되어 있지 않아(AC-43 미구현) 13.9초 대기에도 오류가 나지 않았다.

1. **동시 게스트 생성 지연 → (a) 그대로 둔다.** 전역 잠금으로 상한을 지키는 설계(FS-006b §3.1)와 단일 트랜잭션 복사(§3.3)를 유지한다. 같은 초에 20명이 몰리는 경우만 대기가 길어진다(최대 13.9초, 오류 0).
2. **미구현 기능 → 1차 범위 밖으로 기록.** 구현하지 않고 아래를 "안 만들기로 한 것"으로 둔다(FS-012 §4-3과 같은 성격).
