# 3D 공장 공간 고도화

2026-09-26 · Codex · `codex/factory-building` · 기준 `b352514`

## 사용자 요청과 범위

사용자가 외관·실내 구조 → 재질·조명 → 설비·소품 → 업무 연결 순서로 진행하도록 승인하고 이후 이어서 진행 요청. 기존 공장의 공간·시연을 개선한다. 실제 공장 도면을 재현한 모델이나 실사 품질 보장은 아니다.

## 구현

1. Blender 건물: 기존 23 × 14 동선에 맞춘 사무동·생산동, 외벽 패널·창문·출입구 캐노피·하역 셔터, 지붕 이음·채광창·공조기, 철골·천장 조명·덕트·케이블 트레이, 외부 포장·구획선. 모델은 가상 설계이며 실제 건축/설비 안전 설계가 아니다.
2. 외관이 기본 화면. 내부 펼쳐보기/층 선택/걷기/설비 확대는 외벽 전면·오른쪽과 지붕을 연다. 내부 조감도는 천장 설비도 숨기고 걷기에서는 천장 설비를 표시한다. 외관에서 내부 라벨 숨김. 시점 초기화는 외관 모드를 유지한다.
3. 표면: 바닥 미세 입자·줄눈을 로컬 DataTexture로 생성. 금속 반사는 Three.js RoomEnvironment를 64px PMREM으로 생성하며 외부 HDR/텍스처를 다운로드하지 않는다. 방향광 그림자 2048, 주변광과 반구광 조정. 장면 준비 전 로딩 안내 유지.
4. 조립·포장도 Blender 모델로 교체. 프레임·안전 후면 패널·제어판·표시등·프레스·실링바·박스. 두 기구는 시연 재생 중 움직이고 정지하면 멈춘다. 비전검사 기존 판정·상태 시연 유지. PLC 검증/물리 시뮬레이션이 아니다.
5. 현장 후면 자재 선반 3개·공구대·소방함. 새 고정 소품의 사용자 충돌 영역을 추가하고 순회 작업자 경로에서 공구대를 이격.
6. 생산 현장→MES, 사무실→ERP, 에너지→FEMS 진입 카드. 기존 보호된 루트로 이동하는 기능이며 설비별 업무 데이터 매핑/실시간 수집/업무 데이터 쓰기는 추가하지 않는다.

## 원본과 재생성

- `assets/blender/factory-building.blend` / `tools/blender/build_factory.py`
- `assets/blender/assembly-cell.blend`, `packaging-cell.blend` / `tools/blender/build_line.py`
- 배포 파일: `frontend/public/models/*.glb`. 새 파일 건물 848,532B·조립 166,332B·포장 163,912B. 기존 비전검사 포함 약 1.45MB(십진수).
- 건물 원본은 부품을 유지하고 export 시 카테고리·재질별 병합해 27개 mesh로 감소. `Roof`/`Envelope`/`Overhead`/`FixedWalls`/`Structure`/`Site` 그룹이 표시 제어 계약.
- Blender 5.2.2 LTS Python background 실행. 외부 에셋 및 새 npm 의존성 없음.

```sh
/Applications/Blender.app/Contents/MacOS/Blender --background --python tools/blender/build_factory.py
/Applications/Blender.app/Contents/MacOS/Blender --background --python tools/blender/build_line.py
```

스크립트 재실행은 해당 모델 원본을 재생성하므로 수동 편집본은 별도 이름으로 보존한다.

## 검증

최종 검증 완료. 결과는 아래와 같다. Node 24.21.0 / Blender 5.2.2 LTS. DB/API 변경 없음.

- 발견·수정: 외관 위 내부 라벨 겹침, React 재렌더 때 OrbitControls target 초기화, 외관 시점 초기화가 내부로 전환되는 문제.
- 초기에 JSX 자동 교체 범위 오류가 발생하여 정리 후 typecheck 통과.
- headless Chromium 초기 환경 반사 계산이 기존 5초 준비 대기보다 길어 PMREM 256→64로 축소. 명시적 장면 준비 안내 및 15초 테스트 준비 한도 사용.
- 기본 병렬 단위 테스트에서 기존 portal/screens의 lazy flow 화면 1초 대기가 간헐 실패. 제품 코드/해당 테스트를 변경하지 않고 낮은 병렬 수로 전체 검증한다.
- backend·DB·공용 통합 스모크·Safari/실기기 성능 측정은 실행하지 않는다. 기존 Three.Clock deprecation, 번들 크기 경고는 남음.
- main 병합·push 없음. 사용자 시각 검토 및 통합 담당자 병합이 후속. 실제 설비별 MES/FEMS 데이터 연결은 별도 설계.

### 확인된 결과

- `npm --prefix frontend run typecheck`, `lint`, `format:check`, `build`: exit 0.
- `npm --prefix frontend test -- --maxWorkers=2`: **346 passed / 36 files**, exit 0. 포털 lazy 화면 테스트를 수정하지 않고 자원 경합을 줄인 실행으로 확인.
- 테스트 중 검사 동작 자체는 통과했으나 동일 테스트의 두 번째 스크린샷에서 30초 전체 예산을 초과하여, 모바일 상세 패널 검증을 별도 테스트로 분리했다.

- `npm --prefix frontend run test:factory-browser`: **10 passed (2.1분)**, exit 0. 기존 이동·층·context loss, 비전검사 정지/재개, 외관/내부/걷기 전환, 외관 라벨 숨김, 모드 유지 초기화, 360px 전체·상세 패널을 확인. 외관/내부/모바일 스크린샷 직접 확인.
- 마지막 시각 보정: 포장 실링바 stroke 0.23→0.10으로 박스 관통 방지. 검사 주기+software WebGL 캡처를 포함하는 사례에만 60초 전체 예산 적용(준비 검증은 15초). 이후 typecheck/lint/format/build를 재실행했고 해당 브라우저 사례도 1 passed(exit 0).
- 작업용 preview는 5187, 독립 검증은 5186만 사용. 사용자 공용 backend/DB/8000/5173는 미사용.
