# GW 실사용 준비 화면 · GW-READY-01

**전체 설계 검토용 시제품이다. 제품 기능이 아니다.** 인증·계정/역할 변경·저장·백업·복원·원문 열람을 실행하지 않는다. 네트워크 API·브라우저 영구 저장소를 사용하지 않는다. 표시된 회사/직원/코드/업무는 합성이다. 실제 비밀번호·OTP·복구 코드를 넣지 않는다.

- 공통 설계: [실사용 보안·운영·UI](../../docs/modules/gw/실사용_보안운영_UI_통합설계_GW-READY-01.md)
- 계약: [DB/API/보안](../../docs/modules/gw/보안운영_DB_API_GW-READY-01.md)
- 기본 구성: 관리자1명/직원9명, 회사1/부서1. 역할 선택기는 시제품 검토 화면을 바꾸는 도구이며 제품의 담당자 가장 기능이 아니다.

로컬에서 정적 서버로 연다.

```sh
python3 -m http.server 8371 --bind 127.0.0.1 --directory prototypes/gw-readiness
```

`http://127.0.0.1:8371`에서 내 업무/회사 시작 안내/직원 연결/내 계정 보안/운영 준비/기준/백업·복원/보관 검토를 이동한다. `#login`·`#recovery`는 로그인과 분실 흐름의 검토 화면이다. `#help`는 정적 사용 안내다.

확인할 흐름:

1. 새 기안에서 설명만 입력→저장 시 제목 오류·설명 유지→제목 수정. 취소/닫기/Escape의 미저장 확인에서 계속 편집 시 값과 포커스 유지.
2. 인증 앱 등록 흐름에서 짧은 번호 오류→6자리 입력 후 ‘다음 화면’ 장면. 실제 검증/세션 발급을 하지 않는 표시 확인.
3. 백업 코드 확인란 선택 전/후의 버튼. 코드는 `DEMO-ONLY` 표시이며 사용할 수 없음.
4. 보관·복구 기준의 범위 오류·백업 간격≥RPO 오류·사유 누락→검토값 반영. 새로고침하면 초기화되며 실제 저장 아님.
5. 직원 검토 화면에서는 관리 메뉴가 없고 관리 hash로 직접 들어가도 안내만 표시. 이는 서버 권한 검증의 대체가 아님.
   6.390px에서 메뉴 열고 닫기, Tab/Enter/Escape, 읽을 수 있는 레이블/오류와 가로 넘침 확인.

검토용 브라우저 검사: 서버를 위 포트로 열어둔 뒤 `node prototypes/gw-readiness/verify.mjs`. 현재 저장소의 frontend Playwright·설치된 Chrome을 사용한다. 모든 결과는 시제품 UI 검사로만 기록한다. 제품 서버·실휴대폰·실제 인증 앱/SSO 검증이 아니다.
