# Factory Studio Taste

원본 Taste를 Factory Studio의 React/Vite/CSS와 Codex에 맞춘 파생본이다. [출처와 수정](ORIGIN.md), [원문](reference/upstream-SKILL.md).

## 시작

1. 루트 AGENTS.md → docs/plan/현재기획_진행현황.md → FS-013 결정서 → 최신 progress를 읽는다. 제품 기준본을 별도 PRODUCT.md로 복제하지 않는다.
2. frontend/src/portal/Entry.tsx와 현재 CSS·테스트를 읽고 실제 화면을 확인한다. 이 프로젝트의 랜딩은 이미 카드 그리드가 아닌 간결한 진입 화면이다.
3. 의도를 한 문장으로 말한다: 제조 업무 포트폴리오를 검토하는 방문자가 가입 없이 체험할 수 있는, 절제된 한국어 랜딩.
4. 새 화면 구조는 프로젝트 설계 승인 규칙을 따른다. 사용자 승인 전에는 검토 문서·시제품까지 작성한다.

## 적용

- VARIANCE 5 / MOTION 2 / DENSITY 4. 기존 한글 글꼴과 CSS를 유지한다. Next.js, Tailwind, Motion, GSAP, 아이콘 패키지를 스킬 때문에 추가하지 않는다.
- 백자 #F7F7F6, 먹색 #1A1C1E, 쪽빛 #1F2D3D. 단색 SVG 라인 아이콘·최대 4% 그림자. 새로운 브랜드 세계나 장식용 WebGL을 만들지 않는다.
- 임의 영문 eyebrow·번호·보라색 발광·그라디언트 글자·동일 카드 반복·자동 타이핑·무한 애니메이션을 피한다.
- 실제 제공 기능을 설명한다. 독립 솔루션을 통합 업무 시스템으로 소개하지 않는다. 허구 고객·추천사·효율 수치·실측 절감률을 만들지 않는다.
- 별칭 게스트 진입을 가장 찾기 쉽게 유지하고 로그인·오류·로딩·별칭 보존·멱등 동작을 지킨다.
- 제품 화면을 증거로 쓰면 최신 합성 화면만 사용한다. 비공개 관리자 POC와 실제 고객 자료는 공개 이미지로 쓰지 않는다.
- 비대칭 구도는 읽는 순서를 돕는 수준으로 제한하고 모바일에서는 단일 열로 바꾼다. 내용은 장식보다 먼저 보인다.

## 확인

데스크톱·모바일, 키보드·확대·reduced-motion, 대비·가로 넘침, 게스트/로그인 오류 흐름을 검증한다. 실행하지 않은 검증은 명시한다. 현황·progress·HANDOFF를 갱신한다. 원본의 패키지/애니메이션/폰트 지침은 위 프로젝트 규칙보다 우선하지 않는다.
