# 내 계정 보안 · 인증 앱과 분실 복구

## 목적과 사용 대상

회사 계정의 본인 확인을 강화하는 화면입니다. 회원은 상단 **내 계정 보안**에서 자신의 인증 앱을 등록합니다. 게스트는 사용할 수 없으며, 총 관리자 `admin`이나 회사 관리자도 다른 직원의 설정 키·복구 코드를 조회하지 못합니다. 실제 회사의 직원 연결·역할·문서 권한은 인증 앱 등록과 별도로 적용됩니다.

이 안내는 GW-READY-02 개발 브랜치에서 구현한 동작 기준입니다. 전체 실사용 준비 작업은 진행 중이며 main·운영 서버에 반영한 상태가 아닙니다.

## 처음 등록하기

1. 아이디·비밀번호로 로그인하고 상단 **내 계정 보안**으로 이동합니다.
2. **현재 비밀번호**를 입력하고 **설정 키 받기**를 누릅니다. 보안 키가 설정되지 않은 서버에서는 진행할 수 없습니다.
3. 휴대폰 인증 앱에서 계정 추가 → 설정 키 직접 입력을 선택합니다. 이름은 Factory Studio, 종류는 **시간 기반**으로 설정합니다. 화면의 설정 키를 입력합니다. 외부 QR 사이트에 키를 보내지 마세요.
4. 10분 안에 앱의 6자리 번호를 **인증 앱 번호**에 입력하고 **번호 확인하고 등록**을 누릅니다.
5. 표시되는 복구 코드 8개를 비밀번호와 다른 안전한 장소에 보관합니다. **코드 8개를 안전하게 보관했습니다**를 체크하고 **로그인 화면으로** 이동합니다.
6. 새로 로그인하고 인증 앱 번호를 입력합니다. 방금 사용한 번호는 다시 사용할 수 없으므로 앱의 다음 번호를 기다립니다.

등록이 완료되면 이전 세션은 모두 종료됩니다. 앱 설정 키와 복구 코드는 발급 화면에서만 표시하며 다시 조회할 수 없습니다. 등록된 계정 보안 화면에는 등록 여부와 미사용 복구 코드 수가 표시됩니다.

## 로그인하기

**계정이 있다면 로그인** → 아이디·비밀번호 → **본인 확인** → 앱 번호 → **확인하고 계속** 순서입니다. 비밀번호 확인만 끝난 상태에서는 업무 세션이 발급되지 않습니다.

번호 입력 전에 페이지를 닫았거나 인증 요청이 만료되었다면 **로그인부터 다시 시작**합니다. 처리 응답이 불명확하면 먼저 새로 접속해 로그인 상태를 확인합니다. 소비한 인증 요청으로 세션을 재발급하지 않습니다.

등록/재발급 응답을 받지 못하면 새로 로그인해 등록 상태를 확인하세요. 발급한 코드는 다시 표시하지 않습니다. 앱으로 로그인할 수 있다면 계정 보안에서 추가 본인 확인 후 새 코드를 발급합니다. 불명확한 발급 요청을 자동으로 반복하지 않습니다.

## 휴대폰을 사용할 수 없을 때

1. 아이디·비밀번호로 로그인한 뒤 **휴대폰을 사용할 수 없어요**를 누릅니다.
2. 미사용 복구 코드 1개를 그대로 입력합니다. 코드는 32자리 소문자 영문·숫자입니다.
3. **인증 앱 다시 등록**에서 **새 설정 키 받기**를 누르고 새 앱에 등록합니다.
4. 앱 번호 확인 후 새 복구 코드 8개를 보관하고 다시 로그인합니다.

복구 코드 사용 즉시 기존 앱·세션·나머지 복구 코드는 회수됩니다. 복구 중에는 기안·결재·문서 조회 등 업무를 사용할 수 없습니다. **복구 중단하고 나가기**는 제한 세션을 종료하며 이전 인증 수단을 되살리지 않습니다. 진행 중 새로고침하면 복구 상태를 확인해 다시 등록을 진행할 수 있습니다. 완료 후 이전 코드로 로그인할 수 없습니다.

## 다른 접속 종료와 코드 재발급

등록된 **내 계정 보안**에서 **접속 중인 세션 보기**로 현재/다른 접속의 시작 시각과 인증 방식을 확인합니다. 접속 목록은 최대 100건입니다.

앱의 다음 번호를 **추가 확인 번호**에 입력해 **본인 확인**을 누릅니다. 확인 뒤 5분 동안 아래 작업을 할 수 있습니다.

- **다른 세션 모두 종료**: 지금 접속은 유지하고 다른 세션 및 진행 중인 이전 로그인 요청을 회수합니다. 다른 접속의 현재 화면은 다음 서버 요청 때 거부됩니다.
- **복구 코드 8개 새로 발급**: 이전 코드와 모든 세션 회수에 동의한 후 사용합니다. 새 코드를 보관하고 다시 로그인합니다. 기존 코드 원문은 다시 조회할 수 없습니다.

## 오류와 취소

- **번호가 맞지 않음**: 앱의 계정과 휴대폰 자동 시간 설정을 확인하고 다음 번호로 다시 시도합니다. 같은 번호 재사용도 거부됩니다.
- **잠시 기다린 뒤 재시도**: 실패 횟수 제한입니다. 새 로그인 요청을 만들어도 계정의 제한은 초기화되지 않습니다.
- **설정 키 만료**: 등록 취소 후 설정 키를 새로 받아 앱에 다시 추가합니다. 아직 확인하지 않은 키는 업무 인증 수단이 아닙니다.
- **보안 설정 확인 필요**: 운영 담당자가 서버 암호화 키·HTTPS·쿠키 설정을 점검해야 합니다. 직원이 화면에서 보안 검사를 해제할 수 없습니다.
- **등록 취소**: 현재 화면의 미확정 키·입력만 버립니다. 확인된 인증 앱은 삭제하지 않습니다.

## 구현 및 검증 범위

격리한 PostgreSQL 합성 계정에서 등록·세션 회수·동일 번호/복구 코드 동시 요청·실패 횟수 보존·제한 복구·HTTP 쿠키/CSRF를 검사했습니다. 실제 휴대폰 인증 앱과 운영 도메인의 검증은 아직입니다.

## 인증 앱과 복구 코드를 모두 잃었을 때

이 절차는 **미리 본인 긴급 복구 문서를 발급해 보관한 현재 GW 보안 관리자**만 사용할 수 있습니다. 직원 전체의 비밀번호 초기화나 다른 사람을 대신하는 로그인 기능은 아닙니다.

1. 서버 운영 담당자에게 별도 보관한 본인 긴급 복구 문서와 대상 회사·계정을 확인받습니다. 담당자는 서버에서 승인 파일을 발급합니다. 승인 파일은 15분 안에 한 번만 사용할 수 있습니다.
2. 기존 아이디·비밀번호로 로그인합니다. **본인 확인**에서 **인증 앱과 복구 코드를 모두 잃었어요**를 누릅니다.
3. **운영자 승인 파일 선택**으로 받은 파일을 선택하거나 **운영자 승인 번호**를 입력한 뒤 **확인하고 계속**을 누릅니다.
4. 제한된 복구 화면에서 새 인증 앱을 등록하고 새 복구 코드 8개를 보관한 뒤 다시 로그인합니다.

승인 파일 발급만으로 기존 접속이 종료되지는 않습니다. 본인이 승인 번호를 사용하면 기존 앱·복구 코드·세션이 회수되고 업무 접근이 차단됩니다. 복구 중 접속을 잃었다면 기존 비밀번호로 로그인부터 다시 시작해 새 운영자 승인을 받아야 합니다. 이미 사용한 문서는 다시 승인할 수 없습니다. 문서·서버 운영 접근·비밀번호도 함께 잃었거나 현재 역할이 회수되었다면 이 경로로 복구할 수 없습니다.

긴급 문서는 **회사 운영 안내 → 운영 준비**에서 미리 준비합니다. 새 문서 발급, 보안 버전 변경, 유효기간 경과 시 이전 문서를 사용할 수 없습니다. 외부 SSO·백업·보관 실행은 아직 후속 구현 중입니다.

이번 긴급 복구는 합성 계정 API 검사와 실제 Chrome에서 문서 다운로드→운영자 승인 파일 발급→파일 선택→제한 복구→재등록까지 확인했습니다. 실제 휴대폰·운영 도메인·실회사 인수는 남아 있습니다.

## 보안 변경 기록을 저장하지 못한 경우

운영 담당자가 별도 기록 저장소를 설정한 환경에서는 인증 앱·복구 코드·세션 종료·긴급 복구와 인증 시도/발급 횟수 변경을 암호화 기록으로 남깁니다. **보안 변경 기록을 저장하지 못해 변경을 적용하지 않았습니다**라는 안내가 나오면 로그인·등록·재발급·종료를 완료한 것으로 생각하지 말고 현재 상태를 확인하세요. 담당자가 저장소를 점검한 뒤 다시 시도합니다. 비밀번호·인증 번호·복구 코드·승인 파일을 오류 제보에 붙이지 않습니다.

이 별도 기록에는 비밀번호와 해시, 인증 비밀·복구 코드·세션 토큰을 넣지 않습니다. 기록의 DB 반영 대조는 서버 담당자의 제한된 점검이며 전체 계정 회수·복원 완료를 뜻하지 않습니다. 자세한 범위는 [회사 운영 도움말](/help/gw/operations)을 확인하세요.
