# 합성 비전 검사실 · 연속 검사 · PLC · C++

## 이 화면에서 하는 일

직접 만든 합성 표면 이미지로 검사 조건을 조절하고, 연속 검사와 가상 PLC 신호 교환을 체험합니다. C++ OpenCV 엔진을 선택하면 서버의 실제 C++ 프로그램으로 같은 조건을 검사합니다. 실제 카메라·PLC·MES 저장·AI 이미지 판정은 연결하지 않았습니다.

[합성 이미지 검사실 열기](/factory/vision-lab)

## 진입과 전체 흐름

3D 공장 → 비전검사 설비 선택 → 합성 이미지 검사실 열기 → 레시피 설정 → 단건 결과 비교 → 연속 검사 → 필요하면 PLC 모드 → 이력 확인·JSON 저장.

3D 공장의 정상·불합격 증가·정지 시나리오와 AI 설명은 별도 합성 자료를 사용합니다. 검사실의 현재 배치 결과가 3D 애니메이션 누계나 AI 설명에 자동 반영되지는 않습니다.

## 레시피 설정과 단건 검사

1. 정상·이물·조명 변화 중 샘플을 선택합니다. 이미지 크기는 160×100픽셀입니다.
2. 검사 영역을 전체 또는 중앙으로 정합니다.
3. 이진화 임계값과 최소 면적을 조절합니다. 임계값보다 어두운 픽셀을 모아 최소 면적 이상의 연결 영역을 검출합니다.
4. 원본/이진화 보기로 전환하고 검출 위치·OK/NG·오검출·미검출을 확인합니다.
5. **레시피·결과 JSON 저장**으로 브라우저 결과를 받습니다.
6. 같은 조건을 C++로 확인하려면 아래 **C++ 단건 검사**를 누릅니다. **C++ 결과 JSON 저장**은 서버에서 받은 네이티브 결과입니다. 조건을 바꾸면 이전 C++ 결과를 지우며 새 조건으로 다시 검사해야 합니다.

서버에서 엔진을 준비하지 않았다면 C++ 검사는 설정 오류를 표시합니다. 이때 브라우저 검사는 계속 사용할 수 있습니다. C++ 오류를 브라우저 결과로 몰래 대체하지 않습니다.

## 비교하기 좋은 조건

| 설정 | 관찰할 결과 |
|---|---|
| 이물 · 기본 조건 | 80px²와 36px²의 두 영역, NG |
| 이물 · 최소 면적 100 | 두 결함을 놓쳐 OK, 미검출 116픽셀 |
| 조명 변화 · 임계값 130 | 그림자 4,000픽셀을 추가 오검출 |
| 이물 · 중앙 영역 | 오른쪽 결함 36픽셀은 검사 영역 밖으로 분류 |

조명 변화 샘플에도 이물이 있습니다. 샘플 이름은 검출 원인이 아닙니다. 면적은 연결 픽셀 수이며 실제 mm²가 아닙니다. 미검출은 검사 영역 안에서만 계산하고 영역 밖 결함은 따로 표시합니다.

## 연속 검사

1. **연속 검사**로 전환합니다.
2. **검사 엔진**에서 브라우저 또는 C++ OpenCV를 고릅니다.
3. 투입 목표 간격 500ms 또는 200ms를 고릅니다.
4. **새 배치 시작**을 누릅니다. 정상 → 이물 → 정상 → 조명 변화를 5번 반복해 총 20회 검사합니다. 기존 3종을 반복하며 서로 다른 20장 영상이 아닙니다.
5. 완료 수·OK/NG·검사 합격률·평균 처리 시간과 NG 이력을 확인합니다.

시작 시 레시피·엔진·간격을 고정합니다. 실행 중에는 엔진을 바꿀 수 없습니다. 설정 모드 이동이나 탭 숨김은 일시정지하며 진행 중 검사는 마무리합니다. 재개는 수동입니다. 배치 종료나 화면 이탈 후 도착한 과거 결과는 집계하지 않습니다.

기본 조건은 OK 10/NG 10입니다. 최소 면적을 100으로 높이면 OK 20/NG 0이지만 미검출은 총 1,160픽셀입니다. **검사 합격률은 실제 생산 수율이나 정확도가 아닙니다.**

검사 처리 시간은 선택한 엔진 안의 검사 함수 실행 시간입니다. C++ 프로세스 기동·웹 통신·PLC 표시 대기는 포함하지 않습니다. 투입 목표 간격은 실시간 보장 시간이 아닙니다.

## 가상 PLC 핸드셰이크

배치 시작 전에 **PLC 모드 사용**을 체크합니다. 브라우저·C++ 엔진 모두 같은 가상 신호 흐름을 사용합니다.

| 단계 | 동작 |
|---|---|
| Ready | 새 검사 요청을 받을 준비 |
| Trigger · Busy | 요청을 받고 검사 시작, 중복 요청 차단 |
| Done · OK 또는 NG | 검사 결과를 고정하고 PLC 확인 대기 |
| 결과 확인 | Trigger·Done·결과 신호 해제, 다음 검사 준비 |

이 화면의 PLC는 브라우저 내부 시뮬레이터입니다. 실제 PLC 통신이나 설비 안전 제어가 아닙니다. PLC 모드에서는 **결과 확인까지 끝난 거래만** 완료 수에 포함합니다.

## 장애를 체험하고 복구하기

- **다음 검사 지연 주입**: 다음 한 번의 응답을 지연시켜 검사 제한 300ms를 넘깁니다.
- **다음 결과 확인 누락**: 자동 확인을 한 번 생략합니다. 1000ms 안에 **PLC 결과 확인**을 누르면 수동 완료할 수 있습니다.
- **중복 트리거 주입**: 검사 중 또는 결과 확인 대기 중 중복 요청이 무시되는 것을 로그에서 확인합니다.
- 제한 시간을 넘기면 **Interlock ON**과 알람을 표시하고 다음 검사를 막습니다. 확인 타임아웃에서는 Done과 판정을 유지합니다.
- **배치 JSON 저장** → **PLC 리셋** → **새 배치 시작** 순서로 복구합니다. 리셋만으로 자동 운전하지 않습니다.

장애는 제품 NG가 아닙니다. C++ 서버가 응답하더라도 PLC의 300ms 제한보다 늦으면 그 거래는 실패합니다. 탭 숨김이나 브라우저 부하도 지연에 영향을 줄 수 있습니다.

## 이력과 JSON 보관

NG 항목을 선택하면 당시 레시피·원본/이진화 이미지·좌표·면적·검사 시간을 다시 볼 수 있습니다. 새 배치는 이전 배치 이력을 교체하며 화면 이탈·새로고침 시 메모리 기록이 사라집니다.

**배치 JSON 저장**에는 고정 레시피, 실행 엔진 출처, 요청 ID, 순번, 시간, 검사 결과, 집계, PLC 사용 여부와 최근 200건의 신호 로그가 포함됩니다. 완료 수가 0인 오류 배치도 저장할 수 있습니다. 서버나 MES에는 이력을 저장하지 않습니다.

## C++ 호출은 어떻게 이어지나요

검사 조건·요청 ID → 인증된 웹 API → 서버 C++ OpenCV 실행 → 이진화·4방향 연결 영역 검사 → JSON 응답 검증 → 요청 ID 확인 → 화면 표시·배치 집계.

PLC 모드를 사용하면 이 흐름 앞뒤에 Trigger/Busy와 Done/결과 확인 단계가 붙습니다. 종료나 타임아웃 이후의 늦은 응답은 폐기합니다. 브라우저에서 서버의 실행 파일 경로나 명령을 지정하지 않습니다.

## 오류가 나타나면

- **엔진 미설정**: 운영자가 서버용 C++ 실행 파일과 실행 경로를 설정해야 합니다.
- **요청이 많음**: 잠시 후 재시도합니다. 서버는 동시 실행 수를 제한합니다.
- **응답 시간 초과·검사 실패**: C++ 실행 또는 통신 상태를 확인하고 재검사합니다. 오류를 OK/NG로 계산하지 않습니다.
- **세션 만료**: 다시 게스트 또는 회원으로 진입합니다.
- **PLC 인터락**: 로그를 저장하고 PLC 리셋 후 새 배치를 시작합니다.
