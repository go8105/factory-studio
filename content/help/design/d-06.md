# API·멱등·동시성

## 결정
- **모든 변경 요청에 멱등 키:** 상태를 바꾸는 요청은 `Idempotency-Key` 헤더가 필요합니다. 같은 키로 다시 보내면 처음 결과를 그대로 돌려주고, 같은 키에 다른 내용을 보내면 거부합니다(422). 키는 24시간 보관합니다.
- **공간 단위 쓰기 잠금:** 쓰기는 요청 공간의 잠금을 먼저 잡고, 같은 트랜잭션에서 활성 세대와 솔루션 사용 여부를 다시 확인한 뒤 실행합니다.
- **오류는 이유를 말한다:** 입력 오류는 400과 항목별 메시지, 확정된 데이터 수정·참조 중 삭제·한도 초과는 409와 이유 코드(참조처별 건수, 한도와 현재값)를 줍니다.
- 쿠키 세션 + 모든 변경 요청에 CSRF 토큰.

## 검토한 대안
| 대안 | 버린 이유 |
|---|---|
| 멱등 없이 버튼 중복 클릭만 막기 | 네트워크가 끊겨 재전송하면 출하·수금이 두 번 생깁니다 |
| 행 단위 낙관적 잠금만 | 합계 한도(소명 합계, 계획 대비 지시 수량)는 여러 행에 걸쳐 있어 행 잠금으로 막지 못합니다 |
| 만료된 키는 새 요청으로 처리 | 조용한 중복 생성보다 거부가 낫습니다 |

## 선택 이유
- 한 공간의 쓰기를 한 줄로 세우면 **합계 한도·겹침 검사가 경합 없이** 맞습니다. 게스트 공간은 사용자가 한 명이라 줄이 길어질 일이 거의 없습니다.
- 실제 동시 요청으로 검증했습니다. 예: 같은 패킹 번호로 동시에 출하하면 한 건만 성공(201·409)하고 매출도 1건만 생깁니다. 같은 LOT를 동시에 패킹해도 양품을 넘지 않습니다. 계획 1,000에 600·500 동시 지시는 초과를 막습니다.

## 한계
- 공간 잠금은 **공간 하나에 쓰는 사람이 많아지면 병목**이 됩니다. 회원 공간을 여럿이 쓰는 운영이라면 더 잘게 나눈 잠금이 필요합니다.
- 잠금 대기·문장 실행 시간 제한은 설정하지 않았습니다.
- 멱등 키 24시간이 지나면 같은 요청을 다시 보낼 수 없습니다(거부됨).
