# 만들지 않은 것과 그 이유

## 결정
범위를 좁혀 **만든 것을 정확하게** 하는 쪽을 택했습니다. 만들지 않은 것은 감추지 않고 이유와 함께 적습니다.

| 만들지 않은 것 | 이유 |
|---|---|
| SCM(공급망) | 공급망 가시성·수요 예측·공급업체 평가는 처음 기획에서 개발 범위 밖으로 정했습니다. 수요 예측이 ERP 판매계획으로 들어가는 연결 지점만 설명 카드로 안내합니다 |
| ERP 결산·재무제표·원가 | 부분적으로 맞추면 틀린 숫자가 먼저 보입니다(설계: ERP 회계 범위) |
| 구매발주·피킹·실사(재고 조사) | 창고는 재고 원장·원천 반영·조정·이동까지. 입고 검수·출고 예약은 확장 중입니다 |
| QMS 수입검사·공정검사·SPC | 1차는 LOT 단위 출하 전 최종검사와 보류·처분만 합니다 |
| QMS 보류로 패킹 차단 | 막으려면 MES가 QMS에 의존해야 합니다. 보류는 배지로만 보여 줍니다 |
| 실제 설비·계측기·공조기 연동 | 전부 합성 데이터와 결정적 모델입니다. 실제 장비를 제어한다고 주장하지 않습니다 |
| 학습 과정·진도·채점 | 제품 안내는 읽는 도움말과 흐름 맵까지입니다. 진도는 저장하지 않습니다 |

## 검토한 대안
- 모든 솔루션을 넓게 흉내 내기: 화면 수는 늘지만 어느 것도 끝까지 닫히지 않습니다. 대신 판매계획 → 생산 → 출하 → 매출 → 수금처럼 **한 흐름이 끝까지 이어지는 것**을 우선했습니다.

## 선택 이유
- 제외 항목을 먼저 밝혀 두면 "왜 없느냐"는 질문에 설계로 답할 수 있습니다.
- 솔루션 간 연계는 실제로 인터페이스가 필요한 지점을 그대로 드러냅니다(팔레트 번호 붙여 넣기, 원천 "반영" 버튼).

## 한계
- 앱 안에서 메뉴로 이동할 때는 저장하지 않은 입력을 보호하지 못합니다(새로고침·탭 닫기만 보호).
- 오래된 세대 정리, 실행 시간 제한, 게스트 상한 도달 시 재시도는 넣지 않았습니다.
- 이 목록은 현재 범위 기준이며, 창고 확장처럼 범위가 늘면 갱신합니다.
