# 회사 GW 시작과 권한 안내

회사 GW는 같은 회사의 직원이 **각자 로그인한 본인 이름**으로 기안·결재·게시·일정·채팅을 사용하는 공간입니다. 화면 위 **사용 공간**에서 회사를 선택합니다. 필요한 메뉴가 즐겨찾기에 없으면 왼쪽 **전체 메뉴**를 엽니다. **개인 체험**은 합성 담당자를 바꾸며 기능을 살펴보는 별도 공간입니다. 회사에서 만든 자료는 개인 체험으로 옮기지 않습니다. Factory Flow는 별도 시스템이며 `/work-os`에서 엽니다.

이 안내는 회사 GW 연결 기능의 로컬 검증 범위를 설명합니다. 회사 1개·부서 1개·10개의 합성 계정으로 동시 조회·채팅과 폐쇄 DB 복원 검사를 수행했습니다. 이 인원은 제품의 최대 사용 한도나 운영 용량 보장이 아닙니다. 실제 회사 시범 운영에는 별도의 인증·계정 복구·백업·보존 정책 인수가 필요합니다. 운영 배포나 실데이터 도입이 완료됐다는 의미는 아닙니다.

## 로그인과 역할

회사 목록에는 본인의 활성 소속만 표시합니다. 직원 연결이 없거나 정지된 경우 업무 원문 대신 연결 안내가 표시됩니다. 회사 소유자·HR 관리자·총 관리자도 비공개 결재·채팅을 자동으로 열람하지 못합니다. 아이디 `admin`의 총 관리자 권한과 회사 관리자, 아래 GW 역할은 서로 다릅니다. 비밀번호는 회사의 기존 계정 관리 절차로 준비하며 이 도움말에 기록하지 않습니다.

| GW 역할 | 할 수 있는 일 |
|---|---|
| 연결 직원 | 본인 기안·배정된 결재, 허용된 글·댓글·일정·참여 채팅 |
| 조직 관리 | HR 직원 가져오기·직원 연결 요청·미수락 요청 취소 |
| 결재선 관리 | 결재선 템플릿 등록·수정 |
| 전결 관리 | 일반 기안의 전결 규칙 등록·수정·삭제 |
| 공지 게시 | 본인 회사·소속 조직 공지 작성·게시 |
| 보안 관리 | 명시적 GW 역할, 연결 정지·복귀, 막힌 결재 재배정, 최소 보안 사건 조회 |
| 보안 사건 조회 | 제목·본문·금액 없는 최소 보안 사건 조회 |

‘담당자·팀장·임원·게시판 운영’이라는 직무 표시는 회사의 보안 역할을 대신하지 않습니다. 회사에서는 다른 직원의 이름으로 전환하는 ‘담당자 역할 체험’을 제공하지 않습니다.

## 처음 설정하고 동료를 연결하기

1. 회사 소유자가 회사 계정으로 로그인한 뒤 **사용 공간 → 회사명**을 선택합니다.
2. 빈 GW에서 표시되는 본인 HR 사번·이름·부서를 확인합니다. **최초 설정 사유**를 입력하고 **확인한 본인으로 최초 설정**을 누릅니다. 본인 1명만 연결하고 관리 역할 5개를 부여합니다. HR 본인 연결이 없거나 이미 직원·문서가 있으면 임의 이름으로 대신 설정하지 않습니다.
3. 조직 관리자가 **G-07 회사 직원·연결·권한 → HR에서 직원 가져오기**에서 재직 직원을 선택하고 **변경 사유**를 입력한 뒤 **선택한 직원 가져오기**를 누릅니다. 이름·조직의 스냅샷을 가져오며 계정 연결·역할은 자동 부여하지 않습니다.
4. 같은 화면의 **본인 연결 요청**에서 GW 직원과 회사 계정을 선택하고 **직원에게 연결 동의 요청**을 누릅니다. 두 항목은 같은 회사의 활성 계정·같은 HR 사번이어야 합니다. 회사 계정이 없으면 기존 회사 사용자 관리에서 먼저 준비합니다.
5. 동료가 자기 계정으로 로그인해 회사를 선택합니다. 표시된 사번·이름·조직을 확인하고 확인란을 선택한 뒤 **본인 연결 동의**를 누릅니다. 관리자가 대신 수락할 수 없습니다.
6. 조직 관리자는 직원 행의 **표시·활성 편집**에서 **GW 직무 표시·GW 직원 활성**과 변경 사유를 검토하고 **직원 상태 저장**합니다. 이름·부서는 이 화면에서 바꾸지 않습니다.
7. 보안 관리자는 직원 행의 **역할 확인**에서 필요한 역할만 선택하고 사유를 입력해 **역할 저장**합니다. 일반 직원은 관리 역할 없이도 허용된 업무를 수행합니다.

미수락 요청이 잘못됐으면 **미수락 요청 취소** 후 새 요청을 만듭니다. 한 번 활성화한 직원·계정 쌍은 다른 사람으로 바꿀 수 없습니다. **연결 정지**와 **동일 계정 복귀**만 가능합니다. 마지막 활성 보안 관리자의 역할 제거·연결 정지는 거부됩니다. 총 관리자의 긴급 계정 정지 뒤 자동으로 다른 사람을 승격하지 않습니다.

## 처음 기안해서 결재 완료하기

1. 결재선 관리자가 **G-06 결재선 템플릿 → 등록**에서 코드·이름·참여 직원을 지정합니다. **참여자 찾기**로 이름·사번을 검색할 수 있습니다. 검색은 최대 100명씩 표시하며 기존에 선택한 직원은 개별 확인합니다.
2. 각 단계에 결재 담당자를 한 명 이상 지정합니다. 같은 단계의 결재·합의가 모두 끝나야 다음 단계로 넘어갑니다. 참고 의견은 진행을 막지 않습니다. 기안자 본인이나 중복 직원을 결재선에 넣을 수 없습니다.
3. 직원이 **G-02 기안함 → 새 기안**에서 제목·본문·결재선과 필요한 금액·통화를 입력하고 **초안 저장**합니다. 회사에서는 **일반 기안**만 사용하며 ERP·PLM 원천 선택은 제공하지 않습니다.
4. 초안 상세에서 내용을 검토하고 **상신**을 선택해 처리합니다. 초안은 기안자만 읽으며, 예정 결재자도 상신 전에는 볼 수 없습니다.
5. 결재자가 자기 로그인으로 **G-03 결재함**을 열고 문서를 확인합니다. 표시되는 **승인·반려·합의·합의 반대·참고 의견** 중 본인 참여 구분에 맞는 작업을 수행합니다. 반려·합의 반대·참고 의견·회수에는 사유가 필요합니다.
6. 완료한 문서는 **G-04 결재 기록**에서 사건과 당시 조직 스냅샷을 확인합니다. 비공개 문서는 제목·검색·건수와 이전/후속 링크에서도 제외됩니다.

초안의 **편집·결재선 다시 선택**은 본인만 가능합니다. 첫 승인 이후에는 회수할 수 없습니다. 반려·회수 문서는 원본을 고치지 않고 **새 초안으로 재상신 준비**합니다. 새 초안은 이전 결재자에게 자동 공개되지 않습니다. 기존 문서·처리 사건은 삭제하거나 덮어쓰지 않습니다. **기록 인쇄 / PDF 저장**은 브라우저의 인쇄 창을 엽니다. PDF 파일 저장 여부와 실제 출력은 기기·브라우저 설정에 따르며 전자서명을 만들지 않습니다.

## 읽기 허용·회수와 막힌 결재

상신 문서의 기안자는 상세의 **문서 읽기 권한**에서 직원을 선택하고 사유를 입력해 **읽기 권한 부여**를 누릅니다. **읽기 권한 회수** 후에는 별도 참여·처리 이력이 없는 직원이 문서·댓글·관련 알림을 다시 읽을 수 없습니다. 읽기 허용은 승인 권한을 만들지 않습니다.

보안 관리자는 **G-07 → 막힌 결재 재배정**에서 비활성 담당자의 미처리 단계를 새 활성 직원에게 배정합니다. 목록에는 제목·본문·금액이 표시되지 않습니다. 본인·기안자·이미 배정된 직원으로 바꾸거나 완료 단계를 바꿀 수 없습니다. 원 담당자와 상신 스냅샷은 보존하며 새 배정 이력을 추가합니다. 이전 담당자는 복귀해도 별도 권한·실제 처리 이력이 없으면 다시 읽지 못합니다.

## 전결·위임

**G-08 전결 규칙**은 전결 관리자가 일반 기안·통화·금액 구간·시작/종료 월·최종 단계를 정합니다. 금액은 하한 이상·상한 미만, 월은 시작·종료 월을 포함합니다. 겹치는 규칙은 등록하지 못합니다. 상신에 사용한 규칙의 내용은 바꾸거나 삭제할 수 없으며 비활성화 후 새 규칙을 등록합니다. 수정·삭제 충돌은 서버 상태를 다시 확인하세요.

**G-09 결재 위임**은 현재 본인에게 배정된 미처리 결재가 있는 직원이 기간·종류·한도·사유를 정해 다른 활성 직원에게 위임합니다. 연쇄 위임·겹치는 기간·자기 자신에게 위임은 거부됩니다. 위임받은 사람도 문서의 기안자나 다른 참여자라면 대신 결재할 수 없습니다. 종료 시각은 포함하지 않습니다. 회수·기간 종료·원 담당자의 계정/연결 정지 뒤에는 새 대리 접근을 막습니다. 실제 대리 처리자의 이력은 남습니다.

## 게시·댓글·일정·채팅

- **G-05 공지·자유 게시판:** 초안은 작성자만, 게시된 회사 글은 활성 연결 직원, 부서 공지는 현재 직접 소속과 작성자만 읽습니다. 하위 조직에 자동 공개하지 않습니다. 공지 작성·게시·변경에는 현재 ‘공지 게시’ 역할이 필요합니다. 본인 초안은 저장/게시, 게시 후에는 철회하거나 정정 초안을 새로 만듭니다. 다른 작성자의 초안을 관리자가 대신 수정하지 않습니다.
- **댓글:** 상신 문서나 허용된 게시글에서 작성하고 본인 댓글만 수정·삭제합니다. 초안에는 댓글을 작성하지 못합니다. 부모 열람 권한을 잃으면 댓글·수정 이력과 성공 재시도 응답도 볼 수 없습니다.
- **G-10 조직도:** 회사 GW에 가져온 조직을 조회합니다. 조직 관리자는 HR과 대조·갱신합니다. HR의 퇴사 표시만으로 기존 GW 접근을 자동 회수하지 않습니다. 계정/회사 소속 정지 또는 GW 직원·연결 정지를 구분합니다.
- **G-11 일정:** 본인 작성·명시적 참석·현재 직접 부서 범위만 읽습니다. 작성자만 수정·취소하며 초대받은 본인만 참석 응답을 바꿉니다. 종일 일정은 한국 시간 자정부터 자정까지 입력합니다. 조회 기간은 최대 93일입니다.
- **G-12 알림:** 본인 수신 알림 중 현재 부모 문서·게시·일정을 읽을 수 있는 것만 표시합니다. 열람이 회수된 대상의 제목과 미리보기도 숨깁니다.
- **G-13 채팅:** 같은 회사의 활성 직원을 선택해 1:1 또는 그룹 대화를 만듭니다. 참여 중인 본인만 메시지를 보내고 읽음 처리·탈퇴합니다. 탈퇴 후 메시지와 이전 전송 응답을 다시 받을 수 없습니다. 현재 방식은 HTTP 조회이며 실시간 연결·참여자 변경·재입장은 제공하지 않습니다.

## 저장·취소·오류 해결

입력 패널의 **취소·닫기**는 저장 전 입력을 버립니다. 미저장 입력이 있으면 **변경 버리기 / 계속 편집**으로 확인합니다. 요청을 처리하는 동안 공간을 바꾸지 않습니다. 응답이 불명확하면 같은 입력으로 다시 확인한 뒤 변경합니다. 브라우저 탭마다 URL의 회사가 다르며 다른 탭의 선택이 세션 공간을 바꾸지 않습니다.

- **다른 작업으로 변경됨:** 버전이 바뀌었습니다. **서버 상태 다시 확인** 후 다시 검토합니다.
- **HR 또는 GW 정보가 바뀜:** 가져오기 미리보기를 다시 확인하고 선택합니다.
- **활성 GW 직원 연결 필요 / 세션 만료:** 본인 연결·계정·회사 소속을 확인하고 필요하면 다시 로그인합니다. 다른 직원을 선택해 우회하지 않습니다.
- **열람 가능한 대상 없음:** 접근 권한이 없거나 회수됐을 수 있습니다. 화면은 원문·선택 상태를 비우며, 회사/직원 연결을 확인한 뒤 **권한과 연결 다시 확인** 또는 다른 메뉴로 이동합니다.
- **마지막 보안 관리자:** 다른 활성 보안 관리자를 먼저 명시적으로 지정합니다. 긴급 정지·복구가 필요하면 별도 운영 복구 절차를 사용합니다.

권한 회수 전에 브라우저에 이미 전달한 내용까지 지운다고 보장하지 않습니다. 회사 원문을 브라우저의 영구 저장소에 저장하지 않으며, 새 요청마다 현재 권한을 확인합니다. 첨부·PDF 전자서명·메일·푸시·실시간 설비 연동은 이 회사 GW 안내의 구현 범위가 아닙니다.

## 계정 보안

회원은 상단 **내 계정 보안**에서 본인 인증 앱을 등록합니다. 등록과 직원 연결·역할 부여는 별개이며, 관리자라는 이유로 직원의 인증 앱 비밀이나 복구 코드를 조회할 수 없습니다. COMPANY 보안 모드에서는 앱 인증을 마친 세션이 회사 업무의 전제입니다. [인증 앱 등록과 휴대폰 분실 복구](/help/portal/account-security)를 따르세요. 운영 준비·SSO·긴급 복구·백업/보관의 전체 구현은 GW-READY-02에서 진행 중입니다.

보안 관리·보안 사건 조회 역할은 회사 공간의 **운영 준비**에서 본인 연결·인증 앱 수와 운영 기준을 확인합니다. [운영 준비와 보관·복구 기준 안내](/help/gw/operations)를 참고하세요. 백업·복원 및 실회사 인수가 끝난 상태를 뜻하지 않습니다.


## 본인 연결 요청을 다시 확인할 때

**본인 연결 요청 다시 확인**을 누르면 현재 회사 연결과 본인 요청을 다시 조회하고 확인 체크를 해제합니다. 표시된 사번·이름·조직을 다시 확인한 뒤 동의하세요. 취소/정지된 연결은 동의할 수 없습니다. 조회 실패 때 이전 요청을 계속 표시하지 않으며 같은 버튼으로 다시 확인할 수 있습니다.

회사 선택 링크로 이동할 때 확인 체크가 남아 있으면 **계속 편집** 또는 **변경 버리기**를 선택합니다. 변경 버리기는 화면 입력만 버리며 관리자에게 보낸 연결 요청을 취소하지 않습니다. 동의 처리 중에는 응답을 기다리세요. 화면 이동이나 초기화가 이미 전송된 동의의 취소를 뜻하지 않으므로 다시 방문하면 현재 연결 상태를 확인하세요.


## 동의 결과가 확인되지 않을 때

연결 요청이 변경됐다는 오류가 나오면 **본인 연결 요청 다시 확인**으로 새 사번·이름·요청을 확인한 뒤 다시 체크합니다. 추가 본인 확인 안내는 **내 계정 보안**에서 확인을 마친 뒤 같은 회사에서 동의를 진행합니다.

네트워크나 서버 오류로 결과가 불명확하면 **같은 동의 요청 결과 확인**을 누릅니다. 이전 요청의 같은 내용으로 결과를 확인하며 자동 재전송하지 않습니다. 이 확인 중 추가 인증이 필요하다는 응답이 와도 이전 결과가 확인된 것은 아닙니다. 이 화면을 유지한 채 **다른 탭에서 내 계정 보안 열기**로 추가 확인을 마치고 돌아와 같은 요청 결과를 확인하세요. 본인 요청을 다시 조회해도 그 명령의 결과가 확인된 것은 아닙니다. 불명확한 요청이 남으면 새 요청 동의와 회사 선택을 차단합니다. 처리 중에는 체크 변경·중복 동의·요청 재조회·회사 선택을 기다리세요.

이 확인 정보는 현재 화면의 메모리에 있습니다. 새로고침·탭 종료 후까지 보관하는 기능은 아닙니다. 화면을 닫거나 강제로 이동해도 서버 처리가 취소되지 않으므로 다시 접속하면 현재 연결 상태를 확인하고, 상태를 확인하지 못하면 조직 관리자에게 문의하세요.
