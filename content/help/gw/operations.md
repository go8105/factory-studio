# 회사 GW 운영 준비 · 보관·복구 기준

## 진입과 권한

회사 GW 공간을 선택한 뒤 **회사 운영 안내 → 운영 준비**로 이동합니다. 활성 GW 보안 관리자는 기준을 적용할 수 있고 보안 사건 조회 역할은 읽기만 가능합니다. 회사 소유자·총 관리자라는 이유로 GW 역할이나 비공개 문서 열람 권한을 자동 부여하지 않습니다. 일반 직원은 자신의 계정 보안 안내만 확인할 수 있습니다.

## 현재 표시와 제한

직원 본인 연결 수와 그중 인증 앱 등록 수를 서버가 계산합니다. 예정 인원은 용량 한도가 아닌 도입 계획입니다. 화면에 남은 조건이 표시되며, 백업·복원과 실환경 인수 연결이 끝나기 전에는 운영 준비 완료가 되지 않습니다. 실제 검사 없이 체크 표시를 눌러 준비 상태를 통과시킬 수 없습니다.

GW-READY-02 개발 브랜치에서 정책·운영 기록·보관 검토 화면과 서버용 암호화 백업·격리 복원 도구를 구현했습니다. 이 화면에서 백업·복원을 직접 실행하지는 않습니다. 운영 준비 판정과 실환경 인수는 아직 후속이며 로컬 검사와 실서버 반영을 구분합니다.

## 운영 기준 적용 순서

1. **내 계정 보안**을 새 탭에서 열고 앱 번호로 추가 본인 확인을 합니다. 5분 안에 적용해야 합니다.
2. **운영 기준 검토·적용**을 누릅니다.
3. 예정 직원/부서 수, 백업 간격, 허용 손실 시간, 복구 목표 시간, 문서/감사 검토 기한, 백업 보관 기간을 검토합니다.
4. **복구 책임자**는 같은 회사의 활성 직원 연결을 선택합니다. 본인이 준비한 책임자와 실제 보관 장소는 별도로 확인합니다.
5. **적용 사유**를 2~500자로 입력하고 변경 내용과 영향에 동의한 뒤 **새 버전으로 적용**합니다.

초기안은 직원10명/부서1개, 백업30분/허용손실60분/복구목표240분, 문서36개월/감사12개월/백업30일입니다. 기본안은 법정 보존 기간이나 실제 복구 성능 보장이 아닙니다.

## 입력 조건과 저장·취소

- 직원1~10000명, 부서1~1000개, 백업5~1440분, 허용손실1~1440분, 복구목표15~10080분, 문서/감사1~120개월, 백업7~365일의 정수입니다.
- 백업 간격은 허용 손실 시간보다 짧아야 합니다.
- 확정된 기준은 덮어쓰지 않고 새 버전을 추가합니다. 문서 기한은 검토 시점이며 원본을 자동 삭제하지 않습니다.
- **취소**·패널 닫기·Escape는 미저장 변경이 있을 때 버릴지 확인합니다. **계속 편집**은 입력을 유지합니다.
- 동시 변경 오류는 현재 서버 값과 입력을 비교해 다시 검토해야 합니다. 사유나 인증 비밀을 브라우저 영구 저장소에 저장하지 않습니다.
- 추가 본인 확인 오류는 계정 보안에서 다시 확인합니다. 다른 사람을 대신 인증하거나 준비 조건을 우회할 수 없습니다.

## 운영 실행 기록 확인·등록

**회사 운영 안내 → 운영 준비 → 운영 실행 기록**에서 최근 등록 순으로 확인합니다. GW 보안 관리자와 감사 역할은 기록을 조회할 수 있으며 보안 관리자만 등록할 수 있습니다. 일반 직원에게는 기록이나 등록 입력이 표시되지 않습니다.

1. 운영 기준을 먼저 적용합니다. 서버 운영 담당자가 실행 도구의 서명된 JSON 증거 파일을 준비해야 합니다.
2. **내 계정 보안**에서 앱으로 본인 확인을 마치고 5분 안에 돌아옵니다.
3. **서명된 실행 증거 파일**에서 20KB 이내 JSON을 선택하고 **실행 증거 확인·등록**을 누릅니다.
4. 등록 결과와 목록의 종류·통과/실패/일부 확인·종료 시각·기준 차수·실행 번호를 확인합니다. 20건씩 **이전 기록 페이지**, **다음 기록 페이지**로 이동합니다.

파일은 선택만으로 전송되지 않습니다. 등록 전에는 다른 파일을 선택하거나 화면을 나가면 됩니다. 등록된 기록은 삭제·수정하지 않으며 실패도 유지합니다. 같은 실행 번호를 새 요청으로 중복 등록하면 기존 기록을 확인하라는 안내가 표시됩니다. 응답이 불명확하면 같은 파일로 재확인하고 목록에서 실행 번호를 대조합니다.

서명·회사·적용 정책·제품/DB 버전·실행 기한이 맞지 않으면 등록하지 않습니다. 이전 기준으로 이미 저장한 기록은 **이전 기준**으로 표시하며 현재 기준의 새 검증을 대신하지 않습니다. 서버 검증 설정 오류는 운영 담당자가 확인해야 합니다. 브라우저에서 성공 여부나 서명을 직접 작성해 검사를 통과시키지 마세요.

**현재는 실행 증거의 등록·조회만 연결했습니다.** 이 버튼은 백업이나 복원을 실행하지 않으며 자동 백업·실환경 인수·운영 준비 완료를 보장하지 않습니다. 합성 실패 파일의 실제 제품 등록과 모바일 표시를 검사했습니다. 서버 운영 도구가 만드는 로컬 백업/부분 복원 증거는 등록할 수 있습니다. 외부 보관·누락 없는 회수 기록·실환경 인수는 후속입니다.

## 본인 긴급 복구 문서 준비

현재 GW 보안 관리자에게만 표시됩니다. **내 계정 보안**에서 앱으로 추가 본인 확인을 하고 5분 안에 돌아옵니다.

1. 발급 사유를 2~500자로 입력합니다.
2. 이전 문서와 미사용 승인 번호가 무효가 된다는 안내를 읽고 동의합니다.
3. **본인 긴급 복구 문서 새로 발급**을 누르고 파일을 내려받습니다. 파일에는 복구 비밀이 있으므로 별도 안전한 장소에 보관합니다.
4. 실제 보관을 확인한 뒤 **보관 확인하고 닫기**를 누릅니다. 화면에서 파일 보관 성공을 자동 확인하지는 않습니다.

문서는 365일 또는 계정 보안 버전 변경 전까지 유효합니다. 앱 재등록·복구 코드 재발급·비밀번호 변경·다른 세션 종료 등 보안 변경 뒤에는 새 문서를 준비하세요. 준비 여부와 만료일만 다시 볼 수 있으며 원문을 다시 내려받을 수 없습니다. 응답을 잃었다면 현재 준비 상태를 확인하고 새 사유로 다시 발급합니다. 같은 요청을 재전송해 원문을 복구하지 않습니다.

문서와 비밀번호는 서로 다른 장소에 보관합니다. 실제 사용에는 기존 비밀번호와 서버 운영자의 승인 파일도 필요하며, 직원이나 총 관리자에게 GW 역할을 자동 부여하지 않습니다. 자세한 순서는 [인증 앱·분실 복구](/help/portal/account-security)를 확인합니다.

## 발급량 제한과 관리자 추가 확인

계정별 정상 비밀번호 로그인 발급은 10분에 20회, 새 인증 앱 설정 키와 긴급 문서 발급은 각각 10분에 3회로 제한합니다. 실패 횟수 제한은 별도로 적용합니다. 제한을 만났다면 요청을 반복하지 말고 기다린 뒤 다시 시도하세요.

COMPANY 운영 모드의 직원 연결·역할·결재선·전결·위임·사용자 관리 변경에는 최근 5분 이내 앱 인증이 필요합니다. 운영 기준 적용과 긴급 문서 발급에는 검증 모드에서도 같은 추가 확인이 필요합니다. 일반 직원의 일상 업무마다 재인증을 요구하는 것은 아닙니다.

## 보관 검토 대상 만들기

**회사 운영 안내 → 운영 준비 → 보관 검토 · 보존 중지**로 이동합니다. GW 보안 관리자는 대상을 갱신하고 처리할 수 있으며 감사 역할은 목록·이력을 조회합니다. 일반 직원은 운영 목록 대신 기존 기안·게시판에서 허용된 원문을 사용합니다.

1. 운영 기준의 **일반 문서 검토 기한 (개월)** 항목을 적용합니다.
2. **내 계정 보안**에서 앱으로 추가 본인 확인을 하고 5분 안에 돌아옵니다.
3. **검토 대상 갱신**을 누르고 처리 사유 2~500자와 원본 유지 안내를 확인한 뒤 **사유 확인하고 적용**합니다.
4. 한 번에 최대 200건을 추가합니다. 남은 대상 안내가 있으면 다시 갱신합니다. 같은 기준의 기존 기록은 중복 생성하거나 상태를 덮어쓰지 않습니다.

대상은 종료된 일반 기안(승인·반려·회수)과 게시된 글(현재 게시 또는 철회) 중 기한이 지난 자료입니다. 초안·진행 중 기안·게시한 적 없는 글·다른 솔루션의 원문은 대상에 포함하지 않습니다. 일반 기안의 종료일, 게시글의 게시일 또는 철회일에 **달력 월**을 더하고 한국 날짜로 판단합니다. 예를 들어 2024년 1월 31일에 1개월을 더하면 2월 29일입니다. 기한이 지났어도 원본을 자동 삭제하지 않습니다.

## 목록·원문·보관 준비

- **검토 상태**로 필터하고 **원문 식별자 검색**에 숫자 ID를 입력해 **식별자로 검색**합니다. 빈 검색은 전체 식별자입니다. 기안과 게시글의 ID가 같으면 두 종류가 함께 나올 수 있습니다. 제목·본문 검색은 제공하지 않습니다.
- 목록은 기한 순이며 20건씩 이전/다음 검토 페이지로 이동합니다. 현재 기준과 이전 기준을 구분합니다. 새 기준은 이전 기록·보류를 덮어쓰지 않습니다.
- 보안 관리자·감사 담당자라도 원문 권한이 없으면 제목·본문 대신 종류·ID·기한·상태만 표시합니다. **원문 열기**는 기존 열람 권한이 있을 때만 나오며 이동한 화면에서도 권한을 다시 확인합니다.
- **보관 준비**는 현재 기준·원문 열람 가능·보류 없음 조건에서만 선택합니다. 원문을 확인하고 사유를 기록해 검토 준비 상태로 바꿉니다. 보관본 생성·검증·보관 완료를 뜻하지 않습니다.
- **준비 취소**는 검토 대기로 되돌립니다. 원본이나 별도 보관본을 삭제하지 않습니다.

## 회사 전체 보존 중지와 개별 보류

**회사 전체 보존 중지**는 해제할 때까지 보관 준비 처리를 막고 원본을 유지합니다. **회사 보존 중지 해제**에는 새 사유와 최근 본인 확인이 필요합니다. 회사 중지를 해제해도 개별 보류는 유지됩니다.

**개별 보류**는 해당 원문의 보관 준비를 막습니다. **개별 보류 해제**는 검토 대기로 되돌립니다. 이전 기준에 남아 있는 보류도 같은 원문에 적용되므로 상태를 **전체 상태** 또는 **개별 보류**로 두고 이전 기준 기록도 확인하세요. 원문 권한이 없는 보안 관리자도 자료 보존을 위한 보류·해제는 가능하지만 원문 열람이나 보관 준비 권한을 얻지는 않습니다.

중지·해제의 사유와 시각, 개별 상태 변경 전후는 **보관 검토 변경 이력**에 남습니다. 최근 변경 순으로 20건씩 조회합니다. 현재 보존 중지 상태와 최근 변경 사유도 목록 위에 표시합니다. 사유에는 비공개 원문·개인정보를 넣지 마세요. 보안 관리자·감사 담당자가 읽는 운영 기록입니다.

## 취소·충돌·현재 제한

입력 중 **취소**, 패널 닫기, Escape는 미저장 내용을 버릴지 확인합니다. **계속 편집**은 사유·동의를 유지합니다. 추가 인증 오류가 나면 새 탭에서 본인 확인 후 돌아와 다시 적용합니다. 동시 변경 오류가 나면 현재 입력을 검토하고 취소한 뒤 최신 목록에서 다시 처리합니다. 과거 성공 요청도 현재 권한·최근 인증을 통과해야 확인할 수 있습니다.

원본 삭제·익명화·보관본 내보내기·**보관 완료** 처리는 아직 연결하지 않았습니다. 보관 준비나 중지 해제만으로 원문이 삭제되거나 운영 준비가 완료되지 않습니다. 합성 자료의 윤년 기한·203건 분할·권한 회수·정책 변경 후 보류와 Chrome 대표 흐름을 검사했으며 실제 회사의 보존 규정·실자료 인수는 남아 있습니다.


## 회사 업무 변경 기록 오류

서버 운영 담당자가 별도 기록 저장소를 설정한 환경에서는 회사 최초 설정, 직원 연결 요청·본인 수락·취소·정지·재개와 역할 변경을 암호화 기록으로 남깁니다. 회사 업무 공통 처리 경로의 문서·열람자·조직·결재 권한·채팅·일정·운영 기준·보관 검토 변경도 현재 권한 상태를 기록합니다. 기록을 저장하지 못하면 **보안 변경 기록을 저장하지 못해 변경을 적용하지 않았습니다**라는 안내가 나오고 해당 변경을 취소합니다. 연결 정지나 업무 저장을 요청한 경우에도 적용된 것으로 생각하지 말고 현재 상태를 확인하세요. 담당자가 기록 저장소를 확인한 뒤 다시 시도합니다.

공통 인증의 앱 등록·번호 확인·복구 코드 사용/재발급·다른 세션 종료·로그아웃·긴급 복구 처리, 인증 시도/발급 횟수 변경과 HR 사용자 관리의 회사/직원 계정 생성·아이디/비밀번호·역할 변경·사용 중지도 같은 별도 기록을 사용합니다. 기록 오류로 중단되면 로그인이나 변경이 성공한 것으로 생각하지 말고 현재 화면과 계정 상태를 확인한 뒤 담당자에게 문의하세요. 인증 번호·복구 코드·비밀번호를 제보에 붙이지 않습니다.

별도 기록에는 직원·계정·역할·열람자의 식별자와 상태, 권한 관련 상태의 지문을 보관하며 비밀번호·비밀번호 해시·인증 번호·복구 코드·세션 토큰·원문은 넣지 않습니다. 운영 담당자는 기록의 지문과 DB 감사 기록을 대조할 수 있습니다. 담당자의 **DB 반영 확인 결과**는 점검한 기록이 해당 DB에 반영됐다는 뜻이며 현재 권한 전체나 복원 완료를 보장하지 않습니다. 미확인 기록은 실패로 단정하지 말고 담당자의 점검을 기다립니다. 설정하지 않은 환경의 자동 수집, 직접 DB 변경과 외부 보관·실제 회사 인수는 아직 확인하지 않았습니다. 기존 화면의 변경 이력과 서버 운영 담당자의 확인을 함께 따릅니다.

## 서버 백업·복원 결과 받기

백업과 복원은 서버 운영 담당자가 별도 비공개 절차로 실행합니다. 이 화면의 파일 등록 버튼으로 회사 전체 원문이나 암호화 키를 내려받을 수는 없습니다.

1. 회사의 운영 기준과 복구 책임자, 별도 보관 장소를 먼저 확인합니다.
2. 서버 운영 담당자가 **암호화 백업**을 실행하고 파일의 인증·서명·지문을 다시 확인합니다. 키는 백업과 다른 장소에 보관합니다.
3. 담당자에게 **서명된 실행 증거 JSON**을 받아 운영 실행 기록에 등록합니다. 암호화된 DB 파일·키 파일·권한 대조 파일은 등록하지 않습니다.
4. **백업 · 통과**는 실행자가 확인한 로컬 저장 범위의 결과입니다. 외부 사본·자동 실행·실제 장애 대응까지 통과했다는 뜻은 아닙니다.
5. 복원은 원본을 덮어쓰지 않는 새 접속 제한 DB에서만 진행합니다. **복원 · 일부 확인**은 직원 접속을 열어도 된다는 승인이 아닙니다. 담당자가 남은 조건을 확인해야 합니다.

변경 기록을 연결한 백업은 백업 시점에 DB 반영이 확인된 기록을 기준으로 삼습니다. 이후 기록과 당시 미확인 기록도 함께 대조하므로, 권한을 회수했다가 다시 활성화했더라도 복원한 계정이나 회사의 GW 연결이 재확인 전까지 제한될 수 있습니다. 회사 보존 중지도 적용할 수 있습니다. 원본 회사의 계정·업무를 중지하는 처리는 아닙니다.

담당자에게 점검 보고의 변경 기록 대조 건수·미확인 건수·제한 적용 범위를 확인받으세요. 미확인은 실패나 회수 완료를 뜻하지 않으며 자동으로 기록을 버리거나 접속을 열지 않습니다. 기록 연결이 없는 과거 백업은 이 대조를 수행한 것으로 인정하지 않습니다.

복원 뒤에는 기존 세션과 진행 중 인증 요청을 회수합니다. 별도로 보관한 최신 기록에서 확인한 권한 제한을 재적용하며, 옛 비밀번호·회수 권한을 자동으로 되살리지 않습니다. 판단할 수 없는 변경은 해당 범위의 연결을 격리하고 보존 중지를 유지합니다. 관리자·직원 업무와 회수 계정 거부를 실제 환경에서 확인하기 전에는 업무 재개로 처리하지 않습니다.

현재 권한 대조 기록은 운영자가 명시적으로 만듭니다. 모든 변경의 자동 외부 기록·누락 검증은 아직 연결하지 않았으므로 도구는 전체 회수 확인이나 운영 준비 완료를 표시하지 않습니다. 실서버 스케줄은 설치하지 않았고 30분 실행 템플릿만 제공합니다. 저장한 운영 기준이 서버 예약 시간을 자동 변경하지는 않습니다.

백업이 실패하거나 오래됐다는 안내가 있으면 이전 통과 기록만 보고 계속 진행하지 말고 운영 담당자에게 마지막 성공·파일 현재성·외부 사본을 확인받으세요. 암호화 키·비밀번호·실제 원문을 오류 제보나 도움말에 붙여 넣지 않습니다.

### 변경이 취소된 뒤 복원을 다시 확인할 때

운영 담당자가 원본 DB에서 변경 거래 전체의 취소를 확인할 수 있는 기록은 새 권한 대조 파일에서 제한 대상에서 제외할 수 있습니다. 기록이 없거나 아직 처리 중인 변경, 일부 단계만 취소된 변경은 자동 해제하지 않습니다.

담당자는 새 대조 파일로 **새 접속 제한 복원본**을 만들고 보고를 확인합니다. 먼저 만든 제한 복원본의 계정을 켜거나 그 DB의 접속을 여는 방식으로 처리하지 않습니다. 새 복원본도 **복원 · 일부 확인** 상태이며, 관리자·직원 업무와 남은 보안 조건을 확인하기 전에는 업무를 재개하지 않습니다. 같은 도움말의 백업·복원 순서를 함께 확인하세요.

### 과거 변경의 결과를 확인할 수 없을 때

운영 담당자에게 최신 변경 기록 지문을 기준으로 만든 점검 보고를 요청하세요. 보고에는 확인된 결과와 추가 조사할 내용이 나뉘어 표시됩니다. 기록이 오래됐거나 근거가 없으면 **확인 불가**로 남기고 해당 복원 계정·회사 연결의 제한을 유지합니다.

담당자가 검토를 마쳤어도 권한이 자동 복구되지는 않습니다. 원본 감사와 변경 경로를 조사하고 새 권한 대조·격리 복원 결과를 확인해야 합니다. 이 점검 보고 자체는 직원 접속이나 업무 재개를 허용하는 문서가 아닙니다.

### 변경 기록 사본을 별도로 보관할 때

운영 담당자는 암호화된 변경 기록을 별도 보관 위치의 새 묶음으로 복사하고, 따로 보관한 최신 지문으로 복사본을 점검할 수 있습니다. 기록 키는 사본에 함께 넣지 않습니다. 점검 통과는 그 위치의 파일을 확인했다는 뜻이며, 외부 저장 장치의 장애 복구까지 확인했다는 뜻은 아닙니다.

사본을 만들었더라도 원본 기록을 지우거나 폴더를 비우지 마세요. 사본 내보내기는 원본 기록을 유지하며 기록 한도를 초기화하지 않습니다. 활성 기록 공간을 확보하는 폴더 전환은 아래 안내를 따릅니다. 실패·누락·지문 불일치가 있으면 운영 담당자가 새 묶음으로 다시 확인해야 합니다.

### 변경 기록 보관 한도에 가까워졌을 때

운영 담당자는 과거 기록을 보존한 새 기록 폴더를 준비해 이후 기록을 이어 쓸 수 있습니다. 전환할 때는 모든 기록 작성 경로를 멈추고 원본과 새 폴더의 최신 지문을 확인한 뒤 함께 전환해야 합니다. 직원이나 회사 관리자가 제품 화면에서 처리하는 작업은 아닙니다.

새 폴더의 보존 기록은 이전 백업과의 연결에 필요하므로 지우지 마세요. 교체 후 과거 원본 폴더로 돌아가 기록을 계속 쓰면 기록이 갈라질 수 있습니다. 오류나 기록 한도 안내가 나타나면 담당자가 기록 상태와 격리 복원 결과를 확인해야 합니다. 교체만으로 운영 재개나 외부 사본 점검이 완료되지는 않습니다.

### 사본 전달 확인이 오래됐다는 안내가 있을 때

운영 담당자는 변경 기록 사본을 보관 위치에 전달하고 다시 확인한 뒤 전달 확인 기록을 남길 수 있습니다. 백업 담당 도구는 이 확인 기록에서 지문을 읽어 사용합니다. 전달이 실패했거나 확인 기록이 오래됐으면 이전 성공만으로 백업·복원을 진행하지 않습니다.

담당자에게 최근 전달 시각·미전달 변경·사본 점검 결과를 확인받으세요. 별도 폴더의 사본만으로 외부 장애 복구가 검증된 것은 아닙니다. 실제 저장 장치와 네트워크 장애 후 복구는 별도 확인이 필요합니다. 키나 실제 회사 정보를 오류 제보에 붙여 넣지 않습니다.

### 실행 증거 확인 결과 읽기

회사 공간의 **운영 준비 → 실행 증거 확인**에서 백업 실행·복원 실행·실환경 업무 인수의 최근 등록 결과를 확인합니다. 보안 관리자와 감사 담당자가 볼 수 있으며, 일반 직원은 내 계정 보안 안내를 따릅니다.

- **등록된 실행 기록이 없음**: 해당 종류의 서명된 실행 증거를 운영 담당자에게 요청합니다.
- **최근 실행 미통과 / 일부 확인**: 원인을 해결하고 새 실행을 검증한 뒤 등록합니다. 과거 통과가 최신 실패를 대신하지 않습니다.
- **기준·제품·DB 버전 불일치 / 기한 경과**: 현재 기준으로 다시 실행합니다. 백업은 허용 손실 시간 안의 시점인지도 확인합니다.
- **실행자 키 또는 결과를 확인할 수 없음**: 운영 담당자가 서버 검증 설정과 기록을 조사합니다. 화면에서 임의로 통과로 바꾸지 않습니다.
- **현재 기준의 등록된 통과**: 보존된 원본의 서명과 등록된 결과를 현재 신뢰 키·기준으로 다시 확인했다는 뜻입니다. 외부 저장소 장애·복구, 모든 권한 회수와 실제 회사 업무 인수까지 완료했다는 뜻은 아닙니다.

실행 증거를 등록하면 이 결과도 갱신됩니다. 현재는 운영 준비 완료로 전환하는 기능을 열지 않았습니다. 전체 회수·실환경 인수 조건이 남아 있으며, 등록된 통과가 보이더라도 직원 접속이나 업무 재개 승인으로 사용하지 않습니다.

### 원본 재검증 불가 또는 서명 대조 실패가 표시될 때

이 기능을 적용하기 전에 등록한 기록은 원본 서명 대상 내용이 없어 다시 검증할 수 없습니다. 없는 내용을 추정해 복원하거나 과거 기록을 수정하지 않습니다. 운영 담당자가 새 실행을 검증하고 서명된 증거를 새로 등록해야 합니다.

원본이 있는 기록도 서명·회사 범위·실행 번호·결과·검사값이 맞지 않거나 현재 신뢰 키로 확인되지 않으면 통과로 표시하지 않습니다. 담당자에게 기록과 키 설정을 조사받으세요. 현재 키로 원본을 다시 확인한 결과도 실제 외부 장애 복구나 모든 권한 회수의 완료를 대신하지 않습니다.

### 로그인 요청이 만료되거나 기록 저장을 확인할 수 없을 때

로그인 요청 생성·실패 횟수·만료도 운영자가 확인할 보안 변경 기록에 포함합니다. 인증 번호나 비밀번호 자체를 별도 변경 기록에 저장하지 않습니다. 요청 만료 안내는 로그인부터 다시 시작하고, 잠시 기다리라는 안내가 있으면 해당 시간을 따른 뒤 시도하세요.

**보안 변경 기록을 저장하지 못해 변경을 적용하지 않았습니다**라는 안내가 있으면 운영 담당자에게 기록 저장소 상태를 확인받으세요. 이 안내만으로 비밀번호나 권한이 변경됐다고 판단하지 않습니다. 담당자에게 비밀번호·인증 번호·복구 코드를 보내지 않습니다.

### 초기 계정 설정과 세션 만료

변경 기록을 설정한 환경에서는 운영 담당자가 회원이나 초기 회사 계정을 만들고 중지·활성화할 때도 계정 상태 기록을 남깁니다. 기록 저장에 실패하면 해당 생성·활성화도 취소되므로, 화면이나 도구의 실패 안내를 계정 설정 완료로 해석하지 않습니다. 실제 초기 계정 설정은 운영 담당자의 절차를 따릅니다.

사용 중 세션의 유휴 만료 시간이 연장되더라도 복원 뒤에 이전 로그인 상태를 되살리지 않습니다. 복원 점검 이후에는 다시 로그인해야 합니다. 로그인 유지 시간이 늘어났다는 이유만으로 회수된 세션을 사용할 수 있는 것은 아닙니다.

### 복원 뒤 이전 로그인으로 접속되지 않을 때

격리 복원에서는 관리자와 직원의 이전 로그인 상태를 모두 회수하고, 아직 끝나지 않은 로그인 요청도 만료시킵니다. 이전 브라우저의 토큰이나 진행 중이던 인증 요청으로 접속되지 않는 것은 이 제한에 따른 동작입니다.

운영 담당자가 별도로 복원 인수와 업무 재개를 승인하기 전에는 직원 접속을 열지 않습니다. 과거 직원 계정이나 권한이 화면에 보인다는 이유만으로 다시 사용할 수 있다고 판단하지 마세요. 역할 변경으로 이미 회수된 로그인도 자동으로 되살리지 않습니다.

### 운영 전환 조건 확인하기

회사 공간의 **운영 준비 → 운영 전환 조건**에서 조건별 상태와 다음 행동을 확인합니다. 보안 관리자와 감사 담당자가 볼 수 있습니다.

- **확인됨**: 현재 DB 상태나 원본 서명을 재검증한 최신 증거가 해당 조건에 맞습니다. 운영 전체의 완료를 뜻하지 않습니다.
- **조치 필요**: 운영 기준·담당자 연결·조직·직원·인증 앱 또는 실행 증거 조건이 부족합니다. 각 항목의 안내를 따라 조치합니다.
- **미확인**: 외부 저장소 장애 복구·전체 수집/회수·실제 회사 업무·최종 전환처럼 제품에 완료 근거가 연결되지 않은 조건입니다. 합성 검사나 기록 사본만으로 확인됨으로 바꾸지 않습니다.

담당자 조건은 현재 계정·회사 멤버십·직원 연결이 모두 활성인지 확인합니다. 담당자 연결을 회수하면 다시 조치가 필요합니다. 조직 등록은 활성 조직 수를 예정 부서 수와 비교하며 모든 직원의 부서 배치까지 확인하는 것은 아닙니다. 직원 조건은 예정 인원 이상의 활성 본인 연결, 인증 앱 조건은 활성 연결 전원의 등록 여부를 확인합니다.

백업·복원·인수 조건은 현재 기준의 원본 서명이 확인된 통과 증거가 필요합니다. 미통과·일부 확인·기한 경과·원본 재검증 불가는 조건 충족으로 세지 않습니다. 확인된 조건이 많아도 미확인 조건이 남아 있으면 운영 준비 완료가 아닙니다. 이번 버전에는 최종 승인이나 직원 접속을 여는 버튼이 없습니다.
